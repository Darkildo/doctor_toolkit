# Каталог типов ресурсов

Идентификаторы ресурсов в Stream — 4-байтные теги (`rwID_*`, RenderWare-стиль)
или строки (`tg4h`/`tg4d`/`LH2`). Ниже — точные layout'ы.

## 1. TG4 — `tg4h` / `tg4d` (текстуры)

**Проверено на GF2 PC**: все 28 246 текстур разбираются, заголовки записываются
обратно побайтно, размеры данных совпадают с цепочкой уровней. Прежнее описание
этого раздела было неверным.

Текстура состоит из двух ресурсов одного потока: `tg4h` (заголовок) и `tg4d`
(пиксели). Последний идентификатор в `SHDR` у обоих равен хэшу имени текстуры;
`tg4d` обычно идёт сразу за `tg4h`. Третий идентификатор (`ids[2]`) — CRC-32 имени
пакета в нижнем регистре (`crc32("assets_shared_fonts") = f3d257db`; проверено на
всех 28 246 текстурах, `docs/navigation.md` §2). Функция хэша имени не найдена.

### 1.1 `tg4h`, версия 3

```
0x00  u32  смещение строки пакета ("assets_shared_fonts")
0x04  u16  версия = 3
0x06  u16  число текстур = 1
0x08  u32  смещение записи текстуры = 0x14
0x0C  u32  0x18 (назначение неизвестно)
0x10  u32  хэш бюджета: 0 (в tx4h — CRC-32 `ui`)
0x14  запись текстуры:
      u32  хэш имени (= последний id ресурсов пары)
      u32  смещение строки имени
      u32  размер данных tg4d
      u16  ширина
      u16  высота
      u16  0
      u8   число поверхностей: mip-уровни (2D), грани (cube, 6) или слои (3D)
      u8   число параметров N
      u32  смещение хэшей имён параметров (N × u32)
      u32  смещение значений параметров (N × 5 байт: u8 вид, u32 значение)
0x30  хэши параметров, значения, затем строки: строковые значения параметров,
      имя пакета, имя текстуры (через NUL)
```

Вид значения 0 — смещение строки, 1 — целое. Хэш имени параметра — CRC-32
имени в нижнем регистре (как у материалов); имена подсказаны сверкой с
другим редактором и подтверждены на всех 28 246 `tg4h`: 76 237 из 104 483
вхождений совпали с CRC-32 известного имени, остальные 28 246 — параметр
размера, его имя не найдено (`size` не подходит).

| Хэш | Имя | Значение |
|---|---|---|
| `0xDEBA72DF` | `format` | формат: `DXT1c`, `DXT1a`, `DXT5`, `DXT5_NM`, `L8`, `A8`, `L8A8`, `RGBA8` |
| `0x4F8B2A9F` | — | размер данных `tg4d` (целое, равно размеру в записи) |
| `0x58BE9388` | `color_space` | `sRGB` для гамма-кодированного цвета |
| `0x7FC45F1D` | `filter` | фильтрация: `aniso`, `point` |
| `0x7506D366` | `edge` | адресация: `clamp`, `border-black` |
| `0x97CA47AB` | `mode` | вид: `cube`, `3d`; отсутствует у 2D |
| `0x96597B2E` | `mipmap` | `"1"` у 28 174 текстур |

Поле `0x10` заголовка — хэш «бюджета»: 0 во всех `tg4h`, CRC-32 строки `ui`
во всех 74 блоках `tx4h` файлов `apx`. Два байта после высоты в записи —
выравнивание (0 везде).

### 1.2 `tg4d`

Поверхности подряд без выравнивания, в порядке DDS: для 2D — mip-уровни от
большего к меньшему; для cube — 6 граней; для 3D — слои. У кубических и объёмных
текстур mip-уровней нет. Блочные форматы округляют каждый уровень до целых
блоков 4×4 (уровень 1×1 занимает целый блок).

Порядок байт `RGBA8` — B, G, R, A (Direct3D `A8R8G8B8`); подтверждено по
таблицам цветокоррекции `lutcolor_*`, где красный растёт по оси X.
`DXT5_NM` хранит нормаль: X в альфе, Y в зелёном.

Встречаемость в GF2: DXT1c 17 296, DXT5 5 507, DXT5_NM 4 717, DXT1a 527, L8 181,
RGBA8 13, A8 4, L8A8 1.

## 2. TXD — `rwID_TEXDICTIONARY` (RenderWare Texture Dictionary)

Тип регистрируется строкой **`rwID_TEXDICTIONARY`** (18 символов).

Классы: `RwTexture`, `RwNativePLG`, `RwBinaryAsset`, `RwBinaryManager`.

Формат — стандартный RenderWare TXD: словарь чанков `rwID_STRUCT` с вложенными
чанками `rwID_TEXTURENATIVE` (`RwNativePLG`: растровые данные + палитра + mip-уровни)
и `rwID_EXTENSION`. Правка внешняя (Magic.TXD); замена текстур без
добавления/удаления.

## 3. DFF — `DFFResource` (RenderWare модель)

Читает чанк `rwID_CLUMP`:

| Порядок | Размер | Поле |
|---|---|---|
| 1 | 12 | chunk header (type/size/version, см. `stream.md` §3) |
| 2 | u32 | `num_atomics` |
| 3 | u32 | `num_lights` (assert == 0: «This Clump has lights!») |
| 4 | u32 | `num_cameras` (assert == 0: «This Clump has Cameras!») |
| 5 | | frame list |
| 6 | | geometry list |
| 7 | | atomics |
| 8 | | extensions |

Иерархия: `RwClump` → `RwFrame` → `RwGeometry` → `RwAtomic`; плагины
`RwBinMeshPLG` / `RwSkinPLG` / `RwUserDataPLG` (стандартные RenderWare PLG).

## 4. LH2 — локализация (magic `LCH2`)

**Проверено на GF2 PC**: все 21 таблица разбираются и записываются обратно
побайтно. Прежнее описание этого раздела было неверным.

```
0x00  "LCH2"
0x04  u32  полный размер
0x08  u16  версия = 1
0x0A  u16  флаги = 0x4000 (строки в UTF-8)
0x0C  u32  смещение таблицы языков; 0, если язык один
0x10  u32  число записей N
0x14  u32  число языков M
0x18  u32  0
0x1C  u32  0
0x20  N × u32      хэши записей, по возрастанию: SDBM имени записи в нижнем регистре
      N*M × u32    смещения строк по языкам: offsets[lang * N + entry]
      строки UTF-8 через NUL, подряд в порядке смещений, без общих строк
      таблица языков (если есть): M × 8 байт, код с нулями ("en", "cs", ...)
```

Основные тексты игры лежат в потоках `gf2/text/<hash>.str`, по одному языку
на поток. Ресурс `lhr` — текстовый список «код языка, поток, хэш потока»:
`en` → `gf2\text\DD7D7050`, `es` → `AD8BF024`, `ss` → `D70E6B6C`, `ll` → `856C146C`.
Таблицы мультиплеерных карт и роликов содержат до 12 языков в одном ресурсе.

### 4.1 Идентификатор записи (этап 18)

**Проверено по коду игры и данным.** Хэш записи — SDBM имени записи, в
котором буквы A–Z переведены в нижний регистр: `h = h × 65599 + байт`
(`godfather2.exe` `0x004DB060`; тулкит — `hash::string_id`). Пример:
`fe_press_start` → `cbd0a3c6` («Press any key»), `ui_pro_select` →
`486f5259`, `ui_pro_create` → `11132259`.

Поиск строки (`0x00603330` → `0x006039D0`): двоичный поиск хэша
(`0x00605D00`) по всем загруженным таблицам, начиная с последней
загруженной; первая найденная выигрывает. Строка форматируется
(`0x00603610`): `$имя` подставляет строку записи `string_id(имя)` (имя —
буквы, цифры, `_`), `#n` — число, `{x:…}` — параметры.

Кто ссылается на строки:

| Где | Как | В корпусе |
|---|---|---|
| интерфейс `apx` (блоки `apti`, `cons`) | строка `$имя` с NUL, например `$fe_press_start` в `gf2/frontend` № 20 | 981 разное имя |
| SimGroup | атрибуты типа `hash` хранят хэш: `NPC.18` (имя), `CSACrewComponent.24`, `UIHudTutorial.2`, `UIHudObjective.2/3`, `UIJobInfo.6–8, 11`, `MultiplayerScenario.6/7`, `MultiplayerMapInfo.2/3`, `JobReward.8–10`, `HitMission.6–9`, `UIFanfare.1`, `UpgradeData.1/2`, `CheckpointFailure.0/1`, `Family.3/4`, `City.5` | 3 981 разный хэш, 4 788 мест |
| `dlg` | имена (`hud_csa_takeover`) | 131 |
| код игры | имена строками (`ammo_pistol`, `cmap_*`) | 682, `data/gf2/string_names.txt` |

С этими именами словарь (`lookup`, `unknown-hashes`) называет 1 236 записей.

**Таблица имён записей (этап 40).** Одна из четырёх таблиц `gf2/text/*.str`
с 9 069 записями — `gf2/text/d70e6b6c` (ресурс `286368cb`) — вместо текста
хранит имена записей: у 8 239 записей SDBM нижнего регистра текста равен хэшу
самой записи (`name_npc_lwd_0154` → `a6201a78`, `Credits_DesignDD_Num` →
`0003ac0a`). Словарь игры берёт текст любой записи, если его хэш — хэш
какой-либо записи игры (`Dictionary::for_game`). Без имени остаются 507
хэшей записей в 2 007 местах (до этапа 40 — 7 963 в 30 901, до этапа 18 —
9 199).

### 4.2 Новые строки

`text-add ИГРА ИМЯ ТЕКСТ [--lang es=…] [--table ПОТОК:НОМЕР]` добавляет
запись с хэшем `string_id(ИМЯ)` во все таблицы языков из `lhr` (или в
указанные таблицы, во все их языковые столбцы) одной операцией рабочего
пространства. Хэши остаются отсортированными, строки идут в порядке записей
(`StringTable::insert`). Имя, чей хэш уже есть в любой таблице игры,
отклоняется: игра нашла бы старую строку. В редакторе — «Add string» в
таблице `lh2` («Every language» — во все таблицы языков).

Ссылки на новую строку: в `apx` — `apx-text-refs ИГРА ПОТОК НОМЕР --set
старое=новое` (строка `$старое` переписывается на месте, поэтому новое
имя не длиннее старого; без `--set` команда перечисляет ссылки с текстом);
в SimGroup — `simgroup-set … --set Класс.индекс=хэш`.

Корпусный тест `new_strings_are_added_to_every_language_and_referenced_on_copies`:
на копиях `gf2/frontend` и четырёх таблиц языков запись добавлена во все
четыре (с испанским переводом), остальные записи не изменились, `$fe_press_start`
в `gf2/frontend` № 20 указывает на новую запись, отмена возвращает файлы
побайтно.

## 5. APX — `apx` (интерфейс на Flash, инструменты Apt от EA)

**Проверено на GF2 PC**: все 97 файлов разбираются и записываются обратно
побайтно, 466 встроенных текстур декодируются. Исключение — один APX в
`globals_global.str`, переписанный старым тулкитом с другим выравниванием;
его оригинал из резервной копии проверку проходит.

```
0x00  "apxf" (little-endian u32 0x61707866, в файле байты "fxpa")
0x04  u32  полный размер
0x08  блоки: u32 тег, u32 размер вместе с этими 8 байтами, данные
```

| Тег | Содержимое |
|---|---|
| `titl` | имя ролика через NUL |
| `apti` | данные ролика Apt, начинаются с `Apt Data:` — это файл `.apt` инструментов EA, **не SWF** |
| `cons` | таблица констант Apt, начинается с `Apt constant file` — файл `.const` |
| `rubi` | неизвестные двоичные данные |
| `tx4h` | заголовки текстур в формате TG4, бывает несколько текстур в одном блоке (§1.1) |
| `tx4t` | данные одной текстуры; идут за своим `tx4h` в порядке записей |
| `alig` | нули; данные следующего блока начинаются на границе 16 байт |

Многотекстурный заголовок — общий случай `tg4h`: массив хэшей имён по
смещению из `0x08`, записи по 0x18 байт по смещению из `0x0C`, поле `0x10`
содержит хэш. Строки параметров, имя пакета и имена текстур лежат в общем пуле
и используются повторно, если совпадают.

**Выравнивание.** Данные каждого блока, кроме `titl` и `alig`, начинаются на
границе 16 байт (все файлы игры, кроме переписанного старым тулкитом). Блок
`alig` стоит только там, где без него выравнивания нет: в 5 файлах из 97
`apti` и `cons` идут подряд, в некоторых `alig` есть и в конце файла. Значит,
блок, изменивший размер, может сдвинуть следующий блок без `alig`.

**Правка** (`AptFile::set_texture`, `import_texture`, `set_apt`,
`set_constants`; команда `apx-import`, кнопки в GUI):

- встроенная текстура заменяется целиком: заголовок в своём наборе `tx4h`
  (остальные заголовки набора не меняются, набор пишется `tg4::set_to_bytes`,
  который воспроизводит все наборы игры побайтно), данные — в своём `tx4t`.
  PNG кодируется в исходный формат, имя, хэш и параметры сохраняются;
- **число мип-уровней сохраняется.** Текстуры APX `frontend` хранят один
  уровень; с полной цепочкой у `popup` (11 уровней) и `cursor` (6) игра
  падает при запуске: запись за границу буфера по адресу `0x00BAADFA`
  (атлас логотипа с 12 уровнями один падения не вызвал — вероятно, его
  буфер не используется на первых экранах). Размер изображения менять можно: курсор 64×64 вместо 32×32
  работает и рисуется в прежнем размере. DDS с другим числом уровней
  отклоняется;
- `.apt` и `.const` заменяются целиком; проверяется только сигнатура
  (`Apt Data:`, `Apt constant file`);
- после любой правки `align_blocks` вставляет `alig` перед блоком, который
  оказался не выровнен; `to_bytes` пересчитывает размеры всех `alig` и полный
  размер в 0x04. На неизменённых файлах это ничего не меняет.

Тест корпуса `every_apx_takes_texture_and_movie_replacements`: в каждом из 97
файлов `apti` удлиняется на 5 байт, все 466 встроенных текстур заменяются PNG
другого размера; после записи все блоки выровнены, заменены ровно нужные
текстуры. В игре (стенд, теневая копия `gf2/frontend.str`): текстуры `popup`
(512×1024, синяя вместо оранжевой) и `cursor` (зелёный, затем жёлтый 64×64)
видны на экране «Select Profile»; `.apt` окна `popup`, удлинённый на 16 байт,
загружается. Логотип на титульном экране — не из `frontend.apx` (замена его
атласа на экране не видна; вероятно, логотип в видеоролике).

## 6. Материалы/шейдеры

Шейдерные базы загружаются из JSON.

### Шейдерные базы (JSON, наша реформулировка)

`gf2_shaders.db`:
```
[{ name, constants: [{ name, register_set: int, register_index: int,
  register_count: int, type: int, class: int }] }]
```
- `register_set` 2 = векторные/скалярные константы, 3 = сэмплеры (текстуры);
- `class` 0..4 — категория (scalar/vector/matrix/…/sampler).

`*_shaders_translations.db`:
```
[{ shader_name_id: uint | shader_name: string, keys: { "TextureName": "<sampler>" } }]
```
- DS2: ключ по `ShaderNameID` (u32); GF2: ключ по `ShaderName` (строка).

## 7. Entity — MetaModel

> **Устарело.** Раздел написан без образцов данных и неверен; формат,
> проверенный на GF2 PC, — в `metamodel.md`.

Игровые сущности — это **MetaModel** (компонент `MetaModelComponent`); при
отсутствии явного имени используется строка по умолчанию «Implicit MetaModel».

Сериализованный формат сущности совпадает с форматом **MetaModel**:

| Порядок | Размер | Поле |
|---|---|---|
| 1 | u32 | `magic` = `0x4D4D646C` (`MMdl`) |
| 2 | u32 | `version` = **10** (`0xA`) или **14** (`0xE`) |
| 3 | u32 | `file_size` (assert == размер читателя) |
| 4 | u32 | поле |
| 5 | 16 | заголовок атрибутов: 4 × u32 (`ZeroBitArray` + `AttributesPresentMap`, как в SimGroup §5.2) |
| 6 | u32 | поле |
| 7 | u32 | поле |
| 8 (только v14) | u32 | поле |
| 9 | u32 | поле |
| 10 (только v14) | u32 | поле |
| 11 | 6 × (u32 + u16) | шесть типизированных массивов (счётчик + размер элемента) |
| 12 (только v14) | u32 + u16 | седьмой типизированный массив |

Шесть (или семь в v14) типизированных массивов — это таблицы подмоделей MetaModel
(состояния, атрибуты, части и т.д.), каждый: `u32 count` + `u16 element_size` + data.

> Замечание: «Entity» — это по сути экземпляр MetaModel (объект сцены), а не
> отдельный формат. Полная схема MetaModel (типы атрибутов, состояния) совпадает
> с reflection-системой `Sim::*` и JSON-схемой `*_simgroup.db` (см. `simgroup.md`).

**Id `smb` и `sbk` — SDBM пути сборки** (этап 40, все 59 + 8):
`levels\<игра>\<уровень>\streams\<поток без первой части>.<тег>`, путь
через обратную косую черту, в нижнем регистре. Поток `gf2/cuba/local` даёт
`levels\gf2\cuba\streams\cuba\local.smb` (`a83a79b8`); папка уровня —
вторая часть имени потока, у глобальных потоков — она же без `_global`
(`gf2/globals_global` → `levels\gf2\globals\streams\globals_global.smb`,
`gf2/globalfolder/…` → `levels\gf2\globals\streams\globalfolder\…`).
Словарь строит эти пути из имён потоков и оставляет тот, чей хэш равен id.
У остальных типов id не равен ни одной известной функции от имени или пути
ресурса.

## 11. `ffn` — растровые шрифты

**Проверено на GF2 PC**: 6 ресурсов, три шрифта по две копии (`frontend` и
`globals_global`): `buttons` (80 глифов, значки кнопок), `impact_lt_std` (241),
`aachen_std_bold` (252). Атлас — текстура того же потока с именем шрифта
(512×512, DXT5). Все прямоугольники глифов лежат внутри атласа.

```
0x000  "TNOF" (u32 0x464F4E54)
0x004  u32  размер файла
0x008  u16  версия = 7
0x00A  u16  число глифов N
0x00C  u32  смещение таблицы глифов = 0x454
0x010  u32  0
0x014  3 × u32  метрики шрифта, смысл не установлен (impact: 43, 50, 41)
0x020  char[32]  имя шрифта = имя текстуры-атласа
0x040  u32  смещение области страниц (конец таблицы глифов)
0x044  256 × u32  каталог страниц: для старшего байта UTF-16 смещение страницы
       0x400 байт от области страниц, 0 — нет глифов
0x448  u32  число записей кернинга
0x44C  u32  смещение кернинга (по 3 байта на запись, раскладка не разобрана)
0x450  u32  0
0x454  N × глиф (24 байта):
       u16 код UTF-16, u16 ширина, u16 высота, u16 шаг,
       i16 сдвиг X, i16 сдвиг Y, 4 × u16 прямоугольник в атласе
       (лево, верх, право, низ) в 1/16 пикселя, u32 0
далее  страницы, заполненные нулями: игра пишет в них указатели на глифы
```

Страницы у `impact_lt_std`: U+00xx–U+03xx, U+20xx–U+22xx, U+FBxx. Кириллицы
(U+04xx) нет ни в одном шрифте. Для её добавления нужны записи глифов, страница
для U+04xx в каталоге, место в атласе (у `impact_lt_std` занята примерно
половина) и сдвиг смещений после таблицы глифов.

Экспорт: `doctor-toolkit fonts <игра> -o <каталог>` — PNG атласа и JSON с метриками.

## 12. `lua` — скрипты

**Проверено на GF2 PC**: все 30 ресурсов — байт-код Lua 5.0 (`luac`), разобран
до конца файла. Все из `x:\assets\shared\audio\lua_scripts\` — логика звука и
музыки. Заголовок:

```
"\x1bLua" 0x50  1 (little-endian)  4 4 4 (int, size_t, Instruction)
6 8 9 9 (SIZE_OP, A, B, C)  4 (sizeof(lua_Number)) + float 3.14159265e7
```

`lua_Number` — **float (4 байта)**, а не double. Полный формат, компилятор,
декомпилятор и правка — `lua.md`. Экспорт байт-кода: `doctor-toolkit
lua-export <игра> -o <каталог>` пишет `.luac` с именами исходных файлов.
