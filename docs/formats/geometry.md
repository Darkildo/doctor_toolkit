# Формат: геометрия `mesh` / `meshvolatile` и материалы

**Проверено на GF2 PC**: все 17 622 ресурса `mesh` и 157 229 записей отрисовки
декодируются; позиции лежат внутри габаритов модели, нормали единичные.
Прежнее описание («EARSGeom», поток полей, подмеши по 0x10) было неверным.
Раскладки получены анализом данных и функции `0x004C7B40` в `godfather2.exe`.

Для Dead Space (V33/V50) данных нет; этот документ описывает только версию 42.

## 1. Общее устройство

`mesh` — образ памяти 32-битного процесса с таблицей релокаций. Каждый
указатель — смещение в склейке `mesh ‖ meshvolatile`; данные `meshvolatile`
начинаются со смещения `len(mesh)`. Нулевой указатель — 0.

`meshvolatile` — следующий ресурс потока с идентификатором `~id` меша
(17 572 из 17 572). Заголовка у него нет: это сырые данные второго
вершинного потока. 50 мешей теней машин и персонажей живут без него.

| 0x3C / 0x3E | u16 | число вершинных / индексных буферов |

## 3. Дескриптор буфера (0x10 байт)

| Смещение | Тип | Смысл |
|---|---|---|
| 0x0 | u32 | размер = число × шаг |
| 0x4 | u32 | число элементов |
| 0x8 | u16 | шаг; у индексных буферов 2 (16-битные индексы) |
| 0xA | u8 | формат вершин (§5); у индексных буферов 1 или 2 |

## 4. Запись отрисовки (0xB0 байт)

| Смещение | Тип | Смысл |
|---|---|---|
| 0x00 | ptr | имя |
| 0x04 | u8 | тип меша: 2 — статика (143 376 записей, без костей), 1 — скиннинг (13 853, в том числе все 519 записей с морф-целями) |
| 0x05 | u8 | тип индексов: 2 — полоса, 1 — список; совпадает с примитивом `0x3C` и байтом 0xA индексного буфера |
| 0x06 | u8 | тип скиннинга: 0xFF — статика, 0 — одна жёсткая кость (`0x24`, 11 921 запись), 1–4 — наибольшее число костей на вершину (все 1 932 записи со скиннингом на CPU; у записей форматов 11/12 всегда 2) |
| 0x07 | u8 | формат вершин |
| 0x08 | u32 | флаги отрисовки; бит `0x4000` (LowLODOnly) стоит у всех записей форматов 11 и 12 и только у них (28 805 записей корпуса), по нему движок выбирает 16-байтный источник скиннинга; запись другого формата с этим битом игра рисует растянутыми треугольниками (этап 24). | 0x0C | u32 | хэш материала = CRC-32 имени в нижнем регистре |
| 0x10 | 4×f32 | ограничивающая сфера записи |
| 0x20 | ptr | габариты: 8 углов OOBB (статика) или AABB (скиннинг) |
| 0x24 | u8 | жёстко привязанная кость или 0xFF |
| 0x25 | u8 | размер палитры костей |
| 0x26 / 0x27 | u8 | шаг потока 0 / потока 1 |
| 0x28 | u8 | слой наложения (декали): 0 — обычная геометрия (136 092), 1–16 — слои поверх неё; совпадает с `_ov_N` в имени записи в 12 472 из 12 480 случаев; флаг `0x1000` стоит только при слое > 0 |
| 0x29 | u8 | группа видимости, всегда 0 |
| 0x2A | u16 | индекс видимости, всегда `0xFFFE` |
| 0x2C / 0x2E | u16 / u16 | число морф-целей / `CustomOpaqueId` (всегда 0) |
| 0x30 | u32 | число индексов |
| 0x34 | u32 | первый индекс в буфере |
| 0x38 | u16 | число вершин = max − min + 1 |
| 0x3A | u16 | смещение записи в динамических (CPU) вершинах; равно минимальному индексу `0x40` у всех 157 229 записей корпуса (корпусный тест). Старое значение из шаблона заставляло скиннинг на CPU писать чужой диапазон — вероятная причина растянутых треугольников у импортированных персонажей (этап 24, исправлено, в игре не проверено) |
| 0x3C | u16 | примитив: 4 — список, 5 — полоса |
| 0x3E | u16 | число примитивов: у полосы — число индексов, у списка — треугольников, по модулю 65 536 (одна полоса `miami/local` длиннее 65 535 индексов). Сверено со всеми 157 229 записями (корпусный тест); сборщик пишет так же (`mesh_build::primitive_count`, до 2026-11-13 ограничивал 65 535) |
| 0x40 / 0x42 | u16 | минимальный / максимальный индекс |
| 0x44 | ptr | палитра костей `{u8 кость скелета, u8 индекс в таблице}` |
| 0x48 | ptr | сдвиг сортировки на вершину, по байту (только у 61 записи с `TriSort`) |
| 0x60 | i32 | номер GPU-индексного буфера |
| 0x64 | i32 | номер статического вершинного буфера (среди GPU) |
| 0x68 | i32 | номер CPU-вершинного буфера (скиннинг на CPU) |
| 0x6C | i32 | номер вершинного буфера потока 1 (среди GPU) |
| 0x70 | i32 | номер CPU-индексного буфера (отсортированного, у записей с `TriSort`); `0x74` — всегда 0 |
| 0x84 | ptr | вершины потока 0, уже со смещением на минимальный индекс |
| 0x88 | ptr | индексы записи |
| 0x8C | ptr | пространственная сетка треугольников (статика) |
| 0x90 / 0x94 | ptr | морф-цели `{u32 хэш, 1, число, начало}` и дельты `{f16×3, u16 вершина}` |
| 0xA0 | 4 × f32 | цвет-множитель `TintRGBA`, (1, 1, 1, 1) во всех записях |

Биты флагов отрисовки `0x08`, которые встречаются в игре:

| Бит | Имя | Записей | Подтверждение |
|---|---|---|---|
| `0x0008` | `AlphaSort` | 2 154 | стекло: `glass*_sort`, `window_sort`, шейдер `WindowGlass` |
| `0x0010` | `TriSort` | 61 | волосы и ресницы; всегда со сдвигами `0x48` и буфером `0x70` |
| `0x0020` | `DrawInSky` | 32 | только небо: `skydome_sky*`, `horiz_sky_clouds` |
| `0x0800` | `DoNotCastShadow` | 5 249 | имена с `_dncs_` |
| `0x1000` | `DoNotRenderDepth` | 20 829 | только записи слоёв наложения (`0x28` > 0) |
| `0x4000` | `LowLODOnly` | 28 805 | ровно записи форматов 11 и 12 |
| `0x8000` | `CustomOpaque_0` | 77 | панорамы зданий и неба, шейдер `gf_pano` (76) |
| `0x0001` | (`Has2UVs` по другому редактору) | 1 381 | **не подтверждено**: второй набор UV только у 11 из них |

Имена полей и битов взяты из сверки с другим редактором игр EARS (этап 39) и проверены
на всех 157 229 записях; поля, которые всегда равны одному значению,
названы по ним, но смысл их не проверен. В отладочном выводе
(`mesh::render_flag_names`, поле `render_flag_names` записей в Python) биты
показываются по этим именам.

Индексы абсолютные; поток 1 читается с `ptr + min × шаг`. В полосе нечётные
треугольники разворачиваются, вырожденные отбрасываются.

**Скиннинг на CPU** (1 932 записи, `0x68 ≥ 0`): исходные вершины лежат по
адресу `0x84`. При GPU-шаге 20 — 32 байта: f32×3 позиция, DEC3N нормаль,
DEC3N касательная, u8×4 индексы палитры, u16×4 веса (сумма 65535). При шаге
12 — 16 байт: f16×4 позиция (в w два индекса палитры), DEC3N нормаль, u16×2 веса.

## 5. Форматы вершин

Объявления Direct3D взяты из `godfather2.exe` (`0x011286C8`). У каждого
формата есть GPU- и CPU-вариант; вариант выбирается по шагам потоков.

| № | Имя | GPU: поток 0 / поток 1 |
|---|---|---|
| 0 | PosColorTex1Tex2NormTan | P / C, T0, T1, N, Tg |
| 1 | PosColorTex1NormTan | P / C, T0, N, Tg |
| 2 | PosColorTex1Norm | P / C, T0, N |
| 3 | PosTex1Tex2NormTan | P / T0, T1, N, Tg (не встречается) |
| 4 | PosTex1NormTan | P / T0, N, Tg |
| 5 | PosTex1Norm | P / T0, N |
| 6 | PosColorTex1 | P / C, T0 |
| 7 | PosColor | P / C |
| 8 | PosTex1Tex2 | P / T0, T1 |
| 9 | PosTex1 | P / T0 |
| 10 | Pos | P |
| 11 | PosTex1Norm_LowLOD | P / H2 T0, N |
| 12 | PosTex1NormAO_LowLOD | P / N, H2 T0 |

P — f32×3; T — f32×2; C, N, Tg — UBYTE4N (`b / 255 · 2 − 1` для N и Tg);
H2 — f16×2. CPU-варианты хранят нормаль и касательную в потоке 0.
Полный список смещений — в `crates/doctor-toolkit/src/resource/mesh.rs`.

Ось Y направлена вверх, как в glTF.

## 6. Материал (`0x0AA0DEED`, версия 19)

Все 77 643 материала разбираются; хэш имени равен CRC-32 имени в нижнем
регистре. Идентификатор ресурса материала с этим хэшем **не** совпадает,
поэтому поиск материала по записи отрисовки требует чтения материалов.

| Смещение | Смысл |
|---|---|
| 0x08, 0x0C | хэш имени (оба поля равны во всех 77 643) |
| 0x14 | флаги: `0x1` — альфа-тест (4 383 материала, ровно те, у которых проход теней имеет параметры: шейдеры теней `…Alpha` и листвы); `0x20`, `0x80` — у стекла и свечения (351 и 750); `0x80000`, `0x100000`, `0x200000` — у одежды (87, 419, 39), смысл не проверен |
| 0x1C | 5 проходов по 8 байт `{u32 хэш шейдера, u8 первый параметр, u8 число, u16 0}`: тени (`ShadowsRigid` 68 096, …), глубина (`DeferredNormals` …), цвет (`gf_building_detail` …), глубина низкого LOD (`DeferredNormalsFastLowLOD` …), цвет низкого LOD (`…_LowRes`) |
| 0x46 | u16 число параметров |
| 0x48 | 6 × u16: смещение и размер таблицы, данных, строк |

Параметр: `{u32 хэш, u16 тип, u16 смещение данных, u16 имя, u16 источник}`.
Типы: 0 — f32, 1 — 8 байт, 2 — f32×3, 3 — f32×4, 5 — текстура (хэш имени,
равный последнему id ресурсов `tg4h`/`tg4d`). Роль текстуры — по имени
параметра: `g_BaseSampler` — основная, `g_materialNormalMap` и
`g_NormalMapSampler` — нормали, также спекуляр, глянец, детали, маска.
Основная текстура одежды и волос персонажей — маска перекраски, а не цвет.

## 7. Запись мешей

**Проверено на GF2 PC**: все 17 622 меша (`mesh` + `meshvolatile`)
разбираются в полную структуру и собираются обратно **побайтно**
(`resource/mesh_image.rs`, корпусный тест
`every_mesh_reencodes_byte_for_byte`). Структура хранит всё, что лежит в
образе, включая поля с неизвестным смыслом (байты записи, габариты, сетки
треугольников, морф-цели); писатель заново раскладывает разделы, ставит
указатели и строит таблицу релокаций.

### 7.1 Порядок разделов

`A(n)` — выравнивание на `n` байт, заполнение нулями.

| Раздел | Выравнивание |
|---|---|
| заголовок 0x100 | — |
| рабочая область A: `0x40 × число вершинных буферов`, нули (0x78) | A80 |
| рабочая область B: `0x40 × число индексных буферов`, нули (0x7C) | A80 |
| записи отрисовки, по 0xB0 | A80 |
| габариты записей, по 0x80 (0x54, у записи 0x20 = 0x54 + 0x80·i) | A80 |
| таблицы морф-целей (0x90) | первая A80, далее A10 |
| дескрипторы вершинных буферов | A80 |
| дескрипторы индексных буферов | A10 |
| данные вершин в порядке буферов: GPU-буфер — его данные; CPU-буфер — встроенные источники записей с этим буфером (0x68), между ними A10 | A80 на буфер |
| данные индексов в порядке буферов: GPU-буфер — его данные; CPU-буфер — индексы записей с ним (0x70), между ними A2 | A80 на буфер |
| байты вершин (поле записи 0x48, по байту на вершину, 61 запись персонажей, смысл неизвестен) | A80 |
| сетки треугольников статических записей (0x8C) | A10, после раздела A80 |
| морф-дельты (0x94) | первая A80, далее A4; после раздела A80 |
| палитры костей (0x44) | A10, далее A2 |
| таблица костей (0x60) | A10 |
| строки: имя модели, затем имена записей; одинаковые имена — одна строка | A10 |
| релокации `{u32 слот, u32 значение}` по возрастанию слота, включая слот 0x4C самой таблицы | A10 |
| дополнение до `len(mesh)` (0x9C) | A80 |
| `meshvolatile`: данные буферов с флагом 2 по порядку | A4, конец A80 |

Поле 0x0C — `len(mesh) + len(meshvolatile)`, 0x24 — 16 при наличии
`meshvolatile`. Нулевые указатели в таблицу релокаций не входят.

### 7.2 Сетка треугольников (0x8C)

Есть у всех 143 376 статических записей, у записей со скиннингом нет.

```
0x00  vec4  минимум (w = 0)
0x10  vec4  максимум (w = 0)
0x20  vec4  ячеек на единицу длины: число ячеек / (макс − мин); +inf при нулевом размере
0x30  u16 × 3  число ячеек по x, y, z
0x36  u16   число элементов E
0x38  u16   число ячеек C = x·y·z
0x3A  u16 × E  элементы: позиция начала участка полосы / 2
      u16 × (C + 1)  первый элемент каждой ячейки; последний равен E
      нули до A10
```

Ячейки идут x быстрее всех, затем z, затем y. Элемент — начало **участка**
полосы: подполосы, которая начинается на чётной позиции (так сохраняется
порядок обхода) и идёт до следующего участка. Ячейка перечисляет участки,
габариты которых её задевают. Правило воспроизводит 83 % сеток корпуса
точно, остальные расходятся на границах ячеек; выбор числа ячеек игрой не
восстановлен. Новые записи получают сетку тулкита (`mesh_grid.rs`):
кубические ячейки примерно по 16 позиций полосы, до 64 по оси.

### 7.3 Поля записи, нужные для новых записей

| Поле | Статика | Жёсткая привязка | Скиннинг на CPU |
|---|---|---|---|
| 0x04, 0x05 | 2, 2 | 1, 1 | 1, 1 |
| 0x06 влияния | 0xFF | 0 | 1–4 |
| 0x24 кость, 0x25 палитра | 0xFF, 0 | кость, 1 | 0xFF, ≤ 42 |
| 0x26 / 0x27 шаги | 12 / по формату | 20 / по формату | 20 / по формату |
| 0x28 | слой наложения 0–16, копируется из шаблона |  |  |
| 0x2A | `0xFFFE` (индекс видимости) | | |
| 0x3E | число индексов (mod 65 536) | число треугольников | число треугольников |
| 0x60 / 0x64 / 0x68 / 0x6C / 0x70 | ib, vb0, −1, vb1, −1 | ib, vb0, −1, vb1, −1 | ib, −1, CPU-vb, vb1, −1 |
| 0xA0–0xAC | 1.0 × 4 (`TintRGBA`) | | |
| габариты | 8 углов, w = 1, x быстрее | AABB, w = 0 | AABB, w = 0 |

Поток 0 записей со скиннингом и жёсткой привязкой всегда 20 байт
(позиция f32×3, нормаль и касательная UBYTE4N), и у форматов без
касательной (2, 5, 10). Формат индексного буфера (байт 0xA дескриптора):
1 — списки, 2 — полосы. Таблица костей меша — только используемые кости,
в порядке первого использования (у 218 мешей из 2638 — весь скелет).
**Исключение — персонажи:** у всех 816 мешей `allcharacters` одна и та же
таблица всего скелета (102 кости) в одном порядке, и игра берёт матрицы
палитры по номеру в этой общей таблице: меш одежды со своей таблицей
(те же кости, другой порядок) в игре рисует части на чужих костях (этап 24,
`docs/analysis/game-bench.md` §13.9). Поэтому импорт сохраняет таблицу
шаблона и дописывает новые кости в конец.

Сборка новых мешей — `resource/mesh_build.rs`, импорт glTF —
`docs/model-import.md`.
