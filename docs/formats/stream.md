# Формат: Stream (.str)

Основной контейнер ресурсов движка EARS/Visceral. Два бэкенда: **RwStream**
(The Godfather 1, RenderWare-чанки; не проверен) и **UStream** (The Godfather II
и Dead Space; для GF2 PC проверен, см. §6).

## 1. Заголовок файла (RwStream)

Порядок чтения (endian-зависимые поля меняются байтсвопом, если платформа
big-endian):

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u8 | `section_count` — число секций |
| +0x01 | u8 | `platform_id` — идентификатор платформы |
| +0x02 | u16 | padding (0) |
| +0x04 | u32 | `hardcoded_prefix` = `0x14` (20), если есть «hardcoded data», иначе 0 |
| +0x08 | u32 | `total_size` = `0x14` + длина hardcoded-данных |
| +0x0C | var | «hardcoded data» (`total_size - hardcoded_prefix` байт) |
| … | | выравнивание до 0x800 |
| 0x800 | | таблица секций: `section_count` × 24 байта |

При загрузке выводится диагностика: «Found .str file with %i Sections, PlatformID
is %i …» и «Loaded %u of hard coded data. Be careful when editing this file!».

«Hardcoded data» — фиксированная служебная область (RenderWare-наследие); для
правки `.str` учитывается при сохранении.

## 2. Секция (`StreamSectionInfo`, on-disk 24 байта)

Читается 6 × u32, пишется симметрично:

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | `MemPolicy` (политика памяти) |
| +0x04 | u32 | флаг сжатия: `0xB9F0B9EC` = RefPack, иначе сырая |
| +0x08 | u32 | размер данных в потоке (compressed/raw size) |
| +0x0C | u32 | размер распакованных данных (uncompressed size) |
| +0x10 | u32 | выровненный размер (вклад секции в смещение, 0x800-aligned) |
| +0x14 | u32 | 0 (зарезервировано) |

Пересчёт полей при записи:

```
+0x08 = data_size
+0x14 = 0
+0x10 = +0x0C = align_up(data_size, 0x800)
```

## 3. Чанк (`RwChunkHeaderInfo`)

Классический RenderWare-чанк. On-disk заголовок — 12 байт (3 × u32):

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | `type` (ChunkId) |
| +0x04 | u32 | `size` (размер данных) |
| +0x08 | u32 | `version` == `0x1802FFFF` (магия версии RenderWare) |

Неизвестный тип чанка → «Unhandled ChunkType [%i]. This chunk will be skipped.»
+ пропуск на `size`.

Известные ChunkType: `0x716` (1814), `0x722` (1826), `0x723` (1827),
`0xD10DFB10` (3507354384), `0` (конец).

## 4. Платформа → порядок байт

```
if (platform_id & 0xFC) == 4 && platform_id != 5:  little-endian (без byteswap)
else:                                              big-endian (byteswap)
```

То есть platform_id = 4, 8, 12, … → little-endian (PC); остальные (5 = PS2 и др.) →
big-endian.

## 5. Запись хвоста

Если размер хвоста > 7 — пишется чанк **«FILL»** (`0x46494C4C`, little-endian)
с размером и padding до 0x800.

## 6. UStream (The Godfather II, Dead Space)

**Проверено на GF2 PC**: все 2300 файлов разбираются, все ресурсы распаковываются,
перекладка блоков воспроизводит файлы побайтно. Прежнее описание этого раздела
описывало раскладку в памяти, а не на диске, и было неверным для GF2. Для
Dead Space раскладка не проверена.

### 6.1 Заголовок файла (12 байт)

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | 4 | magic `3slo` (`ols3` в big-endian файлах — предположение) |
| +0x04 | u32 | смещение первого блока = `0x0C` |
| +0x08 | u16 | версия = 2 |
| +0x0A | u16 | неизвестно, всегда 3 |

### 6.2 Страницы и блоки

Файл — последовательность страниц по **0x20000** байт; длина файла кратна странице.
Страница заполнена блоками; блок никогда не пересекает границу страницы.

| Блок | Раскладка |
|---|---|
| `SHOC` | `"COHS"`, u32 `size` (вместе с 12 байтами заголовка), u32 подтип, тело |
| `FILL` | `"LLIF"`, u32 `size` (вместе с 8 байтами заголовка), нули |

Тег и подтип — FOURCC, записанные как little-endian u32, поэтому в файле байты
идут в обратном порядке. Размер блока кратен 4.

**Правило размещения.** Блок размера `S` кладётся в текущую страницу, если
`S == остаток` или `S + 8 <= остаток`. Иначе остаток закрывается блоком `FILL`,
и блок начинает новую страницу. Последняя страница всегда закрывается `FILL`.

### 6.3 Подтипы `SHOC`

| Подтип | Тело |
|---|---|
| `SHDR` | заголовок ресурса, 0x20 байт (§6.4) |
| `SDAT` | сырые данные, нули до кратного 4 |
| `Rpak` | u32 `compressed_len`, поток RefPack (`10 FB`, 24-битный размер), нули до кратного 4 |
| `LZXD` | LZX (только Dead Space, в GF2 не встречается) |

Ресурс — блок `SHDR` и все блоки данных до следующего `SHDR`. Распакованные тела
конкатенируются; результат длиннее объявленного размера не более чем на 3 байта.
Сырые куски не превышают 0x20000 − 12 байт; сжатые разбиваются произвольно.

### 6.4 Заголовок ресурса (`SHDR`, 0x20 байт)

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | политика памяти, SDBM от имени (`default`, `volatile`, `geometry`) |
| +0x04 | u32 | выравнивание данных при загрузке |
| +0x08 | u32 | `type_id`, SDBM от тега (`tg4h`, `mesh`, `simgroup`, …) |
| +0x0C | 4 × u32 | идентификаторы ресурса |
| +0x1C | u32 | размер распакованных данных |

Четыре идентификатора — **один 128-битный GUID ресурса**: игра хранит
загруженные ресурсы в общей таблице по GUID (без типа) и не загружает
второй ресурс с тем же GUID. Формы: id × 4 (большинство типов);
`0, type_id, хэш пакета, хэш имени` у `tg4h`/`tg4d`; дополнение id меша у
`meshvolatile`; настоящий GUID (8 случайных байт и логин автора) у `graph` и
`materialswaplistresource`; нули у одиночных типов потока (`simgroup`).
Политика памяти и выравнивание определяются типом. Подробности и правила для
новых ресурсов — `docs/analysis/new-resources.md` §1.

Список тегов GF2 — `data/gf2/type_tags.txt`.
