# Граф анимации банков `bnk`

**Проверено на GF2 PC** (этап 43). Банк анимаций (`characters.md` §6) кроме
клипов хранит **граф**: именованные входы, у каждого — дерево узлов, листья
которого играют клипы. Игра просит анимацию по имени входа
(`characters.md` §6.2) и проигрывает его дерево. Здесь — раскладка узлов,
типы узлов и их параметры, данные для родителя, номера слотов, события
клипов и что известно об объектах событий.

Код: `crates/doctor-toolkit/src/resource/anim_graph.rs` (`AnimGraph`),
запись — через `BankImage` (`anim_image.rs`). Корпусный тест
`every_animation_graph_rewrites_identically`.

## 2. Раскладка

Граф — непрерывный блок образа после списков заголовка
(`characters.md` §6.1). Для каждого входа по порядку списка входов:

```
вход   {ptr имя, ptr корень}                         A16
имя    строка с нулём                                 A16
узлы в глубину, для каждого:
  узел {u8 тип, u8 детей, u16 номер,
        ptr параметры (или 0), ptr данные для родителя (или 0),
        ptr ребёнок × детей | ptr клип (тип 0x16)}    A16, 12 + 4·max(детей, 1) байт
  параметры                                           A16
  данные для родителя                                 A16
  дети, по порядку
```

Каждый объект выровнен на 16 байт и дополнен байтами `'_'` (0x5F). Узлы не
делятся между родителями и между входами (16 336 узлов — 16 336 указателей
на них). Указатели из графа ведут только в граф и в записи клипов.
`AnimGraph::to_block` раскладывает граф так же: все **2 751** банк
собираются **байт в байт** (блок графа и его указатели, корпусный тест).

## 3. Как игра исполняет узел

Узел обрабатывают три таблицы функций по типу (`godfather2.exe`, адреса
образа, разобранного Ghidra; на диске секция данных зашифрована защитой и
таблиц не видно):

| Таблица | Что | Пример |
|---|---|---|
| 0x00F294A8 | выборка позы на отрезке времени (время «от», «до», флаги) | 0x0058AA10 — последовательность |
| 0x00F29538 | длительность узла в тиках | 0x0058FE10 — клип: `длительность − начало + 1` |
| 0x00F295C8 | обновление перед выборкой | только тип 5: 0x00590E10 |

Перед вызовом игра маскирует тип `& 0x3F` и сравнивает с 0x23 (0x00584050,
0x0058AC44 и ещё 13 мест): типов 35, функции есть у 1–0x22, кроме 0x18;
в банках встречаются 16 из них (§1). Остальные 17 типов есть в таблицах, но
их параметры по данным не проверить — редактор их не создаёт.

**Слоты.** У каждого проигрываемого входа есть массив float. Номер узла
(`u16` в его заголовке) — его слот: туда родитель кладёт длительность
ребёнка (0x0058FF70). Некоторые типы держат в слотах состояние, номера этих
слотов — в их параметрах (§4). Номера раздаются в глубину: узел, затем его
слоты состояния, затем дети; так у всех 4 446 входов игры
(`AnimGraph::renumber` даёт те же номера). Слово заголовка банка 0x20 —
наибольшее число слотов среди входов (во всех банках равно наибольшему
номеру + 1).

**Управляющие переменные.** Узлы 5, 6 и 0x21 читают значения из таблицы
игры 0x00E52698 (43 записи `{имя, чтение, запись}`; таблицу ставит
0x005703B0, вызов из 0x006E2520). Имена — строки exe:

|---:|---|---:|---|---:|---|
| 0 | null entry | 15 | l foot effector | 30 | gender |
| 1 | true | 16 | r toe effector | 31 | family category |
| 2 | false | 17 | r foot effector | 32 | npc tension zone |
| 3 | pl stick speed | 18 | l hand effector | 33 | pl walk run threshold |
| 4 | pl run turn blend | 19 | r hand effector | 34 | pl velocity |
| 5 | turn angle | 20 | aim pitch | 35 | prev pl velocity |

## 4. Параметры типов

Время везде — в тиках (59,94 в секунду, 2 тика на кадр клипа,
`characters.md` §6.4). «Пара» — два `u16` в одном слове, младший первым.

**0x02, последовательность** (0x0058AA10; длительность — сумма детей,
0x0058FEB0). Дети играют друг за другом: ребёнок вызывается, пока время
меньше суммы длительностей до него. Параметры есть только у корней
входов: `{u32 приоритет, u32 метка}`. Приоритет решает, чей вход с тем же
именем останется при загрузке нескольких банков (0x00573200,
`characters.md` §6.2); во всех банках игры он 0. Метка 0x12032045 — у 2 890
корней, 0 — у 1 535, 0x65F9A138 — у 21. Вложенные узлы 0x02 (204) без
параметров.

**0x03, случайный выбор** (0x0058B4F0 → общий выбор 0x0058AF90, жребий
0x0058AD40). Параметры: пара слотов «текущий ребёнок, предыдущий», пара
«режим, слот времени начала», `f32` тиков перехода. Режим — когда
выбирать заново (0x0058AF90): 0 — когда ребёнок закончился (310 узлов),
1 — так же, но не текущего ребёнка (191, 0x0058AD40 исключает его из
жребия), 2 — при каждом обновлении, 3 — один раз (18). Вес ребёнка — первое слово
его данных для родителя (`f32`, у всех 1 550 детей); жребий — таблица
случайных чисел 0x00FB0B68. Переход 20 тиков у 299 узлов, 10 — у 124,
0 — у 29.

**0x04, задом наперёд** (0x0058B540): время ребёнка `длительность − 1 − t`,
флаг обратного хода инвертируется. Параметров нет.

**0x05, смешивание по переменной** (0x0058BA30; обновление 0x00590E10):
`{u32 переменная, f32 минимум, f32 размах, u32 слот}`. Обновление читает
переменную и пишет в слот `(значение − минимум) / размах`; выборка смешивает
двух детей с этим весом, длительность — смесь их длительностей (0x00590400).
Переменные в игре: 20 (`aim pitch`, 382 узла), 8, 4, 5, 10, 29, 35 и др.

**0x06, выбор по переменной** (0x0058BBA0 → 0x0058AF90, выбор 0x0058BB10):
пара слотов «текущий, предыдущий», пара «переменная, слот времени»,
`u32` «сразу» (1 — выбирать заново при каждом обновлении, 299 узлов; 0 —
когда ребёнок закончился), `f32` тиков перехода. Ребёнок играет, когда
значение переменной в диапазоне его данных для родителя `{f32 мин, f32
макс}` (у всех 1 871 ребёнка). Флаг «сразу» — тот же режим 2 общего выбора
0x0058AF90, без него — режим 0. Чаще всего переменная 30 (`gender`, 497
узлов) — мужской и женский варианты анимации, затем 20 (`aim pitch`, 191),
4 (66), 25 (`combat anim type`, 60).

**0x08, растяжение времени** (0x0058BC70; длительность 0x00590160):
`{f32 множитель}` — длительность ребёнка × множитель, ребёнок идёт в
`1/множитель` раз быстрее (1 — 188 узлов, 0,714, 0,833…). У ребёнка узла 8
есть данные для родителя из одного слова: 0 (443) или 1 (225); функции
узла 8 их не читают, смысл не установлен.

**0x09, включаемая часть** (0x0058BCF0 — как последовательность):
`{u32 флаг (0 у 184 из 186), u32 слот}`. Последовательность-родитель
(0x0058AA10) обходит ребёнка 9 особо: переключает значение его слота
между 1,0 и особым значением и не играет его в общем порядке, а
длительность родителя (0x0058FEB0) берёт из этого слота. Когда и кем часть
включается, до конца не разобрано.

**0x0A, множитель движения корня** (0x0058BD30): `{f32 x, f32 y, f32 z}` —
перемещение корня, полученное от ребёнка, умножается покомпонентно
(1,5; 1,25; 0,8…).

**0x0D, сложение** и **0x0E, разность** (0x0058BE80, 0x0058C340). Оба
крутят детей по кругу в их длительности. 0x0E даёт позу первого ребёнка
относительно второго (0x00584860: поворот умножается на обратный,
0x005828A0); 0x0D прибавляет ко первому ребёнку второго (0x00584120:
произведение поворотов и сумма переносов, 0x005834C0), а с тремя детьми —
разность второго и третьего. Длительность — наибольшая из детей
(0x00590100). Параметров нет.

**0x12, зацикленный поверх** (0x0058C9C0): первый ребёнок играет как есть,
второй — зацикленно в своей длительности, результаты объединяет закрытый
защитой код (0x02163000); длительность — меньшая из двух (0x00590730).

**0x14, скорость** (0x0058D200; длительность 0x005902B0):
`{u32 слот, u32 режим, f32 смещение, f32 масштаб}`. Время ребёнка делится
на скорость из слота; в режиме 0 скорость считается как
`движение × масштаб + смещение` и пишется в слот.

**0x16, клип** (0x00590C40; длительность 0x0058FE10):
`{f32 начало, f32 длительность, f32 тиков на кадр}` — `characters.md`
§6.3. Длительность = кадров × 2 у зацикленных клипов, (кадров − 1) × 2 у
остальных; исключений 3 (проверка их отмечает предупреждением). Последнее
слово узла — указатель на запись клипа.

**0x19, последовательность с вызовом** (0x0058BC00): как
последовательность, затем вызов закрытого кода (0x01D631D0) с параметром
`{u32 хэш}`, во всех 200 узлах 0xEDFCDFBA.

**0x1C, ноги** (0x0058F2D0): ребёнок, затем поправка ног. Параметры:
три пары (`25/14`, `15/26`, `16/17` во всех 104 узлах — индексы костей и
переменные-эффекторы 14–17), `f32` 0,012 и 0,05, `f32` −0,1 (73) или −0
(31), два нуля.

**0x21, копирование переменной** (0x0058FCE0): `{u32 откуда, u32 куда}` —
пишет значение одной переменной в другую (через функции чтения и записи
таблицы §3), затем играет ребёнка. В игре: 34 → 35 (`pl velocity` →
`prev pl velocity`), 5 → 29, 27 → 26 — запоминание прошлого значения.

## 5. Данные для родителя

Второй указатель узла — данные, которые читает **родитель**: у детей узла
3 — вес (1 слово), узла 6 — диапазон (2 слова), узла 8 — слово 0/1 (§4).
У остальных узлов указатель нулевой (5 096 из 7 847 узлов клипов и все
узлы под другими родителями). Корпус: 1 550 + 1 871 + 668 узлов с данными,
ни одного лишнего.

## 6. События клипов

Формат записи — `characters.md` §6 («События клипа»):
`{f32 время, *имя, u32 сигнатура, *аргументы}`, аргумент
`{u32 тег (1 — f32, 2 — строка, иначе целое), u32 значение}`, младший байт
сигнатуры — число аргументов. Самые частые события:

| Имя | Событий | Сигнатура | Аргументы |
|---|---:|---|---|
| `enable PA` | 7 357 | 0xFFFFFF02 | целое, целое |
| `footstep` | 2 805 | 0xFF020203 | строка (`footstep_male_step_hard`), целое, f32 |
| `audio: play` | 2 470 | 0xFF000102 | строка `.emx`, f32 |
| `vibration: play` | 206 | 0xFFFFFF01 | строка (`rumble_shooting_tommy_gun`) |
| `rws: send message` | 201 | 0xFFFFFF01 | строка (`setExpression_Angry`) |
| `item use` | 189 | 0xFFFFFF00 | — |
| `vox: play` | 168 | 0xFF010102 | строка (`punched`), f32 |
| `collision off` / `on` | 164 / 162 | 0xFFFFFF01 / 0xFFFFFF04 | целое / три целых и f32 |
| `footstepl_1`, `footstepr_1`, `_2` | 160, 163, 152, 141 | 0xFF03…, 0xFF07…, 0xFF04…, 0xFF08… 0102 | строка, f32 |
| `living world prop attach` | 125 | 0xFFFFFF01 | строка (`cigarette`) |
| `vfx: play` | 114 | 0xFFFFFF02 | две строки |

Всего 45 имён. Третий байт сигнатуры у звуковых событий — номер канала
(0 `audio`, 1 `vox`, 2 `footstep`, 3, 4, 7, 8 — шаги левой и правой ноги,
0x0D — `item throw`), второй — 0, 1 или 2; у прочих событий оба байта 0xFF.
Смысл байтов игра не раскрывает строками, запись хранит их как есть.
Правка событий — этап 26 (`anim events`, `set_clip_events`).

## 7. Объекты событий (хвост)

Список заголовка 0x34 — объекты по 0x30 байт в хвосте банка с данными
после них. Разобрано по данным (читатель в exe — в коде под защитой, не
разобран): `+0x00` u32 4 (4 559) или 2 (13); `+0x04` −1 (3 077) или SDBM
имени входа (1 495); `+0x14` номер; `+0x18` указатель
(498) или 0; `+0x1C` SDBM клипа (3 460 — клип этого банка); `+0x28` f32 1
(4 035); `+0x2C` 32, 35, 40, 33, 59… — вид данных; `+0x30` указатель на
данные сразу за объектом (4 344). Запись хранит их как есть (перемещаемый
блок, `BankImage::tail`); правка не поддерживается.

## 8. Правка и проверка

`AnimGraph` (`resource/anim_graph.rs`):

- `parse(&BankImage)`, `to_block()`, `store(&mut BankImage)` — граф, список
  входов и слово 0x20;
- `renumber()` — номера слотов, как у игры; вызывается после каждой
  структурной правки;
- `set_param`, `set_extra`, `set_clip` — слова параметров, данных для
  родителя, клип узла 0x16;
- `add_clip_node(родитель, клип, кадров, цикл)` — новый узел клипа
  последним ребёнком узла 2, 3 или 6 (с длительностью по клипу, весом 1 у
  ребёнка 3 и диапазоном после последнего у ребёнка 6);
- `remove_node` (поддерево; только у детей 2, 3, 6 и если у родителя
  останется ребёнок), `move_child`, `rename_entry`, `remove_entry`;
- `check(&BankImage)` — ошибки: тип без функции в игре, число детей не по
  типу, короткие параметры, нет данных для родителя 3/6/8, переменная вне
  таблицы, клип вне банка, слот занят дважды или за пределом, множитель
  времени ≤ 0, размах смешивания 0, одинаковый хэш имён входов;
  предупреждения: корень не 0x02, длительность клипа не по правилу, тиков на
  кадр не 2. На банках игры ошибок нет, предупреждений 3 (длительности).
- JSON (`to_json`/`from_json`): входы с вложенными узлами, слова параметров
  по типу — целое, `f32` или пара `[младший, старший]`; `what` и
  `clip_name` — для чтения. Корпус: JSON → граф без изменений во всех
  банках.

Новый вход с клипом — `BankImage::add_entry` (этап 26, `anim import
--add`).
