# Диалоги F2F: `dlg`, `chv`, `smb` и субтитры речи

Этапы 30 и 83. Код: `crates/doctor-toolkit/src/resource/dlg.rs`, `chv.rs`,
`smb.rs`, `get.rs`, `speech.rs` (форматы), `crates/doctor-toolkit/src/dialogue.rs`
(связи по всей игре), `crates/doctor-toolkit/src/voice.rs` (новая реплика),
`crates/doctor-toolkit-cli/src/dialogue_cmd.rs`, `voice_cmd.rs` (CLI),
`crates/doctor-toolkit-gui/src/dialogue_view.rs` (редактор),
`crates/doctor-toolkit-gui/src/app/wizard/voice.rs` (мастер). Своды по
`smb` и `get` — `research/speech_survey.py`.

**[П]** — проверено на всех файлах игры (тест `corpus`), **[Г]** — гипотеза.
Адреса — виртуальные адреса `godfather2.exe` (PC 1.0.789.0).

## 1. Как устроен разговор

```
SimGroup: NPC.5 / ChangeNPCSettings.27 / ChangeDialog.3 = "gf2\globalfolder\dlg\0c6576f0"
   └─ поток gf2/globalfolder/dlg/0c6576f0: банки анимаций bnk + dlg (дерево)
        узел «реплика»: говорящий 1/2, хэш события речи (N3_LINE1), группы клипов
           └─ chv говорящего: событие N3_LINE1 → записи (sound id, id субтитра, вес)
                └─ smb: sound id → d_mob4_xxx_0001cc7.exa
                     └─ GODFATHn.viv: audiostreams\b4_xxx_0\d_mob4_xxx_0001cc7.exa.snu
                          метаданные SNU: таблица LCH2 с субтитром на 8 языках
        узел «выбор»: до 5 вариантов, у каждого — имя строки lh2 (hud_csa_f2f_choicea)
```

- Диалог — ресурс `dlg` в отдельном потоке `gf2/globalfolder/dlg/<хэш>`
  (143 потока, в каждом ещё банки `bnk` с клипами `f2f_*`). Имя потока —
  хэш, исходное имя диалога неизвестно.
- Кто начинает разговор: строковый атрибут SimGroup с путём потока **[П]**:
  `NPC` атрибут 5 у объектов `CommonNPC` (3431 место), `ChangeNPCSettings` 27
  (112), `ChangeDialog` 3 (13). Ссылок по id ресурса нет. 107 разных путей;
  у 36 диалогов пользователей в SimGroup нет.
- Тексты вариантов выбора — строки `lh2` по имени (`hud_csa_f2f_choicea`,
  `string_id(имя)`), язык — по таблицам `lhr` (`docs/formats/resource-types.md`).
- **Текст реплик — не в `lh2`.** Субтитр сказанной фразы лежит в самом файле
  речи `.snu` в архиве `.viv` (§5). Из 15 263 строк `chv` только 2 имеют id,
  который есть и в `lh2`.

## 2. `dlg` — дерево диалога [П, 143 ресурса, побайтная запись]

Загрузчик `0x006FB320` (класс-обработчик с таблицей `0x00D60A4C`, строка
типа `DLG`), проверка версии 4, перевод смещений в указатели `0x006F0310`,
классы узлов `0x006EFF10`. Файл — образ памяти: смещения вместо указателей.

```
0x00  u32  версия = 4
0x04  u32  0
0x08  u32  число узлов N
0x0C  u32  смещение узлов = 0x34
0x10  u32  0
0x14  u32  число групп анимаций M
0x18  u32  смещение групп, от 0x14
0x1C  u32  смещение записей анимаций
0x20  u32  список подписей вариантов (0 — пуст)
0x24  u32  список слотов реплик         (время работы: u32 0x24 на реплику)
0x28  u32  список состояний реплик      (время работы: 20 нулевых байт на реплику)
0x2C  u32  список состояний камеры/актёров (2 × 20 нулей на реплику и выбор)
0x30  u32  список анимаций
0x34  N × узел (20 байт):
        u32 0 (указатель на класс во время работы)
        u32 вид
        u32 число ветвей
        u32 смещение массива ветвей, от узла
        u32 смещение данных, от узла (0 у узла «конец»)
      массивы ветвей всех узлов по порядку: i32 смещение целевого узла
        от текущего, 0 — ветви нет
      данные узлов: сначала всех прочих по порядку узлов, потом выборов,
        потом реплик
      M × { u32 смещение от записи, u32 число }, затем значения групп
        (номера анимаций)
      на анимацию { u32 номер, u32 флаги, u32 0 }
      списки: смещения записей, 0, 0, затем записи
```

Записи списков: строки с NUL, выровненные до 4 (подписи: по 5 слотов на
каждый выбор, пустая строка — неиспользуемый слот; анимации: 16 нулевых
байт и имя клипа). Списки 0x24–0x2C игра заполняет при работе; тулкит
проверяет, что они такие, как выводятся из числа реплик и выборов, и строит
их заново. Порядок частей одинаков во всех 143 файлах, поэтому
`Dialogue::to_bytes` воспроизводит каждый байт в байт и может писать
изменённые деревья (новые реплики, другие связи).

### 2.1 Виды узлов

Игра знает виды 0..0x2C (таблицы методов `0x00D5FEE8`…`0x00D604F4`); метод
+4 переводит смещения данных, +8 даёт следующий узел, +0x20 вычисляет
номер ветви. В файлах игры встречаются только эти:

| Вид | Узлов | Ветвей | Данные | Что делает |
|---|---:|---|---|---|
| 1 — реплика | 931 | 1 | 16 слов (§2.2) | актёр говорит событие речи |
| 2 — условие `==` | 364 | 2 | `{тип, 0, переменная, значение}` | ветвь 1, если равно, иначе ветвь 0 (`0x006ECF70`) |
| 0x20 — флаг NPC | 235 | 1 | 1 слово x | ставит флаг x−0x13 разговорного NPC (`0x00898480`) |
| 0x21 — флаг NPC (B) | 7 | 1 | 1 слово x | ставит флаг x−0x1A (`0x008982E0`) |
| 0x22 — выбор | 122 | 2, 4 или 5 | 16 слов (§2.3) | варианты игрока, ветвь i — вариант i |
| 0x23 — конец | 143 | 0 | — | конец разговора, ровно один на файл |
| 0x24 — присваивание | 461 | 1 | `{тип, 0, переменная, значение}` | записывает значение (`0x006EFE00`) |

Вид 3 — `!=`, 4 — `<`, 5 — `>` (`0x006ED0A0`, `0x006ED1D0`, `0x006ED300`),
остальные условия и действия в файлах игры не встречаются. Тип значения:
0 — bool, 1 — int, 2 — float. «Переменная» — номер запроса движка
(`0x006EBFF0`), например `0x0C`..`0x12` — флаги 0..6 NPC (`0x00898330`);
названий у номеров нет **[Г: те же флаги ставят узлы 0x20]**.

### 2.2 Реплика (вид 1)

| Слово | Значение |
|---|---|
| 0 | говорящий: 1 — игрок, 2 — NPC (у клипов говорящего флаг 0x02 / 0x04) |
| 1 | 0x14 — смещение второй части от начала данных |
| 2, 3, 4 | 8, 8, 1 (у 95 реплик 0x58, 0x58) |
| 6, 7 | номер реплики по порядку узлов (слоты списков 0x24, 0x28) |
| 8 | **хэш события речи**: `sdbm(lower(имя))` события `chv` (`P2_LINE1`, `F2F_ENJOY_FLIGHT`) |
| 9 | группа клипов перед репликой или −1 |
| 10 | группа клипов говорящего |
| 12 | группа клипов слушающего |
| 13, 14 | 0/2 и флаги (0x1A94 и др.) |
| 15 | 1.0 |

Группа — набор клипов, из которого игра берёт один; флаги клипа: 0x02 / 0x04
— актёр 1 / 2, 0x20…0x200 — роль клипа **[Г]**, 0x40000 — у большинства.

### 2.3 Выбор (вид 0x22)

| Слово | Значение |
|---|---|
| 0 | время на ответ, f32 секунд (600, 10, 6; −1 — без ограничения) |
| 1–4 | клипы/слоты ожидания **[Г]** |
| 5 | флаги (0x40102 и др.) |
| 8–10 | 0x1080, 8, 8 |
| 11–15 | номера слотов подписей пяти вариантов в списке 0x20 или −1 |

Слоты выбора k — подписи `5k…5k+4` (k — номер выбора по порядку узлов).

## 3. `chv` — события речи персонажа [П, 259 ресурсов, побайтная запись]

Загрузчик `0x006F4840` (строка типа `CHV`): версия 3, сумма весов строк
каждого события — выбор строки случайный по весу.

```
0x00  u16  версия = 3
0x02  u16  число событий N
0x04  u32  смещение таблицы = 8
0x08  N × { u32 sdbm(lower(имя)), u32 число строк, u32 смещение имени, u32 смещение строк }
      строки всех событий подряд, по 32 байта:
        4 × u32  id звука (ключ smb; во всех файлах — одно значение 4 раза)
        u32      id субтитра: string_id имени файла речи без «d_»
                 (d_mob3_xxx_0001806 → mob3_xxx_0001806)
        f32      вес (1, 2 или 3)
        u32      1
        u32      номер строки в событии
      имена событий с NUL, каждое выровнено до 4
```

На `chv` ссылается `ChatterComponent` атрибутами 0..3 (GUID ресурса). Имена
событий общие у многих персонажей (`N3_LINE1` есть у Рота, Гранадоса,
Мангано, Фредо…): какую запись скажет реплика, решает `chv` говорящего во
время игры. Тулкит показывает все записи события и ставит первыми те, чьи
`chv` лежат в потоках пользователей диалога, а для актёра 1 — голос Доминика
(`dmnc`) (`Catalog::candidates`).

### 3.1 Как игра говорит событие (этап 83, по коду exe)

- **Четыре слова «id звука» — один 128-битный id** записи банка речи: игра
  ищет запись `smb` по всем 16 байтам (`0x00455F50` → двоичный поиск
  `0x004CBDC0`). В файлах игры все четыре слова равны.
- **События в таблице отсортированы по хэшу** (без знака): игра ищет событие
  двоичным поиском (`0x006F4CD0` → `0x006F4C10`). Во всех 259 `chv` порядок
  такой (корпусный тест); новое событие встаёт на своё место
  (`ChatterSet::add_line`).
- `chv` регистрируется под id ресурса из заголовка (`0x006F4840`), ищется по
  нему же (`0x006F4680`); id ресурса `chv` — одно слово четыре раза, как его
  и пишут атрибуты-ссылки.
- **Какой `chv` говорит.** У говорящего — четыре слота наборов речи:
  атрибуты 0, 1, 2, 3 пакета `ChatterComponent` (читатель `0x006F38A0`,
  смещения `+0x14`, `+0x48`, `+0x7C`, `+0xB0`). Событие ищется в слотах в
  обратном порядке — 3, 2, 1, 0 (`0x006F3B80`), говорит первый набор, где оно
  есть. Объект `SimpleChatterBox` может дать свой набор (атрибут 7): тогда
  сначала ищут в нём, потом в слотах говорящего (`0x006F2070`).
- Строка события выбирается с учётом веса (`0x006F5190`), у строки читаются
  id звука (16 байт), id субтитра (`+0x10`) и слово `+0x1C`: строка с
  младшими 16 битами `0xFFFF` не играется (`0x006F15B0`).
- Перед тем как сказать, игра читает запись события в `get` (§6) — без
  проверки на её отсутствие.

### 3.2 `SimpleChatterBox`: сказать событие по сообщению

Объект логики (76 в потоках Кубы; читатель атрибутов `0x006F24D0`, обработчик
сообщений `0x006F26D0`, «сказать» — `0x006F2890`):

| Атрибут | Что это |
|---|---|
| 0 | флаги (`0x80`, `0x100`, `0x200`, `0x01`, `0x10` встречаются). С `0x100` говорящий берётся из сообщения-запуска, с `0x200` — объект, связанный с игроком (`0x006AD7F0` → `0x009A9520`), и без него реплика не запускается: на стенде с `0x200` объект молчал (`game-bench.md` §34) **[Г]** |
| 1 | уровень важности 1–9 → приоритет 400…3000 (`0x006F1890`) |
| 2 | сообщение-запуск |
| 3, 4 | сообщения остановки и отмены |
| 5, 6 | сообщения «включить» и «выключить» |
| 7 | GUID ресурса `chv` — свой набор речи |
| 8 | GUID второго объекта (собеседник) |
| 9 | GUID говорящего; без него реплика звучит без персонажа (объявление по громкой связи `m1_pa_announcement_start`) |
| 10 | имя события речи |
| 11 | флаг, 12 — задержка перед репликой, с; 13 — число (0,1–10) |
| 14 | сообщение, которое объект шлёт после реплики (так реплики идут цепочкой) |

Смысл атрибутов 3, 4, 8, 11, 13 прочитан по коду бегло — **[Г]**; атрибуты 2,
7, 10 проверены на стенде (`audio.md` §15).

## 4. `smb` — банки потокового звука [П, 59 ресурсов, 12 918 записей, побайтная запись]

Банк называет файлы архивов `.viv` и хранит их параметры воспроизведения.
Это не только речь: в банках лежат и музыка (`MUSIC`, `MUSIC_RADIO` — 453
записи), фон (`SFX_AMBIENT`), звук роликов (`IGC`).

```
0x00  u32  0 (во время работы — указатель на таблицу методов), u32 0
0x08  u32  12 — смещение тела
0x0C  u32  13 — версия
0x10  u32  число записей N
0x14  u32  смещение таблицы = 0x18
0x18  N × u32 смещения записей от начала файла, по возрастанию
      N записей по 0x70 байт подряд, отсортированы по id (четыре u32 по очереди):
      +0x00 u16 0x11
      +0x02 u16 флаги: 0x01 — файл озвучки (в путь входит папка языка),
                0x04, 0x08 — переключатели воспроизведения, 0x40 — суффикс `.snu`
      +0x04 4 × u32 id (в игре — одно значение четыре раза)
      +0x14 u32 0
      +0x18 6 × f32 параметры: 2.0, 100.0, 0, 0, 0, −1.0 у большинства
      +0x30 u32 (90 у 96 % записей)
      +0x34 u32 категория микшера — sdbm имени категории `auc` (`DIALOG`, `CHATTER`)
      +0x38 u32 второй хэш (`35048678` у речи, `MUSIC` у музыки) или 0
      +0x3C u32 «дак» — sdbm имени дака `auc` (`CREW_CHATTER_DUCK`) или 0
      +0x40 имя файла, 40 байт с NUL (d_mob3_xxx_0001806.exa)
      +0x68 u32 0 — смещение дополнительных данных, их нет ни у одной записи
      +0x6C u32 sdbm(lower(имя без расширения + ".stx"))
```

По коду exe: загрузчик `0x004563C0` → перевод смещений `0x004CBD10`; список
загруженных банков — в обработчике звуковых ресурсов (`0x00455CF0`, шаг
0x24). Поиск по id — `0x00455F50`: в каждом банке двоичный поиск по 16 байтам
(`0x004CBDC0`), поэтому **записи обязаны идти по возрастанию id**. Поиск по
имени — перебор с хэшем `+0x6C` (`0x00456010`, `0x004CBEC0`) и перебор со
сравнением строк (`0x00456070`, `0x004CBF10`). У двух записей из 12 918 хэш
`+0x6C` не от своего имени (`gf2_dons_view_01.exa`) — след переименования.

Параметры игра копирует в запрос воспроизведения (`0x004A84D0`): `+0x18` и
`+0x1C` — по значениям ближняя и дальняя дистанции **[Г]**; `+0x28` и `+0x2C`
— времена в секундах (игра умножает на 1000; второе — только при ≥ 0),
у каждой записи свои (0 и −1 у 73 %); флаги 0x04 и 0x08 — два переключателя
запроса. Точный смысл параметров не установлен.

**Путь файла строит игра** (`0x004A8460` → `0x004A8580`), а не данные:

```
audiostreams\ [язык\ при флаге 0x01 и выбранном языке]
              [папка\ если имя вместе с ".snu" длиннее 16 символов:
                      символы 4..12 имени, обрезанного по первой точке]
              имя [".snu" при флаге 0x40]
```

`d_mob3_xxx_0001806.exa` → `audiostreams\b3_xxx_0\d_mob3_xxx_0001806.exa.snu`,
`my_new_york.exa` → `audiostreams\ew_york\my_new_york.exa.snu`,
`big_shot.exa` → `audiostreams\big_shot.exa.snu`; вторая озвучка —
`audiostreams\es\…`. **[П]**: путь, построенный так, есть в архивах для всех
12 918 записей, а для 12 466 записей с флагом 0x01 — и путь с `es`
(корпусный тест `every_speech_bank_writes_back_and_names_archive_files`).

Каждый id звука из `chv` есть в каком-нибудь `smb` **[П]**. Сам id — не
`sdbm` и не CRC-32 имени (проверено), он берётся только из таблицы; новый id
достаточно сделать неповторяющимся.

`SpeechBank::parse` / `to_bytes` воспроизводят все 59 банков побайтно;
`insert` ставит запись на место по id, `validate` ловит нарушенный порядок.

## 5. Субтитры в файле речи [П: каждый 10-й файл архивов, побайтная запись]

Метаданные между заголовком SNU (0x20 байт) и блоками SNS (`audio.md` §4):

```
0x20  u32  0xCAE87732
      u32  1
      u32  0xD1A3DDF5
      u32  число кусков K (1 или 2)
      K × { u32 id куска, u32 смещение от 0x20, u32 размер }
      куски подряд; нули до блоков SNS, которые начинаются с кратного 16
```

Кусок `0x3596A436` — таблица `LCH2` (тот же формат, что `lh2`) с одной
записью `string_id(имя строки)` и восемью столбцами
`EN CS NL PL RU ES SS LL` (в `SS` — имя строки). Кусок `0x30B00ADF` есть
примерно у половины файлов и не разобран (**[Г]** данные для губ). У
реплик прохожих (`F2F_GENERIC_GREETING`) субтитров нет вовсе.

Правка субтитра (`speech::with_subtitles`) заменяет кусок, пересчитывает
смещения и начало блоков; звук не трогается. Файл кладётся в накладной
архив, как при `sound-import` (`audio.md` §9).

## 6. Таблица событий речи `get` [П, 1 ресурс, побайтная запись]

Один ресурс в `gf2/globals_global` (49 400 байт): когда событие можно сказать
и насколько оно важно. Ключ — тот же хэш имени, что в `chv` и `dlg`.

```
0x00  u16  версия = 3
0x02  u16  число записей N = 1372
0x04  u32  смещение записей = 8
0x08  N × 36 байт, отсортированы по хэшу (без знака), хэши не повторяются:
      +0x00 u32 sdbm(lower(имя события))
      +0x04 f32 1.0 у 1335 записей (2–30 у остальных)
      +0x08 f32 пауза, с: раньше событие не повторяется (1 у 842; 1200 у 121)
      +0x0C f32 второе время, с; −1 — нет (у 1241)
      +0x10 u32 1 у 1366
      +0x14 f32 100 у 1267 (90–170)
      +0x18 i32 ранг 0–4 (4 у 1218)
      +0x1C u32 флаги
      +0x20 u32 приоритет (356, 300, 396, 488…)
```

По коду exe (загрузчик `0x006F5FA0`, поиск `0x006F5DD0` → двоичный
`0x006F5D80`):

- **событие без записи не говорится**: общий путь «сказать событие»
  (`0x006F3EB0`) первым делом ищет запись и молча выходит, если её нет;
- **а в пути воспроизведения строки запись читается без проверки**
  (`0x006F5530`: `movzx eax, byte [запись+0x20]`) — событие, которое есть в
  `chv`, но не в `get`, там приведёт к чтению по нулевому указателю. Из 5130
  событий всех `chv` записи нет только у одного имени
  (`NEWLY_ADDED_GUARD_SPAWNED`) **[П]**. Вывод: **новому событию запись в
  `get` обязательна**; тулкит добавляет её сам;
- пауза (`+0x08`): после реплики следующее время события = сейчас + пауза
  (`0x006F58D0`; с флагом `0x80` — уже при запросе, `0x006F5870`), до него
  событие отклоняется (`0x006F5940`);
- биты 12–19 флагов — группы: сказанное событие помечает свои группы, и
  событие, чья группа помечена, отклоняется (`0x006F5940`, `0x006F58D0`);
  встречаются `0x1000`, `0x4000`, `0x8000`;
- флаги `0x01`, `0x10`, `0x200`, `0x400` меняют вид запроса (`0x006F3EB0`),
  `0x20`, `0x40`, `0x800`, `0x100000` — условия отказа; имён у них нет;
- к приоритету строки прибавляется **младший байт** слова `+0x20`
  (`0x006F5530`); значения в файле при этом — 300…908, то есть слово шире
  байта. Что читает остальное, не найдено;
- поля `+0x0C`…`+0x14` читаются для списка из 69 событий, зашитого в exe
  (`0x007E85B0`, таблица `0x00D6FC18`); смысл не установлен.

`SpeechEventTable::parse` / `to_bytes` пишут ресурс побайтно, `insert` ставит
запись на место; `SpeechEvent::new(имя)` — запись с самыми частыми значениями
(пауза 1 с, ранг 4, приоритет 356).

## 7. Инструменты

```sh
doctor-toolkit dialogues "$GAME"                         # список: узлы, реплики, выборы, кто начинает
doctor-toolkit dialogues "$GAME" --search "Rosato"       # поиск по текстам, событиям, субтитрам, клипам
doctor-toolkit dialogue "$GAME" 0c6576f0                 # дерево с речью и субтитрами
doctor-toolkit dialogue "$GAME" 0c6576f0 --json > d.json # отчёт; поле data — само дерево
doctor-toolkit dialogue-export "$GAME" -o dialogues      # отчёты всех 143 диалогов
doctor-toolkit dialogue-import "$GAME" d.json            # data → dlg в рабочем пространстве
doctor-toolkit subtitle "$GAME" 'audiostreams\b4_xxx_0\d_mob4_xxx_0001cc7.exa.snu'
doctor-toolkit subtitle "$GAME" 'audiostreams\b4_xxx_0\d_mob4_xxx_0001cc7.exa.snu' --set en="Si. Samuele Mangano."
```

`data` в JSON — узлы (`kind`, `children` — номера узлов или `null`,
`payload` — слова), группы, анимации, подписи; `dialogue-import`
проверяет ссылки и пишет ресурс одной операцией рабочего пространства.
Новые строки для подписей — `text-add`, новая запись речи поверх старой —
`sound-import` поверх файла `.snu` (субтитры сохраняются).

**Новая реплика** (этап 83) — `voice-add`: звук, запись банка, строка события
и запись в `get` одной операцией; подробно — `audio.md` §15.

```sh
doctor-toolkit voice-add "$GAME" --speakers [--event P2_LINE1]   # наборы речи: ключ, голос, событий, реплик
doctor-toolkit voice-add "$GAME" gf2/globals_global:chv:18c7062e hello.wav \
    --event DOCTOR_HELLO --name doc1_xxx_0000001 --subtitle en="Hello." --subtitle ru="Привет."
doctor-toolkit speech-bank "$GAME" d_mchl_xxx_0001cb9            # запись банка: id, категория, путь в архиве
doctor-toolkit speech-events "$GAME" P2_LINE1 F2F_ENJOY_FLIGHT   # записи get
doctor-toolkit speech-events "$GAME" DOCTOR_HELLO --set --cooldown 30
```

Редактор в GUI — руководство, раздел 13 (`docs/guide/13-dialogues.md`).

## 8. Открыто

- Названия «переменных» условий (номера запросов `0x006EBFF0`) и слов 1–4
  выбора.
- Какой `chv` говорит реплику: правило игры известно (§3.1: слоты 3, 2, 1, 0
  `ChatterComponent` говорящего, первым — набор `SimpleChatterBox`), но
  редактор диалогов его ещё не применяет: переход от пользователя диалога к
  NPC и его `ChatterComponent` по GUID в индексе не построен.
- Смысл параметров записи `smb` (`+0x18`…`+0x30`, второй хэш `+0x38`) и
  полей `get` `+0x04`, `+0x0C`…`+0x14`, имён флагов — §4, §6.
- Новая реплика проверена на стенде через `SimpleChatterBox` без говорящего
  (`audio.md` §15); реплика персонажа (атрибут 9) и реплика узла `dlg` с
  новым событием на стенде не проверялись.
- Кусок `0x30B00ADF` файла речи не разобран; новая реплика его не получает
  (у половины реплик игры его тоже нет).
