# Формат: MetaModel

`metamodel` (type id `0xF3F21004`) — описание составного объекта: из каких
частей он состоит (модели, коллизия, свет, эффекты), какие значения
атрибутов действуют в каждом состоянии и при каких условиях объект
переходит из состояния в состояние (`DestructibleState_0` →
`DestructibleState_1`, когда падает `health`). Магия `0x4D4D646C` (на диске
`ldMM`), версия 14.

**Проверено на GF2 PC**: все 12 315 ресурсов разбираются, 149 798 свойств,
ни одного свойства неизвестного типа. Код:
`crates/doctor-toolkit/src/resource/metamodel.rs`; проверки —
`research/metamodel_survey.py`, `tests/corpus.rs` (`every_metamodel_parses`).
Описание в `resource-types.md` §7 (версии 10/14, «массивы со счётчиком и
размером элемента») неверно.

## 1. Заголовок

Ресурс — образ памяти: каждый указатель — **абсолютное** смещение от начала
ресурса, 0 — нулевой указатель. Все значения little-endian.

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | u32 | магия `0x4D4D646C` |
| 0x04 | u32 | версия, 14 |
| 0x08 | u32 | размер ресурса |
| 0x0C | u32 | флаги времени выполнения, 0 |
| 0x10 | 4 × u32 | GUID: id ресурса, четыре раза — GUID-ссылка на сам ресурс (см. `simgroup.md` §5) |
| 0x20 | u32 | хэш имени; `sdbm("metamodel")` в 8 591 ресурсе |
| 0x24 | u32 | хэш пути — id ресурса (во всех 12 315) |
| 0x28 | u32 | исходный путь: id неразделённого metamodel, из которого сделан этот; свой id у 1 461 ресурса с маской `0xFFFFFFFF`; у 4 244 разделённых указывает на существующий неразделённый |
| 0x2C | u32 | хэш пути исходника (не проверен) |
| 0x30 | u32 | маска фильтра — один бит: 1 высокий LOD (5 837), 2 средний (2 194), 4 низкий (969), 8 вид карты (249, только `*/global`), 0x10 интерьер (1 323), 0x20 переход (282); `0xFFFFFFFF` — без разделения (1 461). Совпадает с каталогом потока: `high/` 5 742 из 5 837, `medium/` 2 176 из 2 194, `low/` 963 из 969, `interior/` 1 195 из 1 323 |
| 0x34 | 9 × u32 | указатели таблиц T0..T6, блока данных атрибутов (T7) и пользовательских данных (всегда 0) |
| 0x58 | 8 × u16 | число записей T0..T6, восьмое всегда 0 |
| 0x68 | | таблицы по порядку, списки указателей, блок данных T7, строки |

## 2. Таблицы

| Таблица | Шаг | Запись |
|---|---|---|
| T0 ресурсы | 0x20 | `u32 хэш имени, u32 хэш пути (id), u32 type id, 4 × u32 GUID, u32 пользовательские данные 0`; цель ищется по GUID (ниже) |
| T1 состояния | 0x30 | `u32 хэш типа, *тип, *имя, GUID 16 байт, *свойства, u16 число, u16 флаги, *части, *условия, u16 число частей, u16 число условий` |
| T2 переменные | 0x0C | `*имя, u32 хэш имени, u32 вид` (1 bool, 2 int, 4 float) |
| T3 свойства | 0x18 | `u32 значение, *имя, *класс, u32 индекс атрибута, u32 хэш имени, u32 тип` |
| T4 условия | 0x0C | `u32 значение, *переменная (T2), u32 оператор` (ниже) |
| T5 части | 0x24 | `u32 хэш типа, *тип, *имя, GUID 16 байт, *свойства, u16 число, u16 тип объекта` |
| T6 подобъекты (трансформации) | 0x24 | как T5 |

**Ссылка T0 — это GUID, а не хэш пути.** GUID равен ids заголовка цели (во
всех 42 539 ссылках игры — один id четыре раза); хэш пути совпадает с ним
везде, кроме 2 260 ссылок на вложенные metamodel: там GUID — существующий
metamodel с той же маской фильтра (3 273 из 3 273), а хэш пути —
неразделённый оригинал (1 084) или ничего (1 176). Одна функция разрешения
для всех: `ResourceRef::guid` / `target_id`, `metamodel::resource_refs`; ею
пользуются `check-refs`, сборка уровня (`level/model.rs`) и индекс навигации.
До 2026-11-13 уровень и индекс брали хэш пути (`navigation.md` §1.1,
`levels.md` §2).

Списки (`*свойства`, `*части`, `*условия`) — массивы `u32`-указателей на
записи таблиц. Пустой список имеет нулевой указатель. Все хэши — SDBM имени
в нижнем регистре (проверено для всех переменных, свойств, типов состояний
и частей). Поле «флаги» записей T1/T5/T6 — тип объекта: 1 состояние (все
T1), 2 простая часть (`ModelPart`, `VFXPart`, `CollisionHavok4Part`, …),
4 часть-metamodel (только `MetaModelPart`), 8 часть-сущность
(`Destructible`, `CoverHintNode`, `EARSLight`, `Door`, …), 0x10
трансформация (все T6: `PoweredRotationTransform`, `RotationTransform`,
`TargetTracker`, `PoweredSearchLightTransform`). GUID состояний и частей —
NeoGuid (`simgroup.md` §5); у 12 385 частей и 4 089 состояний машина
`XMMOPTIMIZ` (прежнее «`MMOPTIMI`»).

Операторы условий (T4, u16 + u16 выравнивание): 0 больше и 1 меньше — не
встречаются; 2 `≥` (9 677), 3 `≤` (9 714), 4 `=` (1 412, на bool), 5 `≠`
(141, на bool), 6 — проверка битов int (6 060, `stateEntering` /
`stateLeaving`, значения 0–3). В 10 147 состояниях с `≥` и `≤` на одной
переменной значение `≥` не больше значения `≤` (`health` 50..100,
`distance` — ближний и дальний край LOD). Вид переменной T2 — u16 + u16
выравнивание.

Значение свойства по типу:

| Тип | Значение | Число в корпусе |
|---|---|---|
| 0x01 | bool | 6 142 |
| 0x02 | int | 20 892 |
| 0x04 | float | 25 642 |
| 0x08 | указатель на строку | 2 465 |
| 0x10 | указатель на запись T0 (ресурс) | 42 575 |
| 0x20 | указатель на матрицу 4×4 в блоке T7 | 46 646 |
| 0x40 | цвет ARGB | 4 315 |
| 0x80 | указатель на 3 float | 289 |
| 0x100 | указатель на массив u32 (`u32 число`, затем значения); все 713 — `ComponentList` с тремя значениями `9f3fa445, 1, dc51ebb1` (`dc51ebb1` — sdbm `standarddamagecomponent`, `9f3fa445` — класс SimGroup без имени, 754 места). В JSON — `{"type": "array", "value": ["9f3fa445", …]}` | 713 |
| 0x200 | указатель на запись T6 | 119 |

Свойство — это значение атрибута SimGroup: «класс + индекс атрибута»
адресуют тот же атрибут, что и пакет SimGroup, а имя свойства — имя этого
атрибута. Отсюда взяты имена атрибутов в `data/gf2/simgroup_schema.txt`.

## 3. Содержимое

- Типы ресурсов T0: `mesh` 16 047, `vfx` 9 050, `hkx` 8 523, `metamodel`
  3 273, `treemodel` 2 351 (модели деревьев, см. `treemodel.md`), а также
  `hka` (`0x33A1671E`, 3 193, коллизия `hkx`) и `emx` (`0x32293930`, 102,
  звуки дверей) — ресурсов этих двух типов в потоках нет.
- Самые частые свойства: `CSystemCommands.CMD_LoadMatrix` (матрица части),
  `ModelPart.Model` → `mesh`, `CollisionHavok4Part.CollisionModel` → `hkx`,
  `VFXPart.Vfx` → `vfx`, `TreeModelPart.TreeModel` → `treemodel`,
  `MetaModelPart.fileName` → вложенный `metamodel`, параметры света
  `EARSLight.CMD_Set_t_*`.
- Типы состояний: `DestructibleState`, `State`, `Transition`, `LodState`,
  `KnobState`, `SignalState`, …
- Типы частей: `ModelPart`, `VFXPart`, `CollisionHavok4Part`,
  `TreeModelPart`, `Destructible`, `CoverHintNode`, `EARSLight`, …

SimGroup выбирает metamodel атрибутом `Entity.CMD_SetModel`
(GUID-ссылка на id ресурса).

## 4. JSON

`doctor-toolkit logic-export --type metamodel`: состояния со свойствами и
условиями (имя переменной, оператор, значение по виду переменной), части
со свойствами; ресурсные свойства — индексы в `resources`.

## 5. Неизвестное

Имена полей заголовка, T0, типов объектов и операторов взяты из сверки с
другим редактором игр EARS (этап 39) и проверены на всех 12 315 metamodel.

- Входы хэшей 0x20 и 0x2C заголовка.
- Смысл значения 1 в середине `ComponentList` (`9f3fa445, 1, dc51ebb1`).
- Как движок выбирает начальное состояние и применяет переходы.
- Полная запись (`encode`) не реализована: для правки значений хватает
  заплаток, §6.

## 6. Правка

Код: `crates/doctor-toolkit/src/resource/metamodel_edit.rs`. Ресурс — образ
памяти с абсолютными указателями, поэтому правка меняет байты на месте и
дописывает новые данные в конец, ничего не сдвигая:

- `set_property(данные, индекс, значение)` — значение свойства T3 того же
  типа. bool, int, float, цвет пишутся на месте. Матрица и векторы пишутся на
  месте, если их байты не пересекаются с данными другого свойства (блоки
  общие и перекрываются: вектор может лежать внутри матрицы), иначе
  дописываются в конец (выравнивание 16). Массив u32 (тип 0x100) — так же:
  не длиннее прежнего и не общий — на месте, иначе в конец. Новая строка
  всегда дописывается.
  Ссылка на ресурс или подобъект выбирает другую существующую запись T0/T6;
  `Null` обнуляет указатель;
- `set_condition(данные, индекс, слово)` — значение условия T4.

При дописывании обновляется размер в 0x08. Тест корпуса
`random_metamodel_edits_change_only_the_edited_properties`: 32 426 случайных
правок во всех 12 315 ресурсах, изменились ровно правленые свойства, остальные
таблицы как были. JSON — через `logic-import` (свойства и условия
сопоставляются по спискам состояний, частей и подобъектов; общее свойство,
получившее в документе два разных значения, — ошибка). До 2026-11-13 тип
0x100 читался как 4 float (`"vec4"`), и правка писала 16 байт поверх
соседних данных; такие значения в старых документах JSON пропускаются.
