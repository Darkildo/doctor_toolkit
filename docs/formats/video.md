# Видео: `movies/**/*.vp6`

Ролики игры лежат отдельными файлами в `movies/` и не входят в потоки `.str`.
Код: `crates/doctor-toolkit/src/resource/video/`, команды `video-info`,
`video-export`, `video-import`, окно **Movies** с плеером в редакторе.

**Проверено на GF2 PC**: все 59 файлов (тест `every_movie_parses_rebuilds_and_decodes`);
каждый кадр всех роликов декодируется встроенным декодером
(`every_movie_decodes_every_frame`), выборка совпадает с ffmpeg побайтно (§4.1).

| Каталог | Файлы | Что |
|---|---|---|
| `common/` | `attract`, `credits`, `M6FMV`, `mainmenu`, `logo` | фон титульного экрана и демонстрация, титры, ролик миссии, фон главного меню; `logo.vp6` — не видео |
| `en/` | `FMV01–02`, `TRN01–16`, `load`, `deadspace_trailer` | сюжетные ролики, обучающие ролики, заставка при запуске (EA и Paramount), трейлер |
| `es/`, `ru/` | те же имена | озвучка на испанском и русском; `TRN07`, `TRN10`, `TRN12`, `TRN15` в `es` и `ru` — одинаковая заглушка 2 МБ без звука |

58 файлов — контейнер EA с видео VP6 1280×720 и звуком EA-XA (49 со звуком,
2791 с). `common/logo.vp6` — AIFF (16 бит, 48 кГц, моно, 1,5 с); по имени
в `godfather2.exe` не упоминается.

## 1. Контейнер EA

Поток чанков без заголовка файла, без промежутков (сумма размеров = длина
файла; тулкит собирает файл из чанков побайтно):

```
[4]  тег
u32  размер чанка вместе с этими 8 байтами (little-endian)
...  тело
```

| Тег | Тело |
|---|---|
| `MVhd` | заголовок видео, 24 байта (ниже) |
| `MV0K` | ключевой кадр VP6 |
| `MV0F` | промежуточный кадр VP6 |
| `SCHl` | заголовок звука: `"GSTR"`, `u32 1`, затем элементы PT (ниже) |
| `SCCl` | `u32` big-endian — число чанков `SCDl` |
| `SCDl` | данные звука EA-XA (§3) |
| `SCEl` | конец звука, пустой |

Порядок у английских роликов: `SCHl`, `MVhd`, `SCCl`, затем для каждого
кадра — `MV0K`/`MV0F` и `SCDl` со звуком до конца этого кадра (с
округлением вверх до 28 сэмплов), в конце `SCEl`. У испанских и русских
`MVhd` идёт первым, звук отстаёт на кадр. `mainmenu.vp6` и заглушки — без
звука, только `MVhd` и кадры. Чанки кадров выровнены по 4 байта нулями.

`MVhd`:

```
[4]  кодек "vp60"
u16  ширина          u16  высота
u32  число кадров    u32  размер самого большого кадра (без выравнивания)
u32  числитель частоты кадров    u32  знаменатель
```

Частота — числитель / знаменатель: 982026 / 32767 ≈ 29,97 (у `en/TRN07`,
`deadspace_trailer` и заглушек — 982018). Число кадров в заголовке у всех
роликов совпадает с числом чанков кадров.

Элементы PT в `SCHl`: `u8 ключ, u8 длина, значение big-endian`; `0xFD`
открывает подзаголовок звука, `0xFF` закрывает. В подзаголовке: `0x80`
ревизия (3), `0x82` каналы, `0x84` частота (нет — 48 000), `0x85` число
сэмплов, `0xA0` кодек (нет — 10, EA-XA; 23 — EALayer3). Перед подзаголовком
у всех роликов `00 04 1DF851E0`, у английских ещё `05 01 64`, `06 01 65`.
Тулкит пишет заголовок в том же виде.

## 2. Проигрыватель в `godfather2.exe`

Ролики играет RenderWare Movie (`RWMovie`, `MoviePlayer2`) с реестрами
демультиплексоров, видео- и аудиодекодеров (конструктор `0x00d087f0`).

| Адрес | Что |
|---|---|
| `0x00d0a6c0`, `0x00d0a6f0` | опознание контейнера EA по `SCHl` / `MVhd` |
| `0x00d0a9b0` | разбор контейнера EA: `MVhd` — кодек (`vp60`, `VP60`, `06pv`, `06PV` → VP6; `MPEG` → MPEG; иное — неизвестно), ширина, высота, частота = `u32 [0x10] / u16 [0x14]`, число кадров; чанки с первыми буквами `MV` или `MP` — видео, `SCDl` — звук |
| `0x00d0dc90` | разбор `SCHl`: по умолчанию 1 канал, 48 000 Гц, кодек 10; кодек 10 → `EAXA`, 23 → `EAL3` |
| `0x00d0cfb0` | второй демультиплексор — AVI (`RIFF`/`AVI `, `strh`/`strf`): видео `MJPG`, `VP60`, `MPEG`; звук PCM (`wFormatTag` 1) и ADPCM (0x11) |
| `0x00d18360`, `0x00d18370` | методы `VideoDecoder_Vp6`, возвращают `vp60` / `VP60` |
| `0x009c7e50` | путь `movies/%s/%s` |
| `0x009c82f0` | запуск ролика: третий аргумент 0 — каталог языка озвучки, 1 — языка текста, 2 — `Common` |
| `0x00936b90` | главное меню: `mainmenu.vp6` с флагами 7 из `Common` |
| `0x00925f40` | титры: `credits.vp6` из `Common` |

Других видеодекодеров в программе нет (есть строки только
`VideoDecoder_Vp6`, а `MJPG` и `MPEG` встречаются лишь в таблицах опознания),
поэтому заменять ролики нужно на VP6. Контейнер AVI с VP6 и PCM игра,
судя по коду, тоже прочитала бы, но тулкит пишет контейнер EA, как у
оригиналов. Строки `VideoEncoder_Vp6` и `MovieEncoder_Avi` — остатки
библиотеки, игра ими не пользуется.

Какой ролик где (проверено в игре, §6): `en/load.vp6` — заставки EA и
Paramount при запуске, `common/attract.vp6` — фон титульного экрана «Press
any key» и демонстрационный режим после простоя, `common/mainmenu.vp6` — фон
главного меню после выбора профиля.

## 3. Звук EA-XA (ревизия 3)

**Проверено на GF2 PC**: декодер тулкита совпадает с ffmpeg
(`adpcm_ea_r3`) побайтно (TRN07, 3,5 млн сэмплов).

```
SCDl (big-endian):
u32  сэмплов на канал в чанке (кратно 28)
u32  на канал: смещение его данных от конца этой таблицы
     данные канала — кадры по 28 сэмплов:
       u8 (индекс коэффициентов << 4) | s, 14 байт по два 4-битных сэмпла,
          старший полубайт первым;
          сэмпл = clip16(((n << (20 − s)) + c1·cur + c2·prev) >> 8)
       0xEE, i16 cur, i16 prev, 28 × i16 — кадр без сжатия
     данные каждого канала дополнены до чётной длины, чанк — до 4 байт
```

Коэффициенты c1, c2: (0, 0), (240, 0), (460, −208), (392, −220) — те же, что
у EA-XAS. Состояние (`cur`, `prev`) переходит из чанка в чанк. Кадры без
сжатия встречаются в начале некоторых роликов.

Кодировщик тулкита для каждого кадра перебирает 4 пары коэффициентов и 13
сдвигов и выбирает минимум квадратичной ошибки. Новый звук приводится к
48 кГц (передискретизация с окном Ханна) и стерео; звук короче видео
дополняется тишиной до конца последнего кадра.

## 4. Видео VP6

Кадры — On2 VP6 версии 7 (`vp60`), без фильтра и без чересстрочности.
Картинка хранится снизу вверх: декодированный кадр переворачивается по
вертикали. Ключевые кадры — каждые 30 (раз в секунду), квантователь 31–60.
Коэффициенты ключевых кадров закодированы кодами Хаффмана; промежуточных —
чаще ими же, но в почти статичных роликах (`TRN07`: 807 из 1061)
арифметически.

Тулкит содержит:

- **полный декодер** (`vp6/decode.rs`, `mc.rs`, `huffman.rs`; этап 31) —
  см. §4.1;
- **кодировщик**: ключевые кадры и промежуточные кадры из макроблоков «без
  вектора» (предыдущий кадр плюс закодированный остаток), арифметическое
  кодирование коэффициентов, обновление вероятностей в каждом кадре по
  статистике кадра, ключевой кадр каждые N кадров (по умолчанию 30) и при
  смене сцены. Поиска движения нет: медленные и статичные сцены сжимаются
  хорошо, быстрые — дороже при том же качестве. Скорость — около 50–70
  кадров 1280×720 в секунду на одном ядре.

Качество кодировщика (150 кадров 1280×720 из роликов игры, PSNR яркости
относительно исходных кадров; декодирование ffmpeg):

| Ролик | quantizer 40 | 52 (по умолчанию) | 60 |
|---|---|---|---|
| `mainmenu` | 3,5 Мбит/с, 40,0 дБ | 7,1 Мбит/с, 43,6 дБ | 19,4 Мбит/с, 49,0 дБ |
| `attract` | 3,3 Мбит/с, 38,8 дБ | 6,9 Мбит/с, 43,0 дБ | 17,4 Мбит/с, 48,9 дБ |
| `FMV01` | 4,0 Мбит/с, 38,8 дБ | 8,3 Мбит/с, 42,2 дБ | 22,0 Мбит/с, 48,1 дБ |
| `TRN07` (статичный кадр) | 0,19 Мбит/с, 42,6 дБ | 0,30 Мбит/с, 48,0 дБ | 0,50 Мбит/с, 73,7 дБ |

Для сравнения: ролики игры — 6,3–6,9 Мбит/с вместе со звуком.

### 4.1 Декодер

Повторяет эталон (FFmpeg `vp56.c`, `vp6.c`, `vp6dsp.c`, `vp3dsp.c`) бит в
бит, без внешних программ и без `unsafe`; данные недоверенные — ошибки, а
не паники:

- ключевые и промежуточные кадры; типы макроблоков по контексту соседей
  (0–2 найденных вектора), все 10 типов: без вектора, вектор соседа 1/2,
  сосед + приращение, четыре вектора (по одному на блок яркости, цветность
  — округлённое среднее), каждый из них — от предыдущего или **золотого**
  кадра; обновление статистики типов (в т. ч. 16 предопределённых наборов);
- векторы в четвертях пикселя (яркость) и восьмых (цветность), край
  картинки повторяется (окно 12×12 вокруг блока);
- интерполяция: **билинейная** (`h264_chroma_mc8`, всегда для цветности) и
  **4-отводная «bicubic»** (17 наборов `vp6_block_copy_filter`) — режим 1
  всегда, режим 2 кроме длинных векторов и плоских блоков (порог
  дисперсии); **петлевой фильтр** VP3 по сетке 8 пикселей внутри окна
  (флаг промежуточных кадров при заголовке фильтра);
- коэффициенты: арифметические (одна или две части кадра) и **Хаффман**
  (таблицы строятся из вероятностей каждого кадра, чтение по таблице до
  11 бит); полное и сокращённое (4×4) обратное ДКП, «только DC» — как у
  эталона, включая его особенности: сокращённое преобразование
  отбрасывает коэффициенты вне 4×4 у подверсии 6, коэффициенты блока
  переходят в следующий макроблок, флаг Хаффмана без второй части кадра
  читает коэффициенты арифметически со старыми DC-моделями;
- подверсии 6–8, заголовок фильтра (режим, порог дисперсии, длина
  вектора, набор фильтра), разные смещения части коэффициентов;
- повреждённый макроблок: остаток кадра копируется из предыдущего (как
  `error_concealment` ffmpeg), кадр без целого предшественника
  отбрасывается; чересстрочные кадры и VP6A (альфа) не поддержаны — в
  роликах игры их нет (все 58 — `vp60`, без альфы).

Что используют ролики игры (тест `every_movie_decodes_every_frame`): 86 861
кадр, из них 2 801 ключевой; промежуточные — 80 736 с кодами Хаффмана и
3 324 арифметических; 5 005 становятся золотыми; заголовка фильтра нет
(только билинейная интерполяция, без петлевого фильтра). Макроблоков по
типам: без вектора 155,0 млн, внутрикадровых 25,2 млн, приращение 8,9 млн,
вектор соседа 58,7 и 22,2 млн, золотой без вектора 11,6 млн, золотой с
приращением 2,7 млн, четыре вектора 19,0 млн, вектор соседа от золотого
8,1 и 1,2 млн.

**Точность** (2026-11-12, ffmpeg 6.1.1):

- `vp6_decoder_matches_ffmpeg` (корпус): все 16 509 кадров девяти роликов
  (`mainmenu`, `attract`, `M6FMV`, `en/load`, `en/FMV01`, `en/TRN07`,
  `en/TRN03`, `es/TRN10`, `ru/FMV02`) совпадают с ffmpeg побайтно (YUV);
- `vp6_ffmpeg` (без игры, с ffmpeg в системе): 40 синтетических потоков со
  случайным содержимым при верных заголовках всех видов — подверсии 6–8,
  заголовки фильтра, одна/две части кадра, кадры короче нужного; 960
  кадров совпадают побайтно, среди них 406 с bicubic, 257 с петлевым
  фильтром, 58 с восстановлением повреждённых макроблоков, все 10 типов
  макроблоков. ffmpeg запускается с `-cpuflags 0`: его SIMD-ДКП при
  переполнении 16 бит (случайные коэффициенты) расходится с его же
  C-вариантом, которому следует тулкит; на настоящих роликах они равны;
- модульные тесты: кадры кодировщика тулкита (ключевые и промежуточные)
  совпадают с его реконструкцией, произвольный порядок перемотки
  (`MovieFrames`) — с последовательным декодированием, испорченные кадры
  не останавливают декодер; фильтры — с прямой формулой;
- фаззинг: цели `vp6` (поток кадров с длинами, первый — ключевой до 8×8
  макроблоков) и `video`.

**Скорость** (release, один поток, Ryzen 9 7945HX;
`video-export … --decode /dev/null`):

| Ролик | кадров | декодирование | RGBA (параллельно) |
|---|---|---|---|
| `en/FMV01` | 1 967 | 2,5–2,8 мс (360–400 кадров/с) | 0,6 мс |
| `common/attract` | 6 925 | 3,0 мс (333 кадра/с) | 0,6 мс |
| `common/mainmenu` | 900 | 3,0–3,3 мс (305–335 кадров/с) | 0,7 мс |
| `en/load` | 760 | 3,4 мс (294 кадра/с) | 0,7 мс |
| `ru/FMV02` | 1 612 | 3,1 мс (321 кадр/с) | 0,6 мс |
| `en/TRN07` (статичный) | 1 098 | 1,1 мс (897 кадров/с) | 0,7 мс |

То есть 1280×720 в 10 раз быстрее реального времени (29,97 кадра/с) на
одном ядре; ffmpeg с SIMD — около 640 кадров/с на `FMV01`. Перевод в RGBA
(BT.601, ограниченный диапазон, целочисленный с 13 битами дробной части)
идёт по две строки на строку цветности параллельно (rayon), с переворотом
`vp60` на лету. Перемотка — от ключевого кадра (не дальше 29 кадров, до
0,1 с). Под нагрузкой всех 32 потоков корпусный тест даёт 150–220 кадров/с
на поток.

Библиотека: `vp6::Decoder` (кадр за кадром, `stats()` — что использовал
кадр), `video::MovieFrames` — кадры в любом порядке (перемотка к
ближайшему предыдущему ключевому и докодирование, вперёд без лишнего),
`display()` — кадр как показывается, `rgba()` — в RGBA;
`video::preview_frame` — любой кадр. Команда `video-export --decode
out.y4m` декодирует весь ролик в YUV4MPEG2 без ffmpeg и печатает скорость.

## 5. Экспорт и замена

```sh
T=./target/release/doctor-toolkit
$T video-info "$GAME"                                  # все ролики
$T video-info "$GAME/movies/en/load.vp6" --json
$T video-export load --game "$GAME" -o out --audio --frame 0,300   # WAV и PNG
$T video-export "$GAME/movies/en/FMV01.vp6" -o out --ffmpeg FMV01.mp4  # целиком через ffmpeg
$T video-export FMV01 --game "$GAME" -o out --decode FMV01.y4m     # целиком без ffmpeg (Y4M)
$T video-import "$GAME" en/load --video new.y4m --audio new.wav
$T video-import "$GAME" mainmenu --video new.mp4 --quantizer 56   # mp4 через ffmpeg
$T video-import "$GAME" en/TRN07 --audio speech.wav               # только звук
$T video-import "$GAME" mainmenu --fps 15                          # только частота кадров
$T video-import "$GAME" attract --video other.vp6 -o test.vp6      # в файл, не в игру
$T workspace apply "$GAME"                     # записать в игру (или --direct у video-import)
$T workspace revert "$GAME" --game             # вернуть оригиналы в игру
```

Источники видео без внешних программ: YUV4MPEG2 4:2:0 (`.y4m`, кодируется в
VP6), ролик игры (кадры копируются как есть), AVI с VP6 (`VP60`–`VP62`), FLV
с VP6. Всё остальное (MP4, MKV, MP3, OGG…) тулкит сам передаёт в ffmpeg,
если тот установлен (`FFMPEG=/путь`); ffmpeg не обязателен. FLV хранит VP6
сверху вниз — игра покажет такой ролик перевёрнутым, если источник не был
перевёрнут заранее.

Звук: `--audio` — WAV (8/16/24/32 бит, float) или любой файл через ffmpeg;
`--no-audio` убирает дорожку; без них звук сохраняется: при новой картинке
звук оригинала декодируется и кодируется заново, при `--video` из ролика игры
берётся его звук. `--fps` меняет только `MVhd` (`29.97` записывается как
982026/32767).

Замена ролика — правка рабочего пространства, файл `file:movies/…/x.vp6`
(`docs/workspace.md` §3.5): с отменой, сравнением и откатом. `apply` копирует
оригинал в `_doctor_toolkit/backups/movies/…` (если копии ещё нет) и пишет
новый файл атомарно; символическая ссылка (теневой каталог) заменяется
файлом, а не пишется насквозь. `--direct` записывает сразу. Повторный импорт
берёт за основу версию рабочего пространства («сохранить звук» — звук
предыдущего импорта). Библиотека: чистая функция `video::build_movie(VideoInput,
AudioInput, &mut BuildOptions) -> Vec<u8>` и `video::import::build_from_files`.

Окно **Movies** (кнопка в верхней панели, меню **Tools → Movies**,
палитра команд): список роликов (двойной щелчок — играть), сведения,
**плеер** (§5.1), **Export audio (WAV)…**, **Export frame (PNG)…** (кадр
под курсором, любой), **Import video…** и **Replace audio only…** с
выбором звука (сохранить, убрать, из файла) и качества; готовый ролик
записывается в рабочее пространство (в режиме «Write to game at once» —
сразу в игру).

### 5.1 Плеер (этап 31)

Код — `crates/doctor-toolkit-gui/src/video_view/player.rs`.

- **Декодирование в фоновом потоке**: поток владеет `MovieFrames`; по
  запросу «кадр N» он перематывает (ключевой кадр и докодирование),
  переводит кадр в RGBA и отправляет; при воспроизведении продолжает
  следующими кадрами через очередь на 3 готовых кадра, то есть идёт на
  несколько кадров впереди. Кадры, которые курсор уже прошёл (поток
  отстал), декодируются, но не переводятся в RGBA. Каждый запрос несёт
  номер поколения: после перемотки старые кадры из очереди отбрасываются.
- **Синхронизация**: как в редакторе роликов (`cutscene_view/sound.rs`,
  тот же `SoundPlayer`): звук EA-XA декодируется в фоне при первом Play и
  приводится к формату устройства; время курсора — часы звукового вывода
  (не идут назад), картинка — самый новый готовый кадр не позже курсора.
  Без звука (ролик без дорожки, сборка с `--no-default-features`,
  нет устройства) — таймер кадров интерфейса. Пауза останавливает на
  показанном кадре; перемотка во время воспроизведения переводит и звук.
- **Управление**: Play/Pause (пробел), шкала времени по всей ширине
  (перетаскивание — перемотка), `|<` `<` `>` `>|` (Home, ←, →, End —
  кадр назад/вперёд ставит паузу), время `м:сс.сс / длительность`, номер
  кадра и пометка ключевого, громкость и Mute, **Full window** (или
  двойной щелчок по картинке) — картинка на всё окно редактора, Esc —
  обратно; внизу время декодирования кадра. Картинка вписывается в
  место с сохранением пропорций, по краям чёрные поля.

`DOCTOR_TOOLKIT_GUI_MOVIES=<имя>[:<кадр>][,play][,full]` открывает окно с
роликом и кадром, `play` — сразу играть, `full` — на всё окно (для снимков
без пользователя, `docs/viewers.md` §5). Снимок промежуточного кадра 1000
`en/FMV01` во вложенном Xephyr совпадает по виду с кадром ffmpeg; с `play`
снимок через 150 кадров интерфейса показывает воспроизведение (кадр 1000
после старта с 900, сборка без звука — таймер).

## 7. Открытые вопросы

- Поиск движения в кодировщике (векторы, золотой кадр) — сжатие быстрых
  сцен в 2–3 раза хуже, чем могло бы быть.
- VP6A (альфа) и чересстрочные кадры не поддержаны: в игре их нет.
- Ролики в формате мода (поля описаны в `docs/workspace.md` §3.5, этап 14).
- Округление в декодере EA-XA самой игры не сверено (ffmpeg — без
  округления); разница не больше младшего бита.
- Кодек EALayer3 (23) в роликах не встречается и не поддержан.
