# Звук: `sbk`, архивы `.viv`

Звук игры построен на EA AudioCore (SndPlayer, AEMS). Строки `godfather2.exe`
называют декодеры EALayer3 и EA-XA (`Snd::CEAXABLKDecf`), но это декодеры звука
роликов (`video.md`); во всех звуковых файлах — EA-XAS v1.

| Где | Что | Объём | Разбор |
|---|---|---|---|
| `GODFATH0..2.viv` | 24 913 файлов `audiostreams\*.exa.snu`: речь (английская и `es`), музыка, фоновые голоса | 4,7 ГБ | полный |
| `sbk` (8 ресурсов) | банки звуков уровней и меню: 942 эмиттера, 2 938 вариаций, 2 399 сэмплов, 40,8 мин | 35 МБ | полный: метаданные (§3), чтение, запись байт в байт, правка, новые звуки и эмиттеры |
| `smb` (59) | банки потокового звука: id → `.exa`-файл архивов и параметры (речь, музыка, фон) | 1,5 МБ | полный: чтение и запись байт в байт (`dialogues.md` §4); субтитры речи — `dialogues.md` §5 |
| `get` (1) | таблица событий речи | 49 КБ | полный, запись байт в байт (`dialogues.md` §6) |
| `auc` (2) | конфигурация звука: категории микшера, пулы банков, «даки» | 11 КБ | полный, запись байт в байт (§13) |
| `mix` (43) | снимки микшера | 81 КБ | структура полностью, запись байт в байт; смысл уровней — по данным (§14) |

## 1. Заголовок SNR

**Проверено на GF2 PC.** 8 байт big-endian (12 с флагом цикла):

```
u32  версия:4 | кодек:4 | (каналы − 1):6 | частота:18
u32  тип:2 (0 — в памяти, 1 — поток, 2 — gigastream) | цикл:1 | число сэмплов:29
u32  начало цикла — только при флаге цикла
```

Кодек во всех файлах — 4, EA-XAS v1. Частоты: 32 000 Гц (речь и музыка в
архивах), 14 000–24 000 Гц в банках.

## 2. Блоки SNS и EA-XAS v1

**Проверено на GF2 PC.**

```
u8   0x00, последний блок — 0x80
u24  размер блока вместе с заголовком (big-endian)
u32  число сэмплов в блоке (big-endian)
     кадры EA-XAS: по 0x4C байт на канал на 128 сэмплов, каналы чередуются
```

Кадр EA-XAS v1 одного канала — 4 группы по 32 сэмпла. Сначала 4 заголовка
групп по 4 байта: два little-endian `i16`; первый — сэмпл 0 (младший полубайт —
индекс коэффициентов 0–3), второй — сэмпл 1 (младший полубайт — сдвиг `s`).
Затем 15 строк по 4 байта: байт `g` строки — два сэмпла группы `g`, старший
полубайт первым. Сэмпл: `((n << (20 − s)) + p1·c1 + p2·c2 + 0x80) >> 8` с
насыщением до `i16`; коэффициенты ×256: (0, 0), (240, 0), (460, −208), (392, −220).
Декодер — `crates/doctor-toolkit/src/resource/audio.rs`; все 2 399 звуков банков
и каждый 200-й файл архивов декодируются в точно заявленное число сэмплов.

## 3. Банк `sbk`

**Проверено на GF2 PC**: все 8 банков игры (этап 41). Банков в архивах
`.viv` и отдельными файлами нет: все 8 лежат в потоках
(`gf2/frontend`, `gf2/cuba/local`, `gf2/miami/local`, `gf2/queens/local`,
`gf2/globalfolder/audio/emx_global_folder_stream` — 855 звуков из 942,
`gf2/globalfolder/audio/emx/ui/in_game`, `mp_warehouse/mp_warehouse`,
`gf2/cuba/global/objectives/cp_010_030_mission_1/m1_always_stream`).
Код: `crates/doctor-toolkit/src/resource/sbk.rs`.

Банк — образ EARS AudioCore для загрузки на месте: метаданные сессии,
затем секция сэмплов `sdat`. Все поля little-endian. Подсказки о порядке
полей взяты из стороннего редактора игр EARS (раскладка по отладочной
Xbox-сборке); каждое поле проверено на
всех банках, а разбор указателей, поиск звука по имени и инструмента — по
коду `godfather2.exe` PC (§3.5). Своды ниже — по всем 8 банкам.

### 3.1 Заголовок банка (0x18)

```
0x00  "sbnk"
0x04  u32  206 — версия банка
0x08  u32  размер метаданных от 0x18 (до конца последней таблицы)
0x0C  u32  размер sdat
0x10  u32  смещение sdat = выравнивание (0x18 + размер метаданных) на 0x40, нули между ними
0x14  u32  размер sdat, которым владеет сессия; везде равен 0x0C
```

### 3.3 Пулы — строго по порядку

Игра (`0x005F0990`, PC) не читает записанные смещения пулов, кроме 0x50 и
0x30: она идёт одним курсором от пула эмиттеров и прибавляет размеры. Так
раскладка задана однозначно, и записанные смещения во всех банках с этим
обходом совпадают:

```
пул эмиттеров         0x54 на эмиттер
банки инструментов    8 на банк: u32 число инструментов, u32 смещение в таблице инструментов
таблица инструментов  u32 на инструмент: смещение в пуле инструментов
пул инструментов      инструменты подряд, без выравнивания
пул команд            8 байт на команду
пул вариаций          8 байт на вариацию
lookup эмиттеров      24 байта на эмиттер (смещение 0x30)
lookup инструментов   24 байта на инструмент (сразу после)
таблица имён          0x30 на эмиттер, если есть
```

Банки инструментов делят таблицу подряд: банк i — (1, 4·i) во всех банках
игры, то есть у каждого эмиттера свой банк с одним инструментом. Игра
(`0x005F09E0`) прибавляет к смещению банка начало таблицы, а к каждой
записи таблицы — начало пула, поэтому записи разных банков пересекаться не
могут. Команды и вариации эмиттеров лежат в порядке эмиттеров без пропусков.

### 3.5 Как игра находит звук

По коду `godfather2.exe` PC 1.0.789.0:

- Lua `PlayEmx(name, …)` (`0x00436A90`, строка `PlayEmx` — `0x00E30C18`)
  хэширует имя функцией `0x004DAFD0` — SDBM (множитель 65599) с переводом
  A–Z в нижний регистр — и передаёт хэш в `0x005E49D0` → `0x005F0560`;
- `0x005F0560` идёт по списку загруженных сессий и в каждой **перебирает
  lookup эмиттеров подряд**, сравнивая поле 0x14 (хэш имени) с хэшем;
  первый найденный эмиттер берётся из таблицы эмиттеров по полю 0x04
  (индекс). Порядок lookup для поиска по имени не важен; при одинаковом
  имени в двух загруженных банках играет первый по списку;
- при загрузке `0x005F0490` вызывает обход пулов (`0x005F0990`), разбор
  инструментов (`0x005F09E0`) и эмиттеров (`0x005F0A30`). Последний для
  каждого эмиттера ищет инструмент (`0x005F0B20`): **двоичный поиск**
  (`0x005F0BE0`) ключа 0x48 дорожки по полю 0x00 lookup инструментов, затем
  банк из поля 0x08 (с ограничением числом банков) и инструмент из поля 0x04
  (с ограничением числом инструментов банка). Если инструмент не найден,
  запись таблицы эмиттеров обнуляется — звук молча пропадает.

Отсюда правила записи: lookup инструментов отсортирован по ключу без
знака, ключ инструмента = поле 0x48 дорожки; хэш имени в lookup эмиттеров =
id шаблона эмиттера. Проверку версии 206 в PC-сборке найти не удалось
(в выпуске assert'ов нет).

### 3.6 Инструменты и тоны

```
инструмент: u16 число тонов (1–20), u8 флаги (0), u8 0, затем тоны по 0x94
тон:        f32 громкость до огибающей, 16 × (f32 громкость, f32 секунды),
            (f32, f32) затухание после отпускания, i32 число сегментов (0–3),
            u32 номер сэмпла в sdat
```

3 176 тонов. В 2 937 тонах сегментов нет; громкость до огибающей 1 у 2 970
тонов, отпускание 10 мс у 2 905. Неиспользуемые сегменты у всех тонов —
(1, 0): громкость 1, 0 с. Сэмплы делятся: 444 сэмпла играют несколько тонов,
неиспользуемых нет.

### 3.7 Вариации и команды

Вариация — один из вариантов звука: заголовок (u32 начало, u32 конец
автоприглушения; `0, FFFFFFFF` у 2 910 из 2 938) и команды секвенсора, у всех
вариаций дорожки их одинаковое число. Команда, 8 байт:

```
u16 задержка перед командой, мс    u8 код    i8 аргумент    i32 аргумент
```

| Код | Команда | Аргументы | В игре |
|---|---|---|---|
| 0 | нет | — | 1 348: добивка до общего числа, почти всегда в начале, с задержкой 0 |
| 1 | конец | задержка — пауза цикла; i8 — сколько команд пропустить при повторе | 153 |
| 2 | нажать тон | i8 — тон инструмента, i32 — сила 0–127 | 4 406, все тоны в пределах инструмента |
| 3 | отпустить тон | i8 — тон | 53 |
| 4 | высота | i32 / 65536 | 179, 0,5–2,4 |
| 5 | изменение высоты за такт | i32 | 0 |
| 6 | частота модуляции | i32 / 65536 | 57 |

Чаще всего вариация — одна команда «нажать тон» (1 829), затем два нажатия
(257), «нет + нажать» (131), «высота + нажать» (65).

### 3.8 Lookup-таблицы (24 байта)

```
u32 ключ   u32 индекс   u32 значение[3]   u32 хэш имени
```

| Таблица | Ключ | Индекс | Значения | Хэш имени |
|---|---|---|---|---|
| эмиттеров | 32-битная свёртка GUID ассета — кратна 4 во всех 942 записях, по имени не вычисляется; у одинаковых звуков в разных банках одинакова | номер эмиттера (перестановка) | 0, 0, 0 | id шаблона эмиттера |
| инструментов | id шаблона эмиттера | 0 | номер банка инструментов, 0, 0 | хэш имени одного из эмиттеров банка, но не всегда своего (совпадает у 10 из 942) — след сборщика, игра его не читает |

Обе таблицы отсортированы по ключу.

### 3.9 Имена эмиттеров

Таблицы имён (0x30 на эмиттер) нет ни в одном банке, имён в банке нет.
Их подбирают по хэшу (как на этапе 40): SDBM нижнего регистра от кандидата
с `.emx` должен дать id шаблона. Источники кандидатов: строки ресурсов игры
(события анимаций `bnk`, `grt`, скрипты) и `godfather2.exe` — 383 имени,
номерные варианты подтверждённых — ещё 3. Итог — **386 из 905** разных
звуков, список `data/gf2/emitter_names.txt`; остальные показываются хэшем. Случайное совпадение исключено: на ~20 тыс. кандидатов и 905
хэшей ожидаемо 0,004 ложных.

### 3.10 `sdat`

```
"sdat", u32 N, N × {u32 номер = позиция, u32 0x0313BABE, u32 смещение от sdat, u32 0xFEEDFEED}
```

По смещению — заголовок SNR и сразу его блоки SNS (тип «в памяти»). Первый
сэмпл — сразу после таблицы, сэмплы идут подряд без зазоров (смещения
кратны 4 из-за размеров блоков), последний кончается в конце ресурса.

### 3.11 Запись, правка, добавление

`SoundBank::parse` читает всё (обход пулов — как в игре), `to_bytes`
пишет заново, выводя все смещения и размеры. **Все 8 банков записываются
побайтно равными исходным** (корпусный тест
`every_sound_bank_round_trips_and_takes_new_sounds`), `validate()` не
находит в них ни одной проблемы, каждый эмиттер находит свой инструмент.

| Правка | Как |
|---|---|
| громкость, случайные высота и громкость, затухание, приоритет, «не больше одновременно», флаги, выбор вариации, категория микшера | поля эмиттера и дорожки |
| высота (постоянная) | команды «высота» всех вариаций; если их нет — команда ставится перед нажатием тона: на место добивки, а нет добивки — все вариации растут на одну команду (добивка в начале, как в игре) |
| сила нажатия | аргумент всех команд «нажать тон» |
| удалить вариацию | вариация уходит, тоны и сэмплы остаются |
| новый звук в эмиттере | сэмпл в конец `sdat`, тон в инструмент эмиттера (огибающая первого тона), вариация «нажать новый тон» с силой и автоприглушением первой вариации; при большем числе команд — добивка |
| новый эмиттер | сэмплы, инструмент в своём банке инструментов, запись lookup инструментов (ключ — хэш имени, банк — новый), эмиттер с параметрами образца и id = SDBM имени, по вариации на звук, запись lookup эмиттеров: хэш имени, ключ — хэш с обнулёнными двумя младшими битами, первый свободный (+4); обе таблицы остаются отсортированными |

Проверка ссылок (`validate`): размеры таблиц, сортировка и повторы ключей,
индексы lookup, хэш имени = id шаблона, банк и номер инструмента, тоны
не пустые, номера сэмплов в пределах `sdat`, сэмплы — SNR, у каждого
эмиттера находится инструмент, число команд вариаций, коды команд < 7,
сила 0–127, тон команды — в инструменте, громкость и разбросы в 0–1, не
больше 255 вариаций. Правки CLI и GUI отказываются записать банк, если у
него появились новые проблемы; для нового эмиттера CLI проверяет, что имени
нет ни в одном банке игры (иначе игра сыграет тот, что загружен первым),
GUI — что его нет в банке и в списке имён игры.

Пересобранная правка тоже проверяется заново: тот же корпусный тест на
каждом банке добавляет вариацию, меняет высоту, добавляет эмиттер с двумя
звуками — банк читается снова, равен записанному, проблем нет, новый
эмиттер находится по имени, старое чтение сэмплов (`parse_sbk`) видит все
сэмплы.

Фаззинг: цель `sbk` (`fuzz/fuzz_targets/sbk.rs`) разбирает, проверяет,
пишет (записанное должно читаться и писаться так же), меняет высоту и силу,
добавляет вариацию и эмиттер. Первый прогон нашёл панику — новый звук в

## 4. Архивы `.viv` (BIGF) и файлы SNU

**Проверено на GF2 PC**: 3 архива, 24 913 файлов, все разбираются.

```
0x00  "BIGF"
0x04  u32 LE  размер архива
0x08  u32 BE  число файлов
0x0C  u32 BE  размер заголовка с таблицей
0x10  записи: u32 BE смещение, u32 BE размер, имя с `\` и NUL
```

Файлы выровнены по 0x800. 12 681 файл лежит в `audiostreams\` и его
подкаталогах групп (`ar_xxx_0\d_gear_xxx_0001a95.exa.snu`, музыка
`ro_cuban\bolero_cubano_a.exa.snu`), 12 232 — в `audiostreams\es\` (вторая
озвучка, тот же набор групп).

Файл SNU:

```
0x00  u8   3 (у двух файлов 1, и тогда 0x03 = 0)
0x01  u8   0, 4, 8 или 12; смысл неизвестен. О метаданных не говорит: у
           четверти файлов речи с метаданными здесь 0 (этап 83,
           `research/snu_flags.py`). Метаданные
           есть, когда блоки SNS начинаются дальше 0x20 (поле 0x08)
0x03  u8   число каналов
0x04  u32 LE  длительность в целых миллисекундах (число сэмплов · 1000 / частота, вниз)
0x08  u32 LE  смещение блоков SNS: 0x20, а с метаданными — дальше (0x160, 0x1230…)
0x0C  u32  обычно 0 (у 2 % файлов не 0, смысл неизвестен)
0x10  заголовок SNR (тип 1 — поток)
0x20  метаданные речи: таблица и чанк `LCH2` с субтитрами реплики на всех
      языках («Hola, Dominic...», кириллица и т. д.), имя реплики
…     блоки SNS до блока с флагом 0x80; файл выровнен на 16 байт (добивка
      внутри последнего блока)
```

Блоки SNS: первый — 13 кадров стерео или 26 моно (1984 байта), дальше по 14
стерео или 27 моно кадров (около 2 КБ). **Проверено** на каждом 20-м файле
архивов (1248 файлов): поле 0x04 равно длительности, отклонение только от
округления.

`.snu` воспроизводят vgmstream и foobar2000 с vgmstream. Звуки банков тулкит
оборачивает в такой же SNU.

## 7. Кодировщик EA-XAS v1 и запись SNR/SNS

Код: `crates/doctor-toolkit/src/resource/audio_encode.rs`.

Кодировщик — точное обращение декодера (§2). Для каждой группы из 32 сэмплов
перебираются все 4 набора коэффициентов и все 16 сдвигов; квантование идёт по
замкнутому циклу — предсказание строится по уже декодированным сэмплам, как их
увидит игра. Остаётся вариант с наименьшей квадратичной ошибкой. Первые два
сэмпла группы хранятся с точностью 12 бит (младший полубайт занят индексом и
сдвигом), они округляются к ближайшему.

Входной звук (WAV 8/16/24/32 бит или float; любой другой формат — через
ffmpeg, если он установлен) приводится к формату заменяемого звука:
число каналов (моно дублируется, лишние каналы сводятся: нечётные — влево,
чётные — вправо), частота (оконный sinc), флаг цикла (начало цикла сохраняется,
если помещается в новую длину). Длительность может быть любой.

Запись:

| Что | Функция | Раскладка |
|---|---|---|
| звук банка | `build_inline` | заголовок SNR + блоки SNS, тип 0 |
| файл `.snu` | `build_snu` | заголовок SNU (флаги, поле 0x0C и метаданные с субтитрами берутся из заменяемого файла), SNR тип 1, блоки как в игре, выравнивание на 16 |
| отдельный файл | `sound-encode` | `.snu` или `.snr` |

**Качество** (корпусные тесты `encoder_round_trips_game_sounds` и
`encoder_quality_on_movie_soundtracks`):

| Проверка | Результат |
|---|---|
| Звуки игры: декодировать → закодировать в том же формате → декодировать; все 2 399 звуков банков и каждый 100-й файл архивов (2 650 звуков, 144,5 млн сэмплов) | SNR: медиана 98,4 дБ, минимум 38,7 дБ, по всему объёму 62,6 дБ; PSNR: медиана 118 дБ, минимум 49,6 дБ. Кодировщик почти без потерь находит параметры исходного кодирования |
| Устойчивость: второе поколение (кодировать уже перекодированное) | PSNR медиана 129,5 дБ, минимум 87,6 дБ: повторное кодирование почти ничего не меняет |
| Звук, никогда не бывший EA-XAS: дорожки 37 роликов (EA-XA, 48 кГц, по 20 с) и AIFF `logo.vp6` | при 48 кГц SNR 40–51 дБ (logo — 30,5 дБ), при 32 кГц (как музыка и речь в архивах) 33–43 дБ (logo — 27,7 дБ) |
| Заголовок SNU при перекодировании звука игры | совпадает с исходным побайтно вместе с метаданными |
| Пересборка банка `sbk` с тем же звуком на месте | побайтно равна исходному банку (все 2 399 звуков) |

## 8. Замена звука в банке `sbk`

`replace_sbk_sound(банк, позиция, сэмпл)` пересобирает секцию `sdat`: таблица
сохраняет порядок и номера, данные звуков раскладываются заново в прежнем
порядке и с прежним выравниванием, смещения в таблице пересчитываются. Размер
секции обновляется в `0x14` и в `0x0C` (там он же). Метаданные банка (§3) не
меняются — длительности в них нет: звук другой длины играется целиком
(проверено в игре, §10). Номер звука — номер сэмпла в `sdat`; один сэмпл
могут играть несколько тонов разных эмиттеров (§3.6), замена слышна во всех.

```sh
doctor-toolkit sound-import "$GAME" 'gf2/frontend:sbk:6d4bafbd#11' click.wav --direct
```

Номер после `#` — номер звука, как в именах файлов команды `audio`. Правка —
обычная замена ресурса в рабочем пространстве (отмена, diff, моды). В GUI — кнопка
**Import…** у звука в списке банка; банк берётся из рабочего пространства, так
что несколько замен в одном банке складываются.

## 9. Замена потокового звука в `.viv`

Архивы занимают 4,7 ГБ, поэтому тулкит их **не переписывает**. Как игра ищет
файл (`godfather2.exe`):

- при запуске монтируются `GODFATH0.VIV` … `GODFATH12.VIV` по порядку, какие
  есть (функция запуска движка `0x0068bd30`, цикл с `0x0068bf87`; число 13 — `0x00e2f000`; `rw::core::BigHandler::AddArchiveFromFile`,
  `0x00b901d0`, с флагом 0 добавляет архив в конец списка);
- открытие файла (`0x00b90fb0`) идёт по списку с начала и берёт **первый**
  архив, где имя есть. Отдельные файлы `audiostreams\…` на диске игра не
  ищет: под Wine (`WINEDEBUG=+file`) нет ни одной попытки их открыть;
- под Wine архив `GODFATH3.VIV`, положенный после архивов игры, открывается
  (`openat`), то есть монтируется, но по коду выше запись из него для имени,
  которое есть в `GODFATH0..2`, не выбирается.

Поэтому изменённые записи кладутся в **накладной архив с номером 0**, а
архивы игры **переименовываются** на номер выше (`GODFATH2.viv` →
`GODFATH3.viv`, затем 1 → 2, 0 → 1). Переименование не копирует данных,
атомарно, а для теневого каталога из ссылок переименовывает саму ссылку.
Накладной архив — обычный BIGF (тот же формат и выравнивание, §4; запись
заголовка тулкитом побайтно совпадает с заголовками всех трёх архивов игры —
тест `archive_writer_reproduces_the_game_archive_headers`), первая запись —
`_doctor_toolkit\overlay.txt` с владельцем и списком файлов; по ней накладной
архив отличается от архивов игры.

Применение и откат — в рабочем пространстве (`docs/workspace.md` §3.5):

```sh
doctor-toolkit sound-import "$GAME" 'audiostreams\e_screen\title_screen_01.exa.snu' theme.wav
doctor-toolkit workspace apply "$GAME"         # GODFATH0.viv — накладной, 0..2 → 1..3
doctor-toolkit workspace revert "$GAME" --game # накладной удалён, имена возвращены
```

Откат после прерванной записи доводит переименования по записи в
`applied.json` (каждое переименование проверяет, что уже сделано). Команда
`restore` возвращает файлы из резервных копий, но накладной архив не трогает —
для него `workspace revert --game`.

`viv-list "$GAME" [фильтр]` показывает записи всех архивов (с накладным).

## 11. Правка банка и новые звуки

Все правки — обычные правки ресурса в рабочем пространстве
(`docs/workspace.md`): отмена, `workspace diff`, моды, `--direct`.

```sh
B=gf2/frontend:sbk:6d4bafbd
doctor-toolkit sbk-info "$GAME" $B [--emitter fanfare.emx] [--json]   # эмиттеры, тоны, вариации, проблемы
doctor-toolkit sbk-edit "$GAME" $B --emitter '#4' --volume 0.5 --pitch 1.5 --velocity 100

doctor-toolkit sound-add "$GAME" $B click2.wav click3.wav --emitter '#4'   # новые вариации
doctor-toolkit sound-add "$GAME" $B beep.wav --new my_beep --like '#0'     # новый эмиттер my_beep.emx
```

Эмиттер задаётся именем `.emx` (расширение можно опустить), хэшем или
`#номером`. Новые звуки приводятся к формату первого сэмпла эмиттера
(`--rate`, `--channels` — свой). Новый эмиттер берёт параметры у `--like`
(по умолчанию — первый эмиттер банка); игра найдёт его по имени файла
`ИМЯ.emx` (`PlayEmx("ИМЯ.emx", …)` в скриптах — без `.emx` не находит,
§12; `audio.play_emx` визуальных скриптов, `audio: play` событий
анимации), если банк загружен. Имя самого банка у нового эмиттера не
хранится: таблицы имён в банках нет, поэтому `sbk-info` и GUI показывают его
хэш (метка правки в рабочем пространстве хранит имя).

В GUI у банка две вкладки: **Звуки** — дерево эмиттер → вариации → тоны и
сэмплы (кнопка тона проигрывает его сэмпл с высотой вариации), параметры
выбранного звука (громкость, случайные высота и громкость, затухание,
приоритет, «не больше одновременно», выбор вариации, флаги 3D, доплер,
реверберация, высота и сила нажатия), **Сохранить** / **Отменить правки**,
**Добавить звук…** (вариации из файлов) и **Добавить новый звук…** (эмиттер
с введённым именем); **Сэмплы** — прежний список с прослушиванием, WAV и
заменой (§8).

Python: `doctor_toolkit.sound_bank(data)` — структура банка словарём
(эмиттеры с именами и номером инструмента, инструменты, lookup, сэмплы,
проблемы).

## 13. `auc` — конфигурация звука

**Проверено на GF2 PC** (этап 83): два одинаковых ресурса по 5 700 байт
(`gf2/frontend`, `gf2/globals_global`), запись байт в байт (корпусный тест
`audio_config_and_mixes_write_back`). Код: `resource/auc.rs`, своды —
`research/speech_survey.py`.

```
0x00  u32 0 (во время работы — таблица методов), u32 0
0x08  u32 12 — смещение тела
0x0C  u32 11 — версия
0x10  u32 число категорий C = 49
0x14  u32 число пулов банков P = 6
0x18  u32 число «даков» D = 3
0x1C  u32 0 (не 0 — после даков идут цепочки плагинов; в игре их нет)
0x20  C × 100 байт: имя[32], второе имя[32] (пусто), имя родителя[32], u32 0
      P × 40 байт:  имя[32], u32 размер, u32 вид
      D × 176 байт: u32, u32, 8 байт без инициализации, имя[32], имя mix[128]
```

- **Категории** — дерево из трёх корней: `DIALOG` (8: `CHATTER`,
  `COMBAT_CHATTER`, `CREW_CHATTER`, `CHATTER_FOLLOWUP`, `CHATTER_DEATH_TAUNT`,
  `IGC`, `MOVIE_PLAYER` и сам `DIALOG`), `MUSIC` (4), `SFX` (37: `FOOTSTEPS`,
  `VEHICLE`, `SFX_AMBIENT_*`, `UI`…). `DIALOG` и `MUSIC` записаны родителями
  самих себя, у `SFX` своей записи нет. Звуки (`smb` `+0x34`, эмиттеры `sbk`
  `+0x18`) и каналы `mix` называют категорию хэшем `sdbm(lower(имя))`.
- **Пулы банков**: `audio_bank_00` (1536, вид 1), `audio_bank_01` (125),
  `audio_bank_02` (89), `Mission` (33), `Venue Large` (22, вид 2), `Venue
  Small` (5, вид 3). По именам и размерам — места под банки `sbk` **[Г]**.
- **Даки**: `WEAPON_DUCK` (95, 50; `combine_weapon_duck.mix`),
  `CREW_CHATTER_DUCK` (100, 20; `combine_crew_chatter_duck.mix`),
  `CHATTER_FOLLOWUP_DUCK` (90, 20; `combine_chatter_followup_duck.mix`).
  Записи `smb` называют дак хэшем имени (`+0x3C`). Восемь байт перед именем
  первого дака — мусор сборщика (`rsion='1` — обрывок XML), тулкит хранит их
  как есть. Имя последнего микса — 33 символа, а имя в самом ресурсе `mix`
  обрезано до 31 (`combine_chatter_followup_duck.m`): хэши разные, так что
  этот дак свой микс по имени, по-видимому, не находит **[Г]**.

По коду exe 1.0.789.0: обработчик звуковых ресурсов (`0x00455CF0`) делит типы
в `0x004560E0`; `auc` — `0x00456460` → `0x005E35E0` (проверка версии 11):
категория регистрируется по хэшу имени вместе с хэшами второго имени и
родителя (`0x005DC510`), пулы складываются в список (`0x005F0720`), дак — по
хэшам имени и микса (`0x004C9690` → `0x004C8CE0`). **Банк `sbk` не
загружается, пока не загружен ни один `auc`** (`0x004562F0` проверяет флаг,
который ставит `0x00456460`).

Правка: новая категория под существующим родителем —
`AudioConfig::add_category`, CLI `audio-config --add-category ИМЯ --parent
РОДИТЕЛЬ` (в оба ресурса сразу). На стенде новая категория не проверялась.

## 14. `mix` — снимки микшера

**Проверено на GF2 PC** (этап 83): 43 ресурса (3 в `gf2/frontend`, 2 в
`gf2/cuba/local`, 1 в `gf2/miami/local`, 37 в `gf2/globals_global`), 1749
каналов, запись байт в байт. Код: `resource/mix.rs`.

```
0x00  u32 0, u32 0
0x08  u32 0x1C — смещение тела
0x0C  3 × u32 0 (поля времени работы)
0x18  u32 0x7C90EE18 — одно значение во всех миксах
тело (смещения от него):
0x00  имя[32], обрезано до 31 символа (`occlusion.mix`, `igc_02.mix`)
0x20  u32 15 — версия
0x24  u32 флаги; бит 0 игра ставит сама после перевода смещений
0x28  u32 число каналов N (2–48)
0x2C  u32 смещение первого канала = 0x38
0x30  u32 число записей второго списка = 0
0x34  u32 смещение второго списка = конец каналов (0x38 + 44·N)
0x38  N × 44 байта, связаны в список:
      +0x00 u32 категория: sdbm имени категории `auc` (все 1749 — из `auc`)
      +0x04 8 × f32 уровни
      +0x24 u32 частота, Гц
      +0x28 u32 смещение следующего канала от этого (44; у последнего 0)
```

Уровни — **по данным, не по коду**:

| Уровень | Значения | Чтение |
|---|---|---|
| 0, 1 | −1 у 1653; иначе 0,25–1 и 0–1 | неизвестно; −1 — «не задано» |
| 2 | 1 (1586) или 0 (163) | неизвестно |
| 3 | 1 (833), 0 (700), 0,1–0,95 | **громкость** категории: в `occlusion.mix` речь 0,6, эффекты 0,8, окружение 0 |
| 4, 5 | 0 и −1 всегда | — |
| 6, 7 | всегда равны: 0, 0,1–4 | **время** перехода, с |
| частота | 96000 (1714), 6000 (32), 2000, 1000, 400 | срез фильтра низких частот: 6000 Гц почти у всех каналов `occlusion.mix` |

По коду: `mix` — `0x004565E0` → `0x004CB440` (версия 15 в `+0x20` тела,
перевод смещений `0x005DDE90`, который идёт по каналам по полю `+0x28` и по
второму списку по полю `+0x1C`); микс регистрируется по хэшу имени
(`0x00456530`). Скрипты включают его по имени: `ApplyMix`, `RemoveMix`,
`SetMixValues`.

Группы миксов по именам: `global_*` (`default`, `pause`, `f2f`, `debug`),
`combine_*` (вождение, вход в здание, телефон, смерть игрока, даки),
`igc_NN.mix` (ролики на движке), `mission_m1_*`, `occlusion.mix`, `demo_*`.

Правка: `mix ИМЯ --category КАТЕГОРИЯ --volume V [--frequency ГЦ] [--time С]`
меняет канал во всех копиях микса; категории, которой в миксе нет, заводится
канал с уровнями первого канала. На стенде правка микса не проверялась.

## 15. Новая голосовая реплика (этап 83)

Чтобы игра сказала новую реплику, нужны четыре вещи (`dialogues.md` §3–§6):

1. файл `.snu` в архивах по пути, который игра строит из имени
   (`dialogues.md` §4), с субтитром в метаданных;
2. запись в загруженном банке `smb`: новый id, имя файла, параметры;
3. строка события в `chv` говорящего: id звука, id субтитра, вес;
4. запись события в `get`, если событие новое.

`voice::add_line` (`crates/doctor-toolkit/src/voice.rs`) делает всё одной
отменяемой операцией рабочего пространства:

- звук кодируется в EA-XAS (§7) в формате реплик говорящего (моно, 32 кГц) и
  получает метаданные с одной таблицей `LCH2` (`speech::new_table`: восемь
  столбцов игры, язык без текста получает английский);
- файл называется `d_<имя>.exa.snu` и кладётся в накладной архив **новой
  записью** (§9; `Workspace::change_resources_and_new_files`). Запись банка
  пишется без флага 0x01 — один файл на все языки игры;
- запись банка копирует параметры реплики-образца — первой реплики того же
  события у говорящего, иначе его первой реплики — и ложится в тот же банк,
  где лежит образец (он загружен там же, где говорящий); времена записи
  (`+0x28`, `+0x2C`) сбрасываются в 0 и −1. Id — `sdbm` имени файла, при
  совпадении с существующим — следующий свободный;
- строка события добавляется в `chv` (новое событие — на место по хэшу); с
  `--only` остальные строки события убираются;
- новое событие получает запись в `get` (`SpeechEvent::new`).

```sh
doctor-toolkit voice-add "$GAME" --speakers                 # наборы речи с голосами
doctor-toolkit voice-add "$GAME" gf2/globals_global:chv:18c7062e hello.wav \
    --event DOCTOR_HELLO --name doc1_xxx_0000001 \
    --subtitle en="Hello." --subtitle ru="Привет." [--weight 2] [--only] [--category DIALOG]
doctor-toolkit workspace apply "$GAME"
doctor-toolkit mods build "$GAME" -o voice.zip --name "My voice line"
```

В редакторе — мастер **Новая голосовая реплика** (меню «Мастера»): набор речи
говорящего, запись, событие (список событий говорящего подставляет имя),
имя реплики, субтитры по языкам, вес.

**Мод.** Формат мода версии 4 (`docs/mods.md`) несёт файлы архивов: список
`files` в `mod.json` с ключами `viv:audiostreams\…`. Менеджер модов пишет их
в свой накладной архив так же, как рабочее пространство, и убирает при
выключении мода.

**Как вызвать событие.** Узел реплики диалога (`dlg`, слово 8 — хэш события),
объект `SimpleChatterBox` (`dialogues.md` §3.2) или события, которые игра
говорит сама (`F2F_*`, `COMBAT_*`…).
