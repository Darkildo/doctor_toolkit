# Навигационный граф `graph`

Type id `0x3C572A4E` (`sdbm("graph")`), 2 178 ресурсов в 2 300 потоках GF2
PC. Граф — пути ИИ уровня: пешеходы, машины и парковка, патрули, наземный
поиск пути, звуковая окклюзия. Код: `crates/doctor-toolkit/src/resource/graph.rs`
(`graph/derive.rs` — выводимые данные, `graph/edit.rs` — правка), просмотр и
правка в уровне — `crates/doctor-toolkit-gui/src/level_view/nav.rs`.

**Проверено на GF2 PC** (этап 42): все 2 178 графов разбираются и пишутся
обратно байт в байт (`every_graph_writes_back_byte_for_byte` в
`crates/doctor-toolkit/tests/corpus.rs`), JSON-форма тоже даёт те же байты;
правка (сдвиг, новый узел с рёбрами, удаление узла) на каждом графе даёт
файл, который читается и пишется устойчиво (`graph_edits_keep_every_graph_writable`).
По коду `godfather2.exe` сверены: проверка версии, список указателей,
поиск по R-дереву, видимость, чтение свойств (адреса ниже). В игре
пересобранный граф не проверялся — это этап 45.

Граф — образ объекта движка в памяти: игра проверяет, что буфер выровнен на
16 и что слово `+8` равно 16, иначе отказывается (`0x005FA870`), затем
переводит 17 смещений заголовка в указатели (`0x00601410`: `0x20, 0x24,
0x28, 0x30, 0x34, 0x38, 0x40, 0x44, 0x48, 0x50, 0x58, 0x60, 0x68, 0x70,
0x7C, 0x80, 0x8C`; ноль — «секции нет»). GUID по `+0x10` игра при загрузке
**перезаписывает** ids заголовка ресурса — граф всегда называется так, как
его ресурс в потоке.

## 1. Заголовок (0x94 байта)

Little-endian, смещения от начала ресурса.

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | 8 байт | нули (заголовок объекта, восстанавливается игрой) |

| 0x0C | u16, u16 | число узлов N, число рёбер C |
| 0x10 | 16 байт | GUID графа (NeoGuid: 8 случайных байт + имя машины) |
| 0x20 | ptr | узлы |
| 0x24 | ptr | рёбра |
| 0x28 | ptr | GUID соседних графов |
| 0x2C | u16, u16 | число GUID соседей, число рёбер в соседей |
| 0x30 | ptr | рёбра в соседние графы |
| 0x34 | ptr | индексы GUID по слотам соседей (u16) |
| 0x38 | ptr | указатели на соседей для игры (8 байт на слот, нули) |
| 0x3C | u16, u16 | число слотов соседей, число узлов R-дерева |
| 0x40 | ptr | таблица путей |
| 0x44 | ptr | индексы узлов в листьях R-дерева (u16 × N) |
| 0x48 | ptr | узлы R-дерева |

| 0x50, 0x54 | ptr, u32 | свойства (поля), число |

| 0x8C | ptr | хэши внешних соседей |
| 0x90 | u16, u16 | число внешних соседей (0 у всех), 0 |

## 2. Записи

**Узел**, 0x24 байта (версии 15–16; 0x20 у версии 14 — по описанию
другого редактора игр EARS, в GF2 таких нет):

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | 3 × f32 | позиция в мире |
| 0x0C | f32 | радиус (0,125…) |
| 0x10 | u16 | первое ребро |
| 0x12 | u16 | экземпляр свойств (0xFFFF — нет) |
| 0x14 | u8 | число рёбер (≤ 255) |
| 0x15 | u8 | число рёбер в соседей по GUID |
| 0x16 | u16 | первое ребро в соседей |
| 0x18 | u16 | флаги узла (0 у всех; §5) |
| 0x1A | i16 | набор света (0 у всех) |
| 0x1C | u8 | число рёбер во внешних соседей (0 у всех) |
| 0x1D | 7 байт | нули (поля игры во время работы) |

**Ребро**, 0x10 байт (0x0C у версий 14–15):

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | f32 | длина — расстояние между узлами (совпадает до 4,8·10⁻⁶ во всех 152 629 рёбрах) |
| 0x04 | u16 | конечный узел |
| 0x06 | u16 | начальный узел (всегда узел, которому принадлежит отрезок) |
| 0x08 | u16 | экземпляр свойств |
| 0x0A | u16 | флаги ребра (§5) |
| 0x0C | 4 байта | нули |

Рёбра узла `k` — отрезок `первое .. первое + число`, отрезки идут подряд в
порядке узлов. В двух графах есть повторы (53 ребра с той же парой узлов).

**Ребро в соседний граф**, 0x10 байт: `f32 длина, u16 узел в другом графе,
u16 начальный узел, u16 экземпляр свойств, u16 флаги, u16 слот соседа, u16 0`.
Отрезки по узлам подряд, как у рёбер; сначала рёбра в соседей по GUID, потом
по хэшу. 28 824 таких ребра в 1 141 графе; все 4 418 GUID соседей —
существующие графы игры; 22 графа указывают соседом самих себя. Слот `k` по
GUID — `guids[index[k]]`, у всех графов `index[k] = k`.

**Узел R-дерева**, 0x24 байта: `3 × f32 min, 3 × f32 max, u16 родитель,
u16 первый потомок, u16 следующий брат, u16 «нить», u16 первый индекс,
u16 число индексов` (0xFFFF — нет).

## 3. Выводимые данные

Всё ниже следует из узлов и рёбер; правка пересчитывает это, неизменённый
граф пишется как был.

**R-дерево** — во всех 2 137 непустых графах: обход в прямом порядке (первый
потомок узла `k` — узел `k + 1`), внутренние узлы двоичные, лист — до 4
узлов графа, рамка листа — рамка позиций его узлов (без радиуса), рамка
внутреннего узла — объединение потомков, листья по порядку обхода занимают
индексы подряд; «нить» узла с братом — 0xFFFF, без брата — брат ближайшего
предка, у которого он есть. Игра ходит только по потомкам и братьям,
сравнивая квадрат расстояния до рамки (`0x005FC5D0`, `0x00601999`), «нить» не
читает. Поэтому тулкит хранит дерево как форму — вложенные списки
(`[[[0,2,8],[1,5]],[6,4,3,7]]`), всё остальное вычисляется; все графы игры
дают ту же форму обратно. Правило разбиения EA не восстановлено (не
наибольшая сторона и не наименьший объём); новые деревья тулкит строит
делением пополам по наибольшей стороне рамки (`build_rtree`).

**Таблица путей** (`0x40`): полубайт на пару `(из, в)` по индексу `из·N + в`,
младший полубайт первым; значение `k + 1` — `k`-е ребро узла `из`, первое на
кратчайшем пути, 0 — тот же узел или пути нет. Проверено на всех 2 087
таблицах: путь по таблице всегда доходит и всегда кратчайший, 0 — ровно у
недостижимых пар. Таблица есть у 2 087 графов и отсутствует у 91 (это решает
автор, а не размер). Наш расчёт (Дейкстра) совпадает с таблицей EA байт в
байт у 1 790 из 2 087; остальные расходятся только выбором между путями
равной длины. Поэтому правка оставляет таблицу, если она всё ещё даёт
кратчайшие пути, и считает заново, если нет (`refresh_paths`). Узел с более
чем 15 рёбрами в полубайт не помещается — таблица тогда снимается.

**Видимость** (`0x70`): бит на пару `a < b` по строкам,
`бит = a·(2N − a − 1)/2 + b − a − 1`, байт `бит / 8`, бит `бит % 8`
(`0x005FC8C0`); длина — `⌈N(N−1)/16⌉` байт. При ненулевом флаге `0x78` игра
читает список как RLE: нулевой байт и за ним число нулей (`0x005FC210`). Во
всех графах GF2 флаг 0, все биты (и лишние в последнем байте) — единицы:
скрытых пар нет. Тулкит хранит список скрытых пар.

## 4. Свойства

Поле свойства — 8 байт: `u32 хэш имени, u16 смещение значения в экземпляре,
u8 тип, u8 0`; типы: 1 int32, 2 uint32, 3 float, 4 GUID (16 байт), 5 хэш.
Набор — `u32 первое поле, u32 число`: наборы идут подряд и покрывают все
поля. Внутри набора поля отсортированы по хэшу имени, а смещения — в порядке
автора (у 186 наборов не по порядку), поэтому смещение хранится, а не
вычисляется. Экземпляр — `u32 смещение в данных, u16 набор, u16 0`; данные
экземпляров идут подряд без промежутков. Значение поля — `данные +
смещение экземпляра + смещение поля` (`0x005FCAD0`). 385 графов со
свойствами; узлы ссылаются на экземпляры 2 782 раза, рёбра 9 609, рёбра в
соседей 1 336. Экземпляры не уникальны (в 27 графах есть одинаковые), один
экземпляр делят многие узлы и рёбра.

Хэши имён в данных: `0x7A1B032E` (GUID, 247 значений, не графы и не
ресурсы — по виду GUID объектов), `0x022C6CC5` (GUID или нули), `0x5B25C73B`,
`0xC2E43267`, `0xCD77CA3A`, `0xEE654334`, `0xF7276BE5` (uint 0/1/4 — флаги),
`0xFDE0BE51` (float 0, 5, 10, 15, 20), `0x48043505` (0, 2, 10), `0x998CAB76`,
`0xC521B15C`, `0xD1FBB69B`, `0xE311F9AA`. Имён нет: имена-кандидаты из
другого редактора не дают этих хэшей ни в одном регистре (SDBM, как у
имён атрибутов) — не подтверждены.

## 5. Флаги

Тип графа (`0x4E`): `0x01` наземный поиск пути (1 042 графа), `0x02`
патруль (83), `0x04` машины (91), `0x08` пешеходы, `0x10` парковка (853),
`0x20` звуковая окклюзия (48); сочетания `0x03` (5) и `0x09` (56).
Названия — по описанию другого редактора игр EARS (фильтр отладочного
показа игры); по коду не проверялись.

Ребро: `0x02` перелезть (364 ребра), `0x04` лестница (494), `0x08` только
для поиска пути (0), `0x10` переход (294), `0x20` падение (21); старшие биты
`0x0400…0x8000` (светофор, заблокировано, выключено) ставит игра во время
работы, в файлах их нет. Узел: `0x4000` выключен, `0x8000` заблокирован —
тоже состояние игры, в файлах 0; выбирая ближайшее к точке ребро, игра
пропускает рёбра в узел с `0x4000` (`0x005FFEB0`).

## 6. Раскладка секций

Порядок и выравнивание, при которых все 2 178 графов совпадают байт в байт:

1. заголовок; GUID соседей (если есть); узлы; указатели соседей (8 × слоты);
   рёбра; рёбра в соседей; поля, наборы и экземпляры свойств (если есть
   свойства);
2. данные значений — указатель есть всегда, даже при нуле байт;
3. 4 нулевых байта, затем биты видимости — указатель есть всегда;
4. дальше с `align4(конец видимости + 3)`: хэши внешних соседей, индексы GUID
   соседей (если есть), таблица путей (если есть, без выравнивания);
5. свет и наборы света (в GF2 нет; тулкит кладёт их с выравниванием 16);
6. узлы R-дерева с выравниванием 16, сразу за ними индексы; ресурс
   кончается последней секцией без дополнения.

Секции без записей имеют нулевой указатель (кроме данных значений,
видимости и таблицы путей пустого графа). 41 граф без узлов.

## 8. Расхождения с описанием другого редактора

Описание формата в другом редакторе игр EARS сверено с данными; где данные говорят иначе — верно то, что здесь:

- **Указатели соседей** — 8 байт на слот, не 4: после них идут рёбра, и
  только с 8 байтами раскладка совпадает у всех 1 152 графов с соседями.
- **Раскладка**: 4 нулевых байта перед видимостью, начало следующей секции
  `align4(конец видимости + 3)`, таблица путей без выравнивания, указатели
  данных значений и видимости есть и при нуле байт — в их раскладчике этого
  нет; таблицу путей они при записи выбрасывают, мы пишем (и пересчитываем).
- **Набор света узла** в GF2 — 0, не −1.
- **Длина ребра** у них «до точности float» на 2 172 рёбрах десяти графов;
  в GF2 — на всех 152 629 рёбрах, расхождение до 4,8·10⁻⁶.
- **Имена свойств** из его описания не подтверждаются хэшем.
- **Повторы**: они отказывают в повторном ребре; в GF2 повторы есть (53),
  тулкит их сохраняет и сам не создаёт.
- **R-дерево** «минимальное» у них; в GF2 дерево строго предписанной формы
  (§3), которую тулкит воспроизводит и сохраняет.

**Проверено в игре** (`game-bench.md` §31.5): пересобранный граф игра
берёт, ИИ ходит по нему с R-деревом и таблицей путей тулкита. Прохожие у
ворот аэропорта Гаваны идут по рёбрам графа `ground` потока
`gf2/cuba/local/yuri/low/zone1` (узлы 46–51, отклонение от ребра — медиана
0,36 м, не больше 0,69 м); после `graph-edit --move 48:…` (узел сдвинут на
6 м) они идут по новым рёбрам: медиана 0,38 м, не больше 1,3 м от новых и
до 3 м от старых.

## 9. Инструменты

- CLI: `graph-info GAME KEY [--nodes] [--json]`; `graph-export GAME KEY -o
  FILE`; `graph-import GAME KEY FILE` (JSON → рабочее пространство; длины,
  R-дерево и пути приводятся к правке); `graph-edit GAME KEY` — `--move
  N:X,Y,Z`, `--add-node X,Y,Z`, `--attach X,Y,Z [--max-links 2]
  [--max-distance 15]` (новый узел, связанный с ближайшими), `--remove-node
  N` (рёбра других графов в этот перенумеровываются), `--link A:B
  [--two-way]`, `--unlink A:B`, `--link-flags A:B=F`, `--node-flags N=F`,
  `--graph-flags F`, `--rebuild-rtree`. Ключ — `поток:graph:ids` (четыре id
  через точку).
- Проект (этап 36): `graph` — вид `document`, файл `graph/<имя>.json`
  (та же JSON-форма); сборка приводит длины, R-дерево и пути к правке.
- Python: `navigation_graph(data)` → dict (с `info`),
  `navigation_graph_bytes(dict)` → данные ресурса.
- Редактор: слой «Навигационные графы» во вкладке уровня (руководство,
  глава 21).
- Библиотека: `Graph::parse`, `to_bytes`, `move_node`, `add_node`,
  `remove_node` (возвращает перенумерацию), `add_link`, `remove_link`,
  `set_link_flags`, `set_node_flags`, `attach_point`, `remap_links_into`,
  `repair_derived`, `info`; `level::navgraph::save_graph`.
