# Формат: модели деревьев `treemodel` (`0xCDB9D42B`)

Деревья, пальмы и кусты городов. На ресурс ссылается свойство
`TreeModelPart.TreeModel` метамодели (`metamodel.md`), дерево ставится
матрицей `TreeModelPart.CMD_LoadMatrix`. Тег найден на этапе 40 (SDBM тега
равен id типа), формат разобран на этапе 68.

**Проверено на GF2 PC** (корпусный тест
`every_tree_model_parses_writes_back_and_finds_its_materials`): все 432
ресурса читаются и пишутся обратно **побайтно**; хэш в заголовке — CRC-32
пути исходного файла, id ресурса — SDBM того же пути; материал каждой
части есть в игре и рисуется шейдером дерева своего вида; индексы углов
листьев — целые от 0 до 39, индексы полос не выходят за вершины.
Код: `crates/doctor-toolkit/src/resource/treemodel.rs`.

| | Частей | Мешей |
|---|---|---|
| Ствол и ветви, вид 0 (`TreeTrunk`, у 115 — `TreeNonRotatingLeaf`) | 575 | 575 |
| Листья к камере, вид 1 (`TreeRotatingLeaf`) | 239 | 239 |
| Листья и ветви пальм, вид 2 (`TreeNonRotatingLeaf`) | 291 | 357 |

Деревья лежат в `gf2/<город>/local` (Гавана 43, Майами 45, Нью-Йорк 43) и
в зонах рельефа Нью-Йорка и сетевых карт; одна модель повторяется в
нескольких потоках. У одной пальмы (во всех трёх городах) первый меш
листьев пустой (0 вершин) — игра его пропускает.

## 1. Заголовок (0x38 байт, little-endian)

| Смещение | Тип | Смысл |
|---|---|---|
| 0x00 | u32 | версия, 2 (игра отвергает другие) |
| 0x04 | u32 | магия `0x54726565` (на диске `eerT`, «Tree») |
| 0x08 | u32 | число мешей всех частей |
| 0x0C | u32 | число частей |
| 0x10 | u32 | CRC-32 пути исходного файла (первая строка таблицы) |
| 0x14 | 2 × u32 | 0 |
| 0x1C | u32 | смещение таблицы строк |
| 0x20 | u32 | размер таблицы строк |
| 0x24 | 4 × f32 | ограничивающая сфера: центр, радиус |
| 0x34 | f32 | высота дерева — константа `TreeHeight` ветра |

## 2. Части и меши

С 0x38 подряд идут части:

| Поле | Тип | Смысл |
|---|---|---|
| вид | u32 | 0 — ствол (полосы), 1 — листья к камере, 2 — листья (четырёхугольники) |
| мешей | u32 | 1 или 2 (два — у 66 частей вида 2) |
| материал | u32 | CRC-32 имени материала в нижнем регистре (`geometry.md` §6) |
| имя | u32 | смещение имени части (узла Maya) в таблице строк |

За заголовком части — её меши, игра рисует **все** меши всех частей
(уровней детализации внутри дерева нет):

| Поле | Тип | Смысл |
|---|---|---|
| вершин | u32 | |
| индексов | u32 | только у вида 0, у листьев 0 |
| четырёхугольники | u32 | виды 1 и 2: 1 — список четырёхугольников (`D3DPT_QUADLIST` Xbox 360, 13), 0 — список треугольников; у вида 0 — 0 |
| вершины | | вершин × шаг (вид 1 — 32 байта, иначе 24) |
| индексы | u16 | только вид 0: **полоса** треугольников (тип 5); вырожденные треугольники отбрасываются, нечётные разворачиваются |
| выравнивание | | до 4 байт; байты выравнивания не всегда нулевые и хранятся как есть |

Второй меш части вида 2 — список треугольников без индексов (66 частей
пальм). Таблица строк: путь исходного `.dae`
(`x:\assets\_library\objects\plants_trees\trees\…\high.dae`), затем имена
частей, каждая строка с нулём на конце; после неё — нули до выравнивания
ресурса.

## 3. Вершины

**Виды 0 и 2** (24 байта): f32×3 позиция, f32×2 UV, u8×4 нормаль
(`b / 255 · 2 − 1`, w = 255). Нормали смотрят наружу при порядке вершин
полосы (сверено с нормалями граней: знак совпадает у 98 % треугольников
стволов и 91 % листьев).

**Вид 1** (32 байта): f32×3 центр листа, f32×2 UV угла, f32 размер
(половина стороны карточки), f32 индекс угла (0–39), f32 значение
`k / 255`, которое вершинные шейдеры не читают. Четыре вершины одного
листа — один центр, UV углов (u = (x + 1)/2, v = (1 − y)/2 от угла).

## 4. Как игра рисует дерево

Загрузчик — `godfather2.exe` 0x9D28D0, отрисовка — 0x9D1A40: сначала все
части вида 1, потом 2, потом 0; материал части и шейдер семейства
`TreeTrunk` / `TreeNonRotatingLeaf` / `TreeRotatingLeaf` (у каждого —
проходы глубины и цвета). Пиксельный шейдер цвета — как у мира
(`renderer.md` §10): `sampColor^2.2 · g_BaseTintColor`, × буфер света × 2,
туман; листья — с альфа-тестом (флаг материала `0x1`).

**Листья к камере.** Вершинный шейдер берёт угол из таблицы `LeafQuads`
(40 векторов) по индексу угла, умножает на размер листа и на масштаб
дерева по высоте (`Orientation[1].y`) и прибавляет к центру. Таблицу и
нормали листьев (`LeafNormals`, 10 векторов) игра считает каждый кадр
(0x9D0D20) от поворота камеры (рысканье и тангаж): лист `v = 5i + j`
(i < 2, j < 5) — квадрат с углами (−1, 1), (−1, −1), (1, −1), (1, 1),
наклонённый вокруг горизонтальной оси камеры на `t = (i − ½) · 20°` и
повёрнутый в плоскости экрана на `t + 0,075 · cos(π (j/4 − ½) + 5 · время)`;
нормаль — (0, 1, 0) с тем же поворотом. Так соседние листья кроны
повёрнуты по-разному и чуть качаются. Код: `treemodel::leaf_corner`.

**Ветер.** Все три вершинных шейдера сдвигают вершины по
`WindDir`, `WindFrequency` (1, 2,3, 3,7, 4,3), `WindAmplitude`
(1, 0,6, 0,25, 1): фаза — `dot(позиция.xz, WindDir.xz) + время`, сила
растёт с высотой вершины до `TreeHeight / 2,5`; вершины у оси ствола
(`x² + z² < 0,04`) гнутся вдвое слабее.

## 5. В редакторе

Вид уровня, ролики с миром, просмотр модели и превью Content Browser
рисуют деревья общим рендером (`render/tree.rs`): части — меши с материалом
(текстура `sampColor`, цвет `g_BaseTintColor`), полосы и четырёхугольники —
треугольники, углы листьев вида 1 — вершины-«карточки»
(`Vertex::BILLBOARD`), которые вершинный шейдер разворачивает к камере по
таблице игры (наклон и поворот листа — как у игры без ветра). Ветер не
моделируется: деревья стоят неподвижно, как в игре в безветренный кадр.
Деревья, которых нет в файлах игры, остаются зелёными столбиками-маркерами.
Экспорт (`doctor-toolkit models`, `scene::game::tree_scene`): части с
материалом (текстура, альфа-маска, цвет), листья к камере — двумя
скрещёнными карточками (к +Z и к +X) с наклоном и поворотом листа игры.

## 6. Открыто

- Значение `k / 255` последнего поля вершин листьев (возможно, затенение
  кроны для другого прохода).
- Правки деревьев в редакторе нет: ресурс читается и пишется обратно
  побайтно, новых деревьев инструмент не собирает.
