# Файл сохранения The Godfather II (PC)

Формат файлов `GF2-EN-autosave` и `GF2-EN-<цифры>` из папки профиля
(`Documents/EA Games/<название игры>/<номер профиля>/`). Издание — только
PC 1.0.789.0; адреса — виртуальные адреса `godfather2.exe` этого издания.

Код: `crates/doctor-toolkit/src/save/` (разбор и текст), команда
`doctor-toolkit save`, окно редактора «Инструменты → Посмотреть
сохранение…». Тулкит сохранения **только читает**.

**Проверено на файлах:** 14 сохранений (8 со стенда, 6 из профиля игрока с
8 часами игры): все разбираются, три контрольные суммы сходятся с
вычисленными, все 25 блоков каждого файла опознаны
(`crates/doctor-toolkit/tests/saves.rs`, переменная `EARS_GF2_SAVES`).
Исследовательские скрипты этапа в репозиторий не входят: всё, что они
проверяли, закреплено этим тестом.

Пометки в таблицах: **exe** — по коду, **данные** — по 14 файлам,
**стенд** — опыт в игре (`docs/analysis/game-bench.md` §32), **догадка** —
не проверено.

## 1. Общий вид

Все числа little-endian. Файл всегда 272 740 байт (0x42964): четыре части
подряд, свободное место заполнено нулями.

| Смещение | Размер | Часть | Источник |
|---|---|---|---|
| 0x0000 | 0x2028 | заголовок файла `RGMH` | exe `0x00ACD8A0` |
| 0x2028 | 0x80C | блок имени `NMSD` | exe `0x00ACFFF0`, `0x00AD0070` |
| 0x2834 | 0x1C | заголовок контейнера (`20CM` на диске) | exe `0x00AD1330`, `0x00AD2540` |
| 0x2850 | 0x114 | блок 1: сведения | данные |
| 0x2964 | 0x40000 | блок 2: состояние игры блоками | exe `0x004C03C0` |

### 1.1 Заголовок файла

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | u32 | магия `RGMH` (`0x484D4752`) |
| 0x04 | u32 | версия, 1 |
| 0x08 | u32 | размер заголовка, 0x2028 |
| 0x0C | 28 байт | нули |
| 0x28 | UTF-16, 0x800 байт | название игры: `The Godfather™ II` во всех файлах |
| 0x828 | UTF-16, 0x800 байт | имя профиля (`Profile 1`) |
| 0x1028 | UTF-16, 0x800 байт | город (`Cuba`); при старте `-stream` — неразвёрнутая строка `{$city_name_havana}` |
| 0x1828 | UTF-16, 0x800 байт | время игры `ч:мм:сс` |

Список сохранений в меню читает только эти две первые части файла
(`0x00ACD8A0`: профиль, город, время, затем имя из блока имени).

### 1.2 Блок имени

`u32` магия `NMSD` (`0x44534D4E`), `u32` версия 1, `u32` размер 0x80C, затем
строка UTF-16 в 0x800 байтах: имя в списке сохранений —
`<профиль> - <город> - <время>`; у автосохранения перед ним `Auto:` (данные).

### 1.3 Заголовок контейнера и контрольные суммы

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | u32 | `0x4D433032` (на диске байты `20CM`) |
| 0x04 | u32 | размер контейнера: 0x1C + размер блока 1 + размер блока 2 (0x40130) |
| 0x08 | u32 | размер блока 1, 0x114 |
| 0x0C | u32 | размер блока 2, 0x40000 |
| 0x10 | u32 | контрольная сумма блока 1 |
| 0x14 | u32 | контрольная сумма блока 2 |
| 0x18 | u32 | контрольная сумма первых 0x18 байт заголовка |

Проверка при чтении (`0x00AD2540`): магия, размер, сумма заголовка; при
несовпадении — код ошибки 4 (в игре есть строки `$ui_pro_save_corrupt`,
`$savegame_load_failed`).

Контрольная сумма (`0x00D373D0`, таблица `0x00F0C828`) — CRC-32 с
многочленом `0x04C11DB7`, старшим битом вперёд, без отражения; начальное
значение — инверсия первых четырёх байт данных (старший байт первым),
результат инвертируется. Для данных короче 4 байт — 0.

```text
crc = ~be32(data[0..4])
для каждого байта b из data[4..]:
    crc = ((crc << 8) | b) ^ TABLE[crc >> 24]
результат = ~crc
```

Сумма блока 2 считается по всем 0x40000 байтам, включая нули после данных.

### 1.4 Блок 1

| Смещение | Тип | Поле | Источник |
|---|---|---|---|
| 0x00 | u32 | 6 во всех файлах — вероятно, версия | данные, догадка |
| 0x04 | u32 | время игры в секундах (134 при строке `0:02:14`) | данные |
| 0x08 | u32 | ёмкость блока 2, 0x40000 | данные |
| 0x0C | u32 | занято в блоке 2, байт | данные |
| 0x10 | … | нули до конца блока | данные |

### 1.5 Блок 2: блоки сохраняемых объектов

```text
u32 маска                      — 0xB во всех файлах
повторять до занятого размера:
    u32 идентификатор блока
    u32 0
    u32 размер данных N
    N байт данных, затем выравнивание до 4 байт
```

Байты выравнивания игра не обнуляет (после блока нечётного размера остаётся
мусор буфера — данные), поэтому пересобранный файл может отличаться от
исходного этими байтами.

## 2. Как игра пишет и читает

Объект игры, который хочет попасть в сохранение, при создании
регистрируется в списке `*0x0122341C` записью из 12 байт: идентификатор
блока, указатель на интерфейс, маска. Идентификатор — константа в коде
(у `mobface` это `sdbm("mobface")`; у остальных строка не найдена).
Методы интерфейса: `+4` размер блока, `+8` запись в буфер, `+0xC`
восстановление из данных.

| Адрес | Что делает |
|---|---|
| `0x004C03C0` | сохранение: спрашивает размер у каждого объекта, чья маска пересекается с маской сохранения, и пишет блоки подряд |
| `0x004C0540` | пересборка буфера: блоки объектов, которых сейчас нет в списке, **копируются как есть**, блоки новых объектов дописываются в конец |
| `0x004C0860` | обновление на месте: блок переписывается, если его размер не изменился |
| `0x004C0920` | загрузка: для каждого блока ищет объект по идентификатору (`0x00463A80`) и зовёт восстановление; блок без объекта **пропускается** |
| `0x004C0A60` | новая игра: восстановление каждого объекта с пустыми данными |
| `0x008F2690` | менеджер сохранений: сообщения `iMsgGamePersistenceSaved`, `…Loaded`, `…Restored`, `…NewGame`, `iMsgManualSaveEnable/Disable` |
| `0x008F2460` | имя файла автосохранения: `GF2-%s-` + `autosave` |

Следствия для модов:

- блок неизвестного объекта не ломает загрузку — он пропускается;
- у объекта, блока которого в сохранении нет, остаётся состояние по
  умолчанию;
- свой блок мод может завести только кодом (модулем в игре); данными —
  только переменные (§4).

## 4. Переменные сюжета (`variables`)

Запись `0x00442550`, размер `0x00442520`, чтение `0x004425A0`.

```text
u32 число N
N × { u32 хэш записи, u32 значение }
```

- В сохранение попадают переменные менеджера `*0x01223428` с битом 0 в
  поле флагов записи (`+0xE`). Флаги приходят из ресурса
  `variabledictionary`: поле «вид» записи (`logic-types.md` §1) и есть эти
  флаги, вид 1 — «сохраняется» (загрузчик `0x004423F0`).
- Ключ в сохранении — **хэш записи** словаря (первое поле записи ресурса),
  а не `sdbm` имени. Данные: во всех 14 файлах каждый сохранённый хэш, кроме переменной опыта §32, —
  переменная вида 1 из словарей игры, переменных вида 0 нет.
- Сохраняются только переменные, которые есть в менеджере в момент
  сохранения, то есть из загруженных словарей: в обычной игре 59 из 63
  переменных вида 1, при старте `-stream gf2 cuba` — 46, `-stream gf2
  queens` — 50.
- Чтение: переменная ищется по хэшу записи; найдена — значение
  записывается и наблюдатели будятся (`0x00442240`); не найдена —
  пропускается (менеджер создан с флагами 0 — `0x0067FD77`; при флаге 1 он
  завёл бы запись). Ёмкость менеджера — 320 переменных.
- Если при загрузке словаря переменная с таким хэшем уже есть, повторное
  определение не меняет её (при флагах менеджера 0).

### Своя сохраняемая переменная мода

Добавьте в `variabledictionary` запись вида 1 со своим хэшем записи (он не
должен совпадать с хэшами игры; игре важно только, чтобы хэш был один и
тот же от запуска к запуску). Словарь должен быть загружен, когда игра
сохраняется и когда сохранение читается: переменная словаря, которого в
этот момент нет в памяти, в сохранение не попадает и из него не
восстанавливается. Проверено на стенде: §32 `game-bench.md`.

### Удаление мода

Сохранение с переменной мода загружается и без мода: её пара пропускается.
При следующем сохранении пары уже нет — значение потеряно; если мод
вернуть, переменная начнёт с начального значения словаря.

## 5. Деньги и семья игрока (`player-family`)

Запись `0x008BCBC0`; объект — `*0x01129908` (тот, из которого счётчик денег
на экране берёт копию).

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | u32 | версия, 4 |
| 0x04 | f32 | деньги игрока (объект `+0x14`) |
| 0x08 | u32 | число записей N |
| 0x0C | u32 | флаг (байт `+0x18`) |
| 0x10 | 16 байт | нули |
| 0x20 | N × 0x2C | записи членов семьи |

Запись: 24 нулевых байта (данные), GUID объекта `SimNpc`, `u32` (1, 2 и 4
в файлах; смысл не выяснен). В сохранении после пролога записей нет, в
сохранении с 8 часами игры — 13.

## 6. Семьи (`families`)

Запись `0x008C72D0`, чтение `0x008C7940` (принимает версии 8 и 9).

Заголовок 0x18 байт: `u16` версия 9, `u16` число семей (6), `u16` число из
объекта команды игрока (`*0x0112989C +0x14`; при чтении уходит в
`0x0090B8E0`), остальное нули. Затем записи семей (`0x008C3CD0`), первая —
`corleone`.

Заголовок записи — 0x60 байт (`0x008C1850`):

| Слово | Поле |
|---|---|
| 0 | хэш имени семьи (`sdbm`): `corleone`, `rosato_carmine`, `rosato_tony`, `granados`, `almeida`, `mangano` |
| 1 | f32 деньги семьи (`+0x100`); у `corleone` — константа −1 000 000: деньги игрока лежат в `player-family` |
| 3–7 | f32 из объекта семьи: `+0x150`, `+0x148`, `+0x14C`, `+0x154`, `+0x158` (у соперников 600–1200, 90–150, …; смысл не выяснен) |
| 8 | байт `+0x15C` |
| 9, 10 | числа A и B: идентификаторы зданий двух списков (`+0x108`, `+0x114`) |
| 11 | число C: пары `{хэш семьи, u32}` — остальные семьи (`+0x18C`) |
| 12, 13 | число D записей членов семьи и сумма их добавочных слов |
| 14, 15 | число E записей последнего списка и сумма их добавочных записей |
| 16 | флаги семьи (`+0x84`) |
| 19 | `+0x120` |

За заголовком: A × `u32`, B × `u32`, C × 8 байт, члены семьи
(`0x008BFB90`: D записей по 0x50 байт, первые 16 байт — GUID члена, затем
добавочные слова), последний список (`0x008C1BB0`: E записей по 0x10 и
добавочные по 0x10). У `corleone` в конце — книги доходов (`0x00892760`):
0x20 нулевых байт, затем четыре списка `u32 число, 12 нулевых байт, число ×
f32`.

Чтение ищет семью по хэшу (`0x008C74D0`); запись неизвестной семьи
пропускается.

## 7. Заведения и здания (`buildings`)

Запись `0x006B0C90`, чтение `0x006B1190` (версии 5–7).

Заголовок 0x14 байт: `u16` версия 7, `u16` число зданий (113), нули. Запись
здания (`0x006B2360`) — 0x60 байт и два списка:

| Слово | Поле |
|---|---|
| 0 | номер здания (`+0x38`) |
| 1 | флаги (`+0x34` с маской `0x17DA17FD`) |
| 2 | хэш семьи-владельца (`+0x40`) |
| 3 | хэш семьи `+0x3C`; в файлах — владелец в начале игры (данные) |
| 4 | состояние (`+0x16C`) |
| 5 | f32 |
| 7–13, 16, 17, 19, 20 | числа объекта: `+0x5C`, `+0x60`, `+0x68`, `+0x6C`, `+0x74`, `+0x7C`, `+0x80`, `+0x64`, `+0xC8`, `+0x174`, `+0x178` |
| 14, 15 | числа записей двух списков |

Запись списка (`0x006B2470`) — 0x14 байт: `u32` и GUID объекта (охрана

Владельцы в файлах — девять семей из 28: шесть семей стратегической игры,

(`0x006B0EE0`); запись неизвестного здания пропускается.

## 8. Города (`cities`)

Запись `0x00849AC0`: `u32 1`, `u32` число, пары `{u32 хэш имени, u32
состояние}`. Имена — `cuba`, `florida`, `newyork` (`sdbm`). В сохранении
после пролога: `cuba` 0, `florida` 1, `newyork` 1; в сохранении с 8 часами
игры — все 0 (догадка: 1 — город ещё закрыт сюжетом). При старте `-stream`
в блоке только загруженный город; после загрузки такого сохранения из меню
городов снова три, все с состоянием 0 (§32 `game-bench.md`).

## 9. Игрок (`player`)

Запись `0x007AAD80`: два f32 (виртуальные методы `+0xC0` и `+0xC4` объекта
игрока; 4500 и 4500 во всех файлах — догадка: здоровье и его предел),
`u32` число N, `u32 0`, N хэшей списка одной из частей игрока (0 записей
после пролога, 11 в сохранении с 8 часами — догадка: купленные навыки).

## 10. Журнал (`history`)

Запись `0x009385A0`: `u32 1`, `u32` число, строки UTF-8 с завершающим нулём
и разметкой интерфейса (`[c=YELLOW]TALK:[c=RESET] …`). Размер блока не
кратен 4.

## 11. Чекпоинт и точка возврата (`checkpoint`)

Запись `0x008FD0F0`, чтение `0x008FD510`; 0x90 байт:

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | u32 | номер текущего чекпоинта (`Checkpoint +0x74`); 0 — чекпоинта нет |
| 0x04 | u32 | флаг «матрица записана» |
| 0x08 | 8 байт | нули |
| 0x10 | 16 × f32 | матрица 4×4; место — последняя строка |
| 0x50 | 0x40 байт | четыре вектора, не разобраны |

Матрица — не место игрока в момент сохранения. Функция берёт место игрока
(`0x00471610`), ищет по нему объект в `*0x011299B8` (`0x008F18E0`) и
копирует матрицу этого объекта (`+0x60`) — точку возврата (догадка: ближайшая
точка сохранения; рядом сообщение `iMsgSavePointPersistableRestore`). Если
текущий чекпоинт сам задаёт возврат (`0x008FC140` вернула не ноль), флаг
остаётся 0 и матрица единичная.

Данные 14 файлов: флаг 0 — у сохранения на террасе после пролога (чекпоинт
10) и трёх автосохранений старта `-stream gf2 cuba` (чекпоинт 735); флаг
1 — у остальных (чекпоинт 0 или 966). Точка одна и та же у сохранений, сделанных в разных
местах: (−405,306; 6,400; −228,123) у обоих сохранений этапа 63 в
Нью-Йорке — там же игрок оказывался после загрузки (−405,3; 6,2; −228,1,
`game-bench.md` §30); (−73,123; 4,497; 68,476) у всех шести сохранений
игрока; (295,969; 0; 360,462) у сохранений старта `-stream gf2 cuba`
(§32).

## 12. Оружие (`inventory`)

Запись `0x00705CF0`:

```text
u32 флаги: 32 байта-флага инвентаря (+0x118…)
u32 флаги: ещё три; бит 31 — флаг +0xF4 (догадка: бесконечные патроны —
           рядом сообщение iMsgInfiniteAmmoUnlocked)
11 ячеек:
    u32 число предметов; 0 — ячейка пуста, полей ниже нет
    GUID шаблона оружия (+0x264)
    GUID объекта (−0x28)
    только у ячеек 0–4: u32 (+0x4C8, 0–4 — догадка: уровень улучшения),
                        u32 патроны (0x007013C0)
u32 число K, K байт
u32 0xABBA
```

## 13. Чего здесь нет

- `profiles.dat` (1296 байт рядом с папками профилей) не разбирался: в нём
  имя профиля и данные учётной записи.
- Блоки с пометкой «нет» в §3 и поля с пометкой «догадка».
- Смысл маски `0xB` и масок объектов.
- Запись сохранений: тулкит их не пишет. `save::build` собирает файл из
  блоков только для тестов.

## 14. Команда

```sh
doctor-toolkit save ФАЙЛ                      # сводка: имя, время, суммы, блоки
doctor-toolkit save ФАЙЛ --chunk variables --game ИГРА   # блок, с именами
doctor-toolkit save ФАЙЛ --all --json         # всё в JSON
doctor-toolkit save ПАПКА                     # список сохранений в папке
```

Имена переменных и объектов берутся из файлов игры (`--game`); без неё —
хэши и GUID. При несовпадении контрольных сумм команда завершается с
ошибкой.
