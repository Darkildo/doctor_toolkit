# Формат: Table of Contents (StreamTOC)

TOC связывает имена файлов с их расположением в Stream-контейнере. При сохранении
Stream TOC обязан быть пересчитан (иначе игра падает — Godfather).

Две формы хранения: `StreamTOCFile` (отдельный файл, Godfather II / Dead Space) и
`StreamTOCResource` (ресурс в «_global» Stream, Godfather I / The Simpsons).

## 1. Заголовок

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | `magic` = `0x9CBA7B28` (байты `28 7B BA 9C`; проверено на GF2 PC) |
| +0x04 | u32 | `version` = 8 или 10 |

Если magic не совпал → «Unknown StreamTOC header: 0x%X cannot load.»
Если version не 8 и не 10 → «Unknown StreamTOC version: %u cannot load.»

По версии выбирается бэкенд **Version8** или **Version10**.

## 2. StreamTOCBackend_Version8

### 2.1 Заголовок V8

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | `count_a` (неиспользуемое после чтения) |
| +0x04 | u16 | `num_files` — число файловых записей |
| +0x06 | u16 | `count_c` |
| +0x08 | u32 | `num_allocations` — размер allocation-таблицы |
| +0x0C | u32 | `alloc_table_offset` — файловое смещение allocation-таблицы |

### 2.2 Allocation-таблица

По смещению `alloc_table_offset` читается `num_allocations` × u32 — **таблица
allocation-значений** (фактические смещения/размеры секций в Stream). Эти значения
пересчитываются при сохранении.

### 2.3 Файловая запись (на каждую из `num_files`)

| Порядок | Размер | Поле |
|---|---|---|
| 1 | u32 | `hash` (SDBM-хэш имени) |
| 2 | u32 | `alloc_index` (индекс в allocation-таблице) |
| 3 | string | `name` (имя файла) |
| 4 | u8 | `flag_a` |
| 5 | u8 | `flag_b` |
| 6 | u8 | `num_sections` |
| 7 | u8 | `flag_d` |
| 8 | u32 | `section_list_offset` (смещение к данным секций) |
| 9 | u32 | `section_offset` (seek-цель для чтения секций) |

При `num_sections != 0` и `section_offset != 0` читается `num_sections` записей
секций, каждая:

| Размер | Поле |
|---|---|
| u8 | `hi` |
| u8 | `mid` |
| u8 | `alloc_ref` — индекс в allocation-таблице |

Значение секции = `(hi << 16) | (mid << 8)`, а `alloc_table[alloc_ref]` даёт
allocation-значение этой секции. (24-битный размер секции + ссылка на allocation.)

### 2.4 Ссылки/зависимости (второй проход)

Для каждой записи: `num_refs = flag_a + flag_b`. Если `num_refs != 0` и
`alloc_value != 0`: по `alloc_value` читается `num_refs` × u32 `hash`; каждый хэш
ищется в таблице записей → в запись добавляется ссылка на другую файловую запись.
Это граф зависимостей «файл → файлы».

## 3. StreamTOCBackend_Version10

**Проверено на GF2 PC**: все 25 таблиц разбираются и записываются обратно
побайтно. Прежнее описание этого раздела было неверным.

### 3.1 Layout

Смещения абсолютные, от начала файла.

```
0x00  u32  magic 0x9CBA7B28
0x04  u32  version = 10
0x08  u16  num_files       — файловые записи
0x0A  u16  num_names       — записи имён (>= num_files)
0x0C  u16  num_dep_words   — слова зависимостей
0x0E  u16  0
0x10  file_entries[num_files]     по 20 байт
      name_records[num_names]     по 8 байт
      dep_words[num_dep_words]    по 4 байта
      string pool: один NUL, затем имена через NUL, в порядке name_records
      нули до кратного 0x800
```

### 3.2 Файловая запись (20 байт)

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | смещение записи имени в файле |
| +0x04 | u32 | `data_size`: сумма распакованных размеров всех ресурсов потока (поле `+0x1C` блоков `SHDR`) |
| +0x08 | u8 | `f[0]`, `NumShared`: общие потоки среди зависимостей (1 у 54 записей; всегда `globals_global`) |
| +0x09 | u8 | `f[1]`, `NumForceLoad`: потоки, загружаемые вместе с этим (1–6 у 76 записей) |
| +0x0A | u8 | `f[2]`, флаги: бит `0x1` `HAS_PARENT` — первая зависимость родитель (у всех, кроме 25 записей `*_global`); бит `0x4` `LOAD_DISABLED_DEFAULT` — поток выключен, пока его не включит `EnableDisableStreams` (110 записей, каждая — в списке `NumForceLoad` другой записи). Дочерний поток **без** этого бита (`0,0,1,0` в списке `NumForceLoad` родителя) игра открывает при каждой загрузке родителя — в файлах игры таких нет, проверено в игре на этапе 84 (`new-resources.md` §3.1) |
| +0x0B | u8 | `f[3]`, выравнивание, 0 |
| +0x0C | u32 | `DlcIndex`: номер префикса пути дополнения; 0 во всех 4 305 записях |
| +0x10 | u32 | смещение первого слова зависимостей |

Имена полей и битов — из сверки с другим редактором игр EARS (этап 39), проверены на
всех 25 файлах `.toc` игры (4 305 записей). Биты `0x2` (`EXTERNAL`), `0x8`,
`0x10` (принудительная загрузка вкл./выкл.) и `0x20` (дополнение, к нему
относится `DlcIndex`) в GF2 не встречаются и не проверены. Встречаются
сочетания `0,0,1,0` (4 062), `0,0,5,0` (110), `0,1,1,0` (62), `1,0,1,0` (32),
`1,0,0,0` (22), `0,2,1,0` (6), `0,0,0,0` (3), `0,3…6,1,0` (по 2). Поле
заголовка `+0x0C` (`num_dep_words`) у них называется `NumSharedRefs`, но
считает все слова зависимостей; `+0x0E` — 0, смысл неизвестен обоим.

Число зависимостей = `f[0] + f[1] + (f[2] & 1)`. Первые `f[0] + (f[2] & 1)`
— предпосылки: игра загружает их раньше потока; остальные `f[1]` — дочерние
потоки, загружаются вместе с ним (`godfather2.exe`, `0x00403C40`). Бит 2
`f[2]` (флаги `0,0,5,0`) — «parented stream»: загружается только как
дочерний и только после того, как действие SimGroup `EnableDisableStreams`
с его хэшем включит принудительную загрузку (бит `0x8` в памяти, этап 45,
`docs/analysis/new-resources.md` §3.1). Обычный поток имеет флаги `0,0,1,0` и одну зависимость — родителя.
Запись `_global` уровня имеет флаги `0,0,0,0` или `1,0,0,0` и данные размера
0. Записи разделяют списки зависимостей. Добавление записей —
`docs/analysis/new-resources.md` §3.

### 3.3 Запись имени (8 байт)

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | свёртка 128-битного GUID потока (§3.5); 0 у потоков `*_global` |
| +0x04 | u32 | смещение NUL-строки в пуле |

Имя — путь потока от каталога игры без расширения, через `\`:
`gf2\frontend`, `gf2\text\856c146c`. Записи имён без файловой записи —
внешние ссылки: на `gf2\globals_global` и на исходный путь сборки
`x:\build\win\ntsc_en\assets\levels\...`.

### 3.4 Слово зависимости

u32 — смещение записи имени, от которой зависит поток.

### 3.5 Хэш и порядок записей

Хэш вычисляется не из имени, а из 128-битного GUID ассета потока. В
`godfather2.exe` свёртка встречается дважды: отдельной функцией
`0x00401F40` (её зовёт менеджер потоков, 4 вызова) и внутри `0x004A82B0`
(свёртка и сразу двоичный поиск записи `0x004A8180`; ссылок на эту функцию
в exe не найдено). GUID читается как четыре little-endian слова:

```
hash = ((a * 33 + b) * 33 + c) * 33 + d   (mod 2^32)
```

Пример: GUID `a301c953 7450558d 4752414e 44515549` даёт `0x43BAECA2`. Байты
8–15 GUID — восьмисимвольный логин автора ассета (`GRANDQUI`). Один GUID может
стоять за разными именами: три уровня ссылаются на общий поток `globals` с
одинаковым хэшем. Пересчитать хэш по имени нельзя: при записи TOC хэши
сохраняются, а для нового потока нужен его GUID.

Файловые записи отсортированы по хэшу во всех 25 таблицах: игра ищет их
двоичным поиском (`0x004A8180`). Записи с хэшем 0 ищутся линейно по имени без
учёта регистра. Поле `data_size` игра использует только для бюджета памяти
потоковой загрузки (`0x0088BB70`), а не для выделения памяти.

## 4. Пересчёт allocation-значений при сохранении

Алгоритм:

1. Берётся путь к каталогу Stream из глобальной конфигурации.
2. Выделяется каталог (всё до последнего `\` или `/`).
3. Итерируются все файловые записи TOC, для каждой пересчитываются
   allocation-значения секций (смещения/размеры в Stream) из фактического
   расположения файла.

**GF2 PC:** пересчитывается только `data_size` файловой записи изменённого потока
во всех TOC, где он упомянут (`<уровень>.toc` и `<уровень>_global.toc` —
одинаковые копии). Под Wine игра принимает такие файлы. Игра также запускается
с устаревшим `data_size`, оставленным старым тулкитом; обязательность пересчёта
при загрузке уровней не проверена.

Для Godfather I / The Simpsons после этого авто-сохраняется родительский «_global»
Stream (иначе игра падает). Точная формула пересчёта сводится к заполнению
allocation-таблицы актуальными смещениями, выровненными по границе секций Stream
(см. §2.2/§3.3).
