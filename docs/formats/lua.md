# Скрипты Lua (`lua`)

**Проверено на GF2 PC.** Все 30 ресурсов `lua` (поток `gf2/globals_global`) —
байт-код Lua 5.0 с числами `float`. Инструмент читает и пишет чанк целиком,
декомпилирует его в исходный текст и компилирует текст обратно. Где скрипты
работают в игре и что ещё отвечает за логику миссий — `mission-logic.md`.

## 1. Формат чанка

Формат `ldump.c` / `lundump.c` из Lua 5.0. Порядок байт little-endian.

```
0x00  "\x1bLua"
0x04  u8  версия 0x50
0x05  u8  1 = little-endian
0x06  u8  sizeof(int), sizeof(size_t), sizeof(Instruction) = 4, 4, 4
0x09  u8  SIZE_OP, SIZE_A, SIZE_B, SIZE_C = 6, 8, 9, 9
0x0D  u8  sizeof(lua_Number) = 4 (float; у стандартного Lua — 8)
0x0E  lua_Number 3.14159265358979e7 — проверка формата чисел
0x12  функция main
```

Функция:

| Поле | Тип |
|---|---|
| имя источника | строка (`u32` длина с нулём, байты, `\0`); 0 — как у родителя |
| строка определения | `u32` |
| число upvalue, параметров, флаг `...`, размер стека | 4 × `u8` |
| строки инструкций | `u32` N, N × `u32` |
| локальные переменные | `u32` N, N × {строка имени, `u32` startpc, `u32` endpc} |
| имена upvalue | `u32` N, N × строка |
| константы | `u32` N, N × {`u8` тип: 0 nil, 3 число (`float`), 4 строка} |
| вложенные функции | `u32` N, N × функция |
| код | `u32` N, N × `u32` инструкция |

Имя источника главной функции — путь исходника у разработчиков без `@`
(`x:\assets\shared\audio\lua_scripts\aud_utils.lua`): скрипты собраны через
`luaL_loadbuffer` и `lua_dump`, а не утилитой `luac`. Отладочная информация
(строки, имена локальных переменных и upvalue) не вырезана — на неё опирается
декомпилятор.

Числа `float` значат, что 0.2 в чанке — это `0.2f` (0.20000000298…), а
константы сравниваются как `float`. Стандартные `luac` и `luadec` такие чанки
не читают; инструмент поддерживает и `float`, и `double`.

## 2. Компилятор

`compile` (библиотека), `lua-compile` (CLI), `lua_compile` (Python) — перенос
парсера и генератора кода Lua 5.0.3 (`lparser.c`, `lcode.c`, `llex.c`) на
Rust. Он выдаёт те же инструкции, константы, строки и диапазоны локальных
переменных, что и `luac` 5.0 той же сборки, то есть чанк побайтно совпадает с
чанком разработчиков, если совпадает исходник.

Почему перенос, а не исходники Lua на C через `cc`: нет зависимости от
компилятора C при сборке под Windows и в колесе Python, нет `longjmp` через
границу FFI, ошибки возвращаются значением с номером строки. Генератор
небольшой (около 1 800 строк), а совпадение проверяется тестами на эталонных
чанках.

Проверка: `luac` 5.0.3, собранный с `LUA_NUMBER=float` и 4-байтными `size_t`
и инструкциями (формат игры), и компилятор инструмента дают побайтно
одинаковые чанки на 20 тестовых файлах из дистрибутива Lua 5.0.3 и на двух
файлах с трудными конструкциями (`crates/doctor-toolkit/tests/data/lua/`;
эталонные `.luac` лежат там же). Сообщения об ошибках — как у `luac`:
`line 4: unexpected symbol near '='`.

Лицензия Lua 5.0.3 — MIT (Copyright © 1994–2006 Tecgraf, PUC-Rio); текст
лицензии приведён в заголовке `crates/doctor-toolkit/src/resource/lua/compiler.rs`.
MIT совместима с GPL-3.0.

## 3. Декомпилятор

`decompile` / `round_trip` (библиотека), `lua-decompile` (CLI),
`lua_decompile` (Python), вкладка скрипта в GUI.

Генератор кода Lua 5.0 детерминирован, и декомпилятор следует его шаблонам:

- регистры выше активных локальных переменных держат незавершённые выражения,
  пока их не заберёт инструкция; запись или вызов при пустых регистрах
  завершает оператор; множественное присваивание узнаётся по записям, после
  которых регистры ещё заняты;
- локальные переменные и их области берутся из отладочной информации; если
  область кончается раньше блока, это `do … end`;
- `if`, `while`, `repeat`, числовой и общий `for`, `break` узнаются по форме
  переходов; условия с `and`/`or`/`not` восстанавливаются по целям переходов
  сравнений; значения с переходами (`x = a or 0`, `x = a == b`) — по
  `TEST` с копированием и парам `LOADBOOL`;
- `luaK_jump` склеивает переходы, ведущие на безусловный переход
  («threading»); декомпилятор пробует оба места назначения;
- операторы ставятся на строки исходника, поэтому номера строк в тексте
  совпадают с оригиналом (и в отладочной информации перекомпилированного
  чанка). Строка инструкции — `lastline` в `luaK_code`, строка последнего
  прочитанного токена, поэтому и токены без своего кода иногда видны в
  строках:
  - переход через `else`/`elseif` кодируется, когда текущий токен уже
    `else`, — у него строка последнего токена ветки `then`. Если ветка
    кончается вложенным `if`, это строка его `end`: декомпилятор ставит
    этот `end` на строку перехода, а не сразу под последним оператором;
  - сброс 32 элементов конструктора таблицы (`SETLIST`, `closelistfield`)
    кодируется перед разбором 33-го элемента, на строке запятой после
    32-го: он относится к предыдущему элементу, и строка следующего
    элемента берётся из кода после сброса.

Где несколько исходников дают один код (`if a then if b then`, `if a and b
then`), выбирается любой: проверка — перекомпиляция.

### Результат на файлах игры

`lua-decompile <игра> -o <каталог>` декомпилирует все скрипты и сразу
компилирует их обратно:

| Результат | Скриптов |
|---|---:|
| Перекомпилированный чанк побайтно равен оригиналу | 30 |
| Те же инструкции, константы и функции; отличаются только номера строк отладочной информации | 0 |
| Код отличается | 0 |

Проверка — корпусный тест `every_lua_script_decompiles_and_compiles_back`:
каждый скрипт декомпилируется и компилируется обратно так же, как при сборке
проекта (`compile_for_game`, имя чанка оригинала), и результат сравнивается
с данными игры побайтно.

До 2026-11-20 три чанка (`aud_pc_car`, `mus_underscore`,
`mus_underscore_content_mia`) отличались одним номером строки каждый —
оба случая из списка выше:

| Скрипт | Функция, инструкция | Инструкция | Строка: игра / перекомпиляция |
|---|---|---|---|

## 4. Правка скрипта

```sh
GAME="/path/to/The Godfather II"
T=./target/release/doctor-toolkit

$T lua-decompile "$GAME" -o scripts            # scripts/gf2/globals_global/*.lua
# правка scripts/gf2/globals_global/aud_utils.lua
$T lua-import "$GAME" scripts/gf2/globals_global/aud_utils.lua   # в рабочее пространство
$T workspace apply "$GAME"                      # записать в игру
```

`lua-import` находит скрипт по имени файла (`--resource` — по имени или id),
компилирует текст с именем источника оригинала и записывает чанк в рабочее
пространство (`--direct` — сразу и в игру). Синтаксическая ошибка
останавливает импорт с номером строки. Прочие команды: `lua-compile
файл.lua -o файл.luac [--chunk-name ...] [--double]`, `lua-list файл.luac`
(инструкции, константы, локальные переменные).

В GUI у ресурса `lua` — редактор: декомпилированный текст с подсветкой,
номера строк, статус перекомпиляции. Текст проверяется компилятором при каждой
правке; строка с ошибкой подсвечивается, сообщение показывается над
редактором. «Save to workspace» записывает скомпилированный чанк; «Bytecode»
показывает инструкции, «Export .lua…» и «Load .lua…» — обмен с файлами.

Python:

```python
import doctor_toolkit as dt
out = dt.lua_decompile(data)            # source, round_trip, detail, errors
chunk = dt.lua_compile(text, chunk_name)  # LuaSyntaxError(message, line)
```

### Что учесть моддеру

- Ресурс может содержать и исходный текст: `luaL_loadbuffer` различает текст и
  байт-код по первому байту. Инструмент записывает байт-код — ошибки видны до
  запуска игры, а не теряются.
- Ошибки скриптов в игре не выводятся: загрузка и вызовы идут через `pcall`
  без обработчика, `print` и `EclipseLog` ничего не делают
  (`mission-logic.md` §3.1). Скрипт с ошибкой выполнения просто перестаёт
  работать с места ошибки.
- `SetWatchValue` и `ClearWatchValue` в релизе не зарегистрированы: вызовы
  `SetWatch`/`ClearWatch` из `aud_utils.lua` дают ошибку в `pcall`.
- Доступны base, string, table, math и `tolua`; io и os нет. `loadfile`,
  `dofile` и `require` читают файлы с диска относительно каталога игры —
  так мод может держать код вне `.str`.

## 5. Проверка в игре

`docs/analysis/game-bench.md` §13.8: изменённый `aud_utils.lua` (пробные вызовы
`loadfile("doctor_probe_…")` в начале, в конце чанка и в функции
`lua_switch`) импортирован в теневую копию; запуск под стендом с
`TRACE_FILES=1` показывает обращения к пробным файлам — чанк загружен,
выполнен до конца, а функция из него вызывается игрой.

Этап 28 проверил в игре **новые** скрипты (ресурс `lua` и объект
`LuaAudioScript`, добавленные тулкитом): чанк, скомпилированный этим
компилятором, выполняется, его функции вызываются игрой и таймерами
(`docs/scripts.md` §1). Пробы видны в трассировке, если в неё входит
`statx` (`TRACE_SYSCALLS=openat,newfstatat,statx,…`): несуществующий файл
Wine проверяет через `statx`, до `openat` дело не доходит.
