# Просмотрщики GUI: 3D-рендер и текстуры

Этап 9. Код — `crates/doctor-toolkit-gui/src/render/` (рендер сцены),
`model_view/` (просмотр моделей), `texture_view.rs` (текстуры). Реестр
просмотрщиков — этап 19 (`views.rs`, §0); оболочка редактора — `docs/shell.md`.

## 0. Реестр просмотрщиков: как добавить вид

Ресурс открывается в панели **Details** или своей вкладкой; в обоих случаях
приложение спрашивает по порядку каждый зарегистрированный вид, умеет ли он
показать этот ресурс, и рисует подходящие сверху вниз, а под ними —
шестнадцатеричный просмотр (если ни один вид его не прячет). Список видов —
`REGISTRY` в `crates/doctor-toolkit-gui/src/views.rs`:

| id | Модуль | Ресурсы |
|---|---|---|
| `external` | `external_view.rs` | строка «Open in external editor» над текстурами, строками, логикой, скриптами и моделями (`docs/external-editors.md`) |
| `model` | `model_view/` | `mesh` |
| `apx` | `apx_view.rs` | `apx` |
| `resource` | `resource_view.rs` | `rcb`, `ffn`, `sbk` (с импортом звука), `hkx` |
| `anim` | `anim_view.rs` | `bnk`: клипы, события, экспорт JSON и glTF (`docs/formats/characters.md` §6) |
| `script` | `script_view.rs` | `lua`: редактор Lua (`docs/formats/lua.md`, прячет hex) |
| `character` | `character_view.rs` | `partsdb`: дерево базы и сборка персонажа (§7) |
| `logic` | `logic_view.rs` | SimGroup, metamodel и прочая логика (прячет hex); у SimGroup — кнопка «Logic graph» (`docs/logic-graph.md`) |
| `texture` | `texture_view.rs` | `tg4h`, `tg4d` |
| `text` | `text_view.rs` | `lh2` |
| `cutscene` | `cutscene_view/` | `trinity_seq_master`: редактор роликов — шкала времени, 3D-просмотр через камеру кадра с актёрами в позе клипа (`docs/formats/cutscenes.md`, руководство §16; прячет hex) |
| `dialogue` | `dialogue_view.rs` | `dlg`: редактор диалогов (`docs/formats/dialogues.md`, руководство §13; прячет hex) |

Новый вид — свой модуль и одна строка в реестре:

```rust
// foo_view.rs
use crate::views::{ResourceViewer, ViewAction, ViewContext, ViewEntry, ViewSource};

pub const VIEW: ViewEntry = ViewEntry { id: "foo", load };

pub struct FooView { /* состояние одного открытого ресурса */ }

fn load(source: &mut ViewSource<'_>) -> Option<Box<dyn ResourceViewer>> {
    if source.type_id != TYPE_FOO {
        return None; // дёшево: остальные ресурсы не трогаем
    }
    // source.data(i) — данные ресурса i потока как их видит редактор
    // (версия рабочего пространства, если ресурс изменён, иначе игры);
    // source.edited(i) — Some только для изменённых; source.original(i) —
    // оригинал игры для сравнения; source.stream — сам поток; source.game,
    // source.assets (материалы и текстуры игры), source.gpu (рендер wgpu).
    let data = source.data(source.index);
    Some(Box::new(FooView::new(data)))
}

impl ResourceViewer for FooView {
    fn show(&mut self, ui: &mut egui::Ui, cx: &mut ViewContext<'_>) -> Option<ViewAction> {
        // рисует; *cx.status = "…" — сообщение в строку состояния;
        // правка возвращается действием, вид сам ничего не записывает:
        // Some(ViewAction::SaveData { data, label: "Edit foo".into() })
        None
    }
    // по желанию: hides_hex(), has_unsaved_edits(), state()/restore()
}
```

и `crate::foo_view::VIEW,` в `REGISTRY` (порядок в списке — порядок на
экране), `mod foo_view;` в `main.rs`.

Действия вида (`ViewAction`): `SaveData` — записать новые данные ресурса в
рабочее пространство одной операцией (отменяется Ctrl+Z), `SaveStrings` —
таблицу строк, `ImportTexture` — картинку поверх текстуры потока, `Apply` —
правку других ресурсов и файлов (замыкание над `GameInstance` и
`Workspace`, например строки всех языков и речь в накладном архиве),
`Open` — открыть другой ресурс,
`OpenExternal { format }` — открыть ресурс во внешней программе со
слежением, `Unlink(key)` — перестать следить. `ViewContext::links` — какие
ресурсы связаны с файлами (для строки внешнего редактора). Нужен новый
вид правки — новый вариант `ViewAction` и ветка в `BrowserApp::view_action`
(`app/edits.rs`). После записи приложение загружает виды ресурса заново из
рабочего пространства; то, что вернул `state()` старого вида (выбор,
фильтр), передаётся `restore()` нового с тем же `id`. Вид без GPU-ресурсов
и без собственных окон можно открыть несколько раз одновременно (Details и
вкладки), поэтому идентификаторы виджетов внутри вида должны зависеть от
родительского `Ui` (обычные `id_salt` так и делают).

Тест `views::tests::view_ids_are_unique` проверяет, что `id` не повторяются.

## 1. Рендер сцены (`render/`)

Рендер общий для просмотра моделей и будущей сцены уровня (этап 11).
Он не знает о форматах игры: на вход получает готовые вершины, индексы и
RGBA-текстуры.

| Часть | Назначение |
|---|---|
| `MeshData`, `PartData`, `Vertex` | Геометрия одного меша: общий вершинный и индексный буфер, части (диапазон индексов + материал + габариты). Вершина 48 байт: позиция, нормаль, UV, цвет, 4 кости скелета и 4 веса, номер части |
| `MaterialData`, `Surface` | Материал части: основная текстура и цвет; необязательная поверхность «как в игре» (§7) — модель цвета, карты нормалей, блеска и деталей, оттенки, блик, смешивание |
| `TextureData` | RGBA8 с цепочкой mip-уровней, флаг sRGB |
| `SceneRenderer` | Конвейеры wgpu, загруженные меши и текстуры. `upload_texture` / `upload_mesh` под ключами вызывающего (`u64`); меши сверх бюджета (48 по умолчанию) выгружаются по давности отрисовки вместе с ненужными текстурами |
| `Scene` | Экземпляры (`Instance`: ключ меша, матрица, оттенок), скрытые части `(меш, часть)`, подсветка `Pick`, линии с проверкой глубины и поверх всего, переключатели `SceneOptions` |
| `Viewport` | Внеэкранные цели: цвет (`Rgba8Unorm`, гамма), 4× MSAA, если адаптер умеет, глубина `Depth32Float`; цвет зарегистрирован в egui как текстура и выводится картинкой |
| `OrbitCamera`, `View` | Камера вокруг цели (вращение, сдвиг, масштаб, «показать всё»); матрицы вида и проекции, луч через точку экрана, проекция точки на экран |
| `Gpu` | Общий для приложения рендер (`Arc<Mutex<SceneRenderer>>`), берётся из `eframe::CreationContext` |

**Кадр.** `SceneRenderer::render(viewport, size, scene, view)` из потока
интерфейса: экземпляры отсекаются по пирамиде видимости (сфера габаритов),
группируются по мешу и пишутся в один буфер экземпляров; на каждую часть
меша — один инстансированный вызов `draw_indexed`. Каркас — отдельный
индексный буфер рёбер, нормали — буфер линий; оба строятся при первом
включении. Просмотрщик перерисовывает картинку только при изменении камеры,
размера или настроек, поэтому неподвижный вид не нагружает видеокарту.

**Выбор объекта.** `SceneRenderer::pick(viewport, scene, view, pixel)`
рисует сцену в цель `Rg32Uint` (номер экземпляра + 1, номер части) с
ножницами на один пиксель и читает его обратно (ожидание GPU).
`Scene::ray_pick` делает то же на CPU лучом по треугольникам с отсечением по
габаритам частей — годится для гизмо и проверки.

**Почему не внутри прохода egui.** Отдельные цели дают глубину и MSAA
независимо от поверхности окна, проход выбора и перерисовку только по
изменению; несколько видов (сравнение, окно) не мешают друг другу.

### Как использовать на этапе 11 (уровни)

Сделано так — `docs/levels.md` (вкладка «Level», `level_view/`); ниже — исходный
план, по которому она устроена.

1. Для каждого уникального меша уровня — `upload_texture` его текстур
   (ключ — хэш имени текстуры) и `upload_mesh` (ключ — поток + ресурс; см.
   `model_view::load_model`, который делает это для одной модели).
   Бюджет мешей поднять `set_mesh_budget` до числа мешей уровня.
2. `Scene.instances` — по экземпляру на размещение SimGroup с его матрицей;
   индекс в векторе = номер объекта, его возвращает `pick`.
3. Выделение — `Scene.highlight = Some(Pick { instance, part: Pick::ALL_PARTS })`;
   гизмо перемещения и поворота — `Scene.overlay_lines` плюс
   `View::ray` / `View::project` для перетаскивания.
4. Для полёта по уровню нужна своя камера: рендеру нужен только `View`
   (матрицы и положение глаза).

## 2. Просмотр моделей (`model_view/`)

- Текстуры и освещение материалов как в игре (§7; переключатель «Game
  shading», без него — основная текстура), альфа-тест, цвета
  вершин, отсечение задних граней (Direct3D: передняя грань — по часовой
  стрелке; позволяет заглянуть в интерьеры), каркас, нормали.
- Камера: левая кнопка — вращение, правая или средняя (или Shift) — сдвиг,
  колесо — масштаб, `F` / «Frame» — показать модель, двойной щелчок —
  показать часть под курсором.
- Части: видимость, «показать все / скрыть все / только выбранную»; под
  курсором и в списке — имя части, материала и текстур (по ролям), формат
  вершин, число треугольников, скиннинг и палитра костей.
- Скелет из подходящего `rcb` (поиск — как при экспорте glTF):
  кости линиями, суставы точками, имя кости под курсором; список костей;
  наведение или щелчок по кости раскрашивает вершины по её весу.
- Кнопка «Window» открывает просмотр в большом окне со списками сбоку.
- **Коллизия** (этап 18): флажок «Collision» рисует поверх модели зелёный
  каркас коллизии Havok — `hkx` той metamodel потока, что показывает меш
  (`DOCTOR_TOOLKIT_GUI_MODEL=collision`). Ресурс `hkx` сам по себе
  показывается списком тел и каркасом (`collision_view.rs`,
  `docs/formats/havok.md` §4).
- **Инспектор материала** выбранной части: шейдеры всех слотов и теней,
  семейство освещения, смешивание, образцы оттенков (маска, кожа, глаза),
  блик, все параметры и сэмплеры с именами текстур (источник — во
  всплывающей подсказке). Замена материала (у персонажа) отмечена.
- **LOD.** Внутри одного `mesh` уровней детализации нет: записи отрисовки —
  это части. LOD — отдельные ресурсы (`…_lod1`, `…_lod2`), их связь
  описывает `metamodel` (этап 1).
- Без адаптера wgpu приложение запускается на OpenGL (glow), модели
  показывает прежний программный растеризатор.

## 3. Текстуры (`texture_view.rs`)

Масштаб колесом вокруг курсора, сдвиг перетаскиванием, «Fit» и «1:1»
(тексель = пиксель экрана), двойной щелчок — вписать. Каналы R, G, B, A по
отдельности (один цветной канал — в оттенках серого), «Alpha only»;
шахматный фон под прозрачностью; выбор mip-уровня, грани куба и слоя
объёмной текстуры; значение пикселя под курсором. Правка из рабочего
пространства показывается рядом с оригиналом с общим масштабом и сдвигом;
картинки разного размера выравниваются, под курсором видны оба значения.

## 4. Звуковые банки (`resource_view.rs`, `audio_out.rs`)

У каждого звука `sbk` — кнопка «WAV…» (декодирование EA-XAS и сохранение) и
«Play» / «Stop». Проигрывание идёт через `cpal` на устройство по умолчанию
с линейной передискретизацией к его частоте и числу каналов. Звук — фича
`audio` крейта `doctor-toolkit-gui`, включённая по умолчанию; на Linux она
линкует `libasound.so.2` (ALSA), для сборки нужны её заголовки. Без неё
(`--no-default-features`) кнопок «Play» нет, а редактор роликов и Movies
идут по таймеру кадров. Нет устройства, поток не открылся или даже паника
внутри `cpal` — это ошибка с текстом (`audio_out.rs`), а не падение окна.

| `DOCTOR_TOOLKIT_GUI_LIVE=<порт>[:<токен>]` | Подключиться к модулю живой связи при старте; с `DOCTOR_TOOLKIT_GUI_LIVE_FOLLOW=1` вкладки уровня следуют за камерой игры, с `DOCTOR_TOOLKIT_GUI_SCRIPT` редактор скриптов открывает вкладку «Игра» (`docs/shell.md` §9.2) |
| `DOCTOR_TOOLKIT_GUI_SHELL=…`, `DOCTOR_TOOLKIT_CONFIG_DIR=…` | Окна оболочки и каталог настроек (`docs/shell.md` §8) |
| `DOCTOR_TOOLKIT_GUI_WIZARD=<мастер>[,опция…]` | Открыть мастер и пройти шаги (`docs/shell.md` §8, §10) |
| `DOCTOR_TOOLKIT_GUI_BENCH=instances:5000` или `model:<поток>:<ресурс>` или `level:<зона>` | Замер рендера без окна (1600×900, 300 кадров с ожиданием GPU, число — `DOCTOR_TOOLKIT_GUI_BENCH_FRAMES`); `DOCTOR_TOOLKIT_GUI_BENCH_SHOT=<png>` сохраняет кадр |

Окно запускается во вложенном X-сервере, не на экране пользователя:

```sh
Xephyr :57 -screen 1600x1000 &
DISPLAY=:57 WAYLAND_DISPLAY= DOCTOR_TOOLKIT_GUI_SHOT=out.png DOCTOR_TOOLKIT_GUI_SELECT=5288 \
  DOCTOR_TOOLKIT_GUI_MODEL=window,skeleton doctor-toolkit-gui "$GAME" gf2/globalfolder/characters/allcharacters
```

Снимки для README и руководства делает `tools/screenshots.sh ИГРА [ПАПКА]
[ИМЯ…]` (по умолчанию `docs/images/`): каждый снимок — свой Xvfb, интерфейс
на английском (`UI_LANG=ru` — на русском), путь игры показан как
`/tmp/The Godfather II`, нужная область вырезается.

Программный рендер: `VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json`
(lavapipe). Адаптер выбирается так: дискретный, встроенный, прочий,
программный; Vulkan/Metal/DX12 раньше OpenGL; для окна — только способный
выводить на его поверхность.

## 6. Замеры (2026-11-12)

1600×900, 4× MSAA, кадр — запись команд + ожидание GPU. Запись команд на
CPU — 0,06 мс для одной модели и 0,2–0,8 мс для 5 000 экземпляров.

| Сцена | RTX 4070 Laptop (Vulkan) | llvmpipe (lavapipe) |
|---|---|---|
| `federal_building` (самая большая модель: 175 частей, 149 147 треугольников, 38 текстур) | медиана 0,19 мс, p99 0,24 мс; выбор 0,17 мс; загрузка 59 мс | медиана 24,6 мс; выбор: id-проход 6,2 мс, луч на CPU 0,8 мс |
| 5 000 экземпляров 4 мешей, 10 млн треугольников, всё в кадре | медиана 3,1 мс, p99 4,3 мс; 8 вызовов отрисовки; CPU 0,5 мс; выбор 1,4 мс | медиана 849 мс; выбор: id-проход 199 мс, луч 0,35 мс |
| те же 5 000, камера внутри сетки (3 675 отсечено) | медиана 1,1 мс, p99 1,2 мс; выбор 0,5 мс | медиана 287 мс; выбор: id-проход 53 мс, луч 0,5 мс |

На программном адаптере id-проход дорог (вершины обрабатываются целиком),
поэтому просмотрщик моделей там выбирает части лучом на CPU; на видеокарте —
id-проходом (он учитывает альфа-тест). Сцене уровня стоит делать так же.

Окно целиком во вложенном Xephyr (`spin`, RTX 4070, 1200×760): интервал
кадра 20 мс и для маленькой модели, и для `federal_building` (23 мс) —
предел задаёт вывод Xephyr; запись кадра рендером — 0,1–0,2 мс CPU.

## 7. Материалы как в игре (этап 17)

Формулы шейдеров игры — `docs/formats/characters.md` §2. Загрузчик
просмотрщика (`model_view/load.rs`) строит для каждого материала
`resource::shading::Shading` (шейдер по хэшу, семейство, текстуры по ролям,
оттенки уже в линейном пространстве, UV деталей с поправкой игры) и
загружает все текстуры. Шейдер рендера (`render/scene.wgsl`):

| Что | Как |
|---|---|
| маска оттенков (одежда) | `R·T0 + G·T1 + B·T2`, где маска деталей синяя — основная текстура как есть |
| волосы | экранное сложение оттенков, альфа из зелёного канала карты блеска, отдельный проход со смешиванием без записи глубины после непрозрачных частей |
| кожа | основная текстура в степени 2.2, оттенок кожи по красному каналу карты блеска |
| остальное | основная текстура (в степени 2.2, если она не sRGB) |
| нормали | `DXT5_NM` восстанавливается в RGB при загрузке; касательный базис — из производных позиции и UV в пикселе (касательные мешей не загружаются); детальная нормаль с весом `g_SpecParams.w × маска.g` |
| свет | направленный + «от камеры» + фон; AO = зелёный канал карты блеска (одежда, кожа); блик Блинна — Фонга: цвет `g_SpecColorAndScale`, показатель из `g_SpecParams.x`, маска — синий канал |

Не повторяются: отложенное освещение и тени, обводящий свет, анизотропный
блик волос, морщины лиц, детальные карты цвета лиц, туман и тональное
отображение. Материалы без поверхности (уровни, маркеры) рисуются как
раньше.

**Персонаж.** Вид `character` реестра (ресурс `partsdb`): дерево базы и **Character
preview** (`character_view.rs`). Игра и индекс ресурсов для поиска мешей
открываются при первой сборке и общие для всех видов сеанса; после правки
базы вид загружается заново с прежним набором и выбором. Состав: части выбранного набора — отдельные меши
одной сцены с заменами материалов и морфами блендера, выбор вариантов по
слотам, внешности пресетов и цветов частей, «Random», «Export glTF…»,
список частей с видимостью и инспектором материалов. Сборка синхронная:
первый раз читает все материалы игры (≈1–2 с), затем меши и текстуры
набора (десятки миллисекунд).

Снимки: игрок `_all` — `character_player_all.png` (рубашка бордовая,
брюки чёрные, как в игре); куртка без замен — отладочная RGB-маска
(зелёная), так и задумано (`characters.md` §1).
