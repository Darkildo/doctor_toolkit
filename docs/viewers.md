# Просмотрщики GUI: 3D-рендер и текстуры

Этап 9. Код — `crates/doctor-toolkit-gui/src/render/` (рендер сцены),
`model_view/` (просмотр моделей), `texture_view.rs` (текстуры). Реестр
просмотрщиков — этап 19 (`views.rs`, §0); оболочка редактора — `docs/shell.md`.

## 0. Реестр просмотрщиков: как добавить вид

Ресурс открывается в панели **Details** или своей вкладкой; в обоих случаях
приложение спрашивает по порядку каждый зарегистрированный вид, умеет ли он
показать этот ресурс, и рисует подходящие сверху вниз, а под ними —
шестнадцатеричный просмотр (если ни один вид его не прячет). Список видов —
`REGISTRY` в `crates/doctor-toolkit-gui/src/views.rs`:

| id | Модуль | Ресурсы |
|---|---|---|
| `external` | `external_view.rs` | строка «Open in external editor» над текстурами, строками, логикой, скриптами и моделями (`docs/external-editors.md`) |
| `model` | `model_view/` | `mesh` |
| `apx` | `apx_view.rs` | `apx` |
| `resource` | `resource_view.rs` | `rcb`, `ffn`, `sbk` (с импортом звука), `hkx` |
| `anim` | `anim_view.rs` | `bnk`: клипы, события, экспорт JSON и glTF (`docs/formats/characters.md` §6) |
| `script` | `script_view.rs` | `lua`: редактор Lua (`docs/formats/lua.md`, прячет hex) |
| `character` | `character_view.rs` | `partsdb`: дерево базы и сборка персонажа (§7) |
| `logic` | `logic_view.rs` | SimGroup, metamodel и прочая логика (прячет hex); у SimGroup — кнопка «Logic graph» (`docs/logic-graph.md`) |
| `texture` | `texture_view.rs` | `tg4h`, `tg4d` |
| `text` | `text_view.rs` | `lh2` |
| `cutscene` | `cutscene_view/` | `trinity_seq_master`: редактор роликов — шкала времени, 3D-просмотр через камеру кадра с актёрами в позе клипа (`docs/formats/cutscenes.md`, руководство §16; прячет hex) |
| `dialogue` | `dialogue_view.rs` | `dlg`: редактор диалогов (`docs/formats/dialogues.md`, руководство §13; прячет hex) |

Новый вид — свой модуль и одна строка в реестре:

```rust
// foo_view.rs
use crate::views::{ResourceViewer, ViewAction, ViewContext, ViewEntry, ViewSource};

pub const VIEW: ViewEntry = ViewEntry { id: "foo", load };

pub struct FooView { /* состояние одного открытого ресурса */ }

fn load(source: &mut ViewSource<'_>) -> Option<Box<dyn ResourceViewer>> {
    if source.type_id != TYPE_FOO {
        return None; // дёшево: остальные ресурсы не трогаем
    }
    // source.data(i) — данные ресурса i потока как их видит редактор
    // (версия рабочего пространства, если ресурс изменён, иначе игры);
    // source.edited(i) — Some только для изменённых; source.original(i) —
    // оригинал игры для сравнения; source.stream — сам поток; source.game,
    // source.assets (материалы и текстуры игры), source.gpu (рендер wgpu).
    let data = source.data(source.index);
    Some(Box::new(FooView::new(data)))
}

impl ResourceViewer for FooView {
    fn show(&mut self, ui: &mut egui::Ui, cx: &mut ViewContext<'_>) -> Option<ViewAction> {
        // рисует; *cx.status = "…" — сообщение в строку состояния;
        // правка возвращается действием, вид сам ничего не записывает:
        // Some(ViewAction::SaveData { data, label: "Edit foo".into() })
        None
    }
    // по желанию: hides_hex(), has_unsaved_edits(), state()/restore()
}
```

и `crate::foo_view::VIEW,` в `REGISTRY` (порядок в списке — порядок на
экране), `mod foo_view;` в `main.rs`.

Действия вида (`ViewAction`): `SaveData` — записать новые данные ресурса в
рабочее пространство одной операцией (отменяется Ctrl+Z), `SaveStrings` —
таблицу строк, `ImportTexture` — картинку поверх текстуры потока, `Apply` —
правку других ресурсов и файлов (замыкание над `GameInstance` и
`Workspace`, например строки всех языков и речь в накладном архиве),
`Open` — открыть другой ресурс,
`OpenExternal { format }` — открыть ресурс во внешней программе со
слежением, `Unlink(key)` — перестать следить. `ViewContext::links` — какие
ресурсы связаны с файлами (для строки внешнего редактора). Нужен новый
вид правки — новый вариант `ViewAction` и ветка в `BrowserApp::view_action`
(`app/edits.rs`). После записи приложение загружает виды ресурса заново из
рабочего пространства; то, что вернул `state()` старого вида (выбор,
фильтр), передаётся `restore()` нового с тем же `id`. Вид без GPU-ресурсов
и без собственных окон можно открыть несколько раз одновременно (Details и
вкладки), поэтому идентификаторы виджетов внутри вида должны зависеть от
родительского `Ui` (обычные `id_salt` так и делают).

Тест `views::tests::view_ids_are_unique` проверяет, что `id` не повторяются.

## 1. Рендер сцены (`render/`)

Рендер общий для просмотра моделей и будущей сцены уровня (этап 11).
Он не знает о форматах игры: на вход получает готовые вершины, индексы и
RGBA-текстуры.

| Часть | Назначение |
|---|---|
| `MeshData`, `PartData`, `Vertex` | Геометрия одного меша: общий вершинный и индексный буфер, части (диапазон индексов + материал + габариты). Вершина 48 байт: позиция, нормаль, UV, цвет, 4 кости скелета и 4 веса, номер части; старший бит номера части — `Vertex::BILLBOARD`, угол листа, повёрнутого к камере (§7b) |
| `MaterialData`, `Surface` | Материал части: основная текстура и цвет; необязательная поверхность «как в игре» (§7) — модель цвета, карты нормалей, блеска и деталей, оттенки, блик, смешивание |
| `TextureData` | RGBA8 с цепочкой mip-уровней, флаг sRGB |
| `SceneRenderer` | Конвейеры wgpu, загруженные меши и текстуры. `upload_texture` / `upload_mesh` под ключами вызывающего (`u64`); меши сверх бюджета (48 по умолчанию) выгружаются по давности отрисовки вместе с ненужными текстурами. Вершины и индексы всех мешей — в общих буферах-страницах (`render/batch.rs`), одинаковые материалы — одна группа привязок (этап 67) |
| `Scene` | Экземпляры (`Instance`: ключ меша, матрица, оттенок), скрытые части `(меш, часть)`, подсветка `Pick`, линии с проверкой глубины и поверх всего, переключатели `SceneOptions` |
| `Viewport` | Внеэкранные цели: цвет (`Rgba8Unorm`, гамма), 4× MSAA, если адаптер умеет, глубина `Depth32Float`; цвет зарегистрирован в egui как текстура и выводится картинкой |
| `OrbitCamera`, `View` | Камера вокруг цели (вращение, сдвиг, масштаб, «показать всё»); матрицы вида и проекции, луч через точку экрана, проекция точки на экран |
| `Gpu` | Общий для приложения рендер (`Arc<Mutex<SceneRenderer>>`), берётся из `eframe::CreationContext` |
| `render/bindless.rs`, `render/post.rs` | «Как в игре» на устройствах с массивами привязок: таблицы материалов и частей, один массив текстур, каскады тени солнца, свет фонарей по плиткам экрана; проход цветовых таблиц (этап 70, §7d) |
| `Scene::lights`, `PointLight` | Свет фонарей в мире (только «как в игре», `SceneOptions::lamps`; тени — `SceneOptions::shadows`) |

**Кадр.** `SceneRenderer::render(viewport, size, scene, view)` из потока
интерфейса: экземпляры отсекаются по пирамиде видимости (сфера габаритов),
группируются по мешу и пишутся в один буфер экземпляров; каждая часть
меша — один инстансированный индексный вызов в общих буферах
(`first_index`, `base_vertex`, `first_instance`). Порядок — меш за мешем по
ключу, сначала непрозрачные части, потом смешиваемые; буферы страницы и
материал привязываются, только когда меняются, а соседние части одной
страницы и одного материала идут одним `multi_draw_indexed_indirect`
(устройства без `INDIRECT_FIRST_INSTANCE` — прямыми вызовами). Порядок
частей решает цвет совпадающих по глубине поверхностей, поэтому он не
меняется (`docs/analysis/editor-performance.md`). Каркас — отдельный
индексный буфер рёбер, нормали — буфер линий; оба строятся при первом
включении. Просмотрщик перерисовывает картинку только при изменении камеры,
размера или настроек, поэтому неподвижный вид не нагружает видеокарту.

**Выбор объекта.** `SceneRenderer::pick(viewport, scene, view, pixel)`
рисует сцену в цель `Rg32Uint` (номер экземпляра + 1, номер части) с
ножницами на один пиксель и читает его обратно (ожидание GPU).
`Scene::ray_pick` делает то же на CPU лучом по треугольникам с отсечением по
габаритам частей — годится для гизмо и проверки.

**Почему не внутри прохода egui.** Отдельные цели дают глубину и MSAA
независимо от поверхности окна, проход выбора и перерисовку только по
изменению; несколько видов (сравнение, окно) не мешают друг другу.

### Как использовать на этапе 11 (уровни)

Сделано так — `docs/levels.md` (вкладка «Level», `level_view/`); ниже — исходный
план, по которому она устроена.

1. Для каждого уникального меша уровня — `upload_texture` его текстур
   (ключ — хэш имени текстуры) и `upload_mesh` (ключ — поток + ресурс; см.
   `model_view::load_model`, который делает это для одной модели).
   Бюджет мешей поднять `set_mesh_budget` до числа мешей уровня.
2. `Scene.instances` — по экземпляру на размещение SimGroup с его матрицей;
   индекс в векторе = номер объекта, его возвращает `pick`.
3. Выделение — `Scene.highlight = Some(Pick { instance, part: Pick::ALL_PARTS })`;
   гизмо перемещения и поворота — `Scene.overlay_lines` плюс
   `View::ray` / `View::project` для перетаскивания.
4. Для полёта по уровню нужна своя камера: рендеру нужен только `View`
   (матрицы и положение глаза).

## 2. Просмотр моделей (`model_view/`)

- Текстуры и освещение материалов как в игре (§7; переключатель «Game
  shading», без него — основная текстура), альфа-тест, цвета
  вершин, отсечение задних граней (Direct3D: передняя грань — по часовой
  стрелке; позволяет заглянуть в интерьеры), каркас, нормали.
- Камера: левая кнопка — вращение, правая или средняя (или Shift) — сдвиг,
  колесо — масштаб, `F` / «Frame» — показать модель, двойной щелчок —
  показать часть под курсором.
- Части: видимость, «показать все / скрыть все / только выбранную»; под
  курсором и в списке — имя части, материала и текстур (по ролям), формат
  вершин, число треугольников, скиннинг и палитра костей.
- Скелет из подходящего `rcb` (поиск — как при экспорте glTF):
  кости линиями, суставы точками, имя кости под курсором; список костей;
  наведение или щелчок по кости раскрашивает вершины по её весу.
- Вкладка ресурса (двойной щелчок, «Open in tab»; до этапа 56 — кнопка «Window» и плавающее окно) — редактор: «Shading ▾» и «Show ▾» на полосе вкладки, части и кости слева, вид на всю вкладку, материал выбранной части — в Details (`docs/shell.md` §11.10).
- **Коллизия** (этап 18): флажок «Collision» рисует поверх модели зелёный
  каркас коллизии Havok — `hkx` той metamodel потока, что показывает меш
  (`DOCTOR_TOOLKIT_GUI_MODEL=collision`). Ресурс `hkx` сам по себе
  показывается списком тел и каркасом (`collision_view.rs`,
  `docs/formats/havok.md` §4).
- **Инспектор материала** выбранной части: шейдеры всех слотов и теней,
  семейство освещения, смешивание, образцы оттенков (маска, кожа, глаза),
  блик, все параметры и сэмплеры с именами текстур (источник — во
  всплывающей подсказке). Замена материала (у персонажа) отмечена.
- **LOD.** Внутри одного `mesh` уровней детализации нет: записи отрисовки —
  это части. LOD — отдельные ресурсы (`…_lod1`, `…_lod2`), их связь
  описывает `metamodel` (этап 1).
- Без адаптера wgpu приложение запускается на OpenGL (glow), модели
  показывает прежний программный растеризатор.

## 3. Текстуры (`texture_view.rs`)

Масштаб колесом вокруг курсора, сдвиг перетаскиванием, «Fit» и «1:1»
(тексель = пиксель экрана), двойной щелчок — вписать. Каналы R, G, B, A по
отдельности (один цветной канал — в оттенках серого), «Alpha only»;
шахматный фон под прозрачностью; выбор mip-уровня, грани куба и слоя
объёмной текстуры; значение пикселя под курсором. Правка из рабочего
пространства показывается рядом с оригиналом с общим масштабом и сдвигом;
картинки разного размера выравниваются, под курсором видны оба значения.

## 4. Звуковые банки (`resource_view.rs`, `audio_out.rs`)

У каждого звука `sbk` — кнопка «WAV…» (декодирование EA-XAS и сохранение) и
«Play» / «Stop». Проигрывание идёт через `cpal` на устройство по умолчанию
с линейной передискретизацией к его частоте и числу каналов. Звук — фича
`audio` крейта `doctor-toolkit-gui`, включённая по умолчанию; на Linux она
линкует `libasound.so.2` (ALSA), для сборки нужны её заголовки. Без неё
(`--no-default-features`) кнопок «Play» нет, а редактор роликов и Movies
идут по таймеру кадров. Нет устройства, поток не открылся или даже паника
внутри `cpal` — это ошибка с текстом (`audio_out.rs`), а не падение окна.

## 4a. Окно «Звук» и таблицы звука (`app/sound.rs`, `sound_table_view.rs`, этап 103)

Tools → Sound (`Command::Sounds`, `cmd.sounds`) — окно `SoundWindow` с
пятью страницами: файлы архивов `.viv` (список, прослушивание, экспорт в
WAV, замена, субтитры речевого файла по языкам), речевые банки `smb`
(чтение), таблица событий речи `get` (добавить запись, пауза, приоритет,
флаги, ранг), аудиоконфигурация `auc` (новая категория микшера) и снимки
микшера `mix` (громкость, время, частота канала, новый канал). Окно ничего
не разбирает и не пишет само: чтение и каждая правка — функции
`doctor_toolkit::sound` (`archive_sounds`, `archive_sound_data`,
`sound_info`, `replace_archive_sound`, `set_subtitles`,
`speech_event_names`, `set_speech_events`, `audio_configs`,
`add_mix_category`, `mixes`, `set_mix`), те же, что зовут команды
`sound-import`, `speech-events`, `audio-config`, `mix` и инструменты
`media`, `import_sound`, `edit_subtitle`. Кнопки окна отдают
`SoundAction`, его выполняет `BrowserApp::sound_action`: одна операция
рабочего пространства на действие, ошибка — `notify(Level::Error)`.
Прочитанное из игры окно сбрасывает, когда меняется история рабочего
пространства (правка, отмена, возврат — где угодно).

Вид `sound_table` (`sound_table_view.rs`) — для ресурсов `smb`, `get`,
`auc`, `mix`: содержимое этого ресурса строками и кнопка «Open in the Sound
window» (`ViewAction::OpenSound`).

## 5. Проверка без пользователя

| Переменная | Действие |
|---|---|
| `DOCTOR_TOOLKIT_GUI_SHOT=<png>` + `DOCTOR_TOOLKIT_GUI_SELECT=<ресурс>` | Снимок окна и выход (как раньше) |

| `DOCTOR_TOOLKIT_GUI_TEXTURE=zoom=4,channels=rgb,alpha,mip=1,layer=0,pan=100:50,compare=0` | Начальные настройки просмотра текстуры |
| `DOCTOR_TOOLKIT_GUI_CHARACTER=set=_all,lod=0,choose=a_hat=a_hat_fedora,yaw=0.5,zoom=1.2,select=3` | Для выбранного ресурса `partsdb`: собрать персонажа сразу (`docs/formats/characters.md` §4) |
| `DOCTOR_TOOLKIT_GUI_CUTSCENE=time=26,zoom=30,scroll=15,load,free,play,select=3:29` | Для выбранного `trinity_seq_master`: курсор, масштаб и прокрутка шкалы, собрать персонажей (`load`), свободная камера, проигрывание, выбор команды `кадр:номер` или субтитра `sub:строка` |
| `DOCTOR_TOOLKIT_GUI_ANIM=clip=3,frame=10,import=<file.glb>,add=<имя>,graph=idle,node=2` | Для выбранного банка `bnk`: показать клип на скелете, открыть импорт анимации, показать граф анимации (во вкладке банка — часть Graph) на входе и выделить его узел (номер в обходе входа; `docs/guide/24-anim-graph.md`) |
| `DOCTOR_TOOLKIT_GUI_IMPORT=<file.glb>` | Открыть окно импорта модели (`docs/model-import.md`) для выбранного меша или metamodel |
| `DOCTOR_TOOLKIT_GUI_EXTERNAL=<формат>` | Открыть выбранный ресурс во внешней программе (`png`, `csv`, `lua`, `glb`…) — программа берётся из настроек, для снимков задайте `DOCTOR_TOOLKIT_CONFIG_DIR` с `[external_editors]` вроде `image = "true"` (`docs/external-editors.md` §5) |
| `DOCTOR_TOOLKIT_GUI_SHOT_FRAMES=<n>` | Кадров до снимка (20 по умолчанию), например для `spin` |
| `DOCTOR_TOOLKIT_GUI_RENDERER=glow` | Принудительно OpenGL и программный просмотр моделей |
| `DOCTOR_TOOLKIT_GUI_LEVEL=<зона>[;опции]` | Открыть вкладку уровня (в раскладке «Level Editor», `docs/shell.md` §11.4; без запоминания раскладок — развёрнутой на всё окно) и загрузить зоны: каталоги, потоки, `preset:<id>`, `set:<имя>` или `last` (`docs/levels.md` §5, §13) |
| `DOCTOR_TOOLKIT_GUI_MOVIES=<ролик>[:<кадр>][,play][,full]` | Открыть вкладку Movies с роликом и кадром; `play` — играть, `full` — на всё окно (`docs/formats/video.md` §5.1) |

## 7. Материалы как в игре (этап 17)

Формулы шейдеров игры — `docs/formats/characters.md` §2. Загрузчик
просмотрщика (`model_view/load.rs`) строит для каждого материала
`resource::shading::Shading` (шейдер по хэшу, семейство, текстуры по ролям,
оттенки уже в линейном пространстве, UV деталей с поправкой игры) и
загружает все текстуры. Шейдер рендера (`render/scene.wgsl`):

| Что | Как |
|---|---|
| маска оттенков (одежда) | `R·T0 + G·T1 + B·T2`, где маска деталей синяя — основная текстура как есть |
| волосы | экранное сложение оттенков, альфа из зелёного канала карты блеска, отдельный проход со смешиванием без записи глубины после непрозрачных частей |
| кожа | основная текстура в степени 2.2, оттенок кожи по красному каналу карты блеска |
| глаза (этап 65) | радужка (альфа основной текстуры) умножена на `g_EyeTintColor`, глаз непрозрачен |
| ресницы `gf_char_hair_aniso` (этап 65) | основная текстура `A8` — чёрная, её альфа — покрытие, со смешиванием |
| остальное | основная текстура (в степени 2.2, если она не sRGB) |
| нормали | `DXT5_NM` восстанавливается в RGB при загрузке; касательный базис — из производных позиции и UV в пикселе (касательные мешей не загружаются); детальная нормаль с весом `g_SpecParams.w × маска.g` |
| свет | направленный + «от камеры» + фон; AO = зелёный канал карты блеска (одежда, кожа); блик Блинна — Фонга: цвет `g_SpecColorAndScale`, показатель из `g_SpecParams.x`, маска — синий канал |

Скиннинг в просмотре ролика берёт обратные матрицы привязки из рига актёра
(`docs/formats/rig.md` §3.1): с первым попавшимся (женским) ригом у мужчин
«сминались» лица (этап 65).

Не повторяются: тени, обводящий свет, анизотропный блик волос, морщины
лиц, детальные карты цвета лиц; свет, туман и небо игры — §7a. Материалы мира
(вид уровня) — §7c; материалы без поверхности (маркеры) рисуются как раньше.

**Персонаж.** Вид `character` реестра (ресурс `partsdb`): дерево базы и **Character
preview** (`character_view.rs`). Игра и индекс ресурсов для поиска мешей
открываются при первой сборке и общие для всех видов сеанса; после правки
базы вид загружается заново с прежним набором и выбором. Состав: части выбранного набора — отдельные меши
одной сцены с заменами материалов и морфами блендера, выбор вариантов по
слотам, внешности пресетов и цветов частей, «Random», «Export glTF…»,
список частей с видимостью и инспектором материалов. Сборка синхронная:
первый раз читает все материалы игры (≈1–2 с), затем меши и текстуры
набора (десятки миллисекунд).

Снимки: игрок `_all` — `character_player_all.png` (рубашка бордовая,
брюки чёрные, как в игре); куртка без замен — отладочная RGB-маска
(зелёная), так и задумано (`characters.md` §1).

## 7a. Освещение как в игре (этап 66)

Переключатель **Shading as in the game** (Preferences → Views и меню
**Lit ▾** вида уровня; `Settings::view.game_look`, по умолчанию включён)
даёт рендеру `SceneOptions::game` — `render::GameLook` (`render/game_look.rs`).
Шейдер `scene.wgsl` тогда повторяет освещённый проход игры
(`docs/analysis/renderer.md` §10):

| Что | Как |
|---|---|
| буфер света | солнце `saturate(n·l + wrap) × цвет` плюс рассеянный свет `(n,1)ᵀ·M·(n,1)` по трём матрицам `GlobalSHTODMessage`, зажато в 0..1, как 8-битная цель игры; альфа — блик солнца |
| цвет | альбедо (линейное) × свет × 2, AO одежды и кожи; блик материала × маска × альфа буфера |
| туман | `m_FogColor` → `m_FogEndColor` по дальности, сила от `near` до `far`, до начала тумана нет |
| выход | `pow(x, 1/2.2)`, а не кривая sRGB |
| небо | полноэкранный треугольник до сцены: `mix(низ, верх, 1 − (1 − h)²)` по высоте над горизонтом в полосе дымки и свечение вокруг солнца; меши купола неба (`sky_dome`, `sky_clouds`, `MaterialData::sky`) в этом режиме не рисуются |

Источник значений — ключи времени суток города
(`doctor_toolkit::time_of_day::CityLight`, кэш на игру и город —
`game_light.rs`): вид уровня берёт город по своим потокам и час из
ползунка **Time of day** (по умолчанию 16:00, пресет `time=HH:MM`,
`shading=game|simple`, `fov=градусы`), вид ролика — час ролика (этап 61);
модели и персонажи — `GameLook::studio()` (свет полудня без неба и тумана).
Яркость солнца и доля рассеянного света подобраны по кадрам игры
(`SUN_AT_NOON`, `AMBIENT_SCALE`: в игре это код, а не ключи). Превью
Content Browser остаются простыми. Кадр вида уровня в Гаване не изменился
(разброс Xvfb: 23,8–35,2 мс против 26,8–37,3 мс до этапа, медианы трёх
участков облёта `spin`).

## 7b. Деревья (этап 68)

Модели деревьев `treemodel` (`docs/formats/treemodel.md`) рисует общий
рендер: `render/tree.rs` (`tree_mesh`) делает из дерева `MeshData` — часть
на часть дерева с материалом (`TreeMaterial`: текстура `sampColor`, цвет
`g_BaseTintColor`, листья с альфа-тестом), полосы ствола и
четырёхугольники листьев — треугольники. Углы листьев, повёрнутых к камере,
— вершины с битом `Vertex::BILLBOARD`: позиция — центр листа, нормаль —
смещение угла в осях камеры (размер листа × угол из таблицы игры
`treemodel::leaf_corner`), веса — нормаль листа в осях камеры. Вершинный
шейдер (`scene.wgsl`, `place`) прибавляет к центру смещение по осям камеры
из `Globals::camera` (правая, верхняя, вперёд) × масштаб объекта по высоте,
как `TreeRotatingLeaf` игры; габариты части растут на размер листа, чтобы
отсечение не теряло крону. Ветра нет.

- **Вид уровня и ролики с миром**: загрузчик (`level_view/loader.rs`,
  `Part::Tree`, ключи `tree_key`) переводит деревья уровня
  (`Level::trees`, найденные как меши) в общем потоке с мешами; дерево —
  элемент `ItemKind::Tree` (переключатель Trees в Show). Дерево, которого
  нет в файлах игры, — зелёный столбик-маркер.
- **Маркеры** (переключатель Markers на панели над видом, тот же флажок в
  Show): точки появления, триггеры, кубы объектов без модели, деревья-
  заглушки. Пока пользователь его не трогал, маркеры скрыты в режиме «как
  в игре» и показаны в простом (`LevelView::markers_shown`); выделенный
  объект виден и со скрытыми маркерами, Outliner и выбор работают как
  прежде. Пресет снимков `nomarkers` вида ролика ставит выбор явно.
- **Просмотр модели** открывает `treemodel` (`ModelPreview::load_tree`,
  `model_view::load_tree`): части, материалы и текстуры в списке, как у
  меша; только на видеокарте.
- **Превью Content Browser**: `treemodel` — в категории «Модели»; превью
  метамодели рисует и её деревья, превью дерева — само дерево
  (`RENDER_VERSION` 2).

## 7c. Материалы мира (этап 69)

Формулы шейдеров мира — `docs/analysis/renderer.md` §10.7. Ядро:
`resource::world_shading::WorldShading::from_material` читает параметры
прохода нормалей (слот 0) и освещённого прохода (слот 1) материала:
модель (`WorldModel`: `Basic`, `Building`, `Detail`, `Panorama`,
`Overlay`, `Window`, `Glass`, `Water`), текстуры (основная, детальная,
маска, нормали, детальные нормали, блеск, карта резкости блика), оттенки в
линейном пространстве, UV слоёв, масштабы, блик и отражение, альфа-тест;
встроенные текстуры игры (`Builtin`: `color`, `normal`, `specular`,
кубические карты) — пропуски (белая, ровная нормаль, чёрная).

Загрузчик вида уровня (`level_view/loader.rs`): `LevelMaterial` (основная
текстура — всё, что берёт простой режим, — купол неба и `WorldShading`),
`world_surface` — `render::Surface` с моделями `SurfaceModel::WorldBasic…Water`
и `WorldParams`; `settle` обнуляет то, чего шейдер для этой модели не
читает (блик без карты блеска, UV слоя без текстуры…), чтобы одинаковые на
вид записи шли одной частью и одной группой привязок. Части меша — по
равенству `MaterialData` (раньше — по основной текстуре): записи с разными
материалами одной текстуры больше не сливаются. Слои наложения
(`overlay_id` > 0, `DoNotRenderDepth`) и стекло `AlphaSort` —
со смешиванием после непрозрачных частей, в порядке записей. Загружаются и
текстуры слоёв, масок, нормалей и блеска (Гавана: 646 → 872 текстуры,
154 → 203 МБ). Части одной основной текстуры идут подряд (в порядке её
первой записи), а `MeshData::layer_coplanar_parts` даёт каждой части слой
порядка: 0 или на один выше слоя более ранней части меша, с которой она
лежит в одной плоскости (общая плоскость треугольников с точностью 1 см и
1/1000 нормали, пересекающиеся границы) — вывеска на стене, пятно на земле.

Порядок отрисовки (`batch::Order`): в простом режиме — как раньше, по мешам
и частям; у частей мира в нём своя группа привязок без поверхности
(`GpuPart::simple`: основная текстура и цвет), поэтому соседние части одной
текстуры снова рисуются одним вызовом и число вызовов то же, что до этапа.
«Как в игре» непрозрачные части рисуются по слою, затем по буферу и
материалу (`Order::Layers`): части, лежащие друг на друге, сохраняют
порядок меша, остальные группируются — материалов мира втрое больше, и
каждая смена группы привязок стоит времени ЦП (`editor-performance.md`
§10). `DOCTOR_TOOLKIT_GUI_BATCHING=given` возвращает порядок мешей и в
режиме «как в игре» (опыт: разница — пиксели на стыках мешей).

Шейдер (`scene.wgsl`, `world_fragment`) работает только «как в игре»
(`uses_surface` пропускает модели мира в простом режиме, и они рисуются
основной текстурой, как раньше): цвет модели, × зелёный цвета вершины, нормаль
из карты нормалей (и детальной по маске), блик буфера света с показателем
`s³·255` из синего канала карты блеска или параметра, цвет блика по шейдеру,
отражение неба (`sky_colour` — та же функция, что рисует небо), туман.
Привязки материала те же шесть текстур: у мира маска — в гнезде маски
деталей (UV маски), детальный слой — в гнезде детального блеска (UV
деталей), карта резкости — сама карта блеска; ключ кэша групп привязок
(этап 67) — байты униформы (в ней теперь оттенки слоёв, `WorldParams` и
биты `HAS_EXPONENT`, `SPEC_*`, `REFLECT_MASKED`, `ALPHA_CUT`, `*_SRGB`) и
выгрузки текстур. Смешиваемые части рисуются с предумноженной альфой
(`PREMULTIPLIED_ALPHA_BLENDING`): стекло отдаёт свой цвет и долю
закрытого фона, остальные — цвет × альфа.

Свет городов подобран заново (`SUN_AT_NOON` 1,2, `AMBIENT_SCALE` 0,3;
`renderer.md` §10.8), свет просмотра моделей и персонажей прежний.
Проверки: корпусный тест `every_world_material_of_the_cities_finds_its_textures`
(8 020 материалов мира в трёх городах, все текстуры найдены, карта
резкости — карта блеска), `world_surfaces_bind_their_layers` (загрузчик),
`world_surfaces_mix_their_layers_by_the_mask_only_in_the_game_look`
(рендер на видеокарте), `parts_in_one_plane_keep_their_order`,
`layers_keep_the_order_of_each_mesh`. Простой режим: кадры Гаваны и Майами
(камеры сравнения с игрой) побайтно те же, что до этапа. Скорость —
`editor-performance.md` §10.

## 7d. Тени, фонари и цвет (этап 70)

Исследование — `docs/analysis/renderer.md` §10.9.

**Два варианта шейдера.** `scene.wgsl` — один текст: строки между
`//#if game` и `//#else`/`//#endif` попадают только в вариант «как в
игре» (`gpu.rs`, `shader_source`). Простой вариант — прежний рендер: группа
привязок на материал; простой режим рисует им побайтно те же кадры, что
до этапа (Гавана и Майами, камеры сравнения с игрой). Вариант «как в игре»
работает там, где у устройства есть массивы привязок
(`TEXTURE_BINDING_ARRAY`, неоднородный индекс, частично заполненный массив;
Vulkan, DirectX 12, Metal — `render/bindless.rs`, `bindless::supported`);
на OpenGL «как в игре» рисует простой вариант шейдера — без теней и
фонарей, с цветом и свечением окон.

**Таблицы вместо групп привязок** (`render/bindless.rs`): все текстуры —
в одном массиве `binding_array<texture_2d<f32>>` (до 8 192, место
текстуры — по её ключу; белая и ровная нормаль — места 0 и 1), параметры
материалов — таблица `GameMaterial` (униформа материала и места шести
текстур) в буфере хранения, у каждого меша — отрезок таблицы частей
(индекс материала на часть). Экземпляр несёт начало отрезка своего меша
(`InstanceRaw::ids.y`), вершина — номер части; вершинный шейдер достаёт
индекс материала, фрагментный — материал и текстуры. Группа привязок
одна на кадр, ключ пакета — только буфер (`DrawKey::material` = 0), и
соседние части одного буфера идут одним косвенным мульти-вызовом при любых
материалах. Выбор объектов (проход id) по-прежнему рисует группами
привязок материалов.

**Тени солнца**: три каскада карты теней `Depth32Float` 2048² (дальние
концы 16, 45 и 100 м от глаза), каждый — ортографический куб вокруг сферы
своего отрезка пирамиды вида, смотрящий вдоль солнца, сдвигаемый целыми
текселями (`bindless::cascades`); отбрасыватели — экземпляры, попавшие в
куб или между ним и солнцем (250 м; во втором и третьем каскадах — не
меньше 0,4 и 1,2 м радиусом), непрозрачные части без неба,
стекла, наложений, панорам и воды (`GpuPart::casts`); части с альфа-тестом
режутся по альфе (`fs_shadow`). Шейдер выбирает каскад по расстоянию,
сравнивает в четырёх точках (`sun_shadow`) и в тени оставляет
`1 −` тени `LightingTODMessage` солнца (`GameLook::shadow`). Солнце не
выше 3° над горизонтом теней не даёт.

**Фонари**: `level::model` собирает части `EARSLight`/`TODEARSLight`
метамоделей (`Light`: вид, матрица, цвет, сила, радиусы, конусы, обёртка,
сила днём и ночью, внутри/снаружи); вид уровня ставит их в мир
(`level_view::scene::build_lights`: без света интерьеров и лиц) и на каждый
кадр даёт рендеру `Scene::lights` — силу по `GameLook::night`, цвет в
линейном свете. Рендер берёт до 1 024 видимых ближайших и раскладывает их
по плиткам экрана 32 × 32 пикселя (до 48 на плитку, `bindless::Frame`);
фрагмент складывает свет своей плитки с солнцем и рассеянным светом и
зажимает в 1, как 8-битный буфер игры.

**Цвет**: сцена «как в игре» рисуется в свой кадр, проход `render/post.rs`
(`post.wgsl`) переводит его в вид по двум таблицам цвета 32³
(`GameLook::grading`, таблицы — `render::register_tables`, их читает
`game_light` вместе с ключами города). Модели и персонажи (`studio`)
таблиц не имеют — проход только копирует.

**Ночное свечение**: окна, лампы и вывески (`WorldShading::glow`,
`m_LightColor`) и панорамы (`g_DayGlowColor`, `g_NightGlowColor`, маска)
— в `world_fragment` по `GameUniform::extra.x` (`g_NightControl`).

Меню **Lit ▾** вида уровня: **Shadows** и **Lamps** (под ползунком времени
суток, `SceneOptions::shadows`, `lamps`; пресет `shadows=off`,
`lamps=off`). Проверки: `grading_weighs_the_tables_of_two_keys`,
`colour_grading_vfx_names_end_their_tables_names`,
`panoramas_glow_by_day_and_night`, `cascades_hold_the_view_and_look_down_the_sun`,
`lights_land_in_the_tiles_they_reach`, корпусный
`every_city_grades_its_colours_and_lights_its_lamps` (таблицы всех ключей
найдены, полдень — `day`, полночь — `night`, сотни фонарей, горящих
только ночью). Скорость — `editor-performance.md` §11.

## 8. Превью Content Browser (этап 55)

Миниатюры моделей и текстур панели Content Browser делает тот же рендер,
что виды моделей и уровня (`app/content/thumb.rs`), на рабочих потоках:

- **текстура** — самый маленький MIP не меньше 256 пикселей, декодированный
  как в просмотре текстур и уменьшенный до 256, непрозрачный;
- **модель** — сетки метамодели (как раскрывает их уровень, самый
  подробный LOD) или одна сетка, загруженные как в просмотре моделей
  (`model_view::load_limited`: игровые поверхности, текстуры не шире 256),
  в 256×256 на прозрачном фоне; камера — та же, что в просмотре моделей по
  умолчанию (`OrbitCamera::framing`). Экземпляр `SceneRenderer` свой, на
  устройстве окна; если окно на OpenGL — на своём `wgpu`-устройстве
  (`GpuContext::headless`).

Кэш на диске — PNG по хэшу данных ресурса и версии рендера
(`preview::RENDER_VERSION`; поменяйте её, если меняется вид превью: старые
файлы не прочтутся и уйдут при чистке). Устройство кэша, ограничения и
замеры — `docs/shell.md` §11.7. Замер на своей машине:

```sh
EARS_GF2_DIR="$GAME" PREVIEW_BENCH_STREAM=gf2/cuba/local \
  cargo test --release -p doctor-toolkit-gui previews_of_a_large_stream -- --ignored --nocapture
```
