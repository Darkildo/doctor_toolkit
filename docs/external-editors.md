# Внешние редакторы

Этап 22, часть A. Ресурс открывается в другой программе (GIMP, Krita,
LibreOffice Calc, текстовый редактор, Blender), и каждое сохранение файла
само попадает в рабочее пространство. Дополнение Blender — `docs/blender.md`,
руководство пользователя — `docs/guide/12-external-editors.md`.

Код:

| Модуль | Что делает |
|---|---|
| `doctor_toolkit::external` (`external/mod.rs`) | форматы рабочих файлов, экспорт ресурса в файл и импорт файла в рабочее пространство |
| `external/csv.rs` | таблицы строк в CSV |
| `external/watch.rs` | когда сохранение готово к импорту: `ChangeDetector` (чистая логика) и `FileWatcher` (`notify` + проверка размера и времени файла) |
| `external/launch.rs` | запуск программы: разбор команды, `{file}`, программа рабочего стола |
| `external/link.rs` | `EditLink`: экспорт, слежение, импорт, склейка частых сохранений в одну операцию |
| CLI `edit_cmd.rs` | `doctor-toolkit edit` |
| GUI `external_view.rs`, `app/external.rs` | кнопка «Open in external editor» над просмотрщиками, опрос связей, строка состояния |

## 1. Что и в каком формате

| Ресурс | Форматы (первый — по умолчанию) | Импорт |
|---|---|---|
| текстура `tg4h`/`tg4d` | PNG (первый слой, без мипов), DDS (все мипы и слои) | как `texture-import`: PNG кодируется в формат оригинала с полной цепочкой мипов, DDS берётся как есть; слоёные текстуры (кубы, объёмы) — только DDS |
| таблица строк `lh2` | CSV, JSON (`text-export`) | меняются только тексты; новые хэши — ошибка (добавление строк — этап 18) |
| `simgroup`, `metamodel`, `variabledictionary` | JSON (`logic-export`) | как `logic-import`: пишутся только отличающиеся значения; файл другого ресурса (поле `id`) отвергается |
| скрипт `lua` | исходник Lua (декомпиляция) | компиляция компилятором этапа 16 с именем чанка и размером чисел оригинала; ошибка — с номером строки |
| `mesh`, `metamodel` | GLB (материалы, текстуры, скелет) | как `model-import` (замена на месте или новый набор, `--new`/`--retarget`); у metamodel экспортируется первый меш, импорт заменяет все меши |

Экспортируется версия рабочего пространства (если ресурс уже правился),
иначе — данные игры. Экспорт и импорт симметричны: неизменённый файл ничего
не записывает. Исключение — PNG: при импорте текстура кодируется заново (DXT
с потерями, новая цепочка мипов), поэтому «тот же» PNG дал бы новую
операцию; поэтому слежение импортирует только файл с **новым содержимым**
(§2).

**CSV.** Первая строка — `hash` и по столбцу на язык (код языка или `text`,
`text1`, …), дальше строка на запись: хэш (8 шестнадцатеричных цифр) и
тексты. Поля с запятой, кавычкой, переводом строки, `;`, табуляцией или
пробелом по краям — в кавычках (RFC 4180), строки разделены `\r\n`. При
чтении принимаются `;` и табуляция (разделитель определяется по первой
строке, как сохраняют Calc и Excel в разных локалях), метка BOM, любой
порядок строк и столбцов, пустые строки; можно оставить только нужные
строки.

## 2. Слежение за файлом

Рабочий файл лежит в своём каталоге
`$TMPDIR/doctor-toolkit-edit/<pid>/<поток>_<тип>_<id>/<имя>_<id>.<формат>`
(или в `--file-dir`). Наблюдается **каталог**, а не файл: GIMP, Krita,
LibreOffice и Blender сохраняют через новый файл и переименование поверх
старого, и наблюдение за самим файлом теряется вместе с его inode.

`ChangeDetector` получает события и решает:

1. событие (`notify`) или изменение размера и времени файла (проверяется
   при каждом опросе — запасной путь, если событий нет) помечает файл
   «изменён»;
2. файл читается, когда с последнего события прошло 400 мс тишины — серия
   записей даёт один импорт;
3. содержимое сравнивается (SHA-256) с последним экспортированным или
   импортированным: то же содержимое — «saved without changes», без
   импорта;
4. файла нет (между удалением и переименованием) — ждать до 5 с, дальше
   «the file was deleted» (слежение продолжается, следующее сохранение
   подхватывается);
5. недописанный файл (запись кусками с паузой) не разбирается импортом —
   ошибка показывается, слежение продолжается, следующая запись приносит
   полный файл и импортируется.

## 3. Одна операция на серию сохранений

`EditLink::import`: если операция предыдущего сохранения этой связи всё
ещё последняя в рабочем пространстве и была меньше 60 секунд назад
(`--coalesce`, у нового набора моделей — всегда), она отменяется, и новое
сохранение записывается вместо неё. Итог: правка в редакторе с десятком
сохранений — один шаг Ctrl+Z, и у нового набора модели клоны создаются
один раз. Если между сохранениями была другая правка, сохранение
записывается отдельной операцией. Неудачный импорт возвращает отменённую
операцию (`redo`).

После Undo файл не меняется сам: «Reload file» (GUI) или
`EditLink::refresh` записывает в него версию рабочего пространства.

## 4. Командная строка

```sh
T=doctor-toolkit
# текстура: PNG в GIMP; Ctrl+C — закончить
$T edit "$GAME" gf2/frontend:tg4h:00000000.4802e0a7.f3d257db.9cf57f36 --with "gimp {file}"
# таблица строк в CSV (программа из настроек или рабочего стола)
$T edit "$GAME" gf2/text/dd7d7050:0
# скрипт; без запуска программы, только слежение за файлом в своей папке
$T edit "$GAME" KEY --format lua --no-open --file-dir ./scripts
# модель в Blender (с дополнением); --wait — закончить, когда Blender закроется
$T edit "$GAME" KEY --format glb --wait \
  --with "blender --python-expr \"import bpy; bpy.ops.doctor_toolkit.link_open(filepath=r'{file}')\""
```

`KEY` — ключ ресурса (`поток:тип:ids`, как в поиске и в редакторе) или
`ПОТОК:НОМЕР`. Ключи: `--with CMD` (программа; `{file}` — файл, без него
файл добавляется последним аргументом; без ключа — `[external_editors]` из
настроек редактора, затем программа рабочего стола), `--format`,
`--file-dir`, `--no-open`, `--wait`, `--coalesce SECONDS`, для моделей
`--new NAME` и `--retarget INDEX`, а также `--direct` / `--workspace-dir`.
Сообщения: `imported: …` (с пометкой «replaces the previous save» при
склейке), `saved without changes`, `cannot import: …; still watching`.

Команда разбирается без оболочки: пробелы разделяют слова, кавычки
группируют, `\` экранирует.

## 5. Редактор

Над просмотрщиками текстуры, таблицы строк, логики, скрипта и модели —
строка **Open in external editor** (вид `external` в реестре,
`docs/viewers.md` §0) с выбором формата, если их несколько. Программа — из
Preferences → External editors (`image`, `model`, `text`; пусто — программа
рабочего стола). После открытия в строке — «Linked: <файл>», число
импортированных сохранений и последнее событие, кнопка **Unlink**. В строке
состояния — «Linked: N»: список связей, Unlink, Reload file (записать
версию рабочего пространства в файл), Show folder.

Сохранения импортируются в начале кадра (`BrowserApp::poll_external`);
поток событий будит окно (`request_repaint`), без событий файлы
проверяются раз в секунду. Импорт — обычная правка: просмотрщики
перезагружаются, Ctrl+Z отменяет, в прямом режиме изменения сразу пишутся в
игру. Связи живут до Unlink, открытия другой игры или закрытия окна; файлы
остаются на диске.

## 6. Проверки

| Тест | Что проверяет |
|---|---|
| `external::watch::tests` | серия записей — одно чтение после тишины; то же содержимое — не изменение; ожидание пропавшего файла; новое время и размер — событие |
| `external::csv::tests` | круговой путь с кавычками, переводами строк и кириллицей; `;`, BOM, другой порядок столбцов; ошибки с номером строки |
| `external::launch::tests` | разбор команды, `{file}` внутри слова и в конце |
| `external::tests` | на синтетической игре: экспорт → импорт без изменений не пишет ничего (DDS, CSV, JSON строк и логики, Lua); правки CSV, JSON, Lua (ошибка — со строкой), PNG; реальные файлы и `notify`: запись на месте, переименование поверх, удаление и новая запись, запись кусками, сохранение без изменений; склейка частых сохранений, отдельная операция после другой правки и после окна склейки, неудачный импорт не теряет предыдущий |
| CLI `tests/edit.rs` | `edit --with "sh fake-editor.sh {file}" --wait`: скрипт сохраняет CSV переименованием, на месте и без изменений — в рабочем пространстве одна операция с обеими правками, игра не тронута; Lua с ошибкой, затем исправленный — ошибка в выводе, в рабочем пространстве исправленный чанк |
| `tools/blender/run-tests.sh --cli` | `edit --format glb` с Blender в фоне как редактором: два сохранения — одна операция, сдвинутая вершина в рабочем пространстве (`docs/blender.md` §5) |

Настоящие редакторы (GIMP, Krita, Blender с окном) тесты не запускают:
вместо них — скрипт или Blender в фоновом режиме.

Снимок окна во вложенном Xephyr (`docs/viewers.md` §5) с
`DOCTOR_TOOLKIT_GUI_EXTERNAL=png`, программой `true` в настройках и
скриптом, который дважды сохраняет полосатый PNG переименованием поверх
рабочего файла: строка «Linked: road_texture02_c_a0688794.png», «2 save(s)
imported», в панели Changes одна операция («replaces the previous save»),
просмотрщик показывает оригинал и новую текстуру рядом.
