# Сверка форматов с файлами The Godfather II (PC)

Редакция от 2026-11-11. Корпус: установленная игра, 2300 файлов `.str` и 25 файлов
`.toc`, плюс 4 оригинала в `<игра>/_toolkit/backups/`. Всего 212 544 ресурса,
2,98 ГБ распакованных данных.

Каждый факт ниже проверен на всём корпусе: скриптами из `research/` и корпусными
тестами `crates/doctor-toolkit/tests/corpus.rs`. Исправленное описание форматов —
в `docs/formats/stream.md` и `docs/formats/toc.md`.

> Корпус не чистый: на игру установлены пять патчей старого тулкита (`.vpat`).
> Ими изменены `gf2/globals_global.str`, `gf2/frontend.str`,
> `gf2/miami/local.str`, `gf2/queens/local.str`.

## 1. Итог по исходной спецификации

| Утверждение спецификации | Результат |
|---|---|
| Godfather использует RwStream, UStream — только Dead Space | **Неверно для GF2.** Все файлы — UStream |
| Заголовок UStream: «поля A/B», `version`, `platform_id`, `section_count` | **Неверно**, см. §2 |
| Блок UStream — запись 0x18 байт с u64-указателем | **Неверно для диска**, это раскладка в памяти |
| `SHDR`: u32, u16, u16, u32, флаг строк, три строки | **Неверно для GF2**, см. §3 |
| RefPack: заголовок и пять классов опкодов | **Подтверждено**: 146 544 блока `Rpak` распакованы в заявленный размер |
| Сжатые данные: `[u32 size][payload]` | **Подтверждено** |
| LZX (`LZXD`) | **Не встречается** в GF2 |
| TOC: magic `0x9CBAB728` | **Неверно.** Магия `0x9CBA7B28` |
| TOC v10: записи 20 байт, имена с встроенной строкой | **Частично**, см. §4 |
| Идентификаторы типов — SDBM | **Подтверждено** для всех 43 типов |
| Хэш имён в TOC — SDBM | **Неверно.** Это свёртка GUID потока, см. §4 |
| Хвост файла — чанк `FILL` | **Подтверждено**; `FILL` закрывает каждую страницу |
| «Без пересчёта TOC игра падает» | **Не подтверждено**, см. §5 |

## 2. UStream на диске

Заголовок, 12 байт, одинаков во всех файлах:

| Смещение | Размер | Значение | Смысл |
|---|---|---|---|
| +0x00 | 4 | `3slo` | magic |
| +0x04 | u32 | `0x0C` | смещение первого блока |
| +0x08 | u16 | `2` | версия |
| +0x0A | u16 | `3` | не установлено |

Далее плоская последовательность блоков.

| Блок | Раскладка |
|---|---|
| `SHOC` | `"COHS"`, u32 размер с заголовком, u32 подтип, тело |
| `FILL` | `"LLIF"`, u32 размер с заголовком, нули |

**Страницы.** Файл состоит из страниц по 0x20000 байт; его длина кратна странице.
Ни один из 445 979 блоков не пересекает границу страницы. Размер каждого блока
кратен 4.

**Правило размещения**, восстановленное по корпусу: блок кладётся в текущую
страницу, если заканчивается ровно на её границе или оставляет не меньше 8 байт
под заголовок `FILL`. Иначе остаток страницы закрывается блоком `FILL`.
Перекладка всех блоков по этому правилу воспроизводит побайтно все 2299
непропатченных файлов и все 4 оригинала. Расходится только `globals_global.str`,
переписанный старым тулкитом.

**Ресурс** — блок `SHDR` и следующие блоки данных до следующего `SHDR`.
Распакованные тела конкатенируются.

- `SDAT`: сырые данные, дополненные нулями до кратного 4.
- `Rpak`: `u32 compressed_len`, поток RefPack с заголовком `10 FB`, нули до кратного 4.
  Наибольший распакованный кусок — 1 763 849 байт.

Сумма распакованных кусков превышает размер из `SHDR` не более чем на 3 байта.
Исключение — один ресурс `vfx` в `globals_global.str`: патч «Improved Effects»
дописал 16 нулевых байт, не изменив размер.

## 3. Блок `SHDR` (тело 0x20 байт)

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | политика памяти: SDBM от имени |
| +0x04 | u32 | выравнивание: `0x10`, `0x20`, `0x40`, `0x80` или `0x1000` |
| +0x08 | u32 | `type_id`: SDBM от тега типа |
| +0x0C | 4 × u32 | идентификаторы |
| +0x1C | u32 | размер распакованных данных |

Политики: `default` (`0x5393AC01`), `volatile` (`0x67456B5C`), `geometry`
(`0x38B2B8D2`). Ещё три значения не названы: `0x67A6002E` у `meshvolatile`,
`0x7A10372B` у `sbk`, `0x58B1F4D8` у `auc`.

Идентификаторы — 128-битный GUID ресурса, ключ общей таблицы загруженных
ресурсов (`0x00421170`). У большинства типов это id × 4; у `tg4h` и `tg4d` —
`0, type_id, хэш пакета, хэш имени`; у `meshvolatile` — дополнение id меша;
у `graph` и `materialswaplistresource` — настоящий GUID с логином автора.
Политика и выравнивание у каждого типа одни. См. `new-resources.md`.

Уникальность. Тройка (имя потока, `type_id`, четыре идентификатора) различна у
всех 212 544 ресурсов; на ней построен ключ рабочего пространства
(`docs/workspace.md` §1, тест `resource_keys_are_unique_and_round_trip`).
Одного `ids[3]` вместо четырёх не хватает: 311 совпадений внутри потоков, в
основном у `graph` и `materialswaplistresource`, где идентификаторы не равны.

Таблица типов строится командой `doctor-toolkit types <игра> --markdown`.
Имена 41 типа восстановлены перебором SDBM по строкам из `godfather2.exe` и
коротким строкам; они лежат в `data/gf2/type_tags.txt`. Последние два —
`covernodetable` (`0xDF14DA75`, 682 ресурса) и `treemodel` (`0xCDB9D42B`, 432
ресурса) — названы на этапе 40 вместе с типами ссылок metamodel `hka` и `emx`.

## 4. StreamTOC версии 10

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | magic `0x9CBA7B28` |
| +0x04 | u32 | версия `10` |
| +0x08 | u16 | число файловых записей |
| +0x0A | u16 | число записей имён |
| +0x0C | u16 | число слов зависимостей |
| +0x0E | u16 | `0` |
| +0x10 | 20 × N | файловые записи |
| далее | 8 × M | записи имён: u32 хэш, u32 смещение строки |
| далее | 4 × K | слова зависимостей: смещения записей имён |
| далее | | пул строк: один NUL, затем имена через NUL |
| далее | | нули до кратного 0x800 |

Файловая запись, 20 байт:

| Смещение | Размер | Поле |
|---|---|---|
| +0x00 | u32 | смещение записи имени |
| +0x04 | u32 | сумма распакованных размеров всех ресурсов потока |
| +0x08 | 4 × u8 | флаги; зависимостей `f[0] + f[1] + (f[2] & 1)` |
| +0x0C | u32 | `0` |
| +0x10 | u32 | смещение первого слова зависимостей |

Подтверждения:

- запись TOC обратно даёт побайтно тот же файл для всех 25 таблиц;
- поле размера совпадает с суммой размеров ресурсов для всех непропатченных
  потоков и для оригиналов из резервных копий;
- каждое имя из файловых записей соответствует файлу `.str` на диске;
- имена записей, на которые нет файловых записей, — внешние ссылки: на
  `gf2\globals_global` с хэшем 0 и на исходный путь сборки
  `x:\build\win\ntsc_en\assets\...`.

**Хэш имён** — свёртка 128-битного GUID потока, а не хэш строки. Найден в
`godfather2.exe` через Ghidra (`0x004A82B0` — свёртка и поиск записи; отдельной
функцией — `0x00401F40`): `((a*33 + b)*33 + c)*33 + d` по
четырём little-endian словам GUID. Поиск 16-байтных окон в распакованных
ресурсах воспроизвёл 3 587 из 4 286 ненулевых записей; GUID остальных не
встречаются в данных `.str`. Записи отсортированы по хэшу во всех 25 таблицах.
Поле размера потока игра использует для бюджета памяти потоковой загрузки.

## 4а. Текстуры TG4

Все 28 246 пар `tg4h`/`tg4d` разобраны: заголовки записываются обратно побайтно,
размер данных совпадает с цепочкой уровней для каждого формата, экспорт в DDS
и обратное чтение не теряют данных. Декодирование BC1/BC3 совпало с PIL на
выборке из 12 текстур. Раскладка — `docs/formats/resource-types.md` §1.

## 5. Проверка в игре под Wine

Префикс: `~/.local/share/doctor_toolkit/wine-gf2`, Wine 9.0, 32 бит.
Критерий успеха — игра проходит заставки и титульный экран и открывает меню
выбора профиля. Опыты этой таблицы шли на основном дисплее; с 2026-11-12
проверка идёт на стенде `tools/game-bench.sh` (вложенный X-сервер, теневой
каталог игры), см. `game-bench.md`.

| Опыт | Результат |
|---|---|
| Исходные файлы | Меню профиля открывается |
| `frontend.str` целиком переписан, все 47 ресурсов сжаты компрессором тулкита | Меню профиля открывается |
| В 7 ресурсов `apx` дописан блок `alig` на 16 байт, размер в заголовке APX исправлен, оба TOC обновлены | Меню профиля открывается |
| В 7 ресурсов `apx` дописаны 16 нулевых байт без правки заголовка APX | Игра зависает при запуске |
| Новый поток `gf2/text/doctor_en` с клоном таблицы `lh2` под новым GUID, записи в трёх TOC, `lhr` направлен на него (этап 5, стенд) | Титульный экран и меню показывают строки нового потока |
| То же без записей в TOC | То же: поток найден по имени, см. `new-resources.md` §3.3 |
| Стенд: `text-import` строк титульного экрана и меню профиля | Новые строки на экране |
| Стенд: `texture-import` PNG атласов шрифтов `frontend.str` | Изменённые глифы на экране |

Выводы:

- запись контейнера и TOC тулкитом принимается игрой;
- APX проверяет свой внутренний размер, и это надо учитывать при правке;
- игра работает с устаревшими размерами в TOC: старый тулкит оставил их
  заниженными до двух раз, а игра под Wine доходит до меню. Насколько поле важно
  при загрузке уровней, не проверено.
