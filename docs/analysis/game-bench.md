# Стенд проверки в игре

Редакция от 2026-11-12. Скрипт: `tools/game-bench.sh`, помощник
`tools/hidden-parent.py`. Стенд запускает The Godfather II (PC) под Wine на
теневой копии каталога игры, ведёт её по меню и снимает экран. Экран и ввод
пользователя не задействованы, файлы игры не меняются.

## 1. Устройство

| Часть | Решение |
|---|---|
| X-сервер | `Xephyr -parent <окно>`. Окно-родитель создаёт `hidden-parent.py` на основном дисплее и никогда не отображает (`IsUnMapped`). На рабочем столе ничего не появляется, ввод основного дисплея не используется. `-parent` стоит перед `-screen`: до 2026-11-13 он шёл после, и Xephyr заводил второй экран для родителя, а первый — тот, где игра, — показывал отдельным окном на основном дисплее (найдено в этапе 33, исправлено). Снимки берутся из буфера самого Xephyr (`ffmpeg -f x11grab -i :N`). `VISIBLE=1` показывает окно для отладки |
| Графика | Программная: Mesa llvmpipe через GLX Xephyr, D3D9 игры — wined3d. Видеокарта хоста не нужна |
| Окна Wine | Виртуальный рабочий стол Wine размером с экран Xephyr (`HKCU\Software\Wine\Explorer`). Смена режима игрой остаётся внутри него, оконный менеджер не нужен |
| Префикс Wine | Отдельный префикс стенда, копия `~/.local/share/doctor_toolkit/wine-gf2` (588 МБ). Создаётся при первом запуске, см. §3 |
| Домашний каталог Wine | `ПРЕФИКС/bench-home` с каталогами XDG внутри: команды Wine стенда не видят `~/Документы` пользователя, §3 |
| Каталог игры | Теневой каталог, см. §2 |
| Остановка | `wineserver -k` только для префикса стенда, затем `Xephyr` и окно-родитель. Срабатывает и при ошибке, и по Ctrl+C |

Готовность дисплея и его номер Xephyr сообщает через `-displayfd`, поэтому
номер выбирается автоматически и не конфликтует с занятыми.

## 2. Теневой каталог

`tools/game-bench.sh shadow ИГРА ТЕНЬ [ОТН_ПУТЬ...]`:

- каталоги создаются настоящими, не ссылками: запись внутрь тени никогда не
  попадёт в каталог игры;
- `.str`, `.viv`, `.vp6`, `.vpat` и файлы больше 16 МБ — символические ссылки на
  оригиналы (2371 ссылка);
- всё остальное копируется (1380 файлов, 84 МБ): `godfather2.exe`, DLL, `.ini`,
  все `.toc`. Игра со скрипт-хуком пишет в свой каталог (`GF2_Hook.txt`,
  `imgui.ini`), запись через ссылку изменила бы оригинал;
- перечисленные `ОТН_ПУТЬ` (например `gf2/frontend.str`) копируются до правки;
- хэши sha256 оригиналов всех `.toc` и перечисленных файлов пишутся в
  `ТЕНЬ/.game-bench/originals.sha256`.

Повторный вызов пересоздаёт тень с нуля; каталог без метки
`.game-bench/shadow` удалять скрипт отказывается. Создание занимает 5 с.

`tools/game-bench.sh verify ИГРА ТЕНЬ` сверяет хэши оригиналов и перечисляет
файлы `.str`, которые в тени стали настоящими файлами.

Тулкит безопасен и для ссылок: `GameInstance::write_with_backup` пишет во
временный файл рядом и переименовывает его, а `rename` заменяет саму ссылку,
не трогая её цель. Резервная копия читает файл через ссылку и ложится в
`ТЕНЬ/_doctor_toolkit/backups/`. Явное копирование целевых файлов оставлено как
вторая защита.

## 3. Префикс стенда

Копия базового префикса с четырьмя отличиями:

1. **Папки пользователя внутри префикса.** Wine делает `Documents`, `Desktop`,
   `Music` и другие ссылками на домашний каталог (`~/Документы`). Профили и
   сохранения игры лежат в `Documents/EA Games/<название игры>/`, и в общем
   префиксе это настоящие профили игрока. В префиксе стенда все ссылки из
   `drive_c` наружу (и вложенные, например `AppData/Roaming/Microsoft/Windows/Templates`)
   заменяются пустыми каталогами — при создании префикса, перед каждым
   запуском и после него (`sanitize_prefix`; найденная после запуска ссылка
   пишется в `timeline.txt` как `WARNING`).
2. **Домашний каталог внутри префикса** (этап 14). Одной замены ссылок мало:
   при создании профиля игра просит папку профиля через
   `SHGetFolderPathAndSubDir(CSIDL_PERSONAL | CSIDL_FLAG_CREATE, "EA Games\<игра>\<номер профиля>")`,
   и Wine создаёт **эту папку** (`…/Крестный отец™ II/2453306352`) ссылкой на
   каталог документов XDG домашнего каталога, то есть на `~/Документы`. Так
   на этой машине и устроена настоящая игра: сохранения игрока
   (`GF2-EN-autosave`, `GF2-EN-<число>`) лежат прямо в `~/Документы`. На
   первом прогоне этапа 14 стенд создал профиль, игра сделала такую ссылку и
   увидела в меню «Choose a saved game to load» сохранения игрока; запись не
   случилась (время изменения файлов в `~/Документы` проверено, новее начала
   опытов нет ни одного), ссылка удалена. Теперь все команды Wine стенда
   идут с `HOME=ПРЕФИКС/bench-home` и `XDG_CONFIG_HOME` с `user-dirs.dirs`,
   где все каталоги XDG — внутри `bench-home`: ссылка профиля ведёт в
   `bench-home/Documents`, сохранения игры ложатся туда. Проверено: после
   этого ссылка профиля указывает внутрь префикса.
3. **Звук выключен** (`HKCU\Software\Wine\Drivers`, `Audio=""`); с
   `AUDIO_CAPTURE=1` включается на один прогон и пишется в файл, §12.
4. **Адаптер NVIDIA.** Под llvmpipe игра останавливается окном «Your Graphics
   Card does not meet The Godfather™ II minimum requirements». Значения
   `VideoPciVendorID=0x10de`, `VideoPciDeviceID=0x0402` (GeForce 8600 GT),
   `VideoMemorySize=1024` в `HKCU\Software\Wine\Direct3D` проверку проходят.

Перед игрой стенд один раз поднимает рабочий стол (`wine cmd /c exit`). Без
этого при первом запуске в новом префиксе игра однажды показала то же окно о
видеокарте.

## 4. Ввод

- Курсор меню игра ведёт по **относительным** движениям (DirectInput), а Wine
  после каждого движения возвращает указатель X в центр экрана. Абсолютных
  координат у курсора игры нет. Один пиксель указателя сдвигает курсор игры
  на 2 пикселя, курсор упирается в края экрана.
- Поэтому щелчок в точку `x,y` экрана игры (`CLICKS`, режим `relative`)
  делается так: движение в `0,0` загоняет курсор в левый верхний угол, затем
  движение в `центр + (x, y) / CURSOR_GAIN`, затем нажатие.
- Кнопка и клавиша удерживаются `HOLD` = 0,4 с: игра опрашивает ввод раз в кадр,
  а программный рендер даёт мало кадров.
- `CLICK_MODE=absolute` — обычное перемещение указателя, для окон Windows вне
  игры.

## 5. Использование

```sh
GAME="/path/to/The Godfather II"
T=./target/release/doctor-toolkit
S=/tmp/bench

tools/game-bench.sh shadow "$GAME" $S/shadow gf2/frontend.str
$T texture-import $S/shadow gf2/frontend impact_lt_std new.png
KEYS="52:Return" SHOTS="50 60" DURATION=65 \
    tools/game-bench.sh run $S/shadow $S/out
tools/game-bench.sh verify "$GAME" $S/shadow
```

Переменные `run`: `DURATION`, `SHOTS`, `CLICKS`, `KEYS`, `MOVES`, `HOLD`,
`CLICK_MODE`, `CURSOR_GAIN`, `SIZE`, `BENCH_PREFIX`, `BASE_PREFIX`,
`HOST_DISPLAY`, `VISIBLE` — описание в начале скрипта.

Результат в каталоге `OUT`: `shot_NN_TTTs.png`, `timeline.txt` (время каждого
события и снимка, итог `status: running` или `exited after Ns`), `wine.log`,
`xephyr.log`, `processes.txt`.

### 5.1 Сценарии, сеансы и ожидание экрана (этап 14)

Время загрузок на программном рендере плавает в разы (другие процессы
машины), поэтому до уровня стенд идёт не по секундам, а по экрану.

| Команда | Что делает |
|---|---|
| `play ТЕНЬ OUT СЦЕНАРИЙ` | запускает игру и выполняет шаги файла (по одному в строке, `#` — комментарий); первый неудачный шаг останавливает прогон (`status: failed at …`) |
| `start ТЕНЬ OUT` | запускает игру и оставляет её работать (не дольше `SESSION_MAX`, 3600 с) |
| `do OUT ШАГ [АРГ…] [-- ШАГ …]` | шаги в запущенной игре: так сценарий подбирается вживую |
| `stop OUT` | останавливает игру сеанса |
| `saves КАТАЛОГ` | копирует профили и сохранения префикса стенда; `SAVES=КАТАЛОГ` при запуске подставляет их |
| `ref PNG ИМЯ X,Y,W,H` | вырезает из снимка эталон для `await` |
| `ahead OUT N [DY] [ВПРАВО]` | точка в N м перед игроком (по `OUT/pos.txt` шага `pos`), DY м выше и ВПРАВО м правее — `X,Y,Z` для `level add --position` (этап 24) |

Шаги: `shot [ИМЯ]`, `key КЛАВИША…`, `hold КЛАВИША СЕКУНДЫ` (ходьба),
`type ТЕКСТ`, `click X,Y`, `move X,Y`, `look DX,DY [N]` (поворот камеры),
`wait СЕКУНДЫ`, `until СЕКУНДЫ` (от запуска игры), `ref ИМЯ X,Y,W,H` (эталон
с экрана), `await ИМЯ [ТАЙМАУТ] [ДОПУСК]` — ждать, пока участок экрана не
совпадёт с эталоном (`!ИМЯ` — пока не перестанет совпадать), `seek ИМЯ
КЛАВИША [N] [СЕКУНДЫ]` — нажимать клавишу, пока эталон не совпадёт (выбор
пункта меню; `!ИМЯ` — пока экран не сменится, то есть повторять пропущенное
нажатие; СЕКУНДЫ — сколько держать клавишу, в меню паузы поверх уровня
нужно 0,7 с).

Шаги этапа 24 (координаты игрока, нужен `MEMORY=1`, §13.2): `find X,Y,Z
[ДОПУСК]` — найти матрицы игрока там, где его ставит сохранение; `track
X,Y,Z [РАДИУС] [КЛАВИША] [СЕКУНДЫ]` — найти их, пройдя вперёд; `pos` —
положение и направление игрока в `OUT/pos.txt`; `walk КЛАВИША МЕТРЫ
[ТАЙМАУТ]` — идти, пока игрок не пройдёт МЕТРЫ, не упрётся или не выйдет
время (путь — в `OUT/walk.txt`).

Эталон — участок экрана в оттенках серого (`REFS`, по умолчанию
`~/.local/share/doctor_toolkit/bench-refs`, файлы `ИМЯ.gray` и `ИМЯ.area`);
совпадение — средняя разница яркости не больше 12 из 255. Снимки игры в
репозиторий не входят: эталоны делаются на своей машине из снимков сеанса
(`do OUT shot …`, затем `ref`). Разница на снимках этапа 14: совпадающие
экраны 0–7, соседние экраны 20–117.

| Эталон | Участок | Экран |
|---|---|---|
| `title` | 680,580,250,40 | «Press any key» титульного экрана |
| `profiles` | 180,120,200,45 | заголовок «Select Profile» |
| `profile-name` | 180,135,260,40 | «Enter Profile Name» |
| `autosave` | 280,325,460,35 | «Autosave is now turned on…» |
| `menu` | 100,350,150,70 | пункты «Options», «Unlocks» главного меню |
| `new-game-selected` | 100,315,130,32 | выделенный (оранжевый) пункт «New Game» |
| `character` | 60,515,340,90 | «Customize the look of your character…» |
| `hud` | 45,48,28,22 | «$0» над полоской здоровья в игре |
| `resume-selected` | 100,240,180,32 | выделенный пункт «Resume Game» (профиль с сохранением, этап 24) |
| `pause` | 100,70,300,90 | заголовок «PAUSE MENU» |
| `pause-save` | 190,340,80,30 | выделенный пункт «Save» меню паузы |

Прочие переменные: `GAP` — пауза между клавишами шага (0,3 с), `TAP` —
нажатие в `seek` (0,15 с: в меню удержанная клавиша повторяется),
`TRACE_FILES=1` — `strace` всех открытий файлов игрой в `OUT/files.trace`
(какие потоки грузит уровень).

## 6. Сценарий до меню и время

Префикс стенда, 1024×768, llvmpipe. Время от запуска `wine`:

| Время, с | Экран |
|---|---|
| 5 | Копирайт |
| 10–25 | Заставки Paramount и EA |
| 30 | Логотип The Godfather II |
| 35–50 | Титульный экран «Press any key» |
| 52 | Стенд нажимает `Return` |
| 55 и далее | Меню «Select Profile» с кнопкой «Create Profile» |

Прогон в 80 с занимает 82 с вместе с запуском и остановкой. Пять запусков
подряд на новом префиксе дошли до логотипа без ошибок.

### 6.1 До уровня (этап 14)

Сценарии `tools/bench/new-profile.txt` (префикс без профилей: создать
профиль `bench`) и `tools/bench/new-game.txt` (профиль из `SAVES`, без
сохранений) ведут игру до первого управления в уровне. Путь:

1. Заставки Paramount и EA **не пропускаются** (`Escape`, `Return`, `space`
   на них не действуют); титульный экран — на 48–55-й секунде.
2. «Press any key» → `Return`; «Select Profile» → `Return` выбирает первый
   профиль (новый — щелчок по «Create Profile», имя `type bench`, щелчок по
   «Accept»); окно «Autosave is now turned on» → `Return`.
3. Главное меню **не принимает щелчков мыши**, только клавиши. Без сохранений
   «Resume Game» серый и выделен «Play Online»; удержанная 0,4 с клавиша
   повторяется, поэтому `seek new-game-selected Down` нажимает `Down` коротко,
   пока не выделится «New Game», затем `Return`.
4. Загрузка, ролик-титры (не пропускается), экран внешности персонажа
   (`Tab` — принять). Надпись «Customize…» появляется раньше, чем экран
   принимает ввод: `seek !character Tab` нажимает `Tab`, пока надпись не исчезнет.
5. Вступительная сцена на движке (Куба, 31 декабря 1958 г., терраса отеля,
   сегменты `igc01_s01…s15` потока
   `gf2/cuba/global/objectives/cp_010_030_mission_1/cp_009/…`) — **не
   пропускается** ни `Escape`, ни `space`, ни `Return`, ни удержанием 2,5 с.
6. Управление: та же терраса ночью, подсказка «TALK: Press E…», `$0` и
   полоска здоровья (`hud`). Ходьба — `hold w/a/s/d СЕКУНДЫ`, поворот камеры —
   `hold Left/Right`; относительное движение мыши (`look`) камеру не
   поворачивает.

Время (1024×768, llvmpipe, машина с 32 потоками, загруженная сборками других
агентов, средняя нагрузка 9–25):

| Событие | Прогон без правок | Прогон A |
|---|---|---|
| титульный экран | 48 с | 49 с |
| главное меню | 53 с | 54 с |
| экран внешности | 201 с | 159 с |
| управление в уровне (`hud`) | 845 с | см. §10 |

Вступительная сцена идёт ~10 минут вместо ~3: программный рендер даёт
1,4 кадра/с при нагрузке ~20 (подсчёт разных кадров `ffmpeg … mpdecimate`
за 10 с), а сцена идёт по кадрам. Сохранения на этом месте нет: игра
сохраняется позже (за 4 минуты на террасе не появилось ни одного файла
сохранения), поэтому каждый прогон проходит сцену заново — ~15 минут до
уровня, прогон с проверкой ~17 минут.

Какие потоки грузит уровень, показал `TRACE_FILES=1` (86 потоков к
появлению управления): глобальные (`globals_global`, `cuba*`, `miami*`,
`queens*`, `allcharacters`), `c01_001_folderstream` (ролик и внешность),
`cp_009_hotel_interior_folderstream` и его `igc01_s*`, `gf2/cuba/local` и
зоны района `xenia` (`high/business_019`, `interior/business_019_balcony`,
`high/terrain11…14`, `filler_*`, `medium/zone3…8`, `low/zone1` всех районов),
`sky`, `ocean`.

## 8. Найденные проблемы стенда

| Симптом | Причина | Решение |
|---|---|---|
| Окно «Your Graphics Card does not meet ... minimum requirements» | Под llvmpipe wined3d сообщает программный адаптер | Адаптер NVIDIA в реестре префикса, §3 |
| «Unable to find your profile, please try again» вместо меню профиля | Стенд запускал Wine с `LC_ALL=C`. Wine переводит имена файлов в кодировку локали, в ASCII нет `™`, и игра не может создать `Documents\EA Games\The Godfather™ II` (`err:shell:SHGetFolderPathAndSubDirW Failed to create directory`) | Стенд меняет только `LC_NUMERIC`, кодировка остаётся UTF-8 |
| Под `LC_ALL=C` перед заставками появляется окно выбора языка мода (English/Russian) | То же | Под UTF-8-локалью окна нет; щелчок по «English» — `CLICKS="13:540,332"` |

## 12. Запись звука (`AUDIO_CAPTURE=1`)

Для проверки звука стенд включает драйвер Wine `alsa` (значение `Audio`
ставится перед каждым прогоном: `alsa` или пусто) и даёт ALSA собственную
конфигурацию `OUT/asound.conf` через `ALSA_CONFIG_PATH`:

```text
pcm.!default { type file; slave.pcm "bench_null"; file "OUT/audio.wav"; format "wav" }
pcm.bench_null { type null }
```

Системная конфигурация ALSA при этом не читается вовсе, поэтому устройство
по умолчанию не может уйти на звуковую карту, PulseAudio или PipeWire;
`PULSE_SERVER` и `PIPEWIRE_REMOTE` указывают в никуда. Результат —
`OUT/audio.wav`, 48 кГц, стерео, 32 бит. Заголовок WAV не дописывается, если
игру останавливают (размеры 0) — читать как сырые данные после `data`.
Устройство `null` не держит темп, поэтому время в записи растянуто
относительно реального; звук опознаётся по спектру (чистые тоны) или
корреляцией с декодированными дорожками игры: `tools/bench/audio_tones.py
OUT/audio.wav 1000 1930` (доля энергии тонов по секундам) и
`tools/bench/audio_match.py OUT/audio.wav ref1.wav …` (какая дорожка звучит;
нужен numpy). Результаты опытов — `docs/formats/audio.md` §10.

`TRACE_FILES=1` с `TRACE_SYSCALLS=openat,pread64,…` расширяет журнал strace
(например, чтобы увидеть, какие архивы открываются).

Замечание по вводу (этап 15): шаг `key` держит клавишу `HOLD` = 0,4 с, и в
главном меню одно нажатие Down сдвигает выбор на **два** пункта (игра видит
повтор). Для меню — `seek` (держит `TAP` = 0,15 с, до совпадения с образцом)
или `HOLD=0.15`; остальные экраны (титульный, профиль, Tab в редакторе
персонажа) с `HOLD=0.15` тоже срабатывают.

### 13.1 Сохранение после пролога

В меню паузы (`Escape`) есть пункт **Save** (пятый: History Log, Tutorials,
Online, Options, Save, Quit, Quit to Windows). На террасе сразу после
вступительной сцены он сохраняет без выбора ячейки: файл
`GF2-EN-766744105283785153800800` (272 740 байт) появился в папке профиля,
то есть в `bench-home/Documents` префикса (папка профиля — ссылка внутрь
префикса, §3). Меню паузы поверх уровня видит клавишу, только если держать
её ~0,7 с (`seek pause-save Down 8 0.7`, `hold Return 0.7`): 0,15–0,4 с
пропускаются через раз.

Порядок (один раз на префикс):

```sh
SAVES=<профиль без сохранений> tools/game-bench.sh play ТЕНЬ OUT tools/bench/save-terrace.txt
tools/game-bench.sh saves ~/bench-saves/terrace        # профиль + сохранение
SAVES=~/bench-saves/terrace tools/game-bench.sh play ТЕНЬ OUT tools/bench/resume.txt
```

`resume.txt`: титульный экран → профиль → «Autosave is now turned on» →
главное меню, где с сохранением выделен **Resume Game** (эталон
`resume-selected`) → `Return` → терраса. Под нагрузкой игра иногда
пропускает нажатие, поэтому каждое нажатие повторяется, пока экран не
сменится (`seek !ИМЯ`). Фон главного меню меняется от запуска к запуску,
эталон берёт только пункт меню.

| Прогон | Нагрузка машины | Титульный экран | Управление (`hud`) |
|---|---|---|---|
| новая игра (этап 14) | 9–25 | 48 с | 845 с |
| новая игра, этап 24 (`run1`) | 4–24 | 41 с | 751 с |
| сохранение, `c0` | ~4 | 40 с | **67 с** |
| сохранение, `run2` | ~10 | 41 с | 161 с |
| сохранение, прогоны со стенами | 45–60 | 54–128 с | 190–250 с |

Загрузка сохранения ставит игрока **в одно и то же место с точностью до
миллиметра**: (179,410; 21,165; −25,438), лицом к перилам (−0,574; −0,819),
камера в (182,23; 22,886; −21,987); Майкл — в (176,651; 21,176; −26,838).
Это не `SpawnPoint` 14/16 (186,4; 21,2; −21,6), которые прежде считались
местом появления (§10.2): до них 7,9 м.

### 13.2 Координаты игрока: чтение памяти игры

Выбран способ без изменения игры: стенд читает память процесса.
`godfather2.exe` (0x00550d30, точка, которую использует таблица Cheat Engine
из `scripts/` каталога игры) берёт положение игрока из мировой матрицы
4×4: строки — правый вектор, верх, вперёд, перенос (`+0x30`, `+0x34`,
`+0x38`), четвёртый столбец 0, 0, 0, 1. Скрипт-хук `GF2ASI.asi` показывает
то же в своём окне ImGui («Position: %f %f %f»), но он меняет игру
(`dinput8.dll`) и требует мыши — не используется.

- Ядро (Yama `ptrace_scope=1`) даёт читать память только потомков, поэтому
  при `MEMORY=1` игра запускается дочерним процессом
  `tools/bench/gamemem.py serve OUT/mem.sock -- wine godfather2.exe`; шаги
  стенда спрашивают его через сокет. Память только читается.
- `scan X,Y,Z R`: все матрицы (16 float, выравнивание 16, единичные
  ортогональные строки, столбец 0,0,0,1) с переносом в радиусе R —
  0,5 с на ~1,5 ГБ памяти процесса (numpy).
- Матриц игрока много: 40–75 копий (отрисовка, физика, анимация), часть
  остаётся на месте появления. `find` берёт вертикальные матрицы
  (верх = (0, 1, 0)) в точке, куда ставит сохранение; `pos` при первом
  движении оставляет только сдвинувшиеся копии и отбрасывает те, что
  «прыгнули» дальше 20 м (память, занятая чем-то другим), и берёт самую
  большую группу копий в одном месте. `track` для мест без известной
  точки: две выборки до и после ходьбы, игрок — самая большая группа
  вертикальных матриц, сдвинувшихся вдоль своей оси «вперёд» (камера —
  наклонная группа, она следует за игроком в 4,5 м сзади и 1,7 м выше).
- Направление: третья строка матрицы игрока — куда он смотрит.
- `walk КЛАВИША МЕТРЫ`: темп игры следует частоте кадров (1–2 кадра/с под
  нагрузкой), поэтому одинаковое `hold a 5` проводит игрока на 0,06 м в
  одном прогоне и на 0,9 м в другом. `walk` держит клавишу и опрашивает
  положение раз в секунду, пока игрок не пройдёт нужное расстояние, не
  упрётся (меньше 0,15 м за 6 замеров после 15 с) или не выйдет время.
  Путь — в `OUT/walk.txt`. Путь от точки сохранения по `a` повторяется в
  прогонах до сантиметра.
- `tools/game-bench.sh ahead OUT N [DY] [ВПРАВО]` — точка перед игроком для
  `level add --position`. Правая сторона экрана — (−dz, dx) от направления
  взгляда (dx, dz); поворот `simgroup-set --rotation 0,θ,0` переводит
  локальную ось X в (cos θ, 0, −sin θ).

Что видно из точки сохранения: «белый стол» справа — это тележка
обслуживания номеров (`Destructible` 97 группы
`cp_010_hotel_interior_zonestream` № 89, metamodel `daa0769a`, меш
`room_service_cart01`, 1,4 × 1,1 × 0,9 м, с пачкой тарелок — дочерний
metamodel `8f4187f6`), а не статическая модель зоны, как считалось в §10.

окружение; `DURATION`, по умолчанию 70 с, потом игра останавливается).

```sh
doctor-toolkit play ТЕНЬ --method command \
    --command 'tools/bench/play-command.sh {dir}' --apply --revert-after
```

В рабочем пространстве тени `s21` — новая строка `doctor_play` («PLAY TEST:
APPLIED BY DOCTOR-TOOLKIT», `text-add`) и ссылка `$fe_press_start` →
`$doctor_play` в `frontend.apx` (`apx-text-refs`), не применены.

| Шаг | Вывод `play` | Проверка |
|---|---|---|
| запись | `applied: 5 stream(s) written, 17 file(s)` | — |
| запуск | `started`, `the game is running (process …)` | на титульном экране «PLAY TEST: APPLIED BY DOCTOR-TOOLKIT» (`results/s21-play-applied-title.png`) |

видит **любой** `godfather2.exe` на машине, а в это время другой агент

закрылась. Для одного пользователя это верно (вторая копия игры держит те же
файлы), для стенда рядом с другими — нужно учитывать.

## 16. Этап 32: быстрый вход без сохранения (`GAME_OPTIONS`)

Игра читает свои флаги не из командной строки, а из `cmd.txt` в папке игры
(`launch-flags.md` §2). `GAME_OPTIONS` пишет строку в `ТЕНЬ/cmd.txt` на
прогон (копия — `ТЕНЬ/.game-bench/cmd.txt`, в `timeline.txt` — строка
`game options: …`); прогон без переменной убирает файл прошлого прогона.
`cmd.txt`, который стенд не писал, не трогается: прогон с `GAME_OPTIONS`
тогда отказывается.

```sh
# Гавана днём у точки по умолчанию потока gf2/cuba
GAME_OPTIONS="-stream gf2 cuba" SHOTS="60 80 90" DURATION=95 \
    tools/game-bench.sh run $S/shadow $S/out
# своя точка на террасе: копия точки по умолчанию в тени, новый GUID — из --list-spawns
tools/game-bench.sh shadow "$GAME" $S/shadow gf2/cuba.str
doctor-toolkit level duplicate $S/shadow gf2/cuba 6 1 \
    --offset=-104.49,21.231,-397.235 --direct
doctor-toolkit play $S/shadow --stream gf2/cuba --list-spawns
GAME_OPTIONS="-playerspawn {EEDCCCDF-3F36-4E1A-444F-43544F52544B} -stream gf2 cuba" \
    MEMORY=1 tools/game-bench.sh play $S/shadow $S/out сценарий.txt
# то же через тулкит: он пишет cmd.txt в тень и убирает после выхода игры
doctor-toolkit play $S/shadow --method command \
    --command "$PWD/tools/bench/play-command.sh {dir}" --stream gf2/cuba
```

Правила (§3 `launch-flags.md`): `-stream` — последний флаг, имена без
`.str`, **один поток верхнего уровня** (с двумя игра падает в
`0x0042138B`, дочерний один — в `0x00890CEB`); точка — из загружаемого
потока (точка `gf2/cuba/local` при `-stream gf2 cuba` оставляет игрока в
пустоте); сохранения и профиль не нужны (`SAVES` не задаётся), сюжет — как
у новой игры.

| `GAME_OPTIONS` | Прогонов | Падений | Управление (`$0`, мини-карта) |
|---|---|---|---|
| своя точка на террасе, `-stream gf2 cuba` | 2 | 0 | 20 с (нагрузка 1,5); `pos` — (179,407; 21,166; −25,438) |
| `-stream gf2 cuba` | 7 | 0 | 70–80 с (нагрузка 25–45) |
| `-stream gf2 miami` | 2 | 0 | ≤ 60 с (нагрузка 9) |
| `-stream mp_mall mp_mall` | 5 | 0 | ≤ 65 с |
| `-stream gf2 queens` | 1 | 0 | ~100 с (нагрузка ~40) |
| два–четыре потока | 12 | 11 | — |
| `-stream gf2 cuba\local` | 3 | 3 | — |

Сквозная проверка тулкита: `play --stream gf2/cuba` через
`play-command.sh` — игра в Гаване, после выхода `took away cmd.txt`.

Эталон `hud` этапа 24 снят ночью на террасе; для `await` у другой точки
нужен свой эталон того же участка (`ref ИМЯ 45,48,28,22` со снимка прогона).
Снимки и журналы этапа — в рабочей папке проверки (в репозиторий не входят).

- **Ускорение.** У Xephyr и Xvfb нет DRI3: OpenGL игры — только llvmpipe.
  Vulkan NVIDIA выводит в Xephyr (`vkcube` 1280×720 — ~46 к/с), но игра

  графики недоступен (`amdgpu_query_info … -13`), DXVK из Lutris адаптера
  не нашёл; Vulkan-рендерер wined3d (`WINE_D3D_CONFIG=renderer=vulkan`)
  падает на шейдерах d3d9. Путь к 30 к/с — DXVK и 32-битный Vulkan
  видеокарты (или вложенный сервер с DRI3: gamescope, Xwayland в
  безголовом компоновщике).

## 19. Доработка этапа 33: DXVK и 32-битный Vulkan (2026-11-13)

Цель — играбельная частота во вкладке «Игра». Владелец поставил
`libnvidia-gl-595:i386` (32-битные библиотеки драйвера NVIDIA 595.99.02, в
том числе Vulkan) и `xvfb`. DXVK v2.6.2 — из Lutris
(`~/.local/share/lutris/runtime/dxvk/v2.6.2/x32/d3d9.dll`), в систему и в
префиксы не ставился.

**Стенд.** Новые переменные `tools/game-bench.sh`:

- `DXVK=1` — `d3d9.dll` DXVK (`DXVK_DLL` или новейший из Lutris) кладётся
  в тень на время прогона (отметка `.game-bench/d3d9.dll`, после прогона
  файл убирается, если его не меняли), `WINEDLLOVERRIDES` дополняется
  `d3d9=n,b`, журнал DXVK — в `OUT`. `DXVK_HUD=fps,frametimes` рисует
  частоту на снимках.
- `SERVER=xvfb` — вложенный сервер Xvfb (только память, окна на хозяине нет
  вовсе) вместо Xephyr, как во вкладке редактора.

**Проверка видеокарты.** В Xvfb `vulkaninfo` видит RTX 4070 (Vulkan
NVIDIA), `vkcube` — 600 кадров за 4,1 с. Тестовая программа d3d9 (очистка
и `Present` 1280×720) с DXVK видит адаптер NVIDIA 10de:2860: Xvfb — 53 к/с,
Xephyr — 49 к/с. У обоих серверов нет DRI3; NVIDIA выводит в них копией
кадра через X-сервер.

**Игра** (`-stream gf2 cuba`, Гавана у ворот аэропорта, DXVK v2.6.2):

| Сервер | Размер | Кадров/с | Время кадра |
|---|---|---|---|
| Xephyr | 800×600 (без `-resolution`) | 61 | 14,6–20,4 мс |
| Xephyr | 1280×720 | 26,5–31,9 (49 при взгляде в сторону) | 19–54 мс |
| Xvfb | 1280×720 | 27,2–35,1 | 27–43 мс |
| до DXVK (этап 33, llvmpipe) | 1280×720 | 1–2 | — |

Частота падает почти пропорционально числу точек (800×600 → 1280×720:
×1,9 точек, ÷1,9 кадров), нижняя граница времени кадра ~28–31 мс — предел
задаёт вывод кадра в сервер без DRI3 (копия через процессор), не
видеокарта. 320 с в уровне (клавиши ходьбы, движение мыши, смена дня и
ночи) — без падений; после прогона `d3d9.dll` из тени убран. Игрок при
старте `-stream` по-прежнему не ходит (находка §17, этап 45), поэтому ввод
этим прогоном не проверен; он идёт через X-сервер (XTest) и от способа
отрисовки не зависит.

**CLI** (`play --method wine --prefix <стенд> --dxvk --stream gf2/cuba
--resolution 1280x720` в своём Xvfb, `DOCTOR_DXVK` — папка DXVK Lutris):
во время игры `d3d9.dll` в папке и копия в `_doctor_toolkit/dxvk/`,
`WINEDLLOVERRIDES='dinput8=n,b;d3d9=n,b'`; после выхода «took away
cmd.txt», «took away d3d9.dll», журнал DXVK (уровень `warn`) пуст.

**Найдено попутно.** Игра, запущенная во вкладке, пережила закрытие
редактора: Xvfb вкладки и игра остались работать невидимо 26 минут (с
`cmd.txt` в папке игры). Деструкторы при выходе не сработали. Теперь
сервер вкладки запускается с `PR_SET_PDEATHSIG` (SIGKILL с потоком, который
его запустил, — поток интерфейса): редактор закрыт, упал или убит —
сервер уходит, и игра под Wine без X-сервера завершается сама. Тест
`the_server_goes_with_the_thread_that_started_it` (без исправления
падает). Оставшиеся `cmd.txt`, модуль и `d3d9.dll` убирает следующий
запуск («Играть», `play`).

**Что ещё можно ускорить.** Вложенный сервер с DRI3 (Xwayland в безголовом
компоновщике, gamescope `--headless`) дал бы вывод без копии; во вкладке —
меньший размер игры (1024×768 — около 37 к/с по пропорции).

### 20.1 Игрок не ходит после `-stream` — найдено и исправлено

Причина и адреса — `live-link.md` §5.1. Коротко: без меню игра создаёт
игрока до того, как менеджер контроллера получит порт клавиатуры (15):
игрок читает порт 0, его карта действий `basic_aiming_player` лежит на
порту 0. Найдено сравнением памяти двух сеансов (через сохранение и
`-stream`): `Player+0x2498` (15 / 0) и стек карт действий `*0x01223464`
(порт 15 / порт 0); флаги игрока одинаковы. Не помогают: сообщение
`iMsgPlayerControlEnable`, флаг `-inputwithoutfocus`, запись одного порта.

Исправление — модуль (`fix_input`, по умолчанию включено): порт в
`Player+0x2498`, байт «порт занят», перенос карт на порт 15 функциями игры
`0x00464960`/`0x00464A10`. «Играть» и `play --stream` ставят модуль на
запуск сами (запись по сети выключена), если в папке игры есть
ASI-загрузчик; без него — предупреждение.

| Прогон | Результат |
|---|---|
| `-stream`, модуль без исправления | `w` 4 с, `Up`, `d`, `Left`, мышь — позиция и камера не меняются; `Esc` открывает паузу |
| `-stream` + `fix_input` | журнал модуля: `player … read input port 0, given the controller's port 15 and moved action maps [basic_aiming_player]`; `w` 4 с — игрок прошёл 24,9 м, мышь повернула камеру на 34° |
| `play --stream gf2/cuba --resolution 1280x720` без `--live` через `play-command.sh` | «live: module installed for this launch so that the player can move…»; `w` на 40-й секунде — игрок ушёл за ворота (`results/s0-play-stream-cmp.png`); после выхода «took away cmd.txt», «took away the live module» |
| через сохранение | порты уже совпадают — модуль ничего не меняет |

Найдено попутно: стенд оставлял метку своего `cmd.txt` после сеанса
`start`/`stop`, и следующий прогон удалил `cmd.txt`, записанный `play
--stream` с тем же содержимым (игра ушла в меню). Теперь стенд убирает свой
`cmd.txt` при остановке игры (`game_options_remove`).
