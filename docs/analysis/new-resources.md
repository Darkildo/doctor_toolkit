# Новые ресурсы и потоки в The Godfather II (PC)

Редакция от 2026-11-12 (этап 5). Источники: корпус игры (2300 потоков,
212 544 ресурса, 25 TOC), декомпиляция `godfather2.exe` (Ghidra, адреса ниже),
проверка в игре на стенде (`docs/analysis/game-bench.md`). Код:
`crates/doctor-toolkit/src/create.rs`, `container/ustream.rs`
(`rebuild_with`, `build`), `toc.rs` (`add_name`, `add_file`, `attach_child`),
`workspace/deploy.rs`; команды `add-resource`, `clone-resource`, `add-stream`,
`remove-stream`, `check-refs`.

## 1. Заголовок `SHDR`: что значат поля

### 1.1 Четыре идентификатора — это один 128-битный GUID

Загрузчик ресурсов (`0x00421470`, вызывается из разбора блока `SHDR`,
`0x004D0DB0`):

1. если 16 байт `ids` не нулевые, ищет их в **глобальной таблице загруженных
   ресурсов** (`0x00421170`, хэш-таблица по всем 128 битам, `0x004209C0`);
2. если ресурс с таким GUID уже загружен — увеличивает счётчик ссылок и
   **пропускает данные** нового (флаг пропуска блоков в `0x004D0DB0`);
3. иначе по `type_id` находит обработчик типа (таблица `0x01223980`,
   регистрация `0x0049C6E0` по SDBM имени в нижнем регистре — например
   `"MaterialSwapListResource"`), по политике памяти — распределитель
   (`0x00420BE0`, таблица `0x01206B20`), выделяет `data_size` байт с
   выравниванием из `+0x04`;
4. после чтения данных регистрирует ресурс под его GUID (`0x00421550`) и
   привязывает к текущему потоку для выгрузки (`0x004212B0`).

Тип **не входит** в ключ. Нулевой GUID не регистрируется (так у `simgroup`,
`variabledictionary`, `lighttoc`, `bricknmortarres`, `0xDF14DA75`: по одному
на поток, ссылок на них нет).

Формы GUID в корпусе (все 212 544 ресурса):

| Форма | Типы | Пример |
|---|---|---|
| id × 4 | все, кроме перечисленных ниже | `2f4fcbd4` ×4 |
| `0, type_id, хэш пакета, хэш имени` | `tg4h`, `tg4d` (28 246 пар) | `0 4802e0a7 1fae4f10 e2258386` |
| `~id` меша × 4 | `meshvolatile` (17 572 из 17 572 сразу после своего `mesh`) | |
| настоящий GUID: 8 случайных байт + логин автора | `graph` (2 178), `materialswaplistresource` (188) | `… BRINKER2` |
| нули | одиночные типы потока | |

Так GUID разных типов с одним именем не совпадают: текстурная пара различается
`type_id` во втором слове, меш и его `meshvolatile` — дополнением. Ни один
`ids[3]` не используется двумя типами, кроме пар `tg4h`/`tg4d` и `graph` /
`materialswaplistresource` (у последних это логин автора).

**Почему у `graph` и `materialswaplistresource` ids различаются:** это
настоящие GUID, и последние 8 байт — логин (`GRAHAM04`, `EWELCH16`). Отсюда
311 совпадений `ids[3]` внутри потоков.

**Хэш имени** в `ids[3]` текстур и в простой форме не воспроизводится ни
SDBM, ни CRC-32, ни FNV по имени текстуры или меша (проверено на 3000
ресурсах, с расширениями `.tga`, `.dds`, `.psd`): вероятно, это хэш пути
исходного ассета. Для новых ресурсов он и не нужен.

### 1.2 Политика памяти и выравнивание зависят только от типа

| Тип | Политика | Выравнивание |
|---|---|---|
| `mesh` | `geometry` (`0x38B2B8D2`) | 0x80 |
| `meshvolatile` | `0x67A6002E` | 0x80 |
| `material` | `volatile` (`0x67456B5C`) | 0x10 |
| `vfx` | `default` | 0x20 |
| `sbk` | `0x7A10372B` | 0x1000 |
| `auc` | `0x58B1F4D8` | 0x10 |
| `cec`, `dlg`, `grt` | `default` | 0x40 |
| остальные 33 типа | `default` (`0x5393AC01`) | 0x10 |

Без исключений во всём корпусе. Игра регистрирует пять политик
(`0x0067E140`): `0x5393AC01`, `0x9DC401B7`, `0x7A10372B`, `0x38B2B8D2`,
`0x67A6002E`; `volatile` и `0x58B1F4D8` в этом списке нет — вероятно,
регистрируются в другом месте. Таблица — `create::type_defaults`.

### 1.3 Правила выбора ids для нового ресурса

1. GUID не должен совпадать с GUID **любого** ресурса, который может быть
   загружен одновременно: при совпадении игра молча возьмёт уже загруженный.
   Тулкит проверяет по всей игре: новый 32-битный id не встречается ни в одном
   слове ids ни одного ресурса, ни его дополнение (`UsedIds`).
2. Совпадение GUID разрешено только для **одинаковых данных**: так игра
   делит ресурсы между потоками (9 999 разных материалов на 73 007 записей,
   1 360 текстур в 26 315 копиях и т. д.).
3. Форма GUID — как у типа: id × 4; текстура `0, type_id, пакет, новый хэш
   имени` (заголовок и данные — один хэш); `meshvolatile` — дополнение id
   меша; `graph` — канонический NeoGuid машины `XDOCTORTKX`
   (`UsedIds::allocate_guid`, `simgroup.md` §5).
4. Id выводится детерминированно (FNV-1a от «зерна»: имени потока, типа,
   исходных ids) с перебором при занятости — повторный запуск даёт те же ids.

## 2. Как игра находит ресурс по ссылке

| Ссылка | Ключ | Где цель в корпусе |
|---|---|---|
| metamodel T0 → `mesh`, `hkx`, `vfx`, `metamodel`, `0xCDB9D42B` | 16 байт GUID = ids цели | в том же потоке (34 184) или в потоке-предке по TOC (5 060); **ни разу** в постороннем потоке |
| SimGroup `Entity.CMD_SetModel` и другие GUID-атрибуты, ссылки объекта | 16 байт GUID | в потоке или предках; 70 моделей из 9 897 — в потоках, которые грузят данные SimGroup ([раскладка](resource-placement.md) §1, §6.1) |
| запись отрисовки меша → материал | CRC-32 имени в данных материала (`+0x08`), не ids | все — в потоке или предках |
| параметр материала → текстура | хэш имени текстуры = `ids[3]` `tg4h`/`tg4d` | все, кроме 26 хэшей (4 из них — 54 907 ссылок); 21 из них лежит в потоках, которые грузят данные, 5 хэшей (54 918 ссылок) нет ни в одном потоке — текстуры движка |
| `ffn` → атлас | имя текстуры строкой | в том же потоке |
| `lhr` → таблица строк | путь потока и его хэш TOC текстом | отдельный поток `gf2\text\…` |

Типы `hka` (`0x33A1671E`) и `emx` (`0x32293930`) из T0 metamodel не
хранятся в потоках.
Проверка: `doctor-toolkit check-refs` (с этапа проверки раскладки она
считает и потоки, которые грузят данные SimGroup), корпусные тесты
`references_resolve_in_the_stream_or_its_ancestors` и
`material_copies::references_resolve_with_the_streams_data_loads`.

Вывод: **глобальной таблицы «id → поток» нет.** Ресурс доступен, пока
загружен поток, в котором он лежит; ссылки по GUID идут через общую
таблицу загруженных ресурсов, ссылки по хэшам имён — через словари типов
(материалы, текстуры), которые заполняются при загрузке. Поэтому цель ссылки
должна лежать в том же потоке или в потоке, который загружается раньше
(предке по TOC). Порядок в потоке в игре всегда «сначала цели»: текстуры,
материалы, меши, `vfx`, `bnk`, metamodel, simgroup.

## 3. StreamTOC: поля и загрузка потоков

### 3.1 Зависимости

Загрузка записи (`0x00403C40`):

1. первые `f[0] + (f[2] & 1)` зависимостей — **предпосылки**: каждая
   загружается раньше (рекурсивно по TOC, а если её нет в TOC — по имени);
2. затем сам поток (`0x00404590`) — он запоминается под своим хэшем;
3. затем остальные `f[1]` зависимостей — **дочерние потоки** (флаг 0x10).

**Проверено в игре (этап 24, `game-bench.md` §13.5):** дочерние потоки
**не** открываются при каждой загрузке родителя. На террасе в Гаване игра
открывает зону `xenia/high/filler_080_01` (`0,1,1,0`), но не её дочерний
`c67_common_parentedstream_filler80_01`; так же не открываются новые
дочерние потоки тулкита — у зоны задания `cp_010_hotel_interior_zonestream`
и у мировой зоны `xenia/interior/business_019_balcony` (обе записи TOC
такие же, как у игры).

**Условие найдено (этап 45).** Запрос потока (`0x00404590`) смотрит флаги
его записи TOC в памяти (`+0xA`, `0x004A8100`): бит `0x8` — грузить, иначе
бит `0x10` — не грузить, иначе бит `0x4` (`LOAD_DISABLED_DEFAULT`) —
не грузить. Биты `0x8`/`0x10` ставит во время игры менеджер принудительной
загрузки (`0x008142F0` → `0x00406230(хэш, вкл)`, снимает — `0x00406280`) по
приоритетам, а его зовёт действие SimGroup **`EnableDisableStreams`**
(`585bca8e`): атрибут 0 — сообщение «включить», 1 — «выключить», 2 — хэш
записи TOC потока, 17 — 6. Оба дочерних потока Гаваны включает такой
объект в папке своего задания: `c67_common_folderstream` —
`checkpoint_910_loaded` → `9cc0b761`
(`c67_common_parentedstream_filler80_01`), `c59_common_folderstream` —
`checkpoint_732_loaded` → `142bdd06`. Пока задание не дошло до этой
контрольной точки, дочерний поток не грузится — это и видели на этапе 24.

Проверено на стенде (`game-bench.md` §20): дочерний поток
`gf2/doctor/s45kid` (`add-stream --with-parent --parent gf2/cuba/local`,
клон текстуры), в SimGroup `gf2/cuba` — копия объекта c67 (`level add …
--template-stream <c67_common_folderstream> --template-resource 7`, объект 3)
с `EnableDisableStreams.0=doctor_kid_on`, `.1=doctor_kid_off`,
`.2=48444bef` (хэш из `doctor-toolkit toc`). `-stream gf2 cuba`: потока нет
среди загруженных (`live streams`), после `live send doctor_kid_on` (1
слушатель) — `gf2\doctor\s45kid.str` загружен. `doctor_kid_off` сразу его
не выгружает (только снимает принудительную загрузку). Для своих ресурсов в
уровне годятся и поток по запросу через `StreamSet`, и существующий поток.

**Почему дочерний поток не открывается вместе с родителем (этап 84).**
Загрузка записи `0x00403C40` после самого потока обходит его `f[1]`
дочерних и для каждого зовёт запрос `0x00404590` (с флагом `0x10` —
«не явная загрузка»). Отказывает именно `0x00404590`: у записи с битом
`0x4` (`LOAD_DISABLED_DEFAULT`) и без бита `0x8` он возвращает 0. У всех
110 дочерних потоков игры бит `0x4` стоит, поэтому ни один из них не
приходит с родителем сам. Дочерний поток **без** бита `0x4` (флаги
`0,0,1,0`, в списке `f[1]` родителя) этот отказ не задевает.

Проверено на стенде (`game-bench.md` §33): поток `gf2/doctor/s84kid`
(`add-stream --with-parent --auto-load`, родитель — мировая зона
`gf2/cuba/local/van/high/terrain4`) загружен, когда загружена зона (игрок
у её центра, в 29 и в 65 м), и выгружен вместе с ней (игрок в 295 м и
дальше); ни
`EnableDisableStreams`, ни правок сетки не нужно. В бюджете раздела сетки
такой поток считается вместе с родителем (`0x00888080`).

Бит 2 `f[2]` (флаги `0,0,5,0`, 12 записей в `miami.toc`) — «parented stream»:
такой поток не загружается сам по себе (`0x004061F0`, `0x00404590`), только
как дочерний. Пример: `terrain02` (`0,1,1,0`) → `miami\local` и дочерний
`r15_common_parentedstream` (`0,0,5,0`, зависимость — `terrain02`).

Цепочка уровня: `globals_global` → `miami_global` → `miami` → `miami\local`
→ зоны, террейн, задания. Игра держит до 32 загруженных TOC (`0x004040D0`
загружает `<имя>.toc`, массив `+0xA4`, счётчик `+0x124`).

### 3.2 Откуда берутся GUID потоков

Хэш записи — свёртка GUID (`0x00401F40`; та же формула — внутри поиска
записи `0x004A82B0`, `docs/formats/toc.md` §3.5), и данные игры просят поток
по GUID:

| Источник | Хэшей TOC (из 2 287 разных ненулевых) |
|---|---:|
| `wgi` (сетка мира, `docs/formats/wgi.md`): GUID ячеек (потоки зон) и таблицы потоков уровня, с логином автора | 1 868 |
| SimGroup: `StreamSet` (атр. 2–5, 11, 19), `InterestingObject.8` (анимации), `Animated.4` (персонажи, машины), `Door.23`, `WorldGraphManualLoadSet`, ссылки `TrinityGameSequence`, `BindStreams.1` | 766 |

Террейн, зоны и филлеры (1 521 хэш, которых нет в SimGroup) — ячейки
мировой сетки: их грузит раздел сетки по положению игрока (§3.5). Поток просят по GUID сущности, которая им владеет (`0x0045E100`:
объект класса `0xAE986323` берёт поток по GUID **самого объекта**), или по
GUID-атрибуту. Без найденного в данных GUID остаются в основном кадры роликов
`igc*_s*`, банки диалогов `dlg\…` и корни уровней (`gf2\miami`): их,
вероятно, просят последовательности Trinity или код по имени. Текстовые
потоки названы своим хэшем (`gf2\text\856c146c`), `lhr` хранит имя и хэш.

### 3.3 Поток не из TOC

Если запрошенного потока нет в загруженных TOC, `0x00403A50` грузит файл
`<имя>.str` по имени (с фиктивным GUID `badbadba beefbeef eac15a55
91100911`). **Проверено в игре** (§5, опыт 2): новый поток, на который
указывает `lhr`, загружается и без записи в TOC. Запись в TOC нужна, чтобы
поток находили по одному хэшу (данные с GUID), для предпосылок и дочерних
потоков и для бюджета памяти (`data_size`).

### 3.4 Новая запись TOC

1. Запись имени: хэш = свёртка нового GUID (тулкит: NeoGuid машины
   `XDOCTORTKX` с ключами из FNV-1a имени потока, `simgroup.md` §5; хэш не
   занят ни в одном TOC) и путь через `\`.
2. Файловая запись: `data_size` = сумма распакованных размеров, флаги
   `0,0,1,0` (поток по запросу) с предпосылкой-родителем или `0,0,5,0`
   (дочерний, выключен до `EnableDisableStreams`) с зависимостью-родителем;
   дочерний `--auto-load` — те же `0,0,1,0`, но с записью в списке детей
   родителя (§3.1); слова зависимостей дописываются в конец таблицы. Записи сортируются по хэшу (двоичный поиск `0x004A8180`).
3. Для дочернего потока у записи родителя `f[1]` + 1 и новый список
   зависимостей «предпосылки, дети, новый».
4. Во всех TOC, где есть родитель. У текстовых потоков родитель разный:
   `gf2\frontend` во `frontend*.toc`, `gf2\globals_global` в
   `globals_global.toc` — поэтому у `NewStream` есть `toc_parents`.

### 3.5 Мировая сетка: поток, который грузится по подходу игрока

Этап 84; формат и код — `docs/formats/wgi.md`. Коротко:

- В корневом потоке уровня лежит по одному `wgi` на раздел
  `WorldGraphPartition`: высокая детализация (зоны `high`, интерьеры,
  потоки заданий), средняя, низкая и раздел карты «Взгляда дона». Ячейка `wgi` — поток с центром
  и коробкой.
- Каждый кадр раздел считает ячейкам приоритет по расстоянию от **игрока**
  до центра (`(1 − d / R) · 100`, `R` = 200 / 500 / 2 000 / 5 000 м по
  маске мер раздела), сортирует и грузит, пока приоритет не ниже 10, а
  сумма `data_size` из TOC не больше бюджета раздела (атрибут 4
  `WorldGraphMetrics`, МБ: 25 / 20 / 8–10 / 8) и число потоков не больше
  64. Остальные загруженные выгружает.
- **`data_size`** записи TOC — не только бюджет менеджера памяти
  (`0x0088BB70`), но и вес ячейки в бюджете раздела (`0x00888080`:
  поток и его включённые дочерние). Завышенный `data_size` выталкивает
  соседние зоны, заниженный — пускает лишние.
- **Предпосылки** — первые `f[0] + (f[2] & 1)` зависимостей записи TOC:
  загрузчик `0x00403C40` грузит их раньше потока; раздел сетки
  дополнительно держит счётчики на те из них, что есть в таблице потоков
  `wgi` (`0x0088AE10`, `0x0088AF60`).
- Ячейки видов 1, 2, 4, 5 выключены, пока игрок не войдёт в коробку
  объекта `ZoneStreamEnable` с именем ячейки.

Новый поток добавляется в сетку командой `world-grid add` (инструмент MCP
`add_zone_cell`):

```sh
doctor-toolkit add-stream GAME gf2/doctor/island --parent gf2/queens/local
doctor-toolkit world-grid add GAME gf2/queens gf2/doctor/island \
    --min=-420,0,-80 --max=-360,30,-20          # коробка зоны, метры
doctor-toolkit world-grid info GAME gf2/queens --cells | grep doctor
```

`--lod medium|low` кладёт ячейку в сетку с большим радиусом (`map` — в
раздел карты «Взгляда дона»), `--name ИМЯ
--on-enable` делает ячейку, которая ждёт `ZoneStreamEnable` с этим именем.
Всё записывается в рабочее пространство одной отменяемой операцией на
команду. Пример трёх способов — `examples/zones/world-grid-zone.sh`,
проверка в игре — `game-bench.md` §33.

Три способа загрузить свой поток «как родной»:

| Способ | Команды | Когда загружен | Что меняется |
|---|---|---|---|
| ячейка сетки | `add-stream`, `world-grid add` | игрок ближе ~180 м к центру коробки (и хватает бюджета раздела) | `wgi` в корневом потоке уровня, TOC |
| дочерний поток мировой зоны | `add-stream --with-parent --auto-load` | пока загружена зона-родитель | только TOC |
| ячейка с именем и `ZoneStreamEnable` | `world-grid add --name --on-enable`, копия объекта `ZoneStreamEnable` | игрок внутри коробки объекта | `wgi`, SimGroup с объектом, TOC |

`EnableDisableStreams` (поток загружен всегда после сообщения, §3.1) и
`StreamSet` остаются для потоков заданий.

### 3.6 `StreamSet` и `WorldGraphManualLoadSet`

По читателям атрибутов (код не проверялся в игре на этом этапе):

- `StreamSet` (`9c326942`, читатель `0x0047F960`): атрибут 0 — сообщение
  «загрузить»; 1 — **выход** «набор загружен» (читатель подписывает и его, но
  обработчик `0x0047F370` реагирует только на атрибут 0, а атрибут 1 шлёт
  `0x0047FD70` по `iMsgStreamSetLoadComplete`, за ним —
  `iMsgStreamSetCommandComplete`; этап 79); 2–19 — до 18 GUID потоков
  набора; 20–22 — GUID вложенных наборов `StreamSet`, их потоки добавляются
  к списку (`0x0047F610`); 23–40 — флаг на каждый из 18 потоков, используется
  только бит 0 (по позиции: атрибут `23 + n` относится к потоку атрибута
  `2 + n`). Сообщения движка о ходе:
  `iMsgStreamSetLoadStarted`, `iMsgStreamSetLoadComplete`,
  `iMsgStreamSetLoadCancel`, `iMsgStreamSetCommandComplete`.
- `WorldGraphManualLoadSet` (`999826da`, читатель `0x0088E230`): атрибут 0
  — сообщение включения, 1 и 82 — сообщения; 2–51 — до 50 GUID потоков
  первой группы, 52–59 — до 8 второй, 60–79 — до 20 третьей; 80, 81 —
  флаги; 83 — память в МБ; 84 — GUID объекта `WorldGraphMetrics`, к
  разделам которого набор относится. Пока набор включён, его потоки
  получают приоритет помимо расстояния (`0x0088A7B0`): первой группы — 900
  и выше, второй — 800 и выше, третьей — 0 (выгружаются); при флаге 80
  раздел расстояния не считает вовсе (`0x0088A960`); память набора
  вычитается из бюджета раздела (`0x0088BB70`). Это «ручной режим» сетки на
  время роликов и заданий.

## 4. Добавлять в существующий поток или делать новый

| | В существующий поток | Новый поток |
|---|---|---|
| Что менять | поток и `data_size` в TOC | файл, записи в TOC, загрузчик (родитель или данные с GUID/именем) |
| Когда ресурс доступен | вместе с потоком; ссылки из него и его потомков | когда поток загружен; для ссылок из старых данных он должен грузиться раньше них (предпосылка) или вместе (дочерний) |
| Риск | поток растёт, его копии в других уровнях не меняются | новые записи в общих TOC |
| Для модов | **проще всего**: клон рядом с оригиналом, ссылки переводятся на него | для больших наборов и своих уровней |

Добавление в существующий поток проверено корпусным тестом на копиях
(`cloned_models_and_new_streams_round_trip_on_copies`): все ресурсы потока
читаются и совпадают с исходными, клоны разрешаются, TOC обновлены, откат
возвращает файлы побайтно. Вставка рядом с исходным ресурсом сохраняет
порядок «сначала цели».

## 6. Что это значит для этапов 10 и 11

- **Новая модель (этап 10):** проще всего — клон существующего набора
  `metamodel` + `mesh` + `meshvolatile` + материалы + текстуры
  (`create::clone_resources`, ссылки переписываются) и замена данных клона
  импортированными; ids и политики уже правильные. Скелет — ресурс `rcb`,
  ищется по хэшам костей (не по GUID), клон не нужен, если кости те же.
- **Новые объекты (этап 11):** объект SimGroup ссылается на metamodel по
  GUID; клон metamodel должен лежать в потоке SimGroup или в его предке.
  Добавление объекта — правка SimGroup (этап 6) + ресурсы этого этапа.
- Для ресурсов, на которые ссылаются по хэшу имени (материалы, текстуры),
  новый хэш тоже должен быть уникален — тулкит выделяет его вместе с ids.
- Мод с добавленными ресурсами: манифест рабочего пространства версии 2
  (`docs/workspace.md`) переносится в мод формата 2 (`docs/mods.md`, §1.2, этап
  14): добавленные ресурсы, новые потоки, проверки и столкновения модов.
