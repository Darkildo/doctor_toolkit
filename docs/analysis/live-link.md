# Живая связь с запущенной игрой (этап 34)

Редакция от 2026-11-13. Исследован `godfather2.exe` PC 1.0.789.0
(SHA-256 `31f579a8…`, `TimeDateStamp` `0x4AC976E5`, `SizeOfImage`
`0x00E32000`, без перемещаемых адресов: образ всегда с `0x00400000`).
Адреса — виртуальные. Инструменты: Ghidra 12.2 headless (полный
автоанализ копии `exe`, 192 с; сервер MCP Ghidra не отвечал;
проект `~/gf2-project` держит другую сборку — не использовался), `objdump`,
чтение памяти игры самим модулем (`live peek`) и `tools/bench/gamemem.py`.
Проверка — стенд (`game-bench.md` §18).

Код: протокол, адреса и проверка издания — `crates/doctor-toolkit-live`;
модуль — `crates/doctor-toolkit-live-asi` (сборка
`tools/build-live-module.sh`); клиент, установка с откатом, поиск
загрузчика, поддельный модуль — `doctor_toolkit::live`; CLI —
`doctor-toolkit live`, `play --live`; редактор — панель «Связь» вкладки
«Игра» и метки во вкладке уровня (`docs/shell.md` §9.2).

## 1. Главное

- **Модуль работает под Wine.** `doctor_live.asi` (DLL i686, Rust, 414 КБ)
  кладётся в `scripts/` папки игры; его грузит ASI-загрузчик игрока
  (Ultimate ASI Loader как `dinput8.dll`, под Wine — с
  `WINEDLLOVERRIDES=dinput8=n,b`). Из Linux редактор говорит с ним по TCP
  на `127.0.0.1` — Winsock под Wine это обычный сокет хозяина.
- **Издание проверяется до любого действия:** заголовок PE и байты 29 мест
  кода, на которые модуль опирается (§6). На другой сборке модуль ничего
  не меняет и отвечает только «не то издание».
- **Данные игры — только в безопасных точках главного цикла:** чтение —
  перед каждым проходом цикла (перехват вызова `0x0068B04B`), запись —
  внутри кадра уровня, перед обновлением игры (подмена метода `+0x2C`
  таблицы `GameMainLoop`, §2).
- **Читается:** игрок (позиция, поворот — мировая матрица), камера
  (позиция, направление, угол обзора), состояние главного цикла, игровое
  время и время суток, загруженные потоки (61 на старте в Гавани), объекты
  SimGroup рядом с игроком (GUID, класс, позиция; обход 8 600 объектов —
  2 мс).
- **Умеет:** телепорт игрока тем же вызовом, что `PlayerTeleportRelay`;
  сообщение шины SimGroup — всем слушателям, как шлёт игра, или одному
  объекту по GUID; выполнение строки Lua 5.0 в состоянии скриптов игры с
  возвратом значений и ошибок.
- **Стенд:** координаты модуля совпадают с `gamemem.py` до миллиметра;
  телепорт переносит игрока (снимки до и после); сообщение
  `boundary_fade_out` гасит экран (яркость 85,7 → 1,2); 10 минут с модулем и
  модом игрока GF2ASI — без падений; `play --live` после выхода вернул
  тень побайтно (1381 файл).

## 2. Точки входа в главный цикл

`WinMain` (`0x0069D9D0`) → `0x0068AEB0`: цикл

```
do {
    if (0x00439FA0())            // call в 0x0068B04B
        go_on = 0x00683450(&dispatcher);   // кадр текущего состояния
    else ...
} while (go_on);
```

| Адрес | Что |
|---|---|
| `0x0068B04B` | `call 0x00439FA0` (`E8 50 EF DA FF`), раз за проход цикла; `cdecl`, без аргументов, результат в `AL` |
| `0x0112980C` | диспетчер состояний (указатель), `+4` — текущее состояние |
| `0x00D5A1F8`, `0x00D57758`, `0x00D57728` | таблицы `InitOnceMainLoop`, `FrontendMainLoop`, `GameMainLoop` (конструкторы `0x0067C590`, `0x0067C390`) |
| `0x00683450` | кадр: метод `+0xC` состояния; 2 — сменить состояние |
| `0x0067C290` | `GameMainLoop` `+0xC`: `0x0068BAF0(1)` (начало кадра) → метод `+0x2C` (обновление, `0x0067D160`) → `0x0068BCD0(1)` (конец) |
| `0x01206880` | буфер команд отрисовки кадра (указатель); задан только внутри кадра |

**Чтение** — первый перехват: модуль меняет 4 байта цели вызова в
`0x0068B04B` (адрес выровнен на 4 — запись атомарна) на свою функцию; она
снимает «снимок» (игрок, камера, время, состояние цикла), выполняет
задания чтения из очереди и вызывает `0x00439FA0`, результат которого
нужен циклу. Здесь главный поток стоит между проходами, Lua не выполняется.

**Запись** — второй перехват: слот `+0x2C` таблицы `GameMainLoop`
(`0x00D57754`, было `0x0067D160`). Сначала запись делалась в первой точке —
телепорт уронил игру: `Player::Teleport` начинает затемнение экрана
(`0x0093C210` → `0x0040C1F0`), а оно пишет команду в буфер
`0x01206880`, который вне кадра пуст (`Unhandled page fault on read access
to 00000014 at address 0040C278`). Внутри кадра буфер есть: здесь игра сама
обрабатывает сообщения и телепорты. Слот `+0x28` (метод `0x0067C560`)
оказался выходом из состояния и в игре не вызывается.

## 3. Игрок, камера, время

| Что | Как | Доказательство |
|---|---|---|
| список игроков | `*0x012233A0`: `+4` массив, `+0xC` число | Lua `GetPlayerPosition` `0x00469230`, `0x0040E0A0` |
| игрок (`Player`, 0x31D0 байт) | `массив[0] − 0x1F30` | `PlayerTeleportRelay` `0x007DD044` (`add ebx, 0xFFFFE0D0`) |
| мировая матрица | `+0xD0`: строки «вправо», «вверх», «вперёд», перенос (`+0x100`) | `0x00471610` (`lea eax,[ecx+0xD0]`), конструктор `Entity` `0x0046E6B0` ставит здесь единичную матрицу |
| поворот | `atan2(вперёд.x, вперёд.z)` | совпадает с `gamemem.py` |
| менеджер камер | `*0x0122339C`; `+0x154 ≠ 0` → текущая камера `+0x14`, иначе слот 0 TLS потока `+0x24` | `0x0040E0A0` (положение слушателя звука) |
| камера в уровне | статический объект `0x01207DB0`: `+0` обратная матрица, `+0x40` мировая (перенос `+0x70`), `+0x80` шесть плоскостей пирамиды видимости | чтение: камера в 4,5 м за игроком и 1,7 м выше, смотрит на него |
| угол обзора | 180° − угол между нормалями верхней и нижней плоскостей | 36,0° по вертикали при 1024×768 (по горизонтали 46,8°, отношение 4:3) |
| игровое время | `*0x01205224`, мс (`u32`) | Lua `GetSimTime` `0x0046A850` |
| время суток | `*0x0112A53C` — объект `TimeOfDayManager`; часы, минуты, секунды — `u32` в `+0x64`, `+0x68`, `+0x6C` | 16:27:30 → 16:31:00 за 20 с; в `+0x5C` — `0x79E` (1950) |

Байт `0x01205248`, который проверяет `0x0040E0A0`, решает, слушать ли звук
от камеры; на камеру он не влияет (в уровне он 0, а камера есть).

## 4. Объекты и потоки

**SimManager** (`*0x01223410`, конструктор `Base` `0x0046C590` → регистрация
`0x004467C0`). У объекта `+0x1C` — номер группы (маленькое число, ключ
таблицы ниже; это не класс), `+0x20` — GUID, `+0x30` — следующий в таблице
GUID (`+0x80` корзины, `+0x84` их число; поиск — `0x00445FF0`), `+0x3C` —
слушатель сообщений (его виртуальный `+4` вызывает шина).

Таблица групп: `+0x48` корзины, `+0x4C` их число; запись — `[0]` номер,
`[4]` первый объект, `[6]` следующая запись корзины; объекты группы связаны
через `+8`. Модуль обходит её без вызовов кода игры: позиция есть у объекта,
у которого в `+0xD0` лежит мировая матрица (строки единичные и
ортогональные, последний столбец 0, 0, 0, 1 — как у `Entity` и всех
классов от неё). На старте в Гавани — 57 групп, 8 600–8 700 объектов,
обход 1–2 мс (память проверяется по карте регионов `VirtualQuery`,
снятой один раз на задание, и не дольше 400 мс).

**Класс** — по реестру классов `0x004833A0`: отсортированный массив
`*0x012239BC`, `+4` число, запись `{хэш, фабрика, имя, размер}`. У каждого
объекта есть виртуальный `+0x10` `bool As(хэш, void** out)` (`Entity` —
`0x0046D450`, `PlayerTeleportRelay` — `0x007DCCD0`): модуль вызывает его со
всеми хэшами реестра и берёт самый большой подходящий класс. Только для
найденных рядом (десятки вызовов `As` на объект). Хэш имени —
`sdbm(lower(имя))` (`0x004DAFD0`): `Entity` = `0x38523FC3`. Рядом с точкой
по умолчанию `gf2/cuba`: `Player` (0 м), `CommonNPC` (1,8 м), два
`Destructible`.

**Потоки** — `*0x0122337C` (`StreamManager`): `+0x6C` список загруженных,
следующий — `+4`, имя — указатель `+8` и длина `+0xC` (`0x00405F40`).
Через 5 с после старта `-stream gf2 cuba`: 61 поток —
`gf2\globals_global.str`, `embedded:\gf2_patch_text_str.str`,
`gf2\cuba_global.str`, `gf2\cuba.str`, `gf2\cuba\local.str`, зоны
`gf2\cuba\local\…\low|medium|high\…`, персонажи, звук, транспорт.

## 5. Запись: телепорт, сообщения, Lua

**Телепорт** повторяет `PlayerTeleportRelay` (`0x007DD020`, обработчик
сообщения `0x007DD130`):

1. игрок не телепортируется, если в `Player+0x24A0` стоит бит 7 (ролик,
   машина, загрузка);
2. виртуальный `+0x14C` игрока с `(0x46F5C7B4, 1, 0)`;
3. `Player::Teleport` `0x0079E3C0` (`thiscall`, вызываемый снимает 16 байт):
   `(матрица 4×4, выровненная на 16; флаги 0; ручка сообщения «готово» —
   нулевая; список зон мира {4 указателя, число} — пустой)`. Модуль строит
   матрицу из нового положения и прежнего поворота игрока (или курса
   `yaw`). Зоны мира игра подгружает сама по положению игрока.

Игра переносит игрока на следующем кадре с затемнением экрана; с высоты
0,5 м игрок опускается на землю.

**Сообщение** — шина `0x00408A00` (`bool Send(Message*, bool force)`,
`cdecl`), сообщение `{u32 хэш, u32 данные, u8 отправлено}`, как его строит
Lua `SendMessage` (`0x004C82C0`). Хэш имени — `sdbm(lower(имя))`.
Таблица сообщений `*0x01162380` (4096 корзин по `хэш & 0xFFF`): запись
`[0]` следующая, `[1]` блоки слушателей, `[4]` хэш; узел блока — `+4`
следующий, `+0xC` слушатель, `+0x14` флаги (бит 15 — удалён). Шина зовёт
виртуальный `+4` слушателя, если у него включён бит 0 в `+4` (или `force`).

- **всем:** вызов шины — ровно как игра; модуль заранее считает слушателей;
- **одному объекту:** обход тех же слушателей, вызов только того, чей
  объект (`слушатель − 0x3C`) имеет нужный GUID. В игре адресной отправки
  нет — это обход шины, но вызов тот же.

**Lua.** Состояние скриптов игры — `*(*0x012233F4 + 0x18)` (`LuaAudioScript`
`0x00480D90`). Lua 5.0 вкомпилирован с нестандартными соглашениями
(LTCG), поэтому вызовы — на ассемблере:

- `luaL_loadbuffer` `0x00629280`: буфер в `ECX`, имя куска в `EAX`, `L` и
  размер в стеке;
- `luaD_pcall` `0x00636570`: `L` в `ESI`, обработчик ошибок в `EDX` (0),
  в стеке `f_call` `0x006261E0`, `{функция, LUA_MULTRET}` и смещение вершины
  — как в `0x006293C0` (`lua_dobuffer` игры).

После вызова модуль читает значения со стека (`TValue` 8 байт: тип и
значение; числа — `float`, строки — `TString`: длина `+0xC`, текст
`+0x10`) и возвращает вершину на место. Ошибка компиляции или выполнения
приходит текстом (`doctor_live:1: boom`).

## 6. Проверка издания

`doctor_toolkit_live::edition::check` — до установки перехватов, в
`DllMain`:

- `MZ`, `PE`, `TimeDateStamp = 0x4AC976E5`, `SizeOfImage = 0x00E32000`;
- байты 29 мест: перехватываемый вызов и слот таблицы, каждая вызываемая
  функция игры и инструкции, из которых взяты адреса глобальных объектов и
  смещения (`what` в таблице `CHECKS`).

Таблица сгенерирована из `exe` (скрипт в рабочей папке этапа,
`gen_checks.py`); тест `matches_the_game_when_present` сверяет её с игрой
при `EARS_GF2_DIR`. Несовпадение — другая сборка или место уже занято
другим модом: модуль ничего не ставит, пишет причину в журнал и отвечает
`Edition` на всё, кроме Hello (в Hello — `edition_ok = false` и причина).

## 7. Протокол

TCP на `127.0.0.1:ПОРТ` (по умолчанию 47801; установщик берёт свободный).
Почему TCP, а не именованный канал или файл: Winsock в Wine — сокет хозяина,
к нему подключается обычная программа Linux без Wine; именованные каналы
Wine снаружи не видны, файлы в префиксе потребовали бы опроса. На Windows
то же самое работает без изменений.

Кадр: `DTLV`, версия (u16, сейчас 1), вид (u16: запрос, ответ — вид | 0x8000,
ошибка — 0xFFFF), номер запроса (u32), длина (u32, не больше 1 МБ). Первый
запрос — Hello с токеном из `doctor_live.cfg` (у установщика — случайный);
кадр другой версии получает ошибку `Version`. Запросы: Hello, Status,
Player, Camera, Streams, Objects, Teleport, Send, Lua, Peek. Status, Player
и Camera отвечаются из снимка последнего прохода цикла сразу; остальные
ждут главного потока до 20 с (игра на стенде — 1–2 кадра/с). Запись
выключается в конфигурации (`writes=0`), и модуль отвечает `Denied`.

Ошибки: `BadRequest`, `Version`, `Edition`, `NotReady` (нет уровня, нет
игрока, нет кадра), `Timeout` (цикл не дошёл до точки — пауза, свёрнута,
загрузка; запись, опоздавшая к сроку, не выполняется), `Denied`,
`Failed`, `Unsupported`.

## 8. Установка и откат

- **Тень стенда:** `doctor-toolkit live install ТЕНЬ [--writes] [--port N]`,
  `live uninstall ТЕНЬ`.
- **«Играть»** (CLI `play --live [--live-writes]`, в редакторе — флажок
  «Живая связь» в параметрах на панели «Связь»): модуль и
  `doctor_live.cfg` кладутся в `scripts/` на время запуска, после выхода
  убираются (`ModuleInstall`, как `cmd.txt` этапа 32): копии того, что
  записано, лежат в `_doctor_toolkit/live/`; чужой изменённый файл не
  трогается; `scripts/` удаляется, только если его сделал тулкит и он пуст;
  журнал модуля переносится в `_doctor_toolkit/live/last.log`; остаток
  прерванного запуска убирает следующий запуск (`restore_stale`).
- Загрузчик не скачивается: без него (нет `dinput8.dll` и др.) «Играть»
  запускает игру без модуля и говорит почему. Способ Wine сам добавляет
  `dinput8=n,b`; для Steam/Proton — строка запуска
  `WINEDLLOVERRIDES="dinput8=n,b" %command%`.
- Модуль не пишет файлы игры и не трогает сохранения; его единственный
  файл — журнал рядом с собой.

## 9. Ограничения и найденное

- Адреса привязаны к одной сборке (проверка издания это обеспечивает).
- Объекты без матрицы в `+0xD0` (логика, триггеры без `Entity`) в список
  не попадают.
- Время суток только читается; сообщения адресно — только тем, кто слушает
  это сообщение.
- Первый вариант обхода объектов проверял каждое чтение вызовом
  `VirtualQuery`: под Wine это так медленно, что главный поток простоял
  более 3 минут (100 % ЦП) — заменено картой регионов и бюджетом времени.
- Мод игрока GF2ASI открывает своё окно консоли «GF2SE» и уводит фокус:
  окно игры свёрнуто, уровень не грузится, пока ему не вернуть фокус (на
  стенде — щелчок по кнопке игры на панели задач Wine). С модулем он
  уживается: в разные места (GF2ASI перехватывает `0x00403A50`,
  `0x00608930`, `0x00608250`, `0x0069DE10`, `0x0069E840`, `0x006817C0`,
  `0x00682860`, `0x009BCB30`).
- Сообщение `boundary_fade_out` затемняет экран без обратного затемнения
  (так игра выводит игрока за край мира) — для опыта годится, для игры нет.

## 10. Что это даёт этапам 35 и 45

- **35 (отладка вживую):** метка игрока и камеры уже есть (простая, поверх
  картинки уровня); «камера редактора = камера игры» — матрица и угол
  обзора камеры читаются; обратно — телепорт. Подсветка сообщений на графе
  логики — точка входа найдена: шина `0x00408A00` и таблица слушателей
  (можно перехватить отправку так же, как кадр); Lua-консоль готова.
- **45 (проверки в игре):** проверки можно вести без снимков экрана и
  поиска матриц: позиция игрока и объектов, классы, потоки, время, отправка
  сообщений и Lua — из CLI (`live …`) и из редактора; телепорт заменяет
  долгий путь пешком к проверяемому месту.
