# Флаги запуска и отладочные средства выпущенной игры (этап 32)

Редакция от 2026-11-13. Исследован `godfather2.exe` PC 1.0.789.0
(`ears_godfather_f_mt.pdb`, md5 `6f8d6fb070bc8dd3f912c8dcd4b0a990`).
Адреса — виртуальные (`VA = смещение в файле + 0x400000` во всех секциях).
Инструменты: `objdump`, поиск ссылок по байтам, Ghidra 12.2 без сервера MCP
(сервер не отвечал): `analyzeHeadless` на новом проекте с импортом `exe` без
автоанализа и декомпиляцией нужных функций; проект в `~/gf2-project` держит
другую сборку (байты не совпадают с нашим `exe`), его не трогали. Проверка —
стенд (`game-bench.md`), прогоны в префиксе `wine-gf2-bench`, 1024×768,
llvmpipe, нагрузка машины от 1,5 до 50 (параллельно работали другие агенты).

## 1. Главное

- **Игра не читает свою командную строку.** `WinMain` (`0x0069D9D0`)
  `lpCmdLine` не сохраняет; разбор идёт из файла **`cmd.txt` в папке игры**
  (§2). Аргументы Steam, Wine или ярлыка ничего не меняют (для Wine
  проверено, §5); `cmd.txt` работает при любом способе запуска.
- **`-stream` работает: игра сразу в уровне**, без заставок, титульного
  экрана, профиля, меню и сохранения. `-stream gf2 cuba` — Гавана днём,
  `gf2 miami`, `gf2 queens` — Майами и Квинс, `mp_mall mp_mall` — карта
  сетевой игры «Mall» в одиночном режиме. Управление (полоска здоровья,
  `$0`, мини-карта) — через **20 с** при свободной машине и 60–100 с под
  нагрузкой 25–45; через сохранение (этап 24) было 67–250 с, через новую
  игру — 750–845 с.
- **`-playerspawn {GUID}` работает:** игрок появляется у выбранного объекта
  `PlayerSpawn` загружаемого потока. Своя точка — копия точки по умолчанию
  (`level duplicate`): игрок стоит на террасе отеля днём ровно в
  (179,407; 21,166; −25,438), проверено чтением памяти. Точка с сообщением
  (`checkpoint_001_load`) запускает свою цепочку логики: экран внешности,
  ролик пролога — новую игру с миссии 1 без меню.
- **Ограничения:** ровно один поток — с двумя и более игра падает сразу
  (§3.4); дочерний поток (`cuba\local`) нельзя ни отдельно (падение), ни
  точкой из него (игрок в пустоте: поток не загружен). Сюжет — как у новой
  игры.
- **Отладочных средств нет:** код меню `personaldebugmenu.txt` в сборку не
  вошёл (осталась только строка), `*Tweaker` — обычные классы SimGroup с
  параметрами музыки, сервера визуального отладчика Havok нет (§4).
- Встроено: `doctor-toolkit play --stream … [--spawn …] [--list-spawns]`,
  поле `start` настроек «Играть», `GAME_OPTIONS` стенда (§6).

## 2. Откуда игра берёт аргументы

| Адрес | Что |
|---|---|
| `0x0069D9D0` | `WinMain`: `nCmdShow` → `0x00E50B70`, `lpCmdLine` не используется |
| `0x0068D010` | инициализация игры; в `0x0068D0E5` вызывает `0x0067C050` с буфером `0x011625D0` (`0x0040CF60`) |
| `0x0067C050` | сброс (`0x0067BF30`), чтение `cmd.txt` (`0x0067BFA0`); есть файл — разбирается он, нет — буфер `0x011625D0` |
| `0x0067BFA0` | путь `cmd.txt` (`0x00402E90`), файловая система игры `0x01223378`: открыть `0x004015E0`, размер `0x00401970`, прочитать `0x00401780` |
| `0x0067BDB0` | разбиение на слова: `argc` `0x01129804`, `argv` `0x01129808`; чтение — `0x0067BF10`, `0x0067BF20` |
| `0x004D6260` → `0x004D6160` | слово: разделители — пробел, табуляция, `\r`, `\n` и `*` (`0x00D57620`); `"…"` группирует; `//` и `/*` обрывают слово |

Буфер `0x011625D0` в PC-сборке никто не заполняет (запись только обнуляет его
в `0x0040CE63`; ссылок с записью нет) — это место командной строки консольных
платформ. Остался единственный путь — `cmd.txt`. Стенд (`TRACE_FILES=1`)
видит, как игра открывает `<папка игры>/cmd.txt` в первые секунды.

Разбор идёт дважды: состояние `InitOnceMainLoop` (§3) и настройка окна
(`0x0068D25A`). Сравнение — `_stricmp` (`0x00B96882`, `0x0068CFF0`),
регистр не важен. Неизвестные слова пропускаются.

### 3.1 `-stream`

Состояния главного цикла: `InitOnceMainLoop` (таблица `0x00D5A1F8`,
вход `0x0067CC50`), `FrontendMainLoop` (вход `0x0067C7F0`: грузит
`GF2\frontend.str`), `GameMainLoop` (вход `0x0067D140` → `0x0067D090`).
Диспетчер — `0x0112980C` (`0x00683280` имя → номер, `0x006833D0` номер →
состояние, метод `+0x14` — следующее состояние).

`InitOnceMainLoop` по умолчанию переходит во `FrontendMainLoop`. С
`-stream`: слово после флага — папка (`this+8`), все слова до конца
`cmd.txt` через пробел — список (`this+0x18`); нужно хотя бы два слова.
Вызывается `0x0067C9F0(папка, список)` и следующим ставится `GameMainLoop`.
`GameMainLoop` при входе копирует папку (метод `+0x18`, до 64 знаков) и
список (`+0x1C`, до 256 знаков) у предыдущего состояния и снова вызывает
`0x0067C9F0`. Так же игра стартует и из меню: `0x00930E70` кладёт папку и
список во `FrontendMainLoop` (`0x0067C360`) — по умолчанию `gf2` и
`cuba.str miami.str queens.str` (`0x00E56738`, `0x00E5673C`).

`0x0067C9F0`: к папке добавляется `\`; список режется на слова (пробелы и
`*`); для каждого — `0x00411C70`: сообщение `0x01206A28` и запрос потока
`0x00403A50(ПАПКА\ИМЯ, …)`, который ищет поток по имени TOC или открывает
`ПАПКА\ИМЯ.str` (`"%s%s"` + `".str"`); зависимости TOC грузятся сами
(`0x00403C40`). Папка с `#` в начале ищется по имени среди
зарегистрированных записей (`0x00412740`) — не проверялось.

Формат для `cmd.txt`: **имена без `.str`** и через `\`, папка — общий
префикс, последний флаг строки:

```
-playerspawn {32C85C9C-E2F0-1888-5245-4953444F5246} -stream gf2 cuba
-stream mp_mall mp_mall
```

Что получается:

| `cmd.txt` | Прогонов | Итог |
|---|---|---|
| `-stream gf2 cuba` | 7 | Гавана днём у `PlayerSpawn` вида 2 (283,9; −0,07; 371,8), рядом NPC «Sara Arrieta»; управление на 70–80-й с под нагрузкой 25–45; падений нет |
| `-stream mp_mall mp_mall` | 5 | карта «Mall» (сетевая) в одиночной игре, `$0`, мини-карта; к 65-й с; падений нет |
| `-stream gf2 miami` | 2 | «Welcome to Florida», к 60-й с при нагрузке ~9; под нагрузкой ~40 за 115 с не дождались |
| `-stream gf2 queens` | 1 | Квинс у вокзала, ~100 с при нагрузке ~40 |
| `-playerspawn {EEDCCCDF-…}` (своя точка) `-stream gf2 cuba` | 2 | терраса отеля днём, (179,407; 21,166; −25,438); управление через 20 с при нагрузке 1,5 |
| `-stream gf2 frontend` | 1 | чёрный экран: интерфейс меню в игровом цикле не работает |
| `-stream gf2 cuba cuba\local` (с точкой и без) | 8 | падение `0x0042138B` в 7 (при нагрузке 1,5 — на 3-й секунде, 2 из 2) |

(в репозиторий не входят).

Сохранение и профиль не загружаются: состояние сюжета — как у новой игры
(`$0`, без оружия), сохранение игрока не трогается.

### 3.2 `-playerspawn`

`0x004D8F00` проверяет текст (`0x004D9400`: `{`, 36 знаков по шаблону
`0x00E2DF20`, `}`), `0x004D8F50` отвергает «пустой» GUID
`{BADBADBA-BEEF-BEEF-555A-C1EA11091091}` (`0x00E2DF48`), `0x004D8CE0` →
`0x004D9500` переводит в 16 байт: первые три группы — числа little-endian
(4, 2, 2 байта), остальные — байты по порядку (обычный GUID Windows).
`0x008111A0` кладёт их в `0x0112DACC`.

Потребитель — чтение пакета `PlayerSpawn` (класс `0x30AA423A`, функция
`0x008115A0`, место `0x008116F9`): если атрибут 0 = 2 и глобальный GUID ещё
пуст, точка записывает туда свой GUID (точка по умолчанию — первая
загруженная вида 2); точка с совпавшим GUID подписывается на сообщение
появления игрока (`0x00408900`, `0x0120E93C`). Из меню глобальный GUID
задаёт `0x00930E70`: из сохранения, для сетевой игры — «пустой», для новой
игры — текст `XFOWLER102_C8D726A_A11FA3D_v3` (`0x004DA550`, `0x004DA7E0`).

GUID объекта у нас печатается байтами по порядку (`simgroup.md` §5):
`26d7c8323dfa11aa464f574c45523130` → `{32C8D726-FA3D-AA11-464F-574C45523130}`.
`doctor-toolkit play ИГРА --stream gf2/cuba --list-spawns` печатает точки
потока в нужном виде.

Точка должна быть в загружаемом потоке: GUID ищут только прочитанные
объекты. Проверено:

- **Своя точка.** В тени с копией `gf2/cuba.str` точка по умолчанию
  (`level duplicate ТЕНЬ gf2/cuba 6 1 --offset=-104.49,21.231,-397.235
  --direct`) скопирована на место сохранения этапа 24; новая копия получила
  GUID `dfccdcee363f1a4e444f43544f52544b` → `{EEDCCCDF-3F36-4E1A-444F-43544F52544B}`.
  `-playerspawn {EEDCCCDF-…} -stream gf2 cuba`: игрок на террасе днём,
  `find`/`pos` стенда (`MEMORY=1`) — (179,407; 21,166; −25,438), то есть
  точно в точке; смотрит, как исходная точка (−0,943; −0,333). Управление —
  через 20 с от запуска (нагрузка 1,5; эталон `$0` — `await`).
- **Точка сюжета.** `{32C8D726-…}` — терраса (166,76; 21,2; −28,09) с
  сообщением `checkpoint_001_load`: через 6–7 минут — экран внешности
  персонажа: точка запустила контрольную точку миссии 1 (новая игра без
  меню, дальше ролик пролога).
- **Точка дочернего потока** `{32C85C9C-E2F0-1888-5245-4953444F5246}`
  (`gf2/cuba/local`, (−178,13; 1,03; −59,08)): с одним потоком `gf2 cuba` —
  игрок в пустоте, матриц в точке нет (поток с точкой не загружен); вместе
  с `cuba\local` в списке — в единственном удачном прогоне из восьми игрок
  стоял у стены с воротами, в остальных — падение (§3.4).

### 3.3 `-mainloop`

Следующим состоянием становится названное, если оно зарегистрировано. В
`exe` три состояния: `InitOnceMainLoop`, `FrontendMainLoop` (и так по
умолчанию), `GameMainLoop`. `GameMainLoop` без `-stream` получает пустые
папку и список. Пользы нет; `-stream` перекрывает его.

### 3.4 Падение с несколькими потоками

`InitOnceMainLoop` запрашивает потоки сам, до того как `GameMainLoop`
подготовит загрузку (вход `0x0067D090`: `0x0067E210`, `0x006817C0`,
`0x004E0180`, встроенный поток `embedded:\gf2_patch_text_str` через
`0x009C7700`), а `GameMainLoop` запрашивает их второй раз. С двумя и более
потоками игра падает в регистрации ресурса без описания типа:
`0x00421550` (виртуальный, таблица `0x00E30B84`) → `0x004212B0`, чтение
`[x+0x18]+0xC` при `x+0x18 = 0`, адрес `0x0042138B`. При свободной машине —
всегда и сразу (2 из 2, на 3-й секунде), под нагрузкой — 9 из 10 прогонов
с двумя–четырьмя потоками. С одним потоком падений нет (21 прогон
`gf2/cuba`, `miami`, `queens`, `mp_mall`, с точками и без). Дочерний поток один
(`cuba\local`, зависит от `gf2\cuba` через TOC) падает иначе —
`0x00890CEB`, 3 из 3. Поэтому тулкит и стенд пишут один поток верхнего
уровня; зоны мира игра грузит сама по положению игрока (у точки по
умолчанию и у своей точки в `gf2/cuba` город виден полностью).

## 4. Отладочные средства

- **`personaldebugmenu.txt`** — 22 байта начального значения буфера в
  `.data` (`0x00E514E8`). Ни одна команда не ссылается на буфер и соседние
  поля (перебор всех 4-байтовых значений `0x00E51480…0x00E51600` в `.text`;
  совпадение в `0x005A0707` — байты команды `call`). Строк вида
  `DebugMenu` нет. Код меню из финальной сборки вырезан, файл игра не
  читает (стенд: открытий нет).
- **`GameplayTrackingTweaker`, `PlayerTargetingTrackingTweaker`,
  `ViolenceTrackingTweaker`** — классы объектов SimGroup (имена
  регистрируются рядом с `0x0068A53E`, `0x0068A557`, `0x0068A573`; хэши
  `484607f2`, `c4751187` в `logic_schema.toml`). Объекты есть только в
  `gf2/globals_global`: три штуки, атрибут 0 — сообщение
  (`audio_init_delay`, `mus_violence_tracker_on`), дальше — коэффициенты
  0,3–0,8. Это параметры музыки «по накалу» (насилие, прицеливание), их
  можно менять как любые данные (мастер этапа 23), но «подстройки на
  ходу» в игре нет.
- **Визуальный отладчик Havok.** `hkBsdSocket` есть (таблица
  `0x00DD33D4`, `listen` `0x00C72A30`: «Listening on host[…] port»), но
  фабрика `hkSocket::create` (`0x00C721E0`, указатель `0x00EFB8FC`) не
  вызывается ни разу — указатель никто не читает; строк
  `hkVisualDebugger`, `hkServerProcess` и т. п. нет. Сервера нет, порт не
  открывается. Второй `bind`/`listen` — DirtySock (`0x00C807A0`), сеть
  мультиплеера.
- **Своё окно отладки.** У пользователя стоит скрипт-хук (`dinput8.dll`,
  `GF2ASI`, `imgui.ini`) — это сторонний мод, не часть игры (`game-bench.md`
  §13.2).

Итог: из инструментов разработчиков в финальной сборке живы только флаги
`cmd.txt` — `-stream`, `-playerspawn` и настройки окна.

напечатал `cmd.txt: -stream gf2 cuba`, игра на стенде пришла в Гавану
(управление к 80-й с), после выхода — `took away cmd.txt`, в тени
вернулся прежний `cmd.txt`.

## 6. Что встроено

- **Библиотека** `doctor_toolkit::play::start`: `StartOptions` (потоки,
  точка, окно, размер) → строка `cmd.txt` (`-stream` последним, имена без
  `.str`, общая папка); `braced`/`parse_braced` — GUID в виде игры;
  `spawn_points` — объекты `PlayerSpawn` потока (GUID, вид, сообщение,
  положение); `CmdFile` пишет `cmd.txt` на время запуска и убирает после
  выхода (прежний `cmd.txt` игрока возвращается, чужой изменённый — не
  трогается; остаток прерванного запуска убирает `restore_stale`).
- **CLI**: `doctor-toolkit play ИГРА --stream gf2/cuba [--spawn GUID]
  [--windowed] [--resolution 1024x768]` — ждёт выхода игры и убирает
  `cmd.txt`; `--list-spawns` — точки потока; `--dry-run` печатает строку.
  Работает с любым способом запуска (Steam, Wine, Proton, своя команда):
  файл лежит в папке игры.
- **GUI**: поле `play.start` настроек игры (`StartOptions`) — «Играть»
  пишет и убирает `cmd.txt` так же. Элементов окна для выбора потока и точки
  нет: им нужны новые строки интерфейса, а файлы перевода в этой волне
  менять было нельзя.
- **Стенд**: `GAME_OPTIONS="-stream gf2 cuba"` пишет `ТЕНЬ/cmd.txt` на
  прогон (`game-bench.md` §16).

## 7. Что это значит для этапов 33–35

- **33 (игра во вкладке):** быстрый старт есть — `-stream` в один поток
  верхнего уровня (город, сетевая карта) и `-playerspawn` к точке; окно —
  `-windowed -resolution W H`, удобно встраивать. В любое место города —
  своя `PlayerSpawn` в потоке города: копия точки по умолчанию с новым
  положением (`level duplicate --offset`, этап 11), GUID — из
  `--list-spawns`; «Играть сюда» во вкладке может делать это само (правка в
  рабочем пространстве, откат после выхода). Сюжетное состояние — как у
  новой игры; проверки, которым нужен прогресс (оружие, миссии), идут
  по-прежнему через сохранение этапа 24.
- **34 (живая связь):** точки входа найдены: глобальный GUID появления
  `0x0112DACC`, запрос потока `0x00403A50` / `0x0067C9F0`, диспетчер
  состояний `0x0112980C`. Загрузка дочерних потоков вместе с родителем
  падает (§3.4) — запросы потоков из модуля должны идти по одному, после
  загрузки предыдущего.
- **35 (отладка вживую):** готовых средств у игры нет (§4): меню, подстройки
  и визуальный отладчик Havok придётся делать своими (этап 34).
- Открытые вопросы этапа 24 (§13.14 `game-bench.md`) теперь проверяются
  быстрее для мест без сюжета (коллизии, объекты, модели, звук уровня):
  20–80 с вместо 67–250 с и без подготовки профиля и сохранения.
