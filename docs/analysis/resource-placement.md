# Раскладка ресурсов по потокам

Редакция от 2026-11-20. Издание 1.0.789.0. Продолжение
[копий ресурсов](resource-copies.md): там посчитано, сколько копий и где они
лежат, здесь — почему именно там и можно ли это вычислить. Источник —
корпусный тест `placement::placement_census`
(`crates/doctor-toolkit/tests/corpus/placement.rs`) поверх индекса игры и
библиотеки `navigation::placement`. Файлы игры только читаются.

```sh
EARS_GF2_DIR="/path/to/The Godfather II" DOCTOR_PLACEMENT_REPORT=placement.txt \
    cargo test --release -p doctor-toolkit --test corpus placement::placement_census -- --nocapture
```

## 1. Что измерялось

**Ключ** — ресурс без потока: тип и четыре id (у ресурсов с нулевыми ids,
`simgroup` и других одиночных типов, ключа нет). **Держатели** ключа —
потоки, в которых лежит его копия.

**Пользователи** ключа — потоки, в которых есть ресурс, ссылающийся на него:

- ссылки индекса игры ([навигация](../navigation.md) §1): объект SimGroup →
  metamodel, `vfx`, `bnk`, `rcb`, `hkx`, `chv`; metamodel → меш, коллизия,
  дерево, эффект; меш → материал (CRC-32 имени), риг (по костям),
  `meshvolatile`; материал → `tg4h`; `tg4h` → `tg4d`; `partsdb` → меши и
  материалы; с этапа 84 ещё `treemodel` → материалы и
  `materialswaplistresource` → материалы (§3);
- `vfx` → `vfx` и `tg4h` **по имени**: эффект называет запускаемые им
  эффекты (блоки `efv.`) и свои текстуры (блоки `trp.`) строкой; индекс
  хранит строки эффекта, `Placement` сопоставляет их с именами эффектов и
  текстур;
- список замен материалов → поток объекта SimGroup с тем же GUID (§3).

Когда ссылка подходит к нескольким ключам (материалы с одинаковым хэшем
имени, риги с одинаковыми костями), пользователем считается поток только для
тех, что ему достижимы, если такие есть.

**Достижимость.** Поток видит ресурс, если ресурс лежит в нём, в его
**предпосылке** (TOC, транзитивно: `globals_global` → `miami_global` →
`miami` → `miami/local` → зона) или в потоке, который грузят **данные**
потока или его предпосылок: GUID в SimGroup, который не объект и не граф, а
хэш потока в TOC (`toc::guid_hash`). Таких ссылок на потоки 2 582:
`InterestingObject.8` — 1 909, `Animated.4` — 287, `WorldGraphManualLoadSet`
— 169, `StreamSet` — 167, `Door.23` — 48, `BindStreams.1` — 2. Так,
`globals_global` грузит `globalfolder/characters/allcharacters`, 33 потока
машин `vehicle_shared` и потоки заданий — их ресурсы видит любой поток игры.

**Правило `place`.** Копия идёт в каждый поток-пользователь, кроме того,
у которого предпосылка — тоже пользователь (копию получает она).

## 3. Правило

1. **Поток видит только то, что держит сам, его предпосылки и потоки,
   которые грузят его данные.** Таблицы «ресурс → поток» нет
   ([копии](resource-copies.md) §1.1), и сборка это соблюдает: 99,76 %
   пользователей находят копию так, остальные 707 — §5.1.
2. **Копия лежит у пользователя.** 99,4 % копий — в потоке, который сам
   ссылается на ресурс; поток, предпосылка которого уже держит ресурс,
   копии не получает (правило 4 [копий](resource-copies.md) §3).
3. **Общие копии — выше пользователей**, в их общей предпосылке, которая
   сама на ресурс не ссылается (941 копия, §4). Решение, что вынести выше,
   по числу пользователей не вычисляется (§4.1).
4. **Ресурсы потоков, которые грузят данные, не копируются.** Банки анимаций
   `InterestingObject` лежат в своих потоках
   `globalfolder/interestingobjectanimations/…`, и 1 898 ссылок на них из
   заведений находят их через `InterestingObject.8`; персонажи роликов
   (`partsdb` → меши и материалы, меши → риги) берут детали из
   `allcharacters`, который грузит `globals_global` (110 мешей, 356
   материалов, 1 023 рига).

**Списки замен материалов** (`materialswaplistresource`, 188 штук) — новое
этапа: раскладка `0x1008, 0, 0, N`, `N` смещений, в каждом списке число пар и
пары `{материал, замена, третье слово}` по CRC-32 имени (все 188 файлов
разбираются, `resource::material_swap`). Ids ресурса — это GUID объекта
SimGroup того же потока (у всех 188), к модели которого применяется список
(`ZoneRenderLOD`, `Entity`); объект на список не ссылается, связь — общий
GUID. С ним все 188 списков лежат ровно в потоке своего объекта, а 4 345
копий материалов, которые до этапа ничем не объяснялись, получили
пользователя.
Смысл третьего слова пары не выяснен.

### 4.1 Вынос выше не вычисляется по числу пользователей

Для текстур проверено: сколько потоков-пользователей лежит под
`<город>/local` или под `globals_global` и лежит ли текстура там. Порога нет:
под `globals_global` из текстур с 100 и больше пользователями вынесены 162,
не вынесены 117; с одним пользователем вынесены 20, не вынесены 1 158; у
городских `local` картина та же. Пакет текстуры тоже не решает: из 186
пакетов, текстуры которых вынесены хоть раз, у 38 вынесена только часть
(`_library__textures_locale_shared_miami_miami_common` — 128 вынесены, 109
нет). Вероятно, список общих текстур вёлся руками.

Для тулкита это не мешает: `place` даёт копии в каждом пользователе, там, где
игра держит одну общую, — больше копий, но каждый пользователь находит
ресурс, и ни один поток не держит копию под предпосылкой с той же копией.

## 5. Исключения

### 5.1 Пользователь не находит копию (707)

| Почему | Тип | Пар |
|---|---|---:|
| копия есть в другом потоке того же уровня, но не в предпосылке | `material` | 414 |
| — | `graph` | 1 |
| карта мультиплеера, копии только в одиночной игре | `material` | 244 |
| копии только в других уровнях | `material` | 48 |

Все 706 пар с материалами — **пары списков замен материалов**
(`materialswaplistresource`, §3), и во всех ссылка идёт от стороны `from`:
от материала, который список заменяет у модели своего объекта. Записи
отрисовки мешей тут ни при чём: проверка ссылок по всей игре не находит ни
одного меша, чей материал не лежал бы в его потоке, предпосылке или потоке,
который грузят данные (§6). Списки — у зданий `filler_125`, `filler_117`
Нью-Йорка (`genna/high/filler_125_15`: `from` лежит в `filler_125_8` и в
зонах `medium`/`low`) и у заглушек `scott_placeholder_building` на картах
`mp_rooftops`, `mp_niceweather`, `mp_cuba`, где `from` нет нигде. Ищет ли
игра `from` в таблице материалов (§5.5) или только сравнивает хэш с хэшем
записи отрисовки, не проверено; во втором случае эти пары ничего не
значат. До этапа проверки ссылок здесь стояло, что это записи отрисовки
мешей, — неверно: счёт шёл по пользователям `Placement`, а у этих ключей
пользователь — список замен. Граф — ссылка `PatrolRelay.0` в
`miami/local/bruno/high/venue_109` на граф `don/high/venue_106`.

### 5.4 Как правило уточнялось

Первый проход — ссылки индекса до этапа и предпосылки TOC, без потоков по
данным и без имён в эффектах: копий без пользователей 16 206 (из них 4 715
материалов, 3 337 эффектов, 2 774 текстуры, 188 списков замен), копий не у
пользователя и не над ним 856 (415 эффектов, 258 материалов, 109 банков,
61 metamodel, 13 текстур), пар «пользователь без копии» 2 154 (1 898
банков `InterestingObject`, 110 мешей и 88 материалов персонажей роликов,
46 текстур). Их объяснили: потоки, которые грузят данные
(§1), списки замен и деревья (§3), имена в эффектах (§1).

### 5.5 Как меш находит материал (exe)

Адреса издания 1.0.789.0, [обработчики](../kb/exe/mesh-buffers.md),
[таблица материалов](../kb/exe/material-table.md).

- Материалы лежат в **общей таблице по хэшу имени** (CRC-32 имени в нижнем
  регистре, слово `+0x08` данных), указатель на неё — `0x012054AC`,
  8 192 корзины. Узел: `+0` счётчик ссылок, `+8` материал, `+0xC` хэш,
  `+0x10` следующий. GUID ресурса и поток в поиске не участвуют.
- Загрузка `material` (`0x0049D200` → `0x0049D870`): если хэш уже есть в
  таблице, растёт счётчик узла, а прежний материал остаётся. Значит,
  из одноимённых материалов разных потоков действует первый
  загруженный. Иначе материал строится (`0x0049D4B0`) и регистрируется
  (`0x004D2330`). Выгрузка (`0x0049D210` → `0x004D24F0`) снимает ссылку
  по хэшу; на нуле материал удаляется.
- Загрузка `mesh` (`0x0045A560` → `0x0045A2B0`) проходит по записям
  отрисовки (по `0xB0` байт, массив `+0x50`, число `+0x34`). Для каждой
  она ищет хэш материала `+0x0C` в таблице, кладёт материал в `+0x54` и
  увеличивает счётчик узла. Материал, на который сослался меш, живёт,
  пока жив меш, даже если поток материала выгружен.
- Повторной привязки нет. Если материала при загрузке меша нет, в `+0x54`
  остаётся 0, и рисование (`0x0042F2D0` → `0x0049E2F0`) такой элемент
  пропускает. Есть отдельная смена материала у записи по хэшу
  (`0x0045A100`), но её вызывают только `0x0045A8F0` и `0x0045B570` из
  кода мешей и место `0x004B80DD`. Это не повторная привязка после
  загрузки; что именно делают эти функции, не разобрано.
- Внутри потока материалы всегда идут раньше мешей: во всех 1 615 потоках,
  где есть и то и другое, нет ни одного меша перед материалом. Обычный
  порядок: `tg4h`, `material`, `mesh`, `meshvolatile`, `metamodel`,
  `simgroup`.

Для тулкита:
- Копия материала в потоке мода должна стоять раньше мешей, которые на
  неё ссылаются.
- Материал соседней зоны нельзя считать достижимым: он найдётся, только
  если зону загрузили раньше. `navigation::placement` поэтому остаётся
  строгим (предпосылки и потоки, которые грузят данные). Меши игры на
  соседние зоны и не рассчитывают (§5.1, §6).
- Новый материал с хэшем имени, который уже есть у загруженного
  материала, будет проигнорирован. Значит, менять материал мод может
  только под новым именем или во всех его копиях.

## 6. В библиотеке

`navigation::placement` (`crates/doctor-toolkit/src/navigation/placement.rs`):

- `Placement::new(&index, &game.stream_parents()?)` — пользователи,
  держатели и достижимость по всей игре;
- `users`, `holders`, `ancestors`, `requests`, `reaches` — то, что выше;
- `unreached(тип, ids)` — пользователи без копии; в неизменённой игре
  не пусто только у ключей §5.1;
- `copy_streams(тип, ids)` — куда положить новые копии: `place` над
  пользователями без копии;
- `place(&пользователи)` и свободная функция `place(ancestors, users)` — для
  нового ресурса, которого в индексе ещё нет: потоки, ресурсы которых будут
  на него ссылаться, → потоки для копий; `place_by` — то же над именами
  потоков (для потоков, которые создаёт рабочее пространство);
- `StreamHashes` и `guid_reference` — одно правило «данные грузят поток»
  для индекса и для проверки ссылок без индекса: GUID атрибута SimGroup,
  который не ресурс, не ноль и не объект своей группы, и свёртка которого —
  хэш потока в TOC (`StreamHashes::requested_by`). Таблицы TOC называют и
  потоки, которых нет среди файлов игры, иногда с хэшем существующего;
  такие имена отбрасываются (без этого отбора часть потоков, которые
  грузят данные, теряется: в переписи §2 пользователей без копии 981
  вместо 707).

### 6.1 Что тулкит делает с правилом

**Правка материала — во всех копиях.** Игра берёт первую загруженную копию
материала по хэшу имени (§5.5), поэтому правка одной копии может не
сказаться. `resource::material::copies` находит все копии: материалы игры с
тем же хэшем имени (данные `+0x08`; чтение всех материалов игры,
параллельно, около 0,7 с) с учётом правок рабочего пространства и
материалы, которые рабочее пространство добавило. Ids копий не хватает:
из 9 998 имён материалов (77 643 ресурса, у 5 362 имён больше одной копии)
ids одинаковы у всех копий имени, кроме одного имени (у него расходятся и
данные), но игра ищет по имени. `material::set_params` (команда
`material --set`, редактор материала, предустановки) и
`retexture::set_material_params` (MCP `set_material`) пишут правку во все
копии одной операцией; метка называет число копий («… (6 copies)»).
Копия, у которой нет параметра, остаётся как есть и называется в ответе.
Отказаться: `--this-stream-only` у команды, флажок **This stream only** в
редакторе, `this_stream_only` у `set_material`.

**`check-refs` знает потоки, которые грузят данные.** `ReferenceChecker`
считает достижимым то же, что `Placement`: поток, его предпосылки,
потоки, которые грузят данные его SimGroup и их, и так далее
(`ReferenceChecker::reach`, `loads`). Корпусный тест сверяет `loads`
каждого потока с `Placement::requests` — совпадают у всех. Неразрешённых
ссылок по всей игре:

| | ссылок | из них |
|---|---:|---|
| до (только предпосылки TOC) | 55 034 | 54 964 ссылки материалов на 26 текстур, 70 моделей объектов SimGroup |
| после (и потоки, которые грузят данные) | 54 918 | ссылки материалов на 5 текстур, которых нет ни в одном потоке (текстуры движка) |

Ещё `check-refs` проверяет порядок: меш, чей материал держит только его
собственный поток, и этот материал стоит после меша, — ошибка («the game
binds materials when the mesh loads; the material must come before the
mesh», `Unresolved::after`, `create::materials_after_meshes`). В игре таких
мешей нет ни одного.

**`check-edits`** (`validate::validate`) для правок рабочего пространства:

- та же достижимость для ссылок, которые добавляет правка; для
  неразрешённой — где игра держит цель и в какие потоки нужна копия
  (`placement::place_by` над потоками правок с этой ссылкой) — ошибка;
- порядок в потоках, которые правка меняет (добавленные ресурсы с их
  местом `before`, изменённые меши и материалы, новые потоки): материал,
  который держит только сам поток, после меша — ошибка;
- копии изменённого или добавленного ресурса (материал — тот же хэш
  имени, остальное — тот же тип и ids), которые остаются с другими
  данными в других потоках, — предупреждение с именами потоков: игра берёт
  ту копию, которую загрузила первой. Копии, данные которых различались уже
  в игре, не считаются.

Корпусные тесты — `crates/doctor-toolkit/tests/corpus/material_copies.rs`:
счёт неразрешённых ссылок по всей игре и сверка с `Placement`; ни одного
меша раньше своего материала (1 615 потоков с материалами и мешами); правка
материала `filler_057_v3_lowcolumns_01` во временном рабочем пространстве
меняет все 6 копий одной операцией, с `this_stream_only` — одну, и
`check-edits` предупреждает о 5 остальных; новый материал после меша —
ошибка порядка, перед мешем — нет, в недостижимом потоке — неразрешённая
ссылка с потоком для копии.
