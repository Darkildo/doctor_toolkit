# Импорт моделей (glTF, FBX, OBJ, USD → `mesh`)

Редакция от 2026-11-12 (этапы 10 и 25). Импорт полностью новой геометрии в
The Godfather II (PC): свои меши, привязка к скелету игры, свои материалы и
текстуры. Формат мешей и правила записи — `docs/formats/geometry.md` §7,
скелеты — `docs/formats/rig.md`. Файлы моделей — glTF 2.0, FBX, OBJ + MTL,
USD (`.usda`, `.usdc`, `.usdz`): все читаются в общую сцену
(`docs/model-formats.md`), импорт ниже одинаков для всех форматов; там же
API анимаций для этапа 26.

Код библиотеки:

| Модуль | Что делает |
|---|---|
| `resource/mesh_image.rs` | полная структура меша и писатель (`encode(parse(x)) == x` на всём корпусе) |
| `resource/mesh_grid.rs` | сетка треугольников статических записей |
| `resource/mesh_build.rs` | сборка меша из частей: виды записей, форматы вершин, полосы, палитры, разбиение |
| `scene/` | общая сцена, чтение и запись FBX, OBJ, USD, анимации на скелете игры (`docs/model-formats.md`) |
| `import/gltf.rs` | чтение glTF 2.0 (`.glb`, `.gltf` со встроенными или внешними буферами) в сцену |
| `import/model.rs` | план импорта: скелет, материалы, текстуры, ресурсы рабочего пространства |

## 1. Как пользоваться

### Командная строка

```sh
T=./target/release/doctor-toolkit
# заменить модель (меш или все меши metamodel) на месте, ids сохраняются
$T model-import "$GAME" gf2/globalfolder/characters/allcharacters fringe_dress_lod2 dress.glb
# то же для ресурса по номеру; --dry-run только печатает план
$T model-import "$GAME" mp_rooftops/mp_rooftops 173 box.fbx --dry-run   # .fbx, .obj, .usd*, .gltf
# новый набор: клоны metamodel и мешей под новыми ids, импорт в клоны,
# SimGroup 42 этого потока переводится на клон
$T model-import "$GAME" STREAM 319 box.glb --new doctor_box --retarget 42
```

`MODEL` — номер ресурса (`mesh` или `metamodel`) или имя модели меша.
Формат файла — по расширению (`.glb`, `.gltf`, `.fbx`, `.obj`, `.usd`,
`.usda`, `.usdc`, `.usdz`); `model-info FILE` показывает, что импорт увидит
в файле. Ключи: `--new NAME` (новый набор), `--retarget INDEX` (повторяемый, только с
`--new`), `--format N` (формат вершин 0–12 для всех записей), `--dry-run`,
`--json` (план как JSON), `--direct` / `--workspace-dir` — как у остальных
команд правки. Импорт — **одна** операция рабочего пространства:
`workspace undo` отменяет его целиком.

План печатается всегда: части (вершины, треугольники, вид записей,
материал), число записей отрисовки, скелет и число привязанных костей,
материалы (переиспользованы / новые), импортированные текстуры, заменяемые и
добавляемые ресурсы, перенаправленные ссылки, предупреждения.

### Редактор

В панели ресурса `mesh` или `metamodel` — кнопка **Import model…**. Окно
показывает план (таблица частей, ресурсы, предупреждения) и предпросмотр
нового меша на GPU с новыми материалами и текстурами. Переключатель
«Replace the model» / «New model set» с именем и номерами ресурсов для
перенаправления. **Record in workspace** записывает операцию.
`DOCTOR_TOOLKIT_GUI_IMPORT=<file.glb>` открывает окно для выбранного
ресурса (снимки экрана, `docs/viewers.md` §5).

### Python

```python
ws = game.workspace()
summary = ws.import_model("gf2/globalfolder/characters/allcharacters:mesh:e59dc8e9",
                          "dress.glb", new_name=None, retarget=[], dry_run=True)
# версия рабочего пространства как GLB — то, что import_model берёт обратно
glb = ws.export_model("gf2/globalfolder/characters/allcharacters:mesh:e59dc8e9",
                      game.index())
```

Модель можно править и во внешней программе со слежением за файлом
(`doctor-toolkit edit … --format glb`, «Open in external editor»,
`docs/external-editors.md`) и в Blender через дополнение (`docs/blender.md`).

## 2. Что делает импорт

### 2.1 Геометрия и система координат

Позиции берутся в пространстве игры: Y вверх, правая система, метры —
как в glTF; FBX и USD переводятся из своих осей и единиц при чтении, OBJ
берётся как есть (`docs/model-formats.md` §1); экспортёры пишут позиции без
преобразования.
Преобразования узлов применяются к мешам без скина; меш со скином лежит в
пространстве привязки, где glTF узел игнорирует. Полосы и веера glTF
переводятся в списки, точки и линии пропускаются с предупреждением.

Каждый примитив glTF — часть, часть даёт одну или несколько записей
отрисовки одного из трёх видов (`geometry.md` §7.3):

| Вид | Когда | Как пишется |
|---|---|---|
| статика | у части нет скина, а у заменяемой модели есть статические записи (или шаблона нет) | полоса с сеткой треугольников, 8 углов габаритов; поток 0 в меше, поток 1 в `meshvolatile` |
| жёсткая привязка | все вершины на одной кости, или скина нет, а у заменяемой модели только записи с костями (оружие, реквизит без рига — кость из шаблона) | список, кость и палитра из одной кости; поток 0 (20 байт) в меше |
| скиннинг на CPU | веса на нескольких костях | список, палитра ≤ 42 костей; встроенный источник 32 байта на вершину (f32 позиция, DEC3N нормаль и касательная, индексы палитры, веса u16 с суммой 65535) |

Формат вершин — тот, что у записи заменяемой модели того же вида с тем же
материалом (или первой записи этого вида); для жёсткой привязки и скиннинга
допустимы форматы с 20-байтным потоком 0 (0–5, 10), иначе 4. По умолчанию
статика — 1 (PosColorTex1NormTan). Недостающее дописывается: нормали
считаются по треугольникам, касательные — по UV, цвет белый, вторые UV —
копия первых, отсутствующие UV — нули (с предупреждением).

Запись разбивается, если в ней больше 42 костей палитры или буфер набрал
65 535 вершин (16-битные индексы); вершины на границах дублируются.
Неизвестные поля записи (флаги отрисовки 0x08, байт 0x28) копируются из
записи-шаблона.

### 2.2 Скелет

Кости glTF сопоставляются со скелетом игры **по имени**: известное имя
(`data/gf2/bone_names.txt`) → SDBM нижнего регистра, восемь шестнадцатеричных цифр (так
экспортёр называет кости без известного имени) → сам хэш. Скелет — тот, что
у заменяемой модели (по её таблице костей), если в нём есть все кости с
весом; иначе самый большой скелет игры, где они есть (человек — 102 кости,
`this_lod1`). Кость, которой нет ни в одном скелете, — ошибка со списком
имён и ближайшим скелетом. Веса нормируются, используется до 4 влияний
(`JOINTS_0`/`WEIGHTS_0`; ненулевые `WEIGHTS_1` — предупреждение).
Положения суставов в позе привязки (из обратных матриц файла) сравниваются
с `rcb`: если они отличаются больше чем на 1 мм, выводится предупреждение —
вершины берутся как есть, игра использует свои матрицы. Повёрнутые оси
костей (Blender переориентирует кости при импорте) предупреждения не дают:
на вершины в позе привязки они не влияют.

### 2.3 Материалы и текстуры

Для каждого материала glTF:

1. **Основа** — материал заменяемой модели с тем же именем; иначе любой
   материал игры с этим именем (CRC-32 имени в нижнем регистре; если ни
   поток модели, ни его предки по TOC его не загружают, он копируется в
   поток модели без изменений вместе с текстурами — так игра сама делит
   ресурсы между потоками); иначе самый частый материал заменяемой модели.
2. Если найден материал с тем же именем и у glTF нет изображений или
   пиксели совпадают с текстурами игры (`baseColorTexture` — роль
   `g_BaseSampler`, `normalTexture` — карта нормалей, `DXT5_NM`
   восстанавливается как при экспорте), материал **переиспользуется**.
3. Иначе основа **клонируется** с новым хэшем имени, нужные текстуры
   клонируются (новый хэш имени, тот же пакет) и кодируются из изображения в
   формате оригинала с полной цепочкой мипов (PNG и JPEG); ссылки клона
   переписываются. Изображение для роли, которой у основы нет, не
   используется (предупреждение).

Новые материалы и текстуры добавляются в поток модели перед первым
заменяемым мешем, чтобы загружаться раньше него. После импорта
`check-refs` не находит новых неразрешённых ссылок (кроме 26 текстур
движка, которых нет в потоках и у оригиналов).

### 2.4 Ресурсы

- **Замена** (`replace`): данные меша и его `meshvolatile` заменяются
  (у меша без `meshvolatile` он добавляется с ids-дополнением). Для
  metamodel заменяются все его меши в потоке — уровни детализации получают
  одну и ту же геометрию.
- **Новый набор** (`--new`): цель (metamodel или меш) клонируется вместе с
  мешами (`create::clone_resources`, ссылки клона metamodel переписаны на
  клоны мешей), в клоны записываются новые меши, имя модели — `NAME`.
  `--retarget` переписывает GUID ссылок SimGroup или metamodel потока на
  клон (`create::rewrite_references`).

входить в уровень:

1. **Оружие.** `model-import <тень> gf2/globals_global <номер меша оружия> new.glb`
   (например, `colt_m1911` или `tommygun_lvl4`, записи жёсткой привязки),
   войти в уровень, взять оружие: модель новая, оружие в руке на месте.
   Сначала — экспорт и импорт без изменений (проверка писателя в игре),
   затем изменённая геометрия и текстура (`--new` не нужен).
2. **Одежда персонажа.** `model-import <тень> gf2/globalfolder/characters/allcharacters

   костями, нет «взрывающихся» вершин (палитры, веса u16).
3. **Новая модель в уровне.** `model-import <тень> <поток уровня> <metamodel>
   new.glb --new doctor_box --retarget <simgroup>`: объект SimGroup
   показывает новую модель, соседние объекты с той же моделью — старую;
   выстрел по статической модели (сетка треугольников) — декали и
   попадания на месте.

## 4. Ограничения

- Морф-цели, байты вершин (0x48) и неизвестные поля записей-шаблонов не
  создаются для новой геометрии; лицевая анимация новых голов не работает.
- Новый скелет не создаётся: кости должны быть в одном скелете игры
  (`rcb` не пишется). Поза привязки — игровая.
- Материалы не создаются с нуля: новый материал — клон существующего
  (шейдер, параметры), меняются только текстуры основной роли и нормалей.
  Основная текстура одежды и волос персонажей — маска перекраски, а не цвет
  (`geometry.md` §6). Экспорт кладёт в `baseColorTexture` этих материалов
  (и глаз) готовый цвет — маску со смешанными оттенками, у волос с альфой
  из карты блеска (этап 65); импорт узнаёт такое изображение и оставляет
  материал как есть, а изменённое берёт как новую маску (с
  предупреждением).
- Коллизия по умолчанию не меняется: у новой модели коллизия старой.
  `--collision mesh|hull|box` (этап 18) строит новую из импортируемого
  glTF и переводит на неё metamodel (только цель-metamodel с частью
  `CollisionHavok4Part`; `docs/formats/havok.md` §3).
- Импорт в metamodel даёт всем уровням детализации одну геометрию.
- Клон модели персонажа подключается к наборам одежды отдельной командой
  `partsdb add-part` (этап 17, `docs/formats/characters.md` §7).
