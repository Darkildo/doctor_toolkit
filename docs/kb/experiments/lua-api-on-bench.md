# Lua-API на стенде: что проверено

Пять сеансов игры (`-stream gf2 cuba`, модуль связи): функции Lua вызывались строками `live lua` в состоянии игры, вывод скриптов читался из журнала модуля, поток звука — по записи `AUDIO_CAPTURE=1`. Проверено 63 функции из 117.

- **Сообщения.** Обработчик получает `(self, имя, имяТипа, данные)`; число, посланное `SendMessage(имя, "t", 5)`, читается `GetPositionValues(data)`; без строки типа данных нет. `SendMessageEx("iMsgLuaGetPlayerVenue")` вернул `"4"`. `receiver:RemoveMessage` обёртки даёт ошибку, `m_pReceiver:Remove` работает.
- **Время и целые.** `GetSimTime()` и `variable:Get()` — userdata; `x == 7` ложно, `x < 8` — ошибка; `Int32ToNumber` даёт число.
- **Таймеры.** Второй аргумент `CreateTimer` — «один раз»; обработчик получает номер таймера; таймер с несуществующей функцией игру не роняет.
- **Запуск и `shutdown`.** Стоповое сообщение зовёт `shutdown`, таймеры скрипта замолкают; повторный старт выполняет чанк заново.
- **Потоки EARS.** Имя нужно с `.stx`; поток слышен в записи (уровень 4 300–4 800 против фона 3 500–3 580); `Prime` молчит до `Play`; после `Stop` приходит стоповое сообщение; неизвестное имя — `userdata: 00000000` и тишина.
- **Объекты и группы.** `Base` вернула пустую ссылку для 230 объектов 91 класса; `Group:AddMember` с пустой ссылкой уронил игру (`0x00469F85`). Пустая группа работает.
- **Полиция и транспорт.** Без погони — `nil`, пешком — нули и `false`.
- **Сопрограммы.** В игре работают; набор проверок дал те же результаты, что ВМ тулкита.
- **Узлы Blueprints.** Граф с исправленными и новыми узлами отработал в игре: время и переменная — числа, позиция игрока есть, узлы групп с ненайденным объектом игру не роняют, число из данных сообщения читается, поток без `.stx` в имени найден, стоповое сообщение потока пришло.

Не проверено: группа с настоящим объектом, погоня и езда, естественный конец потока, влияние громкости, `ApplyMix`/`RemoveMix`.
