# Сохранения при старте -stream: место игрока и бит потока

Опыты этапа 63 в Нью-Йорке (`-stream gf2 queens`) с модом «Новый Нью-Йорк».

- При `-stream` в меню паузы есть Save (без профиля — в папку документов префикса). Сохранения
  сделаны во дворе острова и внутри укрепления; при втором — «Choose a save» (новое или поверх).
- Загрузка через меню: игрок **всегда** в одной точке у площади генны (−405,3; 6,2; −228,1), а не
  там, где сохранялся. Этап 76: в обоих файлах блок `checkpoint` хранит одну матрицу точки возврата,
  (−405,306; 6,400; −228,123), а не место игрока ([вопрос](../questions/save-player-position.md)).
- Без мода оба сохранения грузятся: падений нет, острова нет, игрок у той же площади.
- С модом 1.0 после загрузки сохранения остров не грузится: сохранение помнит бит «включено» потока
  (`EnableDisableStreams`), повторное «включить» ничего не меняет. `live send nny_boot` — 2
  слушателя, потока нет; `live stream load` — загружен за 28 кадров; «выключить» → «включить» —
  загружен.
- В 1.1 вход в город шлёт «выключить», через 0,5 с «включить» (`MultiManager` по `TriggerAuto`:
  `nny_point_off`, затем `nny_boot`): после загрузки сохранения остров загружен; свежий старт — тоже.

Что из этого следует: мод, который включает свой поток через `EnableDisableStreams`, должен при входе
в город сначала выключать его, затем включать.
