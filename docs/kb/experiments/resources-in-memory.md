# Подмена ресурсов в памяти: проверка на стенде (этап 100)

Стенд Wine + DXVK под Xvfb, тень игры с модулем падений. Игре отдавалось рабочее пространство (или моды менеджера) через модуль связи двумя путями: пересобранными потоками (этап 46) и заплатками ресурсов, из которых модуль собирает поток при открытии (этап 100). Эталон — тень с тем же, записанным `apply`.

| Прогон | Результат |
|---|---|
| Гавана, Майами, Нью-Йорк: замены текстур того же и другого размера, клоны в потоке, новый поток, скрипты `lua` в `gf2/globals_global` | игра прочитала каждый собранный поток целиком (счётчик байт = длина раскладки); все изменённые и добавленные ресурсы найдены в таблице загруженных с размером эталона; `lua` (заменённый того же размера, больший, клон в потоке, клон в новом потоке) совпали в памяти побайтно; исключений нет |
| потоки, собранные модулем внутри игры и выгруженные на диск, против `apply` | `gf2/<город>_global` — тот же файл; остальные — те же ресурсы в том же порядке (изменённые лежат несжатыми); TOC и новые потоки — те же файлы |
| то же рабочее пространство пересборкой (этап 46) | вывод сверки памяти тот же строка в строку |
| три мода из менеджера (новая зона с 70 ресурсами и ячейкой сетки, 157 ресурсов одежды с файлами `.viv`, ролик) | 90 потоков с заплатками, 13 открыты при входе в Гавану и собраны без отказов, совпали с `mods apply` по ресурсам; новая зона загружена; накладной архив — тот же файл |
| замеры: изменение в 172 зонах Гаваны, по три сеанса без изменений / пересборкой / заплатками | подготовка запуска 4,4 с и 368 МБ против 2,3 с и 13,6 МБ; загрузка уровня, догрузка зон после переноса, время в `ReadFile`, занятая память (707–731 МБ) и текстуры (141–145 МБ) — в пределах разброса повторов на всех трёх путях |

Что из этого следует:

- Отвечать за чтение, переход и размер в [файловом устройстве](../exe/file-device.md) достаточно, чтобы игра получила другой поток: разборщик и загрузчик ресурсов трогать не нужно.
- Путь с заплатками даёт игре те же ресурсы, что `apply`, и не стоит ей ни времени загрузки, ни памяти; выигрыш — в подготовке запуска и месте на диске.
- С изменениями в центре Гаваны загружена 41 зона вместо 42 — на обоих путях одинаково: вес зоны в TOC вырос на клон текстуры ([вопрос](../questions/stream-weight-after-substitution.md)).
- Данные ресурса в памяти после загрузки остаются как в потоке только у `lua`, `tob`, `grt` — [образ ресурса после загрузки](../engine/resource-images.md).
- Список загруженных потоков в центре города всё время меняется из-за потоков анимаций прохожих (`ambient_*`): ждать «пока список не перестанет меняться» можно только по потокам зон.

Не проверено: Windows, долгая игра, GF2ASI вместе с заплатками, заплатка к резервной копии уже записанного потока — [вопрос](../questions/resources-in-memory-on-windows.md).
