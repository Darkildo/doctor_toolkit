# Отчёты о падениях: проверка на стенде

Проверяли модуль `doctor_crash.asi` в игре под Wine (`SERVER=xvfb`, DXVK, теневая копия): пишет ли он отчёт и минидамп, что в них попадает, уживается ли с модулем связи.

| Прогон | Что сделано | Результат |
|---|---|---|
| настоящее падение | `-stream gf2 cuba miami` (два потока), без модуля связи | падение `0x0042138B` через 3 с; отчёт узнал адрес по базе знаний, стек — до `WinMain`; в очереди пять потоков, читается `gf2\globals_global.str`; минидамп 1,1 МБ |
| по заказу | `-stream gf2 cuba`, на 75-й секунде `crash-report test --kind jump` | падение в `0x6E756F80`: адрес `0x6E756F7B` оказался в отображённой памяти вне модулей; 61 загруженный поток, 54 520 сообщений шины с отправителями, позиция игрока |
| вместе с модулем связи | `-stream gf2 queens`, две ошибки Lua через `live lua`, мод в списке, `crash-report test --kind read` | проверка издания обоих модулей прошла; в отчёте три ошибки Lua, мод с версией, оба модуля в списке |
| Миссия 3 | `live send cp_325_start_now`, закрыть экраны, `live teleport 232,14,-345` | падение через ~2 с после телепорта, на рабочем потоке заданий (`0x00AC3290`), `EIP = 0xFFFFFFFF` — см. [вопрос](../questions/crash-6e756f7b.md) |

Что из этого следует: отчёт пишется и при падении на главном потоке, и на рабочем; стенд по-прежнему видит падение в `wine.log` (исключение идёт дальше, как без модуля); оригиналы игры не менялись. Строка «Последнее падение» в менеджере модов и редакторе снята под Xvfb.

Не проверено: Windows; переполнение стека; запуск через зеркало Large Address Aware.
