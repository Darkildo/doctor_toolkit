# Отладка вживую (этап 35)

Быстрый стенд: `-stream gf2 cuba`, `DXVK=1`, `SERVER=xvfb`, модуль `live install --writes` (протокол 3,
проверка издания — 58 мест совпали). Для скрипта-Blueprint тень собрана с копией
`gf2/cuba/local.str`, граф размещён `script-deploy --direct`.

| Проверка | Результат |
|---|---|
| камера игры → редактор | `live camera`: (288,20; 1,75; 372,96), вперёд (−0,91; −0,10; −0,40); вкладка уровня с «Следовать за камерой игры» показывает те же ворота аэропорта и метку игрока там же |
| свободная камера | `freecam 283.9,20,380 --yaw 180 --pitch -67` — кадр игры сверху; `--release` — камера игры на прежнем месте |
| точка на сообщении связи | `break --message iMsgPlayerControlEnable` + `live send` → «STOPPED in the frame …»; кадр 2905 не растёт 15 с, `live objects` и `live lua` отвечают; `continue --step` — ровно кадр 2906 |
| точка в шине | `iMsgRunningPostTick` → стоп через 0,2 с; объекты читаются, `live lua` и телепорт — отказ «стоит внутри своего кода» |
| триггер | точка на `aud_enter_tunnel_medium` (`EnterExitTrigger` зоны `yuri/high/terrain3`), телепорт игрока в триггер (221,1; 1; 385,0) → игра встала на этом сообщении |
| граф логики вживую | вкладка `stream:gf2/cuba/local` (348 узлов), `live send m1_pa_announcement_start`: лента «… MultiManager (…) -> PlayAudioStream», точка на сообщении — красная рамка и «Игра стоит перед доставкой сообщения» |
| Blueprint | граф `doctor_dbg` с отметками узлов: `dt:doctor_dbg:1;`, `:2;` при загрузке; `:3;`, `:4;` на `live send doctor_dbg_ping`; `break --print 'dt:doctor_dbg:4;'` → стоп, «Игра стоит на узле 4» |
| текстуры без перезапуска | `texture --stream …/terrain3..5 --tint FF00FF`: 11 текстур — плакаты, провода и надписи у ворот пурпурные в следующем кадре |
| долго | запуски 1 074 с, 949 с и 922 с (610 с по сценарию: 15 циклов, 31 срабатывание точек); падений нет; `verify`: оригиналы не менялись (28 файлов) |

Найдено:

- Камера `0x01207DB0` — не объект, а слот пула видов; поток отрисовки держит свои копии видов, поэтому
  запись матрицы после обновления на экран не попадает — только сеттером вида до записи команд кадра
  (`iMsgBeforeRender`).
- Точка на сообщении, которое шлёт сама связь, не может остановить игру на месте: остановка
  переносится в следующий кадр уровня.
- Сообщение, на котором стоит точка, сначала записывается в журнал, потом игра встаёт.
