# Нативный мод, поставленный менеджером модов

Проверяли [установку кода мода](../engine/native-mod-install.md): пример `examples/native-class` собран в один файл мода формата 5 (данные и два модуля `.asi`) и поставлен командами менеджера на тень игры (`SERVER=xvfb`, DXVK, Гавана).

- Программа версии 0.0.4 мод не открыла: «the mod uses format version 5 … Update doctor_toolkit»; в папке модов тени ничего не появилось.
- Тот же мод без признака `required`: без ответа и с ответом «только данные» `mods apply` пишет поток, в `scripts` и папке игры ничего исполняемого нет.
- Мод примера (`required`): без ответа `mods apply` отказывает и ничего не пишет; ответ «только данные» не принимается.
- После `mods native … --allow` и `mods apply` в тени без загрузчика появились `scripts/doctor_example.asi`, `doctor_example_c.asi`, `doctor_platform.asi` и `dinput8.dll` — [загрузчик тулкита](../engine/asi-loader.md); хэши совпали с показанными в вопросе.
- Ввод через загрузчик тулкита работает: за три секунды зажатой W игрок прошёл 17,7 м.
- В игре: платформа узнала издание и вызвала оба мода, объекты `DoctorCounter` и `DoctorCEcho` созданы из SimGroup мода и слушают, функции Lua модов отвечают, цепочка сообщений работает, скрипт уровня из данных мода напечатал свои строки; исключений нет.
- Выключение мода убрало его модули и платформу сразу; загрузчик остался, пока в `scripts` лежали модуль связи и модуль падений. `mods unapply` убрал всё, включая загрузчик; `mods uninstall --all` убрал запись об ответах. `verify`: оригиналы не менялись.
- Второй прогон — с загрузчиком игрока (Ultimate ASI Loader) в тени: менеджер свой загрузчик не клал, чужой файл после снятия побайтно тот же.
- Open Mod Manager под Xvfb: вопрос с файлами и хэшами, состояния «ждёт согласия», «код поставить нельзя» (другое издание, нет загрузчика), «готов» — снимки сняты скриптом.

Не проверено: Windows; «Играть с модами» с кодом мода; нажатия кнопок вопроса мышью (ответы проверены тестом панели и командами).
