# Координаты игрока: чтение памяти игры стендом

Способ без изменения игры: стенд читает память процесса (`MEMORY=1`).

- `godfather2.exe` (`0x00550d30`, точка, которую использует таблица Cheat Engine из `scripts/`
  каталога игры) берёт положение игрока из мировой матрицы 4×4: строки — правый вектор, верх, вперёд,
  перенос (`+0x30`, `+0x34`, `+0x38`), четвёртый столбец 0, 0, 0, 1.
- Ядро (Yama `ptrace_scope=1`) даёт читать память только потомков, поэтому игра запускается дочерним
  процессом `tools/bench/gamemem.py serve OUT/mem.sock -- wine godfather2.exe`. Память только читается.
- `scan X,Y,Z R` — все матрицы с переносом в радиусе R: 0,5 с на ~1,5 ГБ памяти процесса.
- Матриц игрока 40–75 копий (отрисовка, физика, анимация). `find` берёт вертикальные матрицы в точке
  сохранения; `pos` оставляет сдвинувшиеся копии и берёт самую большую группу; `track` — для мест без
  известной точки (камера следует за игроком в 4,5 м сзади и 1,7 м выше).
- Направление взгляда — третья строка матрицы.
- `walk КЛАВИША МЕТРЫ` держит клавишу и опрашивает положение раз в секунду: темп игры на llvmpipe
  следует частоте кадров, одинаковое `hold a 5` даёт 0,06 м в одном прогоне и 0,9 м в другом.
  Путь от точки сохранения по `a` повторяется в прогонах до сантиметра.
- `ahead OUT N [DY] [ВПРАВО]` — точка перед игроком для `level add --position`.

Найдено этим способом: «белый стол» справа от точки сохранения — тележка обслуживания номеров
(`Destructible` 97 группы `cp_010_hotel_interior_zonestream` № 89, metamodel `daa0769a`, меш
`room_service_cart01`, дочерний metamodel тарелок `8f4187f6`), а не статическая модель зоны.

С этапа 34 координаты даёт модуль связи; его значения и `gamemem.py` совпали до миллиметра
([первый прогон модуля](live-link-module-first-run.md)).
