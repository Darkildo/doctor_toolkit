# Объекты классов из DLL и новые функции Lua в запущенной игре

Проверяли [платформу нативных модов](../engine/native-mods.md) на примере `examples/native-class`: мод на Rust (класс `DoctorCounter`, функции Lua, слушатель, фильтр, перехват) и мод на C (класс `DoctorCEcho`, две функции Lua). Объекты классов и скрипт положены в SimGroup уровня Гаваны и одной зоны; в игре вместе с платформой стояли модуль связи и модуль падений. Числа читались функцией Lua самого мода (`DoctorCounterInfo`) через `live lua`.

- Моды вызваны после регистрации классов движка; LuaManager и таблица сообщений к этому моменту уже есть.
- Игра создала объекты обоих классов из SimGroup: читатель получил атрибуты (хэши сообщений, предел 2), объекты есть в списке всех объектов модуля связи, слушатели включены.
- Цепочка сообщений: два `doctor_example_count` → `DoctorCounter` шлёт `doctor_example_fired` → `DoctorCEcho` (мод на C) шлёт `doctor_example_ping` с собой в данных → слушатель-функция мода на Rust называет объект-отправитель.
- Фильтр проглотил `doctor_example_blocked` («nobody listens», хотя объект подписан); перехват `0x0043E5C0` посчитал оба вызова `EclipseLog`.
- Скрипт уровня из данных мода при загрузке напечатал `doctor_example:start:5:NATIVE` (функции мода на C), по сообщению — шесть чисел `DoctorCounterInfo`.
- Выгрузка зоны вызывает деструктор объекта, загрузка создаёт новый — дважды подряд; автосохранение по `cp_do_autosave_now` записано; сохранение загружено через меню — объекты созданы заново, счёт с нуля.
- Исключений в `wine.log` и отчётов о падении нет ни в одном прогоне.

Не проверено: неупакованные записи объектов, `hook_call`, работа без модуля связи и модуля падений, сохранение через меню паузы, Windows.
