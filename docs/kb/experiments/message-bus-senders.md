# Отправитель, порядок и данные сообщений на стенде (этап 78)

Гавана (`-stream gf2 cuba`), `SERVER=xvfb DXVK=1`, модуль связи протокола 8: перехват шины и трёх мест вызова обработчиков. Два сеанса по 4–7 минут, исключений нет, оригиналы не менялись.

| Проверка | Результат |
|---|---|
| место вызова | у всех 650 сообщений за 25 с; каждое есть в `data/gf2/bus_sites.tsv` |
| отправитель | 338 посланы из обработчика другого сообщения, у 102 отправитель — объект SimGroup |
| доставка одному слушателю | 248 из 650: сущность — компонентам (`0x00482A86`), `iMsgPostSpawnInitialize`, `iMsgManagedEntityCreated` |
| синхронность | Lua шлёт `aud_test_tod` → четыре `TestTimeOfDay` тут же отвечают `aud_not_night`, `aud_not_dusk`, `aud_day`, `aud_not_dawn`; порядок ответов — порядок получателей |
| повторный вход | `iMsgTickUnLinked` из собственного обработчика уходит компонентам сущности |
| объект в данных | у `OrEventGate` (`0x00479F06`) объект в данных равен отправителю |
| `hide`, `show` | `live send` — по 39 слушателей: имена общей шины |
| Lua, данные | `SendMessage("имя", "x", 5)` — указатель на `f32` в стеке; строка — копия в куче; с двумя аргументами данных нет |

Следует: шина синхронная и допускает повторный вход; отправителя можно называть по стеку; статическая таблица мест совпадает с живой игрой. Не проверено: вход игрока в объём, пересылка данных через `MultiManager` на живом примере, подписка во время рассылки, вид экрана после `hide`.
