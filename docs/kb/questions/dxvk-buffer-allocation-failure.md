# Почему DXVK не выделил буфер в первом кадре потока рендера

Динамический буфер индексов графического модуля (2 МБ, `DYNAMIC | WRITEONLY`, пул `DEFAULT`), созданный в первом кадре потока рендера во время загрузки уровня, дважды из двух не получил память: `DxvkMemoryAllocator: Memory allocation failed`, после чего DXVK 2.6.2 прочитал нулевой указатель (`d3d9.dll +0x8D2CE`) и игра упала. Тот же буфер, созданный на экране загрузки, создавался. Догадка: 32-битному процессу в этот момент не хватает адресов под отображаемую память. Модуль обходит это: один буфер пула `MANAGED`, созданный заранее.

Во втором замере этапа 101 (26 сеансов под DXVK в трёх городах, буфер модуля создаётся заранее) отказ не повторился ни разу; сам опыт с созданием в первом кадре не повторялся.

## Следующий шаг

Повторить создание в первом кадре потока рендера с `--laa` (4 ГБ адресов) и с одним драйвером Vulkan (`--vulkan-driver auto`): если отказ исчезает — дело в адресах. Снять карту адресов процесса (`live profile --memory`) в момент отказа.
