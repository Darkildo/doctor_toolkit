# Окупается ли объединение вызовов отрисовки на Direct3D 9 драйвера

Под DXVK объединение серий вызовов отрисовки (`draw_merge` графического модуля) убирает 15–26 % вызовов, но времени не экономит: время кадра то же, поток рендера тратит на 5–8 % больше ЦП, поток `dxvk-cs` — на 0–1,3 % меньше (три города, по три сеанса чередования). Вызов D3D9 в DXVK на потоке игры — запись команды в очередь (объяснение — догадка по устройству DXVK), и работа модуля (перехват 24–43 тыс. вызовов за кадр, сверка состояний с копией) стоит больше сэкономленного. На Windows с Direct3D 9 драйвера видеокарты вызов отрисовки проходит через драйвер и стоит дороже — там знак может быть другим. Не проверялось: стенд — Wine с DXVK. Не измерена и цена самих перехватов против игры без модуля: сеансы без перехватов попали под чужую нагрузку машины, разброс между сеансами больше эффекта.

## Следующий шаг

На Windows (или под Wine с wined3d на видеокарте, без DXVK) повторить серию: `doctor_render.cfg` с `draw_merge=1` и `draw_ab=8`, 280 с стоя в точке появления каждого города, `python3 research/draw_ab.py --skip 4 doctor_render.log` — время кадра и ЦП потока рендера по половинам. Отдельно, на свободной машине: сеансы с `draw_merge=0` и с `draw_filter=1` вперемежку, окна по 30 с (`research/bench_draws_sample.sh`), — цена перехватов. Если поток рендера и там занят больше — ключ `draw_merge` убрать из интерфейса «Играть».
