# Названия «переменных» условий диалогов и слов 1–4 выбора

Этап 75: «переменная» узла диалога — не память разговора, а номер запроса к игре. Чтение логического значения — `0x006EBFF0` (92 случая), запись — `0x006EB980` (индекс — номер минус 3); большая часть записей уходит событием в менеджер разговоров (`0x006F89E0`).

Названо (код и файлы игры):

- `0x0C`…`0x12` — флаги 0…6 собеседника (их ставят узлы `0x20`);
- `0x23`, `0x27`, `0x24` (запись) — собеседник шлёт сообщения, имена которых ему дал `ChangeNPCSettings` (атрибуты 3, 4, 5): так разговор отдаёт результат логике;
- `0x5D` — хэш выбранного города у кассира аэропорта (по файлам игры: сравнивается с хэшами городов).

Узел выбора годится как меню: четыре подписи и ветвь по времени — [выдача из логики](../../analysis/handing-out.md) §7, пример «торговец».

Не названы: чтение `0x00`, `0x01`, `0x09`, `0x0A`, `0x21`, `0x25`, `0x32`…`0x35`, `0x46`…`0x51`, `0x5B`; запись `0x26`, `0x28`…`0x2E`, `0x30` (114 раз в игре), `0x39`, `0x3A`, `0x47`, `0x49` (129 раз), `0x4B`, `0x5A`, `0x5C`, `0x5E`. Слова 1–4 выбора — номера групп клипов (ожидание игрока и собеседника — догадка).

## Следующий шаг

Открыть в Ghidra случаи `0x006EBFF0` и `0x006EB980` (адреса каждого печатает `research/dialogue_exe.py`) и назвать их по вызываемым функциям; начать с `0x30` и `0x49` — они стоят почти в каждом диалоге.
