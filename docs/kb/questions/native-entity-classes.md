# Класс-сущность мира из DLL

[Платформа нативных модов](../engine/native-mods.md) делает только логические классы: объект — `Base` (0x50 байт) с тремя таблицами методов. У сущностей мира (база `Entity`, конструктор `0x0046E6B0`) таблиц больше (`+0x50`, `+0x54`, `+0x58`), есть узел сцены, матрица `+0xD0`, модель, компоненты и списки обновления (этап 79).

Не известно: размер `Entity` и полный набор её таблиц и методов; что из них обязан переопределить наследник; как сущность попадает в списки обновления и отрисовки.

## Следующий шаг

Снять `research/ghidra/ClassDump.java` по фабрике простого класса-сущности (например `TriggerBox`): цепочка конструкторов, размеры, таблицы со слотами. По ним — фабрика «`Entity` + данные мода» в платформе и проверка на стенде: объект с моделью из SimGroup мода.
