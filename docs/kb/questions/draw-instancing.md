# Инстансинг одинакового реквизита

В записи кадра 9–19 % вызовов отрисовки — тот же меш, что предыдущий, с другими константами вершинного шейдера, а после сортировки в пределах прохода таких 17–31 % (Гавана, Нью-Йорк, Майами). Различаются регистры `c0`–`c7`, `c11`, `c14` — матрицы объекта. Объединить их в перехвате D3D9 можно только аппаратным инстансингом (`SetStreamSourceFreq`), а для него матрицы должны приходить из второго потока вершин: нужно переписывать байткод вершинных шейдеров игры и объявления вершин. Не сделано; игра сама использует `SetStreamSourceFreq` (118 вызовов за кадр в Гаване) — для чего, не разобрано.

## Следующий шаг

Разобрать, для каких мешей игра уже ставит `SetStreamSourceFreq` и какими шейдерами их рисует: если у движка есть готовый путь с матрицами из потока вершин, реквизит можно перевести на него данными, а не правкой байткода. Иначе — переписчик байткода: константы матриц объекта заменить входами `TEXCOORDn` второго потока для пар шейдеров прохода глубины, теней и освещённого прохода.
