# Отправитель сообщения в игре

У шины отправителя нет: в сообщении только хэш, данные и флаг. С этапа 78 (протокол 8) [модуль связи](../engine/live-module.md) называет его сам: метит стек в трёх местах, где игра зовёт обработчик слушателя, и при вызове шины читает место вызова, сообщение-причину и слушателя, чей обработчик выполняется; если это объект SimGroup — его GUID. Проверено на стенде: за 25 с из 650 сообщений место известно у всех, 338 посланы из обработчика, у 102 отправитель — объект ([опыт](../experiments/message-bus-senders.md)).

Что остаётся:

- Объект, который шлёт сообщение из своего обновления (его зовёт менеджер по `iMsgRunningTick`), а не из обработчика, отправителем не становится: известны только место и причина `iMsgRunningTick`.
- У сообщения из очереди задержки отправитель — очередь: кто поставил запись, потеряно.
- Переменная метки одна на все потоки; шлёт ли игра сообщения не с главного потока, не проверялось.

## Следующий шаг

В перехвате `0x00440590` запоминать место и отправителя вместе с записью очереди (таблица «запись → происхождение» в модуле) и отдавать их при доставке. Для отправки из обновления — найти, где менеджеры зовут обновление объекта (виртуальный вызов в обработчике `iMsgRunningTick`), и метить его так же.
