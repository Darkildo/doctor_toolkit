# По какому правилу ресурс лежит в нескольких потоках

У 13 020 ключей ресурсов есть копии в других потоках: 164 550 лишних копий, 55 % распакованных данных всех потоков. Больше всего копий у текстур, мешей и материалов (до 404 копий одного материала).

## Что известно

- Ни одни ненулевые ids не принадлежат двум типам; заголовки копий одинаковы.
- Внутри одного уровня (города, карты мультиплеера) копии одинаковы; данные расходятся у 14 ключей (10 `hkx`, 2 `mesh`, 2 `meshvolatile`), и всегда между уровнями.
- Поток не держит копию, если её уже держит его предпосылка по TOC. Исключение — 66 копий в `gf2/globals_global` и в `*_global` городов; этот файл переписан патчем, так что исключение может быть его следом.

Отсюда гипотеза: сборщик клал ресурс в каждый поток, которому он нужен и которому его не дают предпосылки.

## Следующий шаг

По индексу (`navigation::index`, ссылки и `used_by`) проверить для каждой копии, что на неё ссылается что-то в её потоке или в потоках, которые грузятся вместе с ним. Затем вычислить по ссылкам, в какие потоки ресурс должен попасть, и сравнить с фактической раскладкой. Совпадение даёт правило для автоматической раскладки копий новых ресурсов и проверку модов «ресурс нужен потоку, но недостижим из него».
