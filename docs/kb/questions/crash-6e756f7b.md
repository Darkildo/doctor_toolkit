# Падение `0x6E756F7B` при входе в старт Миссии 3

Решено этапом 77: это не сюжет и не модуль связи, а **слишком длинный путь папки игры**. На стенде игра шла из глубокой рабочей папки; у игрока с обычной папкой падения нет.

## Ответ

- Игра собирает путь к потоку `"%s/%s"` (папка игры, путь потока с `.str`) в буфере 256 байт на стеке рабочего потока файлов, без проверки длины: конструктор описателя файла `0x00AC37C0`, его зовёт операция «открыть» `0x00AC3AE0` из цикла `0x00AC3290`.
- Папка стенда (136 символов для игры) и поток чекпоинта 326 `…\cp_326_folderstream\m03_carmine_compound_exp.str` (132) дают 269 символов: адрес возврата `0x00AC37C0` затирается буквами `poun` слова «compound» (`0x6E756F70`), исполнение уходит туда. `0x6E756F7B` и `0xFFFFFFFF` прежних отчётов — где оно после этого остановилось.
- Минидамп (стенд §40, прогон 1): путь лежит на стеке потока с `0x1AE9FD84`, в ячейке адреса возврата — `poun`.
- Без модуля связи то же: скрипт Lua мода шлёт `cp_326_start_now`, падение на 60-й секунде, игрок на месте появления. Из короткой папки (25 символов) те же шаги проходят: чекпоинт 326, поток загружен.
- Правило: `длина папки + 1 + длина пути потока ≤ 255`. Самый длинный поток игры — 142 символа, поэтому папка до 112 символов (под Wine — вместе с `Z:`) безопасна. `validate`, `play` и стенд теперь предупреждают.
- Прежняя версия («испорчен указатель `+0x44` запроса») неверна: запрос цел.

## Что осталось

Вопросов по падению нет. Миссия 3 дальше старта не проходилась — это уже не про падение.
