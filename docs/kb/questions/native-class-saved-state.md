# Как объекту класса мода хранить состояние в сохранении

Объект класса из DLL ([платформа](../engine/native-mods.md)) после загрузки сохранения создаётся заново из SimGroup со значениями атрибутов: в API платформы версии 1 нет хранилища состояния. Классы движка кладут записи в хранилище `*0x01223418` (`0x0043D0D0` — найти, `0x0043D020` — создать) по сообщению `iMsgStoreEntity` и читают их по `iMsgRestoreEntity`; метка `0x137726B7` запрещает создавать отработавший объект (этап 79).

Не известно: формат записи хранилища и её срок жизни достаточны ли, чтобы дать моду «запомнить N байт»; как хранилище ведёт себя с ключом записи, которого игра не знает (сохранение, загруженное без мода).

## Следующий шаг

Прочитать `0x0043D020`, `0x0043D0D0`, `0x0043D260`, `0x0043D450` (создание, поиск, сохранение и восстановление записей); добавить в API платформы пару «записать / прочитать запись объекта»; на стенде: объект мода со счётчиком, сохранение, загрузка с модом и без мода.
