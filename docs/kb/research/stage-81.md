# Этап 81: Нативные моды в менеджере

- Состояние: сделан (2026-11-16).
- Зависит от: этап 71, [этап 80](stage-80.md).
- Целевое издание: только PC 1.0.789.0.

## Что сделано

- Раздел `native` в `mod.json`: модули `.asi`, их SHA-256, издание `1.0.789.0`, версия ABI платформы, признак «без кода мод не работает». Мод с кодом пишется в формате версии 5: программы, читающие версии 3 и 4, раздел пропустили бы и поставили мод без кода — [как ставится код мода](../engine/native-mod-install.md), [описание](../../mods.md) §1.6.
- Согласие игрока — на каждый мод и по хэшу каждого файла; без ответа ничего исполняемого в папку игры не кладётся; мод можно взять без кода, если автор это допускает. Это правило принято в этапе.
- Свой ASI-загрузчик `doctor_loader.dll`: ставится как `dinput8.dll`, только если загрузчика в папке игры нет — [загрузчик](../engine/asi-loader.md).
- Откат: выключение, удаление мода и «Вернуть оригиналы» убирают модули, платформу и загрузчик, если их клал менеджер; чужие файлы не трогаются.
- Open Mod Manager: метка «Исполняемый код», вопрос с файлами и хэшами, состояния «ждёт согласия», «код поставить нельзя».
- Платформа и загрузчик включены в выпуск (`tools/release.sh`, файлы выпуска `doctor_platform.asi` и `doctor_loader.dll`).
- На стенде: мод примера из одного файла поставлен менеджером на тень без загрузчика; объекты классов мода созданы игрой, функции Lua отвечают; после снятия оригиналы целы — [опыт](../experiments/native-mod-in-manager.md).
