# Платформа нативных модов (`doctor_platform.asi`)

Четвёртый модуль тулкита для ASI-загрузчика. Он даёт нативным модам — DLL с расширением `.asi` в `scripts`, которые экспортируют `doctor_mod_init`, — новые классы объектов SimGroup, новые функции Lua, работу с [шиной сообщений](message-bus.md) и перехваты в коде игры.

## Что известно

- Класс мода регистрируется функцией движка `0x004833A0` (хэш, имя, фабрика, размер), как 299 его собственных; игра создаёт объекты класса из SimGroup сама (`0x00483410`): фабрика, затем читатель атрибутов — метод `+4` объекта. Регистрировать можно после движка: реестр — отсортированный массив с вставкой.
- Объект класса мода — `Base` движка (0x50 байт, конструктор `0x0046C590`), за ним заголовок платформы и данные мода; три таблицы методов — копии таблиц `Base` с заменёнными деструктором, читателем и обработчиком сообщений.
- Читатель отдаёт моду каждый атрибут пакета, записанный и нет (незаписанный — 0, как у читателей движка). В файлах игры все 111 518 записей объектов упакованы; второй путь обхода (неупакованные записи) известен только по коду.
- Функции Lua регистрирует «связка» в списке LuaManager (`0x0043E2E0`): её метод зовётся для каждого состояния Lua, существующего и созданного позже. На стенде LuaManager создаётся раньше регистрации классов.
- Сообщения — функциями шины без патчей: рассылка, доставка одному объекту, задержка, подписка объекта и подписка функции. Патч нужен только фильтру рассылки (`0x00408A1A`) и ставится, когда мод его просит.
- Все места, которые патчат модули тулкита, собраны в реестре `platform::CLAIMS` (60 мест); тесты проверяют, что они не пересекаются и что ни один модуль не проверяет байты, которые патчит другой. Моду платформа отказывает в перехвате, задевающем реестр или чью-то проверку издания.
- На другом издании платформа ничего не ставит и модов не зовёт.
- Такт кадра (этап 115): платформа подменяет вызов такта игры `0x0068BC15` и после него зовёт подписчиков `tick_listen` — в уровне, на паузе, во «Взгляде дона» и в главном меню; `iMsgRunningTick` на паузе молчит. События устройства (`device_listen`) — через собственный реестр обработчиков игры `0x00607CA0`, без патча. Рисование поверх кадра (этап 116, `overlay_listen` из `doctor_mod_init`, `overlay_show`): переход на `0x00608E9E` перед `Present`, после интерфейса и постэффектов; состояние устройства — блоком `D3DSBT_ALL`, `doctor_render` предупреждается своими экспортами. Шлюз ввода (этап 117, `input_read`, `input_capture`, `input_reserve`): вызов XInput, три места `GetDeviceState` опроса устройств и курсор меню (движение `0x0069EB00`, `GetCursorPos`) — мод видит настоящее состояние, а пока держит захват, игра и её меню видят «ничего не нажато» и неподвижный курсор; зарезервированную клавишу игра не видит никогда. Рисование для модов на Rust (этап 118) — крейт `doctor-toolkit-overlay`: прямоугольники и текст фиксированным конвейером D3D9 из одной текстуры `MANAGED`, шрифты OFL Oswald и Podkova с кириллицей.
- SDK: крейт `doctor-toolkit-sdk` и заголовок `doctor_sdk.h` с одним ABI (версия 1, таблица из 42 функций, которая только растёт; функции после первых 32 мод находит по полю `size`).
- Тулкит узнаёт классы мода из файла TOML (переменная `DOCTOR_TOOLKIT_CLASSES`): имена, типы атрибутов, входы и выходы сообщений; `simgroup-add` добавляет объект класса.
- На стенде: объекты двух классов (мод на Rust и мод на C) созданы игрой из SimGroup, читают атрибуты, слушают и шлют сообщения; функции Lua отвечают скрипту уровня — [опыт](../experiments/native-class-on-bench.md).

## Ограничения

- Только логические классы (без матрицы, модели, компонентов); до 64 классов.
- Состояние объекта мода в сохранение не попадает.
- Фильтр видит только рассылку всем слушателям.
- Три старых модуля сами ставят свои перехваты; общий у них только реестр.
- Нативный мод распространяется файлом мода формата 5 и ставится менеджером модов только с согласия игрока — [как ставится код мода](native-mod-install.md); класть `.asi` в `scripts` руками тоже можно.
