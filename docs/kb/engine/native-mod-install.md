# Как менеджер модов ставит код мода

[Нативный мод](native-mods.md) едет в обычном файле мода: раздел `native` в `mod.json` формата версии 5 называет модули `.asi` для папки `scripts` игры. Это заметка о правилах тулкита, а не о движке.

## Что известно

- Формат — версия 5. Программы, читающие версии 3 и 4, неизвестные поля пропускают и поставили бы мод без кода, поэтому раздел в версии ниже 5 — ошибка, а старая программа мод версии 5 не открывает (тест `the_section_is_validated_and_needs_format_version_5`; на стенде — программа 0.0.4).
- Без ответа игрока в папку игры ничего исполняемого не кладётся. Ответ даётся один раз на мод (`_doctor_toolkit/mods/native.json`; хэши показанных файлов хранятся записью) и действует для его следующих версий: обновление с новой сборкой DLL ставится без нового вопроса и заменяет прежнюю при следующей записи в игру.
- Ответов три: разрешить код, только данные, выключить мод. У мода с `required` ответа «только данные» нет: без кода он не записывается совсем.
- Код ставится только на издание 1.0.789.0: исполняемый файл сверяется по тем же местам, что проверяет платформа. На другом издании мод с `required` не записывается, остальные — без кода.
- Имя модуля — простое имя `*.asi` строчными буквами; имена модулей тулкита и пути запрещены. Файл с таким именем, который менеджер не писал, не перезаписывается (сравнение без учёта регистра).
- Хэш сверяется при установке мода и ещё раз перед записью; файл должен быть 32-битной DLL.
- Мод не может требовать ABI платформы новее, чем у программы.
- Вместе с модулями менеджер кладёт `doctor_platform.asi` и, если загрузчика нет, [свой загрузчик](asi-loader.md).
- Выключение и удаление мода убирают его модули сразу, «Вернуть оригиналы» — всё, что клал менеджер; изменённый кем-то файл остаётся с предупреждением.

## Ограничения

- Согласие хранится в папке игры: копия игры спрашивает заново.
- Менеджер проверяет, что файл цел, но не что он делает.
