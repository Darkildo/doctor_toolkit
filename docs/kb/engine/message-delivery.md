# Доставка одному слушателю и очередь задержки

Кроме рассылки всем (`0x00408A00`) у [шины](message-bus.md) есть два пути, которые её обходят. Прежние документы называли их адресами `0x00408B70` и `0x004404F0` — это середина чужих инструкций.

## Что известно

- `0x00408BF0(сообщение, слушатель, force)` зовёт обработчик одного слушателя; обёртки `0x00408B80` (без данных, 11 мест) и `0x00408BB0` (с данными, 23 места); всего 127 мест вызова и один переход.
- Так шлют: `iMsgPostSpawnInitialize` объектам загруженной SimGroup, `iMsgTrigger` объёма самому себе с указателем на вошедшего (`0x004C1FF8`), `iMsgDamage`, `iMsgManagedEntityCreated`; сущность так раздаёт сообщения своим компонентам (`0x00482A50`: `footstep`, `audio: play`, `enable PA`).
- На стенде за 25 с игры в Гаване — 248 доставок одному слушателю из 650 сообщений (`bench`).
- Очередь задержки `0x00440590(переменная, слушатель или 0, секунды, данные, флаги)`; обёртка `0x004760D0`. `секунды ≤ 0` — сразу; иначе запись встаёт по сроку `*0x01205224 + секунды × 1000` (время симуляции, мс).
- Очередь разбирает обработчик `iMsgRunningTick` `0x00440760`: без слушателя — `0x00408A00(сообщение, 0)`, со слушателем — прямо его обработчик. Флаги: бит 0 — данные чужие, бит 1 — `force` при немедленной отправке, бит 2 — запись переживает сброс очереди (`0x00440B80`).
- Объекты логики шлют выходы с задержкой именно через очередь: `MultiManager`, `TriggerAuto`, `AndEventGate`, `TriggerDistance`, `TriggerFollow`; `score` — тоже.
- Перехват [модуля связи](live-module.md) на `0x00408A00` этих доставок не видит; с протокола 8 их записывают переходники мест вызова обработчика (`0x00408C31`, `0x00440819`).

## Что неизвестно

- Кто поставил сообщение в очередь, к моменту доставки потеряно: журнал показывает отправителем очередь.
