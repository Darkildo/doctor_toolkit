# Ввод: порт контроллера и карты действий

Ввод игрока идёт через порт контроллера и стек карт действий этого порта. Разобрано ради одной ошибки: после старта сразу в уровень (`-stream`, см. [флаги запуска](launch-flags.md)) игрок не ходит.

## Что известно

- Менеджер контроллера — `*0x01129814`, `+0x14` — порт (байт) того, кто играет: `0x0F` — клавиатура и мышь, меньше `0x10` — устройство, `0x12`/`0x13` — нет.
- Конструктор `Player` (`0x007A2A5A`): порт менеджера меньше `0x10` → `Player+0x2498` и `0x00444D20(порт, 1)` (байт «порт занят» у `*0x01223430`); иначе `Player+0x2498 = 0`. Больше это поле никто не пишет.
- Обновление `GameMainLoop` (`0x0067D1ED`): когда уровень загружен и порта у менеджера нет — даёт ему порт последнего устройства (`*0x012233B4 + 0x53D`).
- Карты действий — `*0x01223464`: на порт блок `0x168` байт, `+0x10` — число карт стека, `+0x14` — стек; `0x00465660` ищет действие только в картах порта. Игрок кладёт свою карту `basic_aiming_player` на свой порт (`0x00464960(порт, имя, 0)`, место `0x0079B5EE`), снимает — `0x00464A10(порт)`. Действие игрока — `0x0079E920`: бит 1 `Player+0x249C` и `0x00465700(порт игрока, действие)`.
- Через меню порт назначает титульный экран («Press any key»), и игрок создаётся уже с портом 15. При `-stream` игрок создаётся раньше, чем менеджер получит порт: в `Player+0x2498` остаётся 0, карта ложится на порт 0, а действия клавиатуры (порт 15) ищутся в пустом стеке. Пауза работает, потому что меню опрашивает все порты.
- Исправление — [модуль связи](live-module.md) (`fix_input`, по умолчанию включено): пишет порт в `Player+0x2498` и байт «порт занят», перекладывает карты старого порта на новый по именам. На стенде: `w` 4 с переносит игрока на 24,9 м, мышь поворачивает камеру. Одного порта без карты мало; сообщение `iMsgPlayerControlEnable` и флаг `-inputwithoutfocus` не помогают.
- Флаг `-inputwithoutfocus` (`0x0068D400` → `0x0120524A`, читает оконная процедура `0x0040FF6F`): ввод без фокуса окна.
- Главный поток заметную долю времени вне кода игры стоит в опросе устройств ввода (`0x00B9513F`, метод `+0x64` — `Poll`); под Wine опрос DirectInput дорог.
- Раскладки управления — ресурсы `cec` (2, например `basic_aiming_player.cec`); формат не разобран.
- Ввод и прицел остаются привязаны к камере игрока, даже когда игра рисует из свободной камеры.

## Что неизвестно

- Формат `cec` и состав карт действий.
- `-inputwithoutfocus` на стенде не проверялся как самостоятельное средство.
