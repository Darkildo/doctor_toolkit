# Объектная модель: SimGroup, классы, GUID

Игровые объекты (здания, двери, триггеры, логика миссий) описаны ресурсами `simgroup` и создаются при загрузке [потока](stream-loading.md). Объекты связаны именами сообщений [шины](message-bus.md) и GUID-ссылками.

## Что известно

- Ресурс `simgroup` (`0xCCB51828`, магия `0x53696D47`): 2006 ресурсов, 111 518 объектов, по одной группе на поток. Области: aux (GUID, векторы, матрицы), строки, пакеты атрибутов, объекты; все указатели относительные.
- Пакет атрибутов хранит атрибуты одного класса иерархии: хэш класса (`sdbm(lower(имя))`, `Entity` = `0x38523FC3`), число атрибутов, маска умолчаний, значения. Тип значения в файле не записан — он выведен по корпусу (`data/gf2/simgroup_schema.txt`, 3634 атрибута). Пакеты общие между объектами с равными значениями.
- Объект: флаги, число ссылок L и пакетов P, указатель на GUID, хэш класса, ссылки на ресурсы, пакеты от базового класса к производному. Первый пакет почти всегда `CAttributeHandler` или `CSystemCommands`; положение — `CSystemCommands.CMD_LoadMatrix` (`0xB390B11A`, атрибут 1).
- Регистрация класса — `0x004833A0` (хэш, имя, фабрика, размер; все вызовы из `0x00688AF0`). Реестр — отсортированный массив `*0x012239BC`, `+4` число, запись `{хэш, фабрика, имя, размер}`. В корпусе 253 класса объектов, 329 хэшей классов, названо 278 (`data/gf2/sim_classes.txt`). Каждый класс читает свой пакет функцией-читателем (обход `0x0043AFF0`, `switch` по индексу).
- `SimManager` — `*0x01223410` (конструктор `Base` `0x0046C590` → регистрация `0x004467C0`). Объект в памяти: `+0x14` флаги, `+0x1C` номер группы — идентификатор потока, который его создал (`0x00446E30`, `0x00446E9D`), `+0x20` GUID, `+0x30` следующий в таблице GUID (корзины `+0x80`, число `+0x84`, поиск `0x00445FF0`), `+0x3C` слушатель сообщений, бит 0 `+0x40` — слушатель включён. Таблица групп — `+0x48`, `+0x4C`.
- Виртуальный `+0x10` — `bool As(хэш, void** out)` (`Entity` — `0x0046D450`, `Base::As` — `0x0046C460`, ничего не сравнивает). Звать `As` у произвольных объектов таблицы групп нельзя — игра зависает: у части в слоте не `As`.
- `Entity` (таблица методов `0x00E32858`, конструктор `0x0046E6B0`): узел преобразования `+0x90` (`+0x90` мировая матрица, `+0xD0` локальная, `+0x110` родитель; `0x006101B0` без родителя копирует локальную в мировую, с родителем умножает на его матрицу; модуль живой связи читает `+0xD0` — она равна мировой, пока родителя нет); `SetMatrix` — слот `+0x28` → `0x00470E30`; `SetVisible` — `0x00471DB0`; `+0x161` — счётчик выключений; `+0x130` — экземпляр metamodel.
- После создания объектов группы движок шлёт им `iMsgPostSpawnInitialize`.
- GUID объекта — NeoGuid: имя машины автора из 10 букв и цифр (первая `X` не хранится; `XCHRIST427`) и два 28-битных ключа; текст — `<имя>_<ключ1>_<ключ2>_v3`. Машин 127. Новые GUID тулкита — машина `XDOCTORTKX`, ключи — FNV-1a имени. Ссылка на ресурс — id, повторённый 4 раза. GUID игрока — `04bdc758713a65b141545a3032373358`; у объектов, созданных игрой на ходу (камера), — `efbe0000…`.
- Metamodel как шаблон: `Entity.CMD_SetModel` — GUID-ссылка на `metamodel` (12 315 ресурсов). Его свойство — значение атрибута SimGroup: «класс + индекс атрибута» адресуют тот же атрибут, что пакет. Metamodel задаёт части (`ModelPart`, `CollisionHavok4Part`, `VFXPart`, `EARSLight`), состояния с условиями по переменным (`health`, `distance`) и вложенные metamodel. Отсюда известны 40 имён атрибутов.
- На старте в Гаване: 57 групп, 8 600–8 700 объектов; 6 080 из `gf2\globals_global.str`; 7 030 без матрицы.
- Переменные сюжета — менеджер `*0x01223428` (ресурсы `variabledictionary`; запись: `+0` хэш записи, `+4` `sdbm(lower(имя))`, `+8` значение `i32`); в главном меню его нет, объекты с переменными там роняют игру.
- Хэш группы (поле 0x10 заголовка) — хэш потока группы в TOC; по нему менеджер SimGroup включает и выключает группу (`0x00447AB0`, таблица `+0xB0`), см. [вопрос](../questions/simgroup-group-hash.md).

## Что неизвестно

- Смысл байта `0x1D` объекта и бита 1 флагов; атрибуты 2 и 3 `CSystemCommands`.
- Имена 3594 из 3634 атрибутов и 51 из 329 классов.
- Почему 434 GUID встречаются больше одного раза.
- Как движок выбирает начальное состояние metamodel и применяет переходы.
- Хэш-функция записи `variabledictionary`.
