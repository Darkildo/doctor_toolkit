# Шина сообщений

Одна глобальная синхронная шина связывает объекты [SimGroup](simgroup-objects.md), системы движка и [Lua](lua.md). Сообщение задаётся именем; провода нигде не хранятся — отправитель и слушатель просто держат одно имя.

## Что известно

- Имя → хэш `sdbm(lower(имя))` (`0x004DAFD0`, см. [хэши](hashing.md)); регистр не важен.
- Таблица сообщений `*0x01162380`: 4096 корзин по `хэш & 0xFFF`; запись — `[0]` следующая, `[1]` блоки слушателей, `[4]` хэш; узел блока — `+4` следующий, `+0xC` слушатель, `+0x14` флаги (бит 15 — удалён).
- Функции: `0x00408260` — найти или создать запись и положить хэш в «ручку» объекта; `0x00408980` — ручка из строки без подписки; `0x004089B0` — то же и подписка (`0x00407E60` → `0x004084D0`); `0x00473EC0` — то же с типом данных (`"BasePtrMsgData*"`); `0x00408240` — ручка из литерала в коде движка.
- Отправка `0x00408A00`: `bool Send(Message*, bool force)`, `cdecl`; сообщение — `{u32 хэш, u32 данные, u8 отправлено}`. Шина зовёт виртуальный `+4` слушателя, если у него включён бит 0 в `+4` (или `force`; обход — `0x00408A70`). Мест вызова — 688 (`call rel32` в `.text`); в базе Ghidra — 675 ссылок из 482 функций, ещё 13 вызовов лежат в неразобранном ею коде. Прежние «482» и «689» — число функций и число мест вместе с одиночным `jmp` в `0x00402040`.
- Доставка синхронная и в глубину: то, что обработчик шлёт без задержки, проходит целиком до следующего слушателя. Задержка — `0x004404F0`: очередь по игровому времени («сейчас + задержка × 1000 мс»); при задержке ≤ 0 — сразу `0x00408980`, адресно — `0x00408B70`.
- Слушатель объекта SimGroup — `объект + 0x3C`; бит 0 `объект + 0x40` — слушатель включён.
- Кто слушает, кто посылает: читатель атрибутов класса пропускает строку через `0x004DAFD0` → `0x00408260`; если затем подписывает объект — пин `in`, если только пишет ручку — `out`. Так у 124 из 136 классов-пакетов с сообщениями; у 12 строка хэшируется позже (направление — по данным). Схема пинов — `data/gf2/logic_schema.toml`.
- Сообщения движка: `data/gf2/engine_messages.txt` — 571 имя (`iMsg*` из exe и литералы, которые код передаёт `0x00408240`, `0x00408980`, `0x004089B0`; в файле 574 строки, три из них — комментарий). Около 15 из них идут каждый кадр: `iMsgSystemTick`, `iMsgRunningTick` (343 слушателя), `iMsgRunningPostTick` (1133), `iMsgPreRender`, `iMsgDoRender` (см. [главный цикл](main-loop.md)).
- Корпус (все 2006 SimGroup): 41 872 сообщения, 57 881 отправка, 72 633 подписки; 32 933 посылают и слышат, 150 слышат от движка, 34 слышит движок, 1 182 слышат, но никто не посылает, 7 573 посылают, но никто не слышит (числа закреплены корпусным тестом; до этапа 73 в документах стояли числа старой схемы пинов).
- Типы (этап 73): сообщение — открытое перечисление `Engine` / `Game` / `Custom` / `Unknown(хэш)`; каталог `data/gf2/game_messages.tsv` знает для каждого имени отправителей и слушателей по классам и атрибутам. Двух имён с одним хэшем в файлах игры нет; новое имя мода проверяется на совпадение хэша с сообщениями игры. См. [сообщения файлов игры](../messages/game-messages.md).
- Данные сообщения: одно слово `u32`. Lua `SendMessage(имя [, тип, данные])` (`0x004C82C0`) строит то же сообщение; приёмник Lua вызывается как `f(self, имя, nil, данные)`.
- Не от SimGroup: Lua (`SendMessage` в скриптах), ролики (`trinity_seq_master`), база очков `score` (около 1200 строк-имён сообщений; назначение — гипотеза). Поэтому, например, `mus_play_igc_01` в SimGroup «слышат, но никто не посылает».
- Адресной отправки в игре нет: [модуль связи](live-module.md) для «одному объекту» обходит тех же слушателей и зовёт только нужного. Его журнал пишет сообщение до доставки (хэш, данные, `force`, число слушателей, до 8 получателей по GUID), не чаще 4 раз за 5 с на сообщение; отброшенное считается по хэшу (`MessageCounts`).

## Что неизвестно

- Отправитель: у сообщения нет поля «кто». Найти его можно по стеку вызова шины — не сделано.
- Порядок слушателей одного сообщения (порядок подписки в таблице) с игрой не сверен.
- Хэш и шина у 12 классов, хэширующих строку не в читателе (`AndEventGate` 0–3, `MessageRelay` 0, `ForwardSender` 0), — по данным.
- `ExecuteVFX` 2–5 подписаны, но никто их не посылает (вероятно, движок шлёт адресно).
- Данные сообщений и отправители из кода движка у большинства сообщений `Engine` — см. вопросы [о данных](../questions/lua-message-data.md) и [об отправителях](../questions/engine-message-senders.md).
