# Главный цикл

Игра — машина из трёх состояний главного цикла; кадр уровня — начало кадра, обновление, конец кадра. Образ `godfather2.exe` всегда загружен с `0x00400000`.

## Что известно

- Точки входа: `WinMain` `0x0069D9D0` → цикл `0x0068AEB0`: раз за проход `call 0x00439FA0` (в `0x0068B04B`), затем кадр текущего состояния `0x00683450` (метод `+0xC` состояния; 2 — сменить состояние). Инициализация игры — `0x0068D010` (читает `cmd.txt`, см. [флаги запуска](launch-flags.md)).
- Состояния: `InitOnceMainLoop` (таблица `0x00D5A1F8`, вход `0x0067CC50`), `FrontendMainLoop` (`0x00D57758`, вход `0x0067C7F0` грузит `GF2\frontend.str`), `GameMainLoop` (`0x00D57728`, вход `0x0067D140` → `0x0067D090`). Диспетчер — `0x0112980C`, `+4` — текущее состояние.
- Кадр `GameMainLoop` (`0x0067C290`): `0x0068BAF0(1)` — начало (счётчик кадров `*0x01129A8C += 1`, взять буфер команд) → метод `+0x2C` `0x0067D160` — обновление → `0x0068BCD0(1)` — конец (буфер команд уходит потоку [рендера](render.md)).
- Внутри обновления: `0x0068BBE0` рассылает такты (`0x0040EBB0`) по [шине](message-bus.md); на `iMsgRunningPostTick` менеджер камер пишет вид; затем отрисовка уровня `0x0040E1F0` первым делом шлёт `iMsgBeforeRender`. Каждый кадр идёт около 15 сообщений движка (`iMsgSystemTick`, `iMsgRunningTick`, `iMsgRunningPostTick`, `iMsgPreRender`, `iMsgDoRender`).
- Часы игры (`0x00409F80`, объект `*0x01223390`): частота такта `0x0110AE4C` (59,94), шаг кадра `0x01206800`/`0x012067E8` — время кадра по `timeGetTime`, не меньше 1 мс и не больше 5 тактов (83,4 мс); время игры — `*0x01205224`, мс. Флаг фиксированного шага `0x0110AE75` вход `InitOnceMainLoop` всегда сбрасывает в 0: шаг переменный.
- Темп не привязан к частоте кадров: время игры за секунду 0,999 при 30–88 к/с; ниже 12 к/с игра замедляется (0,834 при 10 к/с). Исключение — [время суток](time-of-day.md).
- Потоки (Нью-Йорк): главный `godfather2.exe`, рендер `Presentation` (`0x00485AE0`), звук `RWAudioCore Dac`, задания `Job Manager` (физика, анимация), отдельный поток чтения потоков `.str`. ЦП на кадр: главный 3,5–6,5 мс, рендер 8–19 мс. Главный поток вне кода игры чаще всего стоит в `PeekMessageW` (`0x0069D71F`) и опросе устройств ввода (`0x00B9513F`).
- Безопасные точки для вмешательства ([модуль связи](live-module.md)): чтение — перехват вызова `0x0068B04B` (между проходами, Lua не выполняется); запись — слот `+0x2C` таблицы `GameMainLoop` (`0x00D57754`, было `0x0067D160`): вне кадра буфер команд `*0x01206880` пуст, и телепорт оттуда ронял игру. Слот `+0x28` (`0x0067C560`) — выход из состояния, в игре не вызывается.
- Пауза: меню паузы игры (`Escape`) — отдельное состояние. Свой флаг «пропустить кадр» игры не искали: модуль держит главный поток в перехвате обновления (остальные потоки — звук, загрузка, отрисовка — идут) и отпускает его сам через предел (120 с по умолчанию, не больше 900). Шаг — один кадр уровня.
- Пока идёт затемнение телепорта, цикл крутится без кадров (около 70 проходов короче 1 мс).

## Что неизвестно

- Что делает главный поток в кадр прибытия зоны (до 118 мс) и что он ждёт под `0x00808540` (до 39 % выборок).
- Какие из сотни мест, читающих шаг кадра, — физика, анимация, машины, таймеры Lua; езда, стрельба и таймеры миссий на разной частоте не проверялись.
- Порядок команд внутри буфера кадра.
