# Рендер

Direct3D 9, только шейдеры SM 3.0, отдельный поток рендера. Освещение — light pre-pass; константы света приходят из ключей [времени суток](time-of-day.md).

## Что известно

- Устройство: `0x00607990` — `Direct3DCreate9`, `CreateDevice` с флагами `0x54` (`HARDWARE_VERTEXPROCESSING | PUREDEVICE | MULTITHREADED`) → `*0x01205750`. Один задний буфер, без MSAA, `D3DSWAPEFFECT_DISCARD`. `Reset` — `0x00608250`.
- Два потока: главный пишет команды кадра в буфер `*0x01206880` (он задан только внутри кадра), поток рендера `0x00485AE0` (имя `Presentation`, `TLS+0x34 = 1`) исполняет их — весь D3D идёт там. Кадр N рисуется, пока главный поток считает N+1 (см. [главный цикл](main-loop.md)).
- Сцена рисуется в свою цель A8R8G8B8 (`*0x012058A4`; глубина D24S8 `*0x012058A8`, D24S8 1024×1024 `*0x012058AC`); перед `Present` копируется в задний буфер (`0x00608DC0`). Показ: `0x0040DF60` → `0x0060D8B0` → ограничитель `0x00608CA0` и `0x00608E90`.
- «Вертикальная синхронизация» — замок 30 к/с: во весь экран `D3DPRESENT_INTERVAL_TWO`, в окне игра ждёт 33,3 мс (`SleepEx(0)` в цикле). Настройка — `0x00F15A39`. Без неё ограничителя нет; `0x0040D450` — мёртвый код.
- Камера: вид — слот пула видов `0x01206BB0` (16 видов по 0x180 байт; рисуемый — `0x01207DB0`); `SetFov` `0x00422FB0`. Менеджер камер (`0x004252E0` → `0x00425EA0`) каждый кадр отдаёт угол в `0x00425FE4` — единственный вызов, меняющий картинку (60°, на бегу 67,5° при 16:9). Угол в данных горизонтальный при 16:9, пересчёт Hor+: 36,0° по вертикали при 4:3, 16:9 и 21:9 в покое (60°); на бегу (67,5°) — 41,2° по вертикали, от него считались замеры графического модуля (см. [вопрос об угле на бегу](../questions/fov-run-camera-angle.md)). Отладочной камеры в exe нет.
- Текстуры: таблица `0x011A0F28` — 4096 записей по 0x38 байт, битовая карта `0x011D8F28`; создание `0x00606C80` → `0x00618640`; поиск по хэшу имени `0x00611000` (карта `*0x012058E0`); загрузчик `tg4` `*0x01223558`. Занято 65–68 % в плотных зонах. Залить уровни загруженной текстуры того же размера и формата можно командой загрузчика `0x00619EF0` — без перезапуска.
- Шейдеры: 943 скомпилированных (808 `ps_3_0`, 135 `vs_3_0`) в `exe`; материал называет шейдер CRC-32 имени в нижнем регистре, таблица шейдеров `0x00E7B200` (записи по 0x24 байта; флаги `blend` 0x100, `lit` 1) — имена в `data/gf2/shaders.txt`. Сглаживания нет.
- Цепочка кадра: нормали → буфер света (8 бит на канал; солнце, точечные и прожекторы, три каскада теней) → освещённый проход (`albedo × свет × тон × 2`, туман, `pow(1/2.2)`) → постэффекты (блум, LUT 32³ `AlchemyLUTShader`) → интерфейс; порядок проходов снят записью вызовов D3D9 (этап 101): три цели 256×256 → глубина и нормали → карта теней 832×2496 (три каскада) → буфер света → освещённый проход с прозрачным и интерфейсом → постэффекты. За кадр 5 800–8 800 вызовов отрисовки (Гавана и Майами — около 5 800–6 000, Нью-Йорк — 8 800; 1280×720): карта теней 22–37 %, глубина и нормали 26–36 %, освещённый проход 32–38 %; 45 целей рендера. 68–84 % вызовов делает `0x0042FC70` (список элементов прохода) — см. [вызовы отрисовки](../exe/draw-calls.md). Кэш состояний у игры есть: лишних вызовов состояний 3–6 %. Тональная кривая на стенде плоская (`t = 1`).
- Сообщения кадра: `iMsgBeforeRender`, `iMsgPreRender`, `iMsgDoRender`, `iMsgDoRenderFullScreen`, `iMsgPreShowRaster` (хэши — `0x0040D640`).
- Графический модуль `doctor_render.asi` (этап 59; проверка издания — 13 мест): время суток без потери остатка (`0x00826BF5`), `INTERVAL_ONE` вместо `TWO` (`0x006075E2`) и ограничитель со сном, свой предел частоты, множитель угла обзора в `0x00425FE4`, FXAA и резкость перехватом копии кадра в `0x00608E90`. FSR 1 не сделан. Настройки — `doctor_render.cfg`. С этапа 101 — объединение идущих подряд вызовов отрисовки без смены состояния в один (`draw_merge`, по умолчанию выключено) и запись кадра D3D9 (`draw_trace`) — [опыт](../experiments/draw-call-merging.md). Под DXVK объединение убирает 15–26 % вызовов, но времени не экономит: поток рендера с ним занят на 5–8 % больше — [вопрос о Direct3D 9 драйвера](../questions/draw-merge-on-native-d3d9.md).

- Поверх кадра рисуют моды через платформу (этап 116): место `0x00608E9E` перед `Present`, после копии сцены и постэффектов; проверка `doctor_render` по `0x00608E90` сужена до 14 байт, у него экспорты `doctor_render_own_state_block` и `doctor_render_state_changed` для блока состояний платформы — см. [нативные моды](native-mods.md).

## Что неизвестно

- Место между сценой и интерфейсом в освещённом проходе (HUD проходит через фильтр постэффектов) и соответствие проходов сообщениям кадра — [вопрос](../questions/render-pass-command-order.md).
- Что игра проверяет [запросами видимости](../questions/occlusion-queries.md); [инстансинг реквизита](../questions/draw-instancing.md) не сделан.
- Как 23 вызывающих `0x00606C80` переносят отказ при полной таблице текстур.
- Цвет солнца и доля рассеянного света задаются кодом, значения не найдены; тени в сумерки, атрибуты 2, 3 `LightingTODMessage`.
- Ролики при 21:9, полноэкранный режим с `INTERVAL_ONE`, `CreateStateBlock` на Windows с `PUREDEVICE` — не проверены; признак «идёт ролик» для угла обзора не найден.
