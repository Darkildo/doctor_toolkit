# Память

Игра — 32-битный процесс без флага Large Address Aware: 2 ГБ адресов на всё. Ресурсы выделяются по политике памяти, записанной в заголовке ресурса.

## Что известно

- Политика памяти — первое слово `SHDR` ресурса: SDBM имени. Названы три (`data/gf2/mem_policies.txt`): `default` (`0x5393AC01`), `volatile` (`0x67456B5C`), `geometry` (`0x38B2B8D2`). Без имени: `0x67A6002E` (`meshvolatile`), `0x7A10372B` (`sbk`), `0x58B1F4D8` (`auc`).
- Политика и выравнивание зависят только от типа (без исключений в корпусе): `mesh` — `geometry`, 0x80; `meshvolatile` — `0x67A6002E`, 0x80; `material` — `volatile`, 0x10; `vfx` — `default`, 0x20; `sbk` — `0x7A10372B`, 0x1000; `auc` — `0x58B1F4D8`, 0x10; `cec`, `dlg`, `grt` — `default`, 0x40; остальные 33 типа — `default`, 0x10.
- Игра регистрирует пять политик (`0x0067E140`): `0x5393AC01`, `0x9DC401B7`, `0x7A10372B`, `0x38B2B8D2`, `0x67A6002E`. Распределитель по политике — `0x00420BE0`, таблица `0x01206B20`; загрузчик выделяет `data_size` байт с выравниванием из `SHDR` (см. [потоки](stream-loading.md)).
- Бюджет потоковой загрузки: поле `data_size` записи TOC (сумма распакованных размеров) игра использует только для бюджета памяти (`0x0088BB70`), не для выделения. Игра запускается и с заниженным `data_size`.
- Флаг: `IMAGE_FILE_HEADER.Characteristics = 0x0103`, без `0x20` (`LARGE_ADDRESS_AWARE`); `DllCharacteristics = 0`, контрольной суммы нет.
- Сколько занято (Нью-Йорк, Wine 9.0, DXVK): игра закоммитила 727 МБ; по городу за 8 телепортов 705–728 МБ, роста нет. Без LAA в нижних 2 ГБ не отображено 505 МБ (самый большой кусок 362 МБ): ещё около 550 МБ занимают библиотеки Linux (все установленные драйверы Vulkan). Только нужный драйвер (`VK_DRIVER_FILES`) — минус 300 МБ.
- Текстуры: таблица на 4096 записей, занято 2 674–2 795, оценка 160,6–164,2 МБ; все текстуры потоков в пуле `MANAGED` — копия каждой в памяти процесса (DXVK держит отображёнными не больше 128 МБ). См. [рендер](render.md).
- LAA работает: копия `exe` с `Characteristics` `0x103` → `0x123` в зеркале папки игры (`play --laa`); проверка издания модулей на флаг не смотрит. С резервом нижней памяти (`low_memory`) кучи игры (384 МБ) легли выше 2 ГБ; 8 телепортов по Нью-Йорку без ошибок. Флаг читает загрузчик ОС — модуль внутри игры его не поменяет.
- Телепорт на 800 м читает 24–26 МБ потоков зон.
- Статистика памяти движка печатается через `OutputDebugStringA` (`0x0064D030`), на стенде в уровне игра её не зовёт.

## Что неизвестно

- Имена трёх политик памяти; где регистрируются `volatile` и `0x58B1F4D8` (в списке `0x0067E140` их нет).
- Устройство куч игры в документах не разобрано: известны только суммарные числа профиля.
- С LAA не проверены долгая игра, миссии, сохранения; риск — сравнения указателей со знаком.
- Таблица текстур больше 4096 — не делалась.
