# Платформа нативных модов: что она зовёт и патчит в exe

Адреса — виртуальные, издание PC 1.0.789.0. Всё, чем модуль `doctor_platform.asi` пользуется в `godfather2.exe`: регистрация и создание объектов классов, связки Lua, функции шины. Байты каждого места модуль проверяет до установки (`platform::CHECKS`, 37 мест).

| Адрес | Что это | Источник |
|---|---|---|
| `0x0068AB50` | старт приложения: регистрация классов и прочее; зовётся из `0x0068D010` | asi-platform.md §2 |
| `0x0068AB55` | вызов `0x00688AF0` (регистрация классов движка) — платформа подменяет его: после регистрации зовёт `doctor_mod_init` модов | asi-platform.md §2 |
| `0x00483410` | создание объекта по записи SimGroup: класс из реестра, `фабрика(запись, доп)`, компоненты по адресу «объект + размер», затем читатель — метод `+4` объекта | asi-platform.md §2 |
| `0x004838C0` | поиск класса в реестре по хэшу (номер записи или −1) | asi-platform.md §2 |
| `0x004837E0` | вставка записи в массив реестра классов с ростом массива | asi-platform.md §2 |
| `0x0043B910` | память объекта `(размер, доп)`: аллокатор SimManager `*0x01223410 + 0x2D4`, метод `+0`, выравнивание 16 | asi-platform.md §2 |
| `0x00684A50` | фабрика класса `TriggerAuto`: память 0x60 байт и конструктор `0x00477DB0` | asi-platform.md §2 |
| `0x0046C560` | удаляющий деструктор `Base` (`thiscall`, флаги): тело `0x0046C640`, при бите 0 освобождает память | asi-platform.md §2 |
| `0x0046C640` | тело деструктора `Base`: возвращает таблицы `Base`, обрывает слабые ссылки `+0x4C`, снимает подписки слушателя (`0x004083D0`) | asi-platform.md §2 |
| `0x00E3280C` | данные: таблица методов `Base`, 7 методов (деструктор, читатель `0x0046C710`, `0x0043A950`, `0x0046C720`, `As` `0x0046C460`, два пустых) | asi-platform.md §2 |
| `0x00E32828` | данные: таблица слушателя `Base` (`объект + 0x3C`), 4 метода: деструктор `0x0046C780`, обработчик `0x0046C6A0`, выключить `0x00461F30`, включить `0x0046C740` | asi-platform.md §2 |
| `0x00E32838` | данные: третья таблица `Base` (`объект + 0x48`), один метод — деструктор `0x0046C770` | asi-platform.md §2 |
| `0x0046C6A0` | обработчик слушателя `Base`: передаёт сообщение компонентам объекта (`0x00482A50`) | asi-platform.md §2 |
| `0x0043B140` | обход неупакованной записи объекта: пропуск меток `0x20000000`, `0x40000000`, раздел класса по метке `0x80000000` | asi-platform.md §2 |
| `0x0043E2E0` | `LuaManager::AddBinder(связка)`: ставит связку в список `+0x38` и зовёт её метод `+4` для состояний `+0x18` и `+0x1C`; 20 мест вызова | asi-platform.md §3 |
| `0x0043E380` | `LuaManager`: убрать связку, зовёт её метод `+8` для обоих состояний | asi-platform.md §3 |
| `0x00681840` | конструктор игрового объекта: конструктор LuaManager и 18 связок движка подряд | asi-platform.md §3 |
| `0x00681860` | вызов конструктора LuaManager `0x0043E140` — платформа подменяет его: после конструктора добавляет свою связку | asi-platform.md §3 |
| `0x0046A240` | конструктор одной из связок движка (таблица `0x00E32490`: деструктор `0x0046A260`, регистрация `0x0046A2C0`, снятие `0x0046A3D0`) | asi-platform.md §3 |
| `0x00408A1A` | место фильтра рассылки платформы: 10 байт `xor al, al; test esi, esi; je 0x00408AE4` внутри `0x00408A00`; сообщение в `EDX` | asi-platform.md §4 |
| `0x00408A24`, `0x00408AE4` | рассылка: продолжение поиска записи таблицы; конец функции (`pop edi; pop esi; pop ecx; ret`) | asi-platform.md §4 |
| `0x009C8E50` | `operator new` игры (`cdecl`, размер) | asi-platform.md §4 |

## Что неизвестно

Путь неупакованных записей не проверен в игре: в её файлах таких записей нет. Хранилище состояния для объектов мода и классы-сущности не разбирались — см. вопросы ниже.
