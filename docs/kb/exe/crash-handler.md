# Перехват падений: фильтр исключений и места модуля

Адреса — виртуальные, издание PC 1.0.789.0. Модуль `doctor_crash.asi` ставит фильтр необработанных исключений процесса и два своих перехвата — шины сообщений и ошибок Lua — в местах, которые модуль связи и графический модуль не правят и не сверяют. По ним он пишет отчёт о падении. Места сверяются при проверке издания.

| Адрес | Что это | Источник |
|---|---|---|
| `0x00BB527B` | фильтр необработанных исключений C-рантайма игры: для исключения C++ (`0xE06D7363`, сигнатуры `0x19930520`–`0x19930522`, `0x01994000`) зовёт `terminate`, иначе возвращает 0 («искать дальше»); прежний фильтр не зовёт. Игра ставит его при старте, после загрузки модулей ASI | crash-reports.md §3; game-bench.md §37 |
| `0x00BB52B8` | место со ссылкой на `0x00BB527B` (установка фильтра рантаймом) | crash-reports.md §3 |
| `0x00408A11` | `and esi, 0xFFF` в отправке шины `0x00408A00`: хэш в `ECX`, сообщение в `EDX`, адрес возврата отправки — `[esp+0xC]`; перехват модуля падений (6 байт), продолжение — `0x00408A17` | crash-reports.md §4; crates/doctor-toolkit-live/src/crash.rs |
| `0x00408A17` | продолжение шины после перехвата модуля падений | crates/doctor-toolkit-live/src/crash.rs |
| `0x00635A85` | продолжение `luaD_throw` (`0x00635A80`) после пяти байт, занятых переходом модуля падений | crash-reports.md §4; crates/doctor-toolkit-live/src/crash.rs |

## Что известно

- `luaD_throw` получает `L` в `ECX` и код ошибки в `EDX`; текст ошибки в этот момент — на вершине стека Lua. Через неё проходят все ошибки Lua, и те, что скрипт ловит своим `pcall`.
- Порядок загрузки модулей не важен: на стенде модуль падений загрузился раньше модуля связи, проверка издания обоих прошла.
- Таблица имён адресов для отчётов — `data/gf2/exe_symbols.tsv` — собирается из таблиц заметок этого раздела командой `doctor-toolkit kb-gen`.

## Что неизвестно

- На Windows модуль не проверялся (стенд — Wine).
