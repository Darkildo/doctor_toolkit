# Очередь чтения файлов и буфер пути

Адреса — виртуальные, издание PC 1.0.789.0. Файлы игра читает библиотекой `rw::core::filesystem`: запросы «открыть», «прочитать», «закрыть» ставятся в очередь, их выполняет рабочий поток. Путь к файлу собирается в буфере 256 байт на стеке без проверки длины — отсюда падение при длинной папке игры.

| Адрес | Что это | Источник |
|---|---|---|
| `0x00AC3290` | цикл рабочего потока файлов: берёт запрос из очереди (`+8` — голова), переставляет по положению на диске (`0x00AC2DF0`), зовёт операцию `[запрос+0x44]`, пишет результат в `+4`, зовёт обратный вызов `[запрос+0x18]` | analysis/story.md §9 |
| `0x00AC333A` | адрес возврата в цикле рабочего потока файлов, за вызовом операции запроса: первый адрес игры в стеке падения из-за длинного пути папки | analysis/story.md §9; game-bench.md §40 |
| `0x00AB72C0` | вход потока: имя потока исключением `0x406D1388`, затем функция потока | crash-reports.md §9 |
| `0x00AC35A0` | запуск рабочего потока файлов (поток с функцией `0x00AC3290`) | analysis/story.md §9 |
| `0x00AC3610` | постановка запроса в очередь файлов по приоритету `+0xC` и положению на диске | analysis/story.md §9 |
| `0x00AC2810` | отмена запроса файлов, ещё стоящего в очереди (состояние −1, обратный вызов) | analysis/story.md §9 |
| `0x00AC2870` | ожидание запроса файлов до срока (`GetTickCount`), возвращает состояние `+4` | analysis/story.md §9 |
| `0x00AC3AE0` | операция запроса «открыть файл»: выделяет описатель (0x28 байт) и зовёт `0x00AC37C0` | analysis/story.md §9 |
| `0x00AC37C0` | конструктор описателя файла: `sprintf(буфер[256], "%s/%s", папка игры, имя)` без проверки длины; буфер — сразу под адресом возврата | analysis/story.md §9 |
| `0x00AC3B80` | запрос «закрыть файл» (операция `0x00ABFC20`) | analysis/story.md §9 |
| `0x00AC3D30` | запрос «прочитать из файла» (операция `0x00ABD5E0`): буфер, смещение, размер | analysis/story.md §9 |
| `0x00AC2090` | менеджер файловой библиотеки (`*0x0113D18C`), создаётся при первом обращении | analysis/story.md §9 |

Запрос: `+0` следующий, `+4` состояние (0 в очереди, 1 выполнен, −1 отменён), `+0xC` приоритет, `+0x10` описатель, `+0x14` данные владельца, `+0x18` обратный вызов, `+0x20` смещение, `+0x28` размер, `+0x30` буфер или имя, `+0x38` прочитано, `+0x40` устройство, `+0x44` операция.

Правило длины: `папка + 1 + путь потока ≤ 255` символов; самый длинный поток игры — 142, значит папка до 112 символов безопасна (`doctor_toolkit::path_limit`).
