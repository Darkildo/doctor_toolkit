# База знаний: как пользоваться и как обновлять

`docs/kb/` — база знаний о The Godfather II (PC) и движке EARS: короткие заметки, связанные ссылками. Она для людей (Obsidian, GitHub) и для агентов (файлы, MCP). Начало — [карта](index.md).

Подробные описания форматов и систем остаются в `docs/formats/` и `docs/analysis/`. Заметка базы отвечает на три вопроса: что известно, на чём это держится, что читать дальше.

## Как читать

- **Obsidian.** Откройте папку `docs/` как хранилище (Open folder as vault). Настройки лежат в `docs/.obsidian/`: плагинов сообщества нет, граф раскрашен по статусу и типу заметки (оттенки красного и жёлтого — `unknown`, `hypothesis`, `partial`, `planned`; остальное — по разделу). Личные файлы `workspace*.json` в репозиторий не попадают.
- **GitHub и любой редактор.** Ссылки — обычные относительные ссылки Markdown, они работают везде.
- **Агенты.** Читайте файлы напрямую: [карта](index.md) → карта раздела → заметка. Через MCP-сервер тулкита: ресурс `doctor-toolkit://kb/index.md`, поиск `kb_search` (слова, `type`, `status`), чтение `kb_note` — см. [MCP](../mcp.md).

## Свойства заметки

Каждая заметка начинается со свойств (front matter). Все восемь обязательны:

| Свойство | Значение |
|---|---|
| `type` | тип заметки — по папке, см. таблицу выше |
| `status` | `known` — установлено; `partial` — известна часть; `hypothesis` — догадка, которую надо проверить; `unknown` — не известно; `planned` — запланированное исследование |
| `confidence` | на чём держится главное утверждение: `exe` — код исполняемого файла; `data` — файлы игры; `bench` — опыт в запущенной игре; `guess` — догадка |
| `editions` | издания игры, к которым относится заметка. Целевое издание одно: `["1.0.789.0"]`; другие не поддерживаются и не исследуются |
| `stages` | номера этапов проекта, которые создали или меняли заметку, и этапов, где вопрос запланирован |
| `sources` | откуда факты: путь от корня репозитория с разделом (`docs/formats/simgroup.md §8`, `data/gf2/logic_schema.toml`, `research/tunables.py`), адрес exe, опыт на стенде. Путь должен существовать |
| `tags` | метки латиницей в нижнем регистре, через дефис |
| `updated` | дата последней правки по существу, `ГГГГ-ММ-ДД` |

## Правила

1. **Ничего не выдумывать.** У каждого утверждения есть источник: адрес в exe (издание 1.0.789.0), файл данных или скрипт по корпусу, опыт на стенде — либо явная пометка «догадка» и статус `hypothesis`.
2. **Коротко.** Заметка — 10–40 строк. Длинное описание — в документ `docs/formats/` или `docs/analysis/`, а из заметки ссылка на него.
3. **Ссылки** — только относительные ссылки Markdown: `[шина сообщений](../engine/message-bus.md)`. Викиссылки `[[...]]` не используются: они не работают на GitHub.
4. **Один заголовок `# `** в заметке — её название.
5. **Нет сирот.** На каждую заметку ведёт ссылка из другой заметки: из карты, из списка папки или из связанной заметки.
6. **Открытый вопрос** (заметка `questions/` со статусом не `known`) обязан иметь раздел `## Следующий шаг`: что именно сделать, чтобы узнать ответ.
7. **Только публичное.** База входит в публичный репозиторий. В ней нельзя ссылаться на файлы, которых в публичном репозитории нет, и называть их; список таких файлов задан в одном месте — `CLOSED_PATHS` в `crates/doctor-toolkit/src/kb/mod.rs`, проверяет его `kb-lint`.
8. **Одно издание.** Адреса и наблюдения — только для PC 1.0.789.0.

## Как обновлять

После исследования (обязательно для каждого исследовательского этапа, см. [карту исследований](maps/research.md)):

1. Найдите заметки по теме: карта раздела, `kb_search` или поиск по файлам.
2. Вопрос решён — допишите ответ в заметку вопроса, смените `status` (`known`, `partial` или `hypothesis`) и `confidence`, добавьте источник и номер этапа в `stages`, обновите `updated`. Заметку не удаляйте: на неё ведут ссылки, а история вопроса полезна.
3. Появилось новое знание — допишите его в заметку подсистемы (`engine/`, `systems/`) или адресов (`exe/`) либо заведите новую по шаблону ниже и поставьте на неё ссылку из карты раздела или связанной заметки.
4. Выяснить не удалось — оставьте заметку-вопрос со статусом, тем, что уже проверено, и следующим шагом. Новые вопросы заводите сразу.
5. Опыт на стенде — заметка в `experiments/`: что проверяли, как, результат, что из этого следует.
6. Пополнили `data/gf2/` (имена классов, пины, сообщения, перечисления, смысл атрибутов, типы ресурсов) — пересоберите сгенерированные файлы и заметки: `doctor-toolkit types-gen` и `doctor-toolkit kb-gen`. Как обновлять сами данные типов — [граф логики](../logic-graph.md) §2.1.
7. Проверьте базу: `doctor-toolkit kb-lint`. В отчёте этапа перечислите изменённые заметки.

## Генератор и проверка

```sh
doctor-toolkit kb-gen           # пересобрать сгенерированные заметки
doctor-toolkit kb-gen --check   # ничего не писать; ошибка, если заметки устарели
doctor-toolkit kb-lint          # проверить всю базу
```

Обе команды работают в рабочей копии репозитория (ищут `docs/kb` в текущей папке и выше; `--root` задаёт корень явно).

`kb-gen` пишет:

- `classes/<Класс>.md` — заметку на каждый класс SimGroup из `data/gf2/sim_classes.txt` (имена), `simgroup_schema.txt` (виды значений), `logic_schema.toml` (категория, пакеты, пины), `attr_types.toml` (смысл значений), `tunables.toml` (параметры игры); класс без имени получает файл `class-<хэш>.md`;
- `resources/<тег>.md` — заметку на каждый тип ресурса из `type_tags.txt` и `resource_types.ru.toml`;
- `messages/engine-messages.md` — полный список сообщений движка из `engine_messages.txt` с тем, кто их слушает и шлёт в SimGroup;
- `messages/game-messages.md` — сводку каталога сообщений файлов игры (`game_messages.tsv`, `messages.toml`);
- `enums/<ключ>.md` — заметку на каждое перечисление из `enums.toml`: значения, хэши, источник, атрибуты, где оно встречается (`attr_types.toml`);
- `<папка>/index.md` — список заметок каждой папки.

Сгенерированная заметка помечена строкой `<!-- kb-gen: generated … -->`. Руками в ней правится только раздел между метками `<!-- kb:manual:begin -->` и `<!-- kb:manual:end -->` — он сохраняется при пересборке; всё остальное генератор перезапишет. Повторный запуск без изменений данных ничего не меняет; `updated` сдвигается только у заметок, текст которых изменился. Заметка класса или типа, которого больше нет в данных, удаляется.

`kb-lint` проверяет: схему свойств и соответствие типа папке, один заголовок, битые ссылки и несуществующие источники, сирот, вопросы без следующего шага, викиссылки, упоминания закрытых файлов. Проверка идёт в тестах (`cargo test -p doctor-toolkit --test kb`: база без замечаний и сгенерированные заметки не устарели) и в CI.

Два-три предложения: что это и зачем.

## Что известно

- Факт с адресом, числом или именем — как в источнике.

## Что неизвестно

- Коротко; на каждый существенный пункт — заметка в `questions/`.

## Подробнее

- [Документ](../../analysis/live-link.md) §5
