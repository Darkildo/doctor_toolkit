# Моды

Мод — это один файл ZIP с манифестом и новыми данными ресурсов, которые он
заменяет или добавляет (с версии 2 формата — и новые потоки). По сути это
экспортированное рабочее пространство
(`docs/workspace.md`): те же ключи ресурсов, те же хэши данных и оригиналов.
Моды ставит менеджер модов: он хранит установленные моды, их порядок и
записывает в игру общий результат включённых модов теми же средствами, что и
рабочее пространство (резервные копии, атомарная запись, размеры в TOC).
С этапа 46 включённые моды можно и не записывать: `doctor-toolkit play ИГРА
--mods` собирает их результат вне папки игры, а модуль живой связи
подставляет игре эти файлы на время запуска (`docs/guide/11-play.md` §11.11,
`docs/analysis/live-link.md` §14).

Код: `crates/doctor-toolkit/src/mods/` (библиотека), команды
`doctor-toolkit mods …` и `doctor-toolkit integrity` (CLI), окно **Mods**
редактора и отдельная программа для игроков Open Mod Manager — файл
`open-mod-manager` (`crates/doctor-toolkit-mods`, общая панель для обоих).

## 1. Формат мода

```text
example.zip
├── mod.json                 манифест
├── preview.png              картинка (необязательно; .png или .jpg)
└── payloads/<sha256>        новые данные ресурсов, по одному файлу на разное содержимое
```

Данные лежат в распакованном виде, сжаты deflate внутри ZIP. Имя файла данных —
SHA-256 его содержимого; одинаковые данные хранятся один раз.

### 1.1 `mod.json`

```json
{
  "format": "doctor-toolkit-mod",
  "format_version": 1,
  "id": "restored-hq-billboards",
  "name": "Restored HQ Billboards",
  "version": "1",
  "author": "cha1r",
  "description": "…",
  "url": "https://…",
  "preview": "preview.png",
  "game": {
    "profile": "The Godfather II (PC)",
    "executable_size": 13840384,
    "executable_sha256": "…"
  },
  "resources": [
    {
      "key": "gf2/queens/local:tg4d:00000000.4802e0a3.3935459f.1848baba",
      "payload": { "sha256": "…", "size": 786464 },
      "original": { "sha256": "…", "size": 786464 },
      "storage": "raw",
      "label": "Import texture billboard"
    }
  ],
  "converted_from": "vpat"
}
```

| Поле | Смысл |
|---|---|
| `format`, `format_version` | `doctor-toolkit-mod`; 1 — только замены, 2 — ещё добавленные ресурсы и новые потоки (§1.2). Мод более новой версии формата не открывается, сообщение предлагает обновить программу |
| `id` | идентификатор: 1–64 символа `a-z`, `0-9`, `-`, `_`. Установка мода с тем же `id` — обновление: место в порядке загрузки и включённость сохраняются |
| `name`, `version`, `author`, `description`, `url` | метаданные для игрока; `url` только `http://` или `https://` |
| `preview` | имя картинки в архиве: простое имя файла, `.png`, `.jpg` или `.jpeg` |
| `game.profile` | профиль игры; мод для другого профиля не устанавливается |
| `game.executable_*` | исполняемый файл игры, на которой мод сделан. Несовпадение только сообщается: пригодность проверяется по ресурсам |
| `resources[].key` | ключ ресурса `поток:тип:ids` (`docs/workspace.md`, §1) |
| `resources[].payload` | новые данные: SHA-256 и размер |
| `resources[].original` | данные ресурса в игре, для которой сделан мод. По ним проверяется совместимость |
| `resources[].storage` | `raw` или `refpack`; поля нет — как у оригинала |
| `resources[].added` | есть у **добавленного** ресурса (версия 2), §1.2 |
| `streams` | новые потоки (версия 2), §1.2 |
| `converted_from` | откуда мод получен, если не собран из рабочего пространства (`vpat`) |

### 1.2 Добавленные ресурсы и новые потоки (версия 2)

Версия 2 переносит то, что рабочее пространство умеет добавлять
(`docs/workspace.md`, §3.4; `docs/analysis/new-resources.md`): новые ресурсы
в существующих потоках и новые потоки с записями в TOC. Поля те же, что в
манифесте рабочего пространства версии 2:

```json
{
  "format_version": 2,
  "resources": [
    {
      "key": "gf2/level:metamodel:5c7e0a11",
      "payload": { "sha256": "…", "size": 4096 },
      "original": { "sha256": "e3b0c442…", "size": 0 },
      "added": { "mem_policy": 1402186753, "alignment": 16,
                 "before": "gf2/level:mesh:00000003", "order": 3000000 }
    },
    {
      "key": "gf2/doctor/props:mesh:7a3d11c2",
      "payload": { "sha256": "…", "size": 52000 },
      "original": { "sha256": "e3b0c442…", "size": 0 },
      "added": { "mem_policy": 951236818, "alignment": 128, "order": 4000000 }
    }
  ],
  "streams": [
    {
      "name": "gf2/doctor/props",
      "guid": "1f2e3d4c5b6a7988444f43544f52544b",
      "hash": 2271560481,
      "parent": "gf2/level",
      "with_parent": true,
      "tocs": ["gf2/level.toc"]
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `added.mem_policy`, `added.alignment` | политика памяти и выравнивание из заголовка `SHDR`; выравнивание — степень двойки до 0x10000 |
| `added.before` | ключ ресурса того же исходного потока, перед которым встаёт новый; нет — в конец. Для ресурса нового потока не задаётся |
| `added.order` | порядок среди добавленных в одно место |
| `original` добавленного | пустые данные (SHA-256 пустой строки, размер 0) |
| `streams[]` | имя, GUID (32 шестнадцатеричные цифры) и его свёртка `hash`, родитель, `with_parent` (дочерний поток, флаги TOC `0,0,5,0`; иначе `0,0,1,0`), список TOC и другой родитель в отдельных TOC (`toc_parents`) |

В новом потоке могут быть только добавленные ресурсы. Добавлять можно и в
поток, который создаёт другой мод (дополнение к моду): тогда этот мод должен
быть включён.

**Совместимость версий.** Мод, который только заменяет ресурсы, собирается
как версия 1 и читается прежними программами. Версия 1 с полями `added` или
`streams` отвергается (старая программа приняла бы добавленный ресурс за
замену). Неизвестные поля, как и раньше, пропускаются.

### 1.3 Чтение недоверенного файла

Мод присылают незнакомые люди, поэтому чтение (`mods::package`) проверяет всё:

| Проверка | Предел или правило |
|---|---|
| Число записей в ZIP | не больше 250 016 |
| Повторяющиеся имена записей | отказ |
| Расхождение локальных заголовков и центрального каталога | отказ |
| Имена записей | отказ для `..`, `.`, пустых частей, абсолютных путей, `\`, `:`, управляющих символов |
| Символические ссылки, шифрование | отказ |
| Сжатие | только stored и deflate |
| `mod.json` | не больше 32 МиБ, проверка всех полей и длин строк |
| Один ресурс | не больше 512 МиБ (самый большой ресурс GF2 — около 26 МиБ) |
| Все данные мода | не больше 8 ГиБ, не больше 250 000 ресурсов |
| Картинка | не больше 8 МиБ |
| Имя нового потока (по нему создаётся файл `<имя>.str`) | части из `a-z`, `0-9`, `_`, `-`, `.` через `/`; отказ для пустых частей, `.` и `..`, `\`, `:`, абсолютных путей, заглавных букв, пробелов, имён внутри `_doctor_toolkit` и `_toolkit`, имён устройств Windows (`con`, `aux`, `com1`…) и частей, кончающихся точкой |
| TOC нового потока | 1–64 разных пути вида `поток.toc` по тем же правилам; другой родитель — только для своих TOC |
| Новые потоки | не больше 10 000; имена и хэши не повторяются, хэш не 0, GUID — 32 шестнадцатеричные цифры, родитель — не сам поток и не другой новый поток мода |
| Добавленный ресурс | `original` — пустые данные; выравнивание — степень двойки до 0x10000; `before` — ресурс того же потока, не сам ресурс; в новом потоке — без `before` |
| Замена в новом потоке своего же мода | отказ: в новом потоке нет оригиналов |
| Один GUID у двух добавленных ресурсов мода с разными данными | отказ (игра загрузит только один) |
| Версия 1 с `added` или `streams` | отказ |

Файлы никогда не извлекаются по имени из архива: читаются только `mod.json`,
картинка, названная в нём, и `payloads/<sha256>` для хэшей из манифеста. Размер
записи сверяется с манифестом до чтения, а чтение ограничено этим размером:
ZIP-бомба, у которой в заголовке написано 300 байт, а внутри 64 МиБ нулей,
останавливается на пределе. Каждые данные сверяются с SHA-256. Лишние записи
игнорируются и показываются как предупреждения. Всё это проверено тестами
`malicious_packages_are_refused`, `malicious_version_2_manifests_are_refused`
и `malformed_vpat_patches_are_refused`.

## 2. Сборка мода

Мод собирается из изменений рабочего пространства: из всех или из выбранных.

```sh
doctor-toolkit mods build "$GAME" -o billboards.zip --name "HQ Billboards" \
    --mod-version 1.2 --author me --url https://example.org --preview shot.png
doctor-toolkit mods build "$GAME" -o text.zip --name "Text fix" gf2/text/dd7d7050
```

Без `--id` идентификатор получается из названия (`HQ Billboards` →
`hq-billboards`). Ключи в конце команды выбирают изменения (ключ или часть
ключа). Добавленные ресурсы и новые потоки рабочего пространства попадают в
мод (версия 2); при выборе ключей новый поток берётся, если выбран ресурс в
нём. `doctor-toolkit mods info FILE` показывает содержимое мода, версию
формата и новые потоки и проверяет все данные; с `--resources` — список
ресурсов (добавленные помечены `added`, с местом `before`).

В редакторе: окно **Mods** → раздел **Build a mod from the workspace**:
название, версия, автор, описание, адрес, картинка; **Save mod file…**
записывает ZIP, **Install as mod** ставит рабочее пространство в менеджер
этой игры (см. §4).

## 3. Менеджер модов

```text
<игра>/_doctor_toolkit/mods/
├── registry.json     установленные моды в порядке загрузки, включён или нет
├── applied.json      что менеджер записал в игру (формат как у рабочего пространства)
└── <id>/             установленный мод
    ├── mod.json
    ├── preview.png
    └── payloads/ab/ab12…
```

Установка распаковывает мод во временный каталог `.staging-<pid>`, проверяет
каждый ресурс и только потом переименовывает его в `<id>/`; прерванная
установка не оставляет полумода. При установке мод сразу сверяется с игрой, и
несовпадения показываются. Игра при установке не меняется.

| Действие | CLI | Окно |
|---|---|---|
| Список | `mods list GAME` | таблица |
| Установить `.zip` или `.vpat` | `mods install GAME FILE… [--disabled]` | **Install mod…** |
| Включить, выключить | `mods enable/disable GAME ID…` | флажок |
| Порядок загрузки | `mods move GAME ID POSITION` (с 1) | **Up**, **Down** |
| Конфликты | `mods conflicts GAME [--all]` | раздел **Conflicts** |
| Совместимость | `mods check GAME` | столбец State, подробности мода |
| Сравнение с игрой | `mods status GAME` | строка состояния |
| Записать в игру | `mods apply GAME [--force] [--ignore-compatibility]` | **Apply to game** |
| Вернуть оригиналы | `mods unapply GAME [--force]` | **Restore originals** (два щелчка) |
| Удалить | `mods uninstall GAME ID… \| --all` | **Uninstall** (два щелчка) |
| Сохранить установленный мод в файл | `mods export GAME ID -o FILE` | — |

**Порядок загрузки.** Моды применяются по порядку списка: если два включённых
мода меняют один ресурс, используются данные того, что ниже. Конфликт — ключ
ресурса, который меняют или добавляют несколько модов; показываются все
такие моды и победитель, а одинаковые данные помечаются как безвредное
пересечение.

**Столкновения** (`Clash`; `mods conflicts`, `mods check`, раздел
**Conflicts**) — то, что порядком загрузки не решается:

| Столкновение | Что делается |
|---|---|
| два мода создают поток с одним именем по-разному (хэш, родитель, TOC, флаги) | `apply` отказывает, пока оба включены |
| то же, но одинаково (название операции не в счёт) | безвредно: ресурсы обоих модов ложатся в один поток |
| два мода создают разные потоки с одним хэшем | `apply` отказывает |
| два мода добавляют ресурсы с одним GUID под разными ключами и с разными данными | `apply` отказывает (игра загрузит один); с одинаковыми данными — безвредно, игра делит ресурс |
| мод добавляет ресурсы в поток игры, ресурсы которого заменяет другой мод | только сообщение: записываются оба, автору стоит проверить, что добавленное подходит к заменённому |

**Совместимость.** Перед записью каждый ресурс каждого включённого мода
сверяется с оригиналом игры — с тем файлом, из которого поток будет
пересобран (резервная копия или сам файл):

| Результат | Что делается |
|---|---|
| потока нет в игре, ресурса нет в потоке | запись невозможна, мод нужно выключить |
| данные оригинала отличаются от `original` мода | отказ; `--ignore-compatibility` (флажок в окне) записывает всё равно |
| исполняемый файл не тот, на котором сделан мод | только предупреждение при установке; известные издания называются по имени (`doctor_toolkit::edition`, «the mod was made for another edition of the game (PC 1.0.764.0, retail DVD …; this game is PC 1.0.789.0 …)») |
| добавленный ресурс уже есть в потоке | запись невозможна |
| GUID добавленного ресурса занят ресурсом игры с другими данными (проверяется по всей игре, по оригиналам; ~2 с на GF2) | запись невозможна; с теми же данными — можно (общий ресурс) |
| добавленный ресурс — в потоке, которого нет ни в игре, ни среди новых потоков включённых модов | запись невозможна |
| замена ресурса в потоке, который создаёт другой мод | запись невозможна: в новом потоке только добавленные ресурсы |
| ресурса `before` нет в потоке | только сообщение: ресурс встаёт в конец |
| новый поток уже есть в игре (файл или запись TOC) | запись невозможна |
| хэш нового потока занят в TOC, TOC нет в игре, родителя нет в TOC | запись невозможна |

Потоки и TOC, которые создал или дописал сам менеджер, сверяются по
оригиналам (резервным копиям), поэтому повторная проверка после `apply` не
находит «занятых» имён и хэшей.

**Запись** (`apply`) пересобирает каждый затронутый поток из оригинала со
всеми выигравшими данными включённых модов — той же функцией, что и
рабочее пространство (`workspace::deploy`): проверки до первой записи,
резервные копии в `_doctor_toolkit/backups/`, атомарная замена файлов, размеры
потоков во всех TOC. Поток, который больше ни один включённый мод не меняет,
возвращается к оригиналу побайтно. Поток, изменённый другой программой,
перезаписывается только с `--force`. Выключение или удаление мода вступает в
силу при следующем `apply`.

Добавленные ресурсы вставляются при той же пересборке (`ustream::rebuild_with`).
Новый поток пишется с нуля, в его TOC добавляются запись имени, файловая
запись и, для дочернего потока, ссылка у родителя; TOC пересчитывается от
оригинала. Поток, который не создаёт больше ни один включённый мод, удаляется,
и его TOC возвращаются к оригиналу побайтно. Проверка целостности называет
файл созданного потока «changed by the mod manager».

**Возврат оригиналов** (`unapply`) возвращает каждый поток, записанный
менеджером, и его размеры в TOC, удаляет созданные потоки; моды остаются
установленными. Тест `adding_mods_install_apply_and_restore_byte_for_byte`
проверяет побайтный возврат после `unapply`, выключения и удаления мода,
`clashes_between_adding_mods_are_found_and_stop_applying` и
`adding_mods_that_do_not_fit_the_game_are_refused` — таблицы выше; корпусный
`cloned_models_and_new_streams_round_trip_on_copies` — что мод из рабочего
пространства с клонами модели и новым дочерним потоком даёт на копиях
настоящих потоков те же файлы, что и само рабочее пространство. Команда
`doctor-toolkit restore` по-прежнему возвращает из резервных копий все файлы,
которые менял тулкит.

## 4. Моды и рабочее пространство

Рабочее пространство редактора и менеджер модов **не пишут в игру
одновременно**:

- `mods apply` отказывает, пока рабочее пространство игры
  (`_doctor_toolkit/workspace`) держит свои изменения в файлах игры, — даже с
  `--force`. Сообщение предлагает вернуть оригиналы (`workspace revert --game`
  или **Revert game** в окне Changes).
- `workspace apply` (и прямой режим) отказывает, пока менеджер держит моды в
  игре, и предлагает `mods unapply` или установку рабочего пространства как мода.
- Рабочее пространство в другом каталоге (`--dir`) так не проверяется, но его
  запись менеджер видит как изменение другой программой (поток отличается от
  резервной копии) и без `--force` не трогает; то же в обратную сторону.

Почему так: у каждого владельца своя запись `applied.json`, и общий файл,
который пишут двое, превращается в конфликт при каждой записи. Чтобы
проверить свою работу вместе с другими модами, автор ставит рабочее
пространство как мод: `doctor-toolkit mods install-workspace GAME --name …`
или **Install as mod** в окне Mods. Мод встаёт последним в порядке загрузки
(выигрывает конфликты) и включается; повторная установка с тем же `id`
обновляет его. Проверено тестом
`the_workspace_and_the_mods_do_not_write_at_the_same_time`.

## 5. Патчи старого тулкита (`.vpat`)

Формат восстановлен по пяти патчам, которые старый тулкит поставил в игру
(`_toolkit/installed_patches/`), сравнением с изменёнными файлами игры и с
оригиналами в `_toolkit/backups/`. Код старого тулкита не использовался.
Смысл флагов, операций и блока ресурсов, адресуемых по типу, взят из сверки
с другим редактором игр EARS (этап 39) и
не противоречит пяти патчам: у всех флаги патча 0, версия потока 0, флаги
файла 0 или 1, операция 1 у всех 177 ресурсов. Числа little-endian, строки
оканчиваются нулём (Latin-1).

| Поле | Тип | Значение |
|---|---|---|
| магия | 4 байта | `VPAT` |
| версия формата | u32 | 1 |
| название | строка | `Restored HQ Billboards` |
| автор | строка | `cha1r` |
| версия патча | u32 | 1, 3, 4, 8 |
| игра | u32 | 2 — The Godfather II (как `type="2"` в `_toolkit/game_instance.xml`) |
| идентификатор патча | u32 | случайное число, выбранное при создании патча |
| флаги патча | u32 | 1 — поднимать версию при каждой правке; во всех пяти 0. На установку не влияют |
| число файлов | u32 | |
| **файл:** путь | строка | относительно каталога игры, с `\`: `gf2\queens\local.str` |
| версия потока | u32 | 0 |
| флаги файла | u32 | 1 — ничего особого, 2 — после списка идёт блок ресурсов по типу; в старых патчах 0. Другие биты — ошибка разбора |
| число ресурсов | u32 | |
| **ресурс:** ids | 4 × u32 | четыре идентификатора из `SHDR` |
| тип | u32 | `type_id` из `SHDR` |
| операция | u32 | 1 — заменить, 2 — удалить, 3 — добавить; 0 — ничего (пропускается). Другое — ошибка разбора |
| размер | u32 | |
| данные | байты | распакованные данные ресурса |
| **при флаге 2:** число | u8 | ресурсы, адресуемые по типу |
| **ресурс по типу:** тип, операция, размер | 3 × u32 | как выше, без ids |
| данные | байты | |

Ресурс по типу — единственный ресурс этого типа с нулевыми ids в потоке. В
игре нулевые ids только у таких типов, и каждый встречается не больше одного
раза на поток: `simgroup` (1 856 потоков), `covernodetable` (`0xDF14DA75`,
682), `lighttoc` (30), `variabledictionary` (26), `bricknmortarres` (3).
Если в потоке два таких ресурса одного типа, установка отказывает.

Ресурс указывается так же, как ключ ресурса: поток, тип и четыре ids, поэтому
патч переводится в мод без догадок. Файл читается целиком структурно с
проверкой границ (размеры не выходят за файл, после последнего ресурса нет
данных, не больше 10 000 файлов и 250 000 ресурсов).

**Сверка с игрой.** Для каждого из четырёх изменённых потоков каждый ресурс
текущего файла сравнён с оригиналом и с данными патчей в порядке установки
из `game_instance.xml`:

| Патч | Ресурсов | Найдено в игре | Результат |
|---|---|---|---|
| Beta Weapon Icons | 1 (`apx`) | 1 | данные в игре равны данным патча |
| Improved Effects | 42 (текстуры) | 42 | равны |
| Restored HQ Billboards | 6 + 2 (текстуры) | 8 | равны |
| US Font Mod | 6 + 6 (текстуры, шрифт) | 0 | ресурсов с такими ids в этой копии игры нет нигде (шрифты здесь — с другими ids); видимо, патч для другого издания |
| Improved Weapons | 114 (текстуры) | 114 | равны |

Остальные ресурсы потоков не изменены. Старый тулкит переписывал поток
целиком, сохраняя **все** ресурсы несжатыми (`globals_global.str` вырос с
42 до 139 МБ, у `frontend.str` нет ни одной замены, но он тоже распакован), и
**не обновлял размеры в TOC**. Наша запись сохраняет сжатие оригинала и
обновляет TOC (тот же `globals_global.str` после установки тех же патчей —
81 МБ).

**Установка `.vpat`** (`mods install GAME patch.vpat`, **Install mod…**)
превращает патч в мод: `id` из названия, версия — номер версии патча,
`converted_from: "vpat"`. Оригинал каждого ресурса берётся из резервной копии
тулкита, иначе из резервной копии старого тулкита, иначе из файла игры.
Заменяемые ресурсы, которых нет в игре, пропускаются с предупреждением (как
это делал старый тулкит); если не подошёл ни один, установка отказывает.
Добавляемый ресурс становится добавленным ресурсом мода (версия 2, §1.2): в
конец потока, с политикой памяти и выравниванием первого ресурса того же типа
в потоке, а если такого нет — обычными для типа; добавляемый ресурс, который
в игре уже есть, заменяется с предупреждением. Удалять ресурсы игры мод не
умеет, поэтому патч с операцией «удалить» не устанавливается — сообщение
называет число таких ресурсов и первый из них. `mods info --resources`
показывает операцию каждого ресурса и пометку «by type». Установленный патч
можно сохранить как обычный мод (`mods export`).

**Переход со старого тулкита** (`mods import-old GAME`, кнопка **Import from
old toolkit**):

1. резервные копии старого тулкита копируются в `_doctor_toolkit/backups/`
   там, где у тулкита своей копии нет, и становятся оригиналами;
2. установленные патчи ставятся как моды в порядке `game_instance.xml`;
3. файлы игры не меняются. Изменённые старым тулкитом потоки теперь
   отличаются от оригинала, поэтому первая запись — `mods apply --force`
   (флажок **Overwrite files changed by other programs**). Она пересобирает
   потоки из настоящих оригиналов с теми же данными и правильными TOC.

На копии игры из символических ссылок (настоящая игра не менялась): 4 патча
стали модами (US Font Mod не подошёл), `apply --force` переписал 3 потока и
5 TOC за 2 с, `unapply` вернул оригиналы. Корпусный тест
`old_toolkit_patches_install_as_mods_on_copies` делает то же на копиях
оригиналов и проверяет каждый ресурс, размеры в TOC, экспорт мода и возврат
к оригиналам побайтно.

## 6. Проверка целостности

`doctor-toolkit integrity GAME` (кнопка **Check integrity**) проверяет каждый
поток и TOC и называет, кто его изменил:

| Состояние | Когда |
|---|---|
| original | равен резервной копии тулкита, старого тулкита или эталонному хэшу |
| changed by the mod manager | отличается от копии, и `mods/applied.json` говорит, что его записал менеджер |
| changed by the editor's workspace | то же для рабочего пространства игры |
| changed by the old toolkit | отличается от копии старого тулкита (или наша копия совпадает с ней) |
| changed by another program | отличается от копии тулкита, но никто из своих его не писал |
| differs from the reference list | отличается от эталонного хэша |
| not verified | ни копии, ни эталона: проверить не с чем |

Эталон — `_doctor_toolkit/reference.json`, размеры и SHA-256 оригиналов всех
потоков и TOC. Его записывает `integrity --save-reference` на заведомо
неизменённой игре (оригиналы берутся из резервных копий, где они есть).
Без `--full` файлы без копий сравниваются с эталоном только по размеру,
с `--full` — по хэшу (читается вся игра, ~9 ГБ). Готовый эталон для GF2 PC в
поставку не входит: изданий несколько, а копия на этой машине уже менялась.

Ещё проверка показывает установленные патчи старого тулкита и остатки
прерванной записи (`*.doctor-toolkit-tmp`, игра их не читает).
`integrity --adopt-old-backups` делает только шаг 1 перехода со старого тулкита.

## 7. Open Mod Manager (`open-mod-manager`)

```sh
cargo run --release -p doctor-toolkit-mods --bin open-mod-manager -- "$GAME"
```

Отдельная программа для игроков, часть doctor_toolkit («Powered by Doctor»
в правом верхнем углу окна; файл `open-mod-manager`, на Windows
`open-mod-manager.exe`). Руководство — `docs/guide/07-mods-players.md`.
Это та же панель, что окно **Mods** в редакторе (крейт
`doctor-toolkit-mods`, библиотека и программа); в редакторе к ней добавлен
раздел сборки мода из рабочего пространства, а кнопка «Играть с модами»,
перетаскивание файлов и клавиши — только в программе
(`ModsPanel::standalone`). Чтение и запись игры идут в фоновом потоке.

**Этап 64 — удобство для игроков.**

- Игра (`games.rs`): папка из командной строки, иначе запомненная (`game`
  в `mods.toml`), иначе поиск `install::detect` (плюс папки
  `$DOCTOR_TOOLKIT_MODS_SEARCH`; с `DOCTOR_TOOLKIT_MODS_SEARCH_ONLY=1` —
  только они). Одна найденная копия открывается сразу, несколько — выбор
  (путь, издание `Edition::name`, где найдена), ни одной — подсказка и
  «Указать папку игры…».
- Аргументы: папка — игра, файлы `.zip`/`.vpat` — моды; они ставятся после
  вопроса, когда игра открыта. Файлы, брошенные на окно (`dropped_files`),
  ставятся сразу, прочие отклоняются словами. Ярлык
  `tools/desktop/open-mod-manager.desktop` объявляет `MimeType`
  `application/zip` и `application/x-godfather2-vpat` (тип описан в
  `open-mod-manager.xml`, `install-desktop.sh` кладёт его в
  `$XDG_DATA_HOME/mime`): программа появляется в «Открыть с помощью», не
  становясь обработчиком `.zip` по умолчанию. На Windows — «Открыть с
  помощью» → `open-mod-manager.exe`, реестр не трогается.
- Карточки (`cards.rs`): картинка мода, имя, версия, автор, первый абзац
  описания, переключатель, состояние (`state.rs`, `ModState`): Готов,
  Выключен, Не подходит к этой версии игры (несовпадения `check`, кроме
  замечаний), Не работает вместе с … (роковые `Clash`), Конфликт с … (общие
  ресурсы с другими данными; подсказка — чей вариант берётся), Ещё не
  записан в игру (поток мода не `up_to_date`), Повреждён. Порядок —
  перетаскиванием (`DragAndDrop`, линия вставки между карточками),
  контекстное меню и клавиши (Alt+↑/↓) — запасные пути.
- Главные кнопки: «Играть с модами» (`play.rs`: `overlay::availability`;
  копия `Overlay::build(Source::Mods)`, модуль с перенаправлениями, без
  записи в игру; после выхода игры модуль и копия убираются; без модуля
  или загрузчика ASI — окно с объяснением и «Записать в игру и играть»),
  «Записать в игру», «Вернуть оригиналы» — после вопроса, с окном хода
  (`ModManager::apply_with_progress`, `Deployment::sync_with_progress`:
  поток за потоком) и итогом словами.
- Наборы модов: `ModManager::save_set`, `use_set`, `delete_set`,
  `current_set`, `arrange` (файл `sets.json` рядом с `registry.json`,
  формат `doctor-toolkit-mod-sets`). Мод набора, которого уже нет,
  называется; установленный позже набора — выключается и идёт в конец.
- Отмена последнего изменения (вкл/выкл, порядок, набор — прежний
  `arrangement`; удаление — `remove_undoable`: файлы мода переносятся в
  `.removed-*` и возвращаются `restore_removed` на прежнее место;
  `discard_removed`/`purge_removed` удаляют их, когда отмена уже не нужна).
- Свёрнутый раздел «Подробности»: id, источник, потоки и ресурсы мода,
  создаваемые потоки, несовпадения, конфликты по ключам ресурсов,
  проверенные файлы игры. Проверка целостности — в меню «Ещё», итог —
  словами (`integrity_words`).
- Тема — общая с редактором (`doctor_toolkit_mods::theme`, редактор
  реэкспортирует её как `app::theme`).

Python (`docs/python.md`): `ModManager.clashes()`, поля `added` и
`new_streams` в `mods`, `install()` и `Workspace.build_mod()`.

Режим снимка для проверок без пользователя: `DOCTOR_TOOLKIT_MODS_SHOT=<png>`
(снимок и выход), `DOCTOR_TOOLKIT_MODS_SELECT=<id>`,
`DOCTOR_TOOLKIT_MODS_INTEGRITY=1`, `DOCTOR_TOOLKIT_MODS_ASK=write` (вопрос
перед записью), `DOCTOR_TOOLKIT_MODS_SIZE=<w>x<h>`; слежение за процессом
игры в этом режиме выключено. В редакторе `DOCTOR_TOOLKIT_GUI_MODS=1`
открывает окно Mods.

**Проверка.** `crates/doctor-toolkit-mods/src/tests.rs` (панель без окна:
брошенные файлы, состояния карточек, отмена, наборы, итоги словами),
`games.rs` (настройки, аргументы, поиск в папке), `play.rs` (объяснение без
загрузчика), `crates/doctor-toolkit/src/mods/tests.rs` (наборы, ход записи,
возврат удалённого мода). Снимок `docs/images/mod-manager.png` — 1920×1080,
`WINIT_X11_SCALE_FACTOR=1.5`, в Xvfb, на тени игры с тремя модами.

## 8. Открытые вопросы

- Мод, который добавляет ресурсы в поток другого мода, зависит от него, но
  зависимость не записывается: без того мода он просто не подходит к игре
  («потока нет»). Явные зависимости и версии — когда появятся такие моды.
- Удаление созданного потока оставляет пустые каталоги (`gf2/doctor/`), как и
  рабочее пространство; игра их не замечает.
- Блокировки файлов нет: две программы, меняющие менеджер модов одновременно,
  могут потерять запись в `registry.json` (у рабочего пространства есть
  проверка `revision`, у менеджера пока нет).
- Отпечаток игры — только исполняемый файл; эталонных хэшей GF2 PC в поставке нет.
- Патчи `.vpat` с блоком ресурсов по типу и с операциями «удалить» и
  «добавить» в обращении не встречались: читатель проверен на синтетических
  патчах (`mods/tests.rs`) и фаззингом, на настоящих — нет. Удаление ресурсов игры
  модом не поддерживается.
- Окно не сравнивает текстуры мода с оригиналом; для этого есть панель Changes
  рабочего пространства.
- Фаззинг разборщиков ZIP, `mod.json` и `.vpat` сделан на этапе 13 (цели `mod_zip`, `mod_manifest`, `vpat` в `fuzz/`); ошибок не найдено. На этапе 39 цель `vpat` проверяет и ресурсы по типу и операции (новое зерно `by_type_and_operations.vpat`): 2,5 млн прогонов за 3 мин, ошибок нет.
