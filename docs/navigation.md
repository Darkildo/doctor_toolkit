# Навигация и пакетная работа

Этап 8: индекс всей игры с именами и ссылками,
словарь имён для хэшей, глобальный поиск, перекрёстные ссылки, `unpack` /
`pack` и пакетный экспорт из GUI.

Код: `crates/doctor-toolkit/src/navigation/` (библиотека),
`crates/doctor-toolkit-cli/src/nav_cmd.rs` (CLI),
`crates/doctor-toolkit-gui/src/nav.rs` (GUI).

## 1. Индекс игры

`GameIndex` — одна запись (`Record`) на каждый ресурс каждого потока:

| Поле | Что это |
|---|---|
| ключ | `поток:тип:ids`, как в рабочем пространстве (`docs/workspace.md` §1) |
| заголовок | тип, четыре id, размер данных, размер на диске, сжатие |
| `names` | имена, прочитанные из данных, с видом: `name`, `package`, `part`, `object`, `class`, `event`, `variable`, `text` |
| `refs` | исходящие ссылки: метка (откуда ссылка) и цель |
| `anchors` | то, на что ссылаются не по типу и id: хэш имени материала, GUID объекта SimGroup и графа, кости скелета |
| `hashes` | хэши из данных, для которых нужны имена: записи строк, классы SimGroup, шейдеры, кости, имена свойств metamodel |
| `pairs` | хэш, записанный рядом со своим именем (имя текстуры, материала, переменной) — для словаря |
| `texts` | строки таблиц `lh2` с хэшем и языком |
| `error` | почему данные не разобраны, если не разобраны |

Что читается из каждого типа:

| Тип | Имена | Ссылки |
|---|---|---|
| `tg4h` | имя текстуры, пакет | `pixels` → `tg4d` пары |
| `material` | имя; пути исходных текстур (`text`) | параметр-текстура (`g_BaseSampler`, …) → `tg4h` по хэшу имени; якорь — CRC-32 имени |
| `mesh` | имя модели, имена записей отрисовки | запись → материал по CRC-32 имени; `skeleton` → `rcb`, чей скелет совпадает с таблицей костей; `vertex data` → `meshvolatile` (`~id`) |
| `metamodel` | части и состояния, их типы, переменные, строковые свойства | каждая запись T0 → ресурс по типу и id, метка — свойство (`ModelPart.Model`, `CollisionHavok4Part.CollisionModel`) |
| `simgroup` | имена объектов (`CMD_SetName`), классы, строковые атрибуты | атрибут-GUID ресурса → ресурс по id (`Entity.CMD_SetModel` → `metamodel`); ссылки объекта → ресурс; GUID чужого объекта → SimGroup, где он есть, или граф; якоря — GUID своих объектов |
| `graph` | — | якорь — GUID графа |
| `rcb` | имена скелетов | якоря — кости каждого скелета |
| `ffn` | имя шрифта | `atlas` → `tg4h` с тем же именем |
| `treemodel` | строки с NUL (путь исходника, имена частей) | часть дерева → материал по CRC-32 имени (с этапа 84; версия разбора 5) |
| `materialswaplistresource` | — | `swap from` / `swap to` → материал по CRC-32 имени (с этапа 84). Ids ресурса — GUID объекта SimGroup, к модели которого применяется список; объект на список не ссылается ([раскладка ресурсов](analysis/resource-placement.md) §3) |
| `apx` | название ролика, имена встроенных текстур | — |
| `lua` | имя файла, путь исходника, строковые константы | — |
| `bnk` | имена записей, событий и их аргументов (`.emx`) | — |
| `lh2` | строки (`texts`), хэши записей | — |
| `variabledictionary` | имена переменных | — |
| `partsdb` | имя базы, части, варианты, слоты, наборы | меши частей (по id), материалы замен и цветов частей |
| `tg4d`, `meshvolatile`, `hkx`, `sbk` | не читаются: большие, имён нет | — |
| остальные (`vfx`, `trinity_seq_master`, `dlg`, `chv`, …) | строки с NUL длиной от 4 символов, до 64 на ресурс; у `vfx` первая — имя эффекта | — |

### 1.1 Разрешение ссылок

Цель ссылки ищется среди всех записей индекса:

- `Resource {type, id}` — запись с этим `ids[3]` и типом. Тип 0 — любой; если
  подходят несколько типов, `tg4d` и `meshvolatile` отбрасываются (текстура —
  это её заголовок, модель — её меш). Если с этим типом нет ни одной записи,
  берётся любой тип: metamodel пишет тип коллизии как `0x33A1671E`, а у самих
  ресурсов `hkx` тип `0x33A16735` (3 193 ссылки);
- `Material(hash)` — материалы с этим хэшем имени;
- `Guid` — SimGroup с объектом с таким GUID или граф;
- `Bones` — риги, у которых скелет совпадает с таблицей костей меша
  (как `Skeleton::matches`);
- `Named {type, name}` — ресурс типа с таким именем (атлас шрифта).

Если подходящие записи есть в том же потоке, остаются только они; иначе —
все (ресурс лежит в нескольких потоках). Обратное направление («где
используется») строится из разрешённых ссылок. Копии того же ресурса (тот же
тип и ids) в других потоках показываются отдельно («also in»).

### 1.2 Кэш

Индекс хранится в `<кэш>/doctor-toolkit/index-<CRC-32 пути к игре>.bin`, где
`<кэш>` — `$DOCTOR_TOOLKIT_CACHE_DIR`, иначе `$XDG_CACHE_HOME`, `~/.cache` или
`%LOCALAPPDATA%`. **Каталог игры не меняется.** Файл двоичный, little-endian:
заголовок (`DTKINDEX`, версия формата, версия разбора — 5 со ссылок `treemodel` и `materialswaplistresource` на материалы, CRC-32 списков имён
`data/gf2/`, от которых зависят подписи разбора, — теги, кости, классы и
атрибуты SimGroup, шейдеры, — путь к игре), затем по
потоку: путь, отпечаток файла (размер, `mtime` в нс, inode), таблица строк
потока, записи. Пишется атомарно.

При открытии записи потока берутся из кэша, если отпечаток файла совпадает;
остальные потоки читаются заново, исчезнувшие удаляются, и кэш сохраняется,
если что-то изменилось. Запись в игру (`workspace apply`, `restore`) заменяет
файл переименованием — меняются inode и время, поэтому следующее открытие
перечитывает только изменённые потоки. В GUI это делается сразу после
применения или отката. Кэш другой версии, другой игры, других списков имён
или повреждённый игнорируется и перестраивается. Словарь (§2) в кэш не
входит и строится при каждом открытии.

Индекс описывает файлы игры, а не правки рабочего пространства, пока они не
применены.

## 2. Словарь имён

Хэш-функции движка (`HashFn`): SDBM, SDBM нижнего регистра, CRC-32, CRC-32
нижнего регистра, FNV-1a, FNV-1a нижнего регистра; для GUID — свёртка TOC
(`toc::guid_hash`, `((a·33 + b)·33 + c)·33 + d`).

Источники имён:

1. списки `data/gf2/`: теги типов, политики памяти, кости, классы SimGroup,
   имена атрибутов из схемы, `names.txt` (дополняется вручную);
2. все имена индекса (до 128 символов), каждое под каждой функцией;
3. пары «хэш — имя» из данных: если известная функция даёт этот хэш, пара
   записывается как вычисленная, иначе как «хранится в типе X» — функция не
   известна (имена текстур, переменные `variabledictionary`);
4. имена потоков из TOC с их хэшами (свёртка GUID ассета);
5. имена, выведенные из игры и принятые, только если их хэш есть в игре
   (этап 40): текст записи строк, чей SDBM нижнего регистра — хэш записи
   (таблица `gf2/text/d70e6b6c` хранит имена записей вместо текста,
   `resource-types.md` §4.1), и пути сборки `smb` и `sbk`
   (`levels\gf2\cuba\streams\cuba\local.smb`, `resource-types.md` §8).

Что выяснилось:

- **третий id текстуры (`ids[2]` у `tg4h` и `tg4d`) — CRC-32 имени пакета в
  нижнем регистре** (`crc32("assets_shared_fonts") = f3d257db`), проверено на
  всех 28 246 текстурах тем же тестом;
- хэш имени текстуры (`ids[3]`) не равен ни одной из функций выше от имени,
  имени с пакетом, расширением или путём — функция не известна, имена текстур
  берутся из заголовков;
- материалы: CRC-32 имени в нижнем регистре (как в `geometry.md` §6);
  свойства metamodel, классы SimGroup и записи строк `lh2`: SDBM нижнего
  регистра (этап 18, `resource-types.md` §4.1). Имена записей строк берутся
  из ссылок `$имя` интерфейсов `apx` и из `data/gf2/string_names.txt`.

Кости — SDBM имени в нижнем регистре (как классы): `l_elbowTwist` и
`l_elbowtwist` — одна кость; списки пишут имена костей строчными.

`unknown-hashes` показывает виды: хэши записей (`string entry`, `bone`,
`SimGroup class`, …), `type tag` — id типов без тега (у ресурсов и у целей
ссылок), `<тег> id` — id ресурсов без имени, `<тег> reference` — id, на
которые ссылаются, но ресурса с ними нет (тег цели или `any`).

### 2.1 Сверка кандидатов: `research/name_candidates.py`

Скрипт принимает список неизвестных хэшей и любые файлы с кандидатами и
печатает только пары «хэш → имя», подтверждённые хэшем:

```sh
doctor-toolkit unknown-hashes "$GAME" --list 1000000 > unknown.txt
python3 research/name_candidates.py unknown.txt names.txt dump.json \
    [--case] [--prefix m_] [--suffix _lod1] [--kind bone] [--any-function]
```

Из каждой строки файла берутся сама строка, слова в ней, части путей и они
же без расширения, поэтому подходят списки, JSON, исходники, строки exe.
`--case`, `--prefix`, `--suffix` добавляют варианты. Кандидат принимается,
только если функция, которой движок хэширует этот вид имён (теги, id `smb`
и `sbk` — SDBM; кости, классы, записи строк, имена metamodel — SDBM нижнего
регистра; шейдеры — CRC-32 нижнего регистра), даёт неизвестный хэш игры. Для
видов с неизвестной функцией (id ресурсов) `--any-function` пробует все шесть
и помечает совпадения `?`: это подсказки, а не имена — на 0,5 млн кандидатов
случайных совпадений около десятка. Для функций нижнего регистра печатаются
все написания: в список идёт то, что принято в документах.

Подтверждённые имена дописываются в списки `data/gf2/` (`sim_classes.txt`,
`bone_names.txt`, `type_tags.txt`, `names.txt`); списки и пути других
инструментов в репозиторий не входят: в публичных списках только имена,
которые встречаются в самой игре (строки ресурсов и `godfather2.exe`) или
выводятся из неё (пути `smb`/`sbk`, имена записей строк).

## 3. Поиск

Запрос — строка слов (CLI `search`, поле поиска в GUI):

| Слово | Что ищет |
|---|---|
| `wheel`, `"rear wheel"` | имена, содержащие текст, без учёта регистра |
| `car_*_lod?` | имена по шаблону (`*`, `?`), всё имя целиком |
| `0x9cf57f36`, `9cf57f36` | id, хэши в данных, цели ссылок, хэши материалов, записи строк; плюс имена из словаря |
| `gf2/frontend:tg4h:…` | ресурс по ключу |
| `type:mesh,material` | только эти типы |
| `stream:mp_mall` | только потоки, в имени которых есть текст |
| `kind:object` | только имена этого вида |
| `text:Don Corleone` | текст строк `lh2` (остаток строки) |

Восемь шестнадцатеричных цифр без единой цифры 0–9 (`deadbeef`) считаются
именем. Запрос из одних фильтров (`type:apx`) перечисляет все ресурсы. Поиск
по всей игре занимает 1–10 мс.

## 4. Командная строка

```sh
T=doctor-toolkit
$T index "$GAME" [--rebuild] [--unresolved N] [--cache FILE | --no-cache]
$T search "$GAME" type:material rust [--limit N] [--keys]
$T refs "$GAME" gf2/frontend:tg4h:00000000.4802e0a7.f3d257db.9cf57f36
$T refs "$GAME" "type:ffn buttons stream:gf2/frontend"   # запрос с одним результатом
$T hash tg4h Entity                       # хэши текста под всеми функциями
$T hash --guid a301c9537450558d4752414e44515549   # свёртка GUID для TOC
$T lookup 4802e0a7 38523fc3               # имена по спискам data/gf2
$T lookup e9930443 --game "$GAME"         # плюс имена игры и где хэш встречается
$T unknown-hashes "$GAME" [--kind bone] [--list 20]
$T unpack "$GAME" -o out [--stream S]... [--type T]... [--dds] [--wav] [--no-raw | --no-views] [--geometry-only] [--model-format glb|fbx|obj|usd|usda|usdc|usdz]
$T pack "$GAME" out [--workspace-dir DIR] [--dry-run]
```

Команды, которым нужен индекс, открывают его сами (из кэша) и печатают ход
построения в stderr.

## 5. `unpack` и `pack`

`unpack` пишет выбранные ресурсы в `<каталог>/<поток>/<тип>/<имя>.<расширение>`
(имя — имя ресурса из индекса или id; при совпадении добавляется id) и
`manifest.json`:

| Ресурс | Файлы | Правится |
|---|---|---|
| текстура (`tg4h` + `tg4d`) | PNG первой поверхности; DDS для кубических и объёмных или с `--dds` | да: импорт как `texture-import` |
| строки `lh2` | JSON в формате `text-export` (подходит и для `text-import`) | да |
| модель `mesh` | `.glb` с материалами, текстурами и скелетом (`--geometry-only` — без них); `--model-format fbx\|obj\|usd\|usda\|usdc\|usdz` — другой формат, файлы рядом (`.mtl`, текстуры) — в `<имя>_textures/` | да: импорт поверх меша, как `model-import` (этап 25) |
| игровая логика (`simgroup`, `metamodel`, `variabledictionary`, `partsdb`, `graph`), `rcb` | JSON | нет; правится `.bin` (граф — `graph-import`, этап 42) |
| банк звуков `sbk` | `<имя>/<номер>.snu` или `.wav` (`--wav`) | нет; правится `.bin` |
| скрипт `lua` | `.luac` | да (как есть) |
| `apx` | `.apx` | да (как есть) |
| остальное, а также `mesh`, логика, `rcb`, `sbk` | `.bin` — распакованные данные | да (как есть) |

`--no-raw` не пишет `.bin` рядом с просмотровыми файлами, `--no-views` не пишет
просмотровые файлы. Импорта JSON игровой логики пока нет (этап 6), поэтому
JSON — только для чтения.

```json
{
  "format": "doctor-toolkit-unpack",
  "version": 1,
  "game": "The Godfather II (PC)",
  "files": [
    {
      "path": "gf2/frontend/tg4h/buttons.png",
```

`kind`: `texture-png`, `texture-dds`, `strings`, `raw`, `view`, `model`
(файл модели), `model-file` (`.mtl` и текстуры модели; их правка
импортирует модель заново). Повторный
`unpack` в тот же каталог дополняет манифест.

`pack`:

1. Хэширует каждый файл манифеста; совпадающие пропускаются.
2. Ошибка, и ничего не записывается, если: изменён файл `view`; файла нет;
   в каталоге есть файл, которого нет в манифесте (новые ресурсы — этап 5).
   Скрытые файлы (`.имя`) и резервные копии редакторов (`имя~`) не учитываются.
3. Изменённые файлы записываются **в рабочее пространство** (не в игру):
   текстура — `Workspace::import_texture`, строки — `set_string_table` поверх
   текущей версии из рабочего пространства, модель — план импорта
   (`import::model::plan`, замена меша, материалы и текстуры по
   `docs/model-import.md`; все модели планируются до первой записи),
   остальное — `set_resources`.
   Каждый файл — отдельная операция журнала (отменяется по одной).
4. Если данные ресурса в игре отличаются от `sources` (игра изменилась после
   `unpack`), печатается предупреждение.

Запись в игру — обычным `workspace apply`.

**Проверено на GF2 PC** (тест `unpack_then_pack_records_exactly_the_edited_files`,
на теневом каталоге из ссылок на `gf2/frontend.str` и `gf2/text/dd7d7050.str`):
манифест покрывает каждый ресурс; `pack` без правок ничего не записывает и
не создаёт рабочего пространства; после правки одной текстуры (инвертирован
зелёный канал PNG) и одной строки JSON в рабочем пространстве ровно два
изменения — `tg4d` этой текстуры (заголовок не меняется) и `lh2`; изменённый
`.snu` и лишний файл дают ошибку без записи; повторный `pack` ничего не
добавляет; файлы игры не меняются.

Скорость: все 28 246 текстур игры (`--type tg4h`) — 20 с, 1,3 ГиБ PNG;
`pack --dry-run` по ним — 1 с. Два уровня (`building_004`, `mp_mall`, 579
ресурсов с моделями в glTF) — 1,3 с.

## 6. GUI

- Поле поиска на панели инструментов (Ctrl+F): Enter показывает вкладку
  **Search** с результатами (поток, тип, имя, совпадение) и именами хэша из
  словаря; вкладок поиска может быть несколько (Ctrl+Shift+F), они
  переживают перезапуск. Щелчок открывает ресурс в его потоке. Палитра
  команд (Ctrl+Shift+P) ищет ресурсы тем же запросом (`docs/shell.md` §2).
- Панель ресурса: **Names**, **Uses**, **Used by**, **Also in** со ссылками.
  Неразрешённые ссылки показаны серым с целью.
- **<** / **>** (Alt+←/→) — назад и вперёд по открытым ресурсам.
- Множественный выбор в списках потока, **All resources** и результатах
  поиска: Ctrl+щелчок, Shift+щелчок. **Export selected (n)…**, **Export N
  shown…** (весь фильтр типа в **All resources**) и **Export N result(s)…**
  пишут файлы как `unpack` с манифестом в фоне, с ходом и отменой; такой
  каталог потом читает `pack`.
- Индекс строится в фоне при открытии игры (ход — в строке состояния) и
  обновляется после **Apply to game**, **Revert game** и **Restore originals**.
- `DOCTOR_TOOLKIT_GUI_SEARCH=<запрос>` выполняет поиск, когда индекс готов
  (для снимков экрана).

## 7. Открытое

- Импорт JSON игровой логики и моделей из glTF (этапы 6 и 10); пока такие
  файлы только для просмотра.
- Ссылки, которые не извлекаются: `vfx` → текстуры и эффекты (по имени;
  `navigation::placement` сопоставляет их по именам сам), `trinity_seq_master`
  → актёры, `wgi`, `hkx` → материалы Havok, `lhr` → потоки текста.
- Функции хэшей имён текстур, переменных и id ресурсов, кроме `smb` и `sbk`
  (мешей: `docs/formats/logic-types.md` §2).
- Индекс не учитывает неприменённые правки рабочего пространства.
