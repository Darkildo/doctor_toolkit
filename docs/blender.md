# Дополнение Blender

Этап 22, часть B. Модели The Godfather II в Blender и обратно через
рабочее пространство: открыть игру, найти модель, импортировать её с
материалами, текстурами и скелетом, изменить, проверить план импорта и
записать — заменой модели или новым набором. Внешние редакторы вообще —
`docs/external-editors.md`, импорт моделей — `docs/model-import.md`,
руководство пользователя — `docs/guide/12-external-editors.md`.

Код — `tools/blender/`:

| Файл | Что |
|---|---|
| `doctor_toolkit_blender/__init__.py`, `blender_manifest.toml` | дополнение и манифест расширения (Blender 4.2+) |
| `doctor_toolkit_blender/core.py` | вся работа без интерфейса: импорт, проверки, экспорт GLB, запись в рабочее пространство, связанные файлы |
| `doctor_toolkit_blender/ui.py` | панель, операторы, настройки |
| `build-extension.py` | пакет расширения (zip), по желанию с колесом модуля |
| `run-tests.sh`, `tests/` | проверки в Blender без окна (§5) |

## 1. Как устроено

**Python-привязки, а не CLI.** Дополнение вызывает модуль
`doctor_toolkit` (этап 12) прямо во встроенном Python Blender: у Blender
5.3 — Python 3.13, колесо `abi3` подходит к любому CPython от 3.9. Так нет
второй программы, которую надо найти и запустить, ошибки приходят
исключениями с текстом библиотеки, план импорта — словарём, а индекс игры
открывается один раз за сеанс. Расширения Blender 4.2+ умеют везти колёса
с собой (`wheels` в манифесте): Blender сам ставит их в папку расширений
пользователя при установке, ничего не трогая в каталоге программы.

**Обмен — GLB.** Экспорт модели тулкитом (`Workspace.export_model`) и
импорт (`Workspace.import_model`) симметричны (`model-import.md` §3, §5).
Blender читает и пишет GLB своим glTF-импортёром и экспортёром.

- Импорт: `export_model` отдаёт версию рабочего пространства (уже
  изменённую модель — с правками) с материалами, текстурами и скелетом;
  glTF-импортёр Blender — без склейки вершин (`merge_vertices=False`) и
  без лишней сферы формы костей. На объектах запоминаются ключ модели,
  игра, имена материалов (без суффикса `.001`) и поза покоя костей.
- Экспорт: проверки (§3), glTF-экспортёр с `+Y up`, только выделенные
  меши и их арматура, до 4 влияний, без анимаций и морф-целей, с цветом
  вершин; затем имена материалов и костей очищаются от суффиксов `.001`
  (вторая копия модели в сцене), и файл уходит в `import_model` — пробно
  (план) или по-настоящему (одна операция рабочего пространства, Ctrl+Z в
  редакторе или `workspace undo` её отменяют).

## 2. Установка

Нужен Blender 4.2 или новее (проверено на 5.3).

**Расширение с модулем (Linux x86-64).** `tools/release.sh` кладёт рядом с
архивом `dist/doctor_toolkit_blender-0.0.3-linux-x64.zip` — дополнение с
колесом `doctor_toolkit` внутри (и копию в `blender/` архива). В Blender:
Edit → Preferences → Get Extensions → ▾ (вверху справа) → **Install from
Disk…** → этот zip. Blender ставит колесо в свою папку расширений
пользователя (`~/.config/blender/<версия>/extensions/.local/…`); каталог
Blender и системный Python не меняются. Удаление — там же, Uninstall.

**Без колеса** (другая платформа, сборка из исходников):

```sh
# модуль в отдельную папку (не в Blender)
cd crates/doctor-toolkit-py && maturin build --release
pip install --target ~/doctor-toolkit-py target/wheels/doctor_toolkit-*.whl
# дополнение без модуля
python3 tools/blender/build-extension.py -o dist
```

Поставьте `dist/doctor_toolkit_blender-0.0.3-no-module.zip` так же и в
настройках дополнения (Preferences → Add-ons → doctor_toolkit) укажите
**Module folder** = `~/doctor-toolkit-py`. Там же видно, откуда загружен
модуль, или почему он не загрузился. Своё колесо можно и вложить в пакет:
`build-extension.py -o dist --wheel путь/к/колесу.whl` (платформа берётся
из имени колеса).

Настройки дополнения: **Game folder** (игра по умолчанию), **Workspace
folder** (пусто — `<игра>/_doctor_toolkit/workspace`, то же, что у
редактора и CLI), **Module folder**.

## 3. Панель

3D Viewport → боковая панель (N) → вкладка **Doctor Toolkit**:

1. **Game** и **Open game** — открыть игру и её индекс (первый раз
   читаются все потоки, около минуты; индекс кэшируется в
   `~/.cache/doctor-toolkit/`).
2. Поиск — имя, шаблон (`car_*`), хэш или ключ, как в поиске редактора;
   показываются меши и metamodel. **Import model** — импорт выбранной.
3. **Model** — ключ заменяемой модели (заполняется при импорте; для чужой
   модели — впишите ключ). **Replace** — замена на месте, **New model
   set** — клон модели под новыми ids с именем **Name** и перенаправлением
   ресурсов **Retarget** (номера SimGroup/metamodel потока через запятую).
4. **Limit weights** — оставить у каждой вершины 4 наибольших веса костей и
   нормировать их сумму к 1 (то же делается само перед экспортом).
   **Check** — экспорт и пробный импорт: план (части, записи, скелет,
   материалы, добавляемые ресурсы) и предупреждения в панели, ничего не
   записывается. **Export to workspace** — записать.
5. **Linked file** — работа как внешний редактор (§4).

Проверки перед экспортом (`core.prepare_for_export`):

| Проверка | Что делается |
|---|---|
| > 4 весов на вершину или сумма ≠ 1 | исправляется: 4 наибольших, нормировка (группы, не являющиеся костями, не трогаются) |
| вершины без весов у меша со скелетом | предупреждение |
| кости, которых не было в скелете при импорте | предупреждение: импорт найдёт кость только по имени из скелета игры |
| поза покоя костей изменилась (больше 0,1 мм) | предупреждение: игра использует свою позу привязки |
| новое имя материала | предупреждение: импорт клонирует самый частый материал модели с текстурами из Blender |
| у меша нет материала, не выбрано ни одного меша | предупреждение, ошибка |

## 4. Связанный файл (внешний редактор)

«Open in external editor» в редакторе и `doctor-toolkit edit … --format
glb` экспортируют модель в GLB и импортируют каждое его сохранение
(`docs/external-editors.md`). Blender открывает такой файл оператором
**Open linked file** (`doctor_toolkit.link_open`), а **Save linked file**
(`doctor_toolkit.link_save`) делает проверки и пишет GLB поверх (через
временный файл и переименование — тулкит видит одно целое сохранение).
Программа для моделей в Preferences → External editors редактора:

```text
blender --python-expr "import bpy; bpy.ops.doctor_toolkit.link_open(filepath=r'{file}')"
```

Этот путь не требует открывать игру в Blender: ключ, режим и рабочее
пространство знает редактор (или команда `edit`).

## 5. Проверки

Blender в тестах запускается только в фоне (`-b`), с заводскими
настройками и всеми папками пользователя (config, scripts, datafiles,
extensions) во временной папке — настройки и дополнения пользователя не
читаются и не меняются; каталог Blender (Steam) не трогается. Колесо
распаковывается во временную папку и добавляется в `sys.path` (или
ставится расширением во временную папку пользователя). Каталог игры только
читается: поток модели и оглавления копируются.

```sh
tools/blender/run-tests.sh --game "$GAME" --wheel dist/doctor_toolkit-*.whl \
  --blender ~/.steam/steam/steamapps/common/Blender/blender \
  [--extension dist/doctor_toolkit_blender-*.zip] [--cli target/release/doctor-toolkit] \
  [--stream gf2/globalfolder/characters/allcharacters --model fringe_dress_lod2]
```

- `tests/roundtrip.py`: дополнение регистрируется, модель импортируется
  через него, экспортируется обратно в рабочее пространство на копии
  потока (сначала без изменений, затем со сдвинутой вершиной), геометрия
  рабочего пространства сравнивается с исходной по треугольникам с
  допуском: позиции 1e-4, UV 1e-3, веса костей (по именам) 2e-3, цвета
  вершин 2,5/255; со сдвигом — меняются ровно треугольники с этой вершиной;
- `--extension`: пакет ставится в Blender (`--command extension
  install-file`), модуль берётся из колеса расширения, операторы панели
  (Open game, Search, Import, Check, Export) проходят на копии игры;
- `--cli`: `doctor-toolkit edit … --format glb --wait` с Blender в фоне как
  редактором (`tests/link_edit.py` открывает связанный файл, сдвигает
  вершину и сохраняет дважды): в рабочем пространстве одна операция со
  сдвинутой вершиной.

Результаты на Blender 5.3.0 (Steam), 2026-11-12:

| Модель | Треугольники | Без изменений | Сдвиг вершины 0 на 0,25 м |
|---|---|---|---|
| `dmg0_model` (`mp_rooftops`, статика, 19 записей, 19 материалов) | 3464 | все равны: позиции точно, UV точно, цвета ≤ 1/255 | 1 треугольник изменился, 3463 равны |
| `fringe_dress_lod2` (`allcharacters`, скиннинг, 9 костей `this_lod1`) | 223 | все равны: позиции ≤ 1,2e-7, веса точно | 6 изменились, 217 равны |
| `vincenzo_pentangeli_head_lod1` (`allcharacters`, скиннинг, 27 костей) | 2810 | все равны: веса ≤ 1e-5 | 3 изменились, 2807 равны |

Материалы во всех случаях переиспользованы (0 новых), скелет найден по
именам костей. Тест нашёл и исправил две ошибки: вторая копия модели в
сцене давала материалы `имя.001` (импорт клонировал их как новые) — теперь
суффиксы снимаются; меш, импортированный со своей таблицей костей,
экспортировался из рабочего пространства без скелета (`IndexAssets` искал
скелет только по таблицам костей игры) — теперь ищется в любом риге с этими
костями.

## 6. Ограничения

- Колесо в пакете — только для Linux x86-64 (`release.sh`); на других
  платформах — «Module folder» или своё колесо через `build-extension.py`.
- Нормали и касательные Blender пересчитывает; импорт тулкита считает
  касательные заново. Морф-цели, анимации, новые кости и новые скелеты не
  переносятся (`model-import.md` §4).
- Материал с новым именем — клон самого частого материала модели; шейдер
  и параметры из Blender не берутся, только основная текстура и карта
  нормалей.
- После Undo в редакторе связанный файл в Blender не обновляется сам:
  «Reload file» в редакторе и снова Open linked file.
