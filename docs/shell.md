# Оболочка редактора

Этап 19. Код — `crates/doctor-toolkit-gui/src/app/` (оболочка),
`settings.rs` (настройки), `views.rs` (реестр просмотрщиков, см.
`docs/viewers.md` §0), общая часть с менеджером модов —
`crates/doctor-toolkit-mods/src/i18n.rs` (строки) и `icon.rs` (значки).
Руководство пользователя — `docs/guide/10-interface.md`. Что из возможностей
тулкита есть в окне, а что только в MCP или командной строке —
`docs/parity.md`.

## 1. Устройство окна

Сверху вниз: меню (справа в нём назад/вперёд и поиск по игре), главная
панель инструментов (§11.2), **док** вкладок и панелей, строка состояния
(§11.3). Вид и раскладки в духе Unreal Engine 5 — этап 52, §11.

Док — дерево `egui_tiles` 0.18 (единственная библиотека докинга под egui
0.37: у `egui_dock` последняя версия 0.21 — под egui 0.36). Листья —
`Pane` (`app/dock.rs`):

| Pane | Что | Сколько |
|---|---|---|
| `Welcome` | приветствие: открыть игру, недавние игры, справка | одна |
| `Files` | потоки и TOC игры с фильтром | панель |
| `Details` | инспектор выбранного последним: объект уровня или ресурс списка (этап 53, §11.6); в старых раскладках — и `ObjectDetails` | панель |
| `DetailsCopy { id }` | ещё одна панель Details (View → Another Details panel), закрывается насовсем | сколько угодно |
| `Changes` | изменения рабочего пространства (бывшее окно) | панель |
| `Log` | сообщения, предупреждения и ошибки | панель |
| `Index` | все ресурсы игры по типам | одна |
| `Stream { id, path }` | ресурсы потока или содержимое TOC | сколько угодно |
| `Resource { id, key }` | один ресурс — редактор ассета: панель инструментов и редактор на всю вкладку (этап 56, §11.10) | сколько угодно |
| `Search { id, query }` | результаты поиска | сколько угодно |
| `Level { id }` | редактор уровня | сколько угодно |
| `Tasks` | «What do you want to do?»: список мастеров | одна |
| `Wizard { id, kind }` | мастер (этап 23, §10) | сколько угодно |
| `Logic { id, scope }` | граф логики (`docs/logic-graph.md` §6) | сколько угодно |
| `Script` | редактор скриптов (этап 56; до него — окно) | одна |
| `Movies` | ролики игры (этап 56; до него — окно) | одна |
| `Project` | браузер проекта | одна |
| `Game` | игра во вкладке (этап 33) | одна |
| `ContentBrowser` | ассеты игры; пока — папки и потоки (этап 55 — превью) | панель, по умолчанию ящик |
| `Outliner` | объекты уровня впереди: зона → класс → объекты (этап 53) | панель |
| `Zones` | зоны уровня впереди, что показывает вид, прогулка, навигационные графы (этап 53) | панель |
| `Documents` | место документов в раскладке (§11.4), в доке не бывает | — |

**Панели** (`Files`, `Details`, `Changes`, `Log`, `ContentBrowser`,
`Outliner`, `Zones`) при закрытии прячутся, а не удаляются:
View → панель возвращает её на прежнее место. Любую панель можно сделать
**ящиком** (§11.5). **Документы**
открываются вкладкой рядом с последним использованным документом.
Вкладку можно перетащить в другую группу или к краю — получится новое
разбиение. Двойной щелчок по вкладке (или Ctrl+M) показывает её одну
поверх всего дока, повтор — возвращает раскладку.

Состояние вкладок живёт в приложении (`BrowserApp::streams`, `docs`,
`searches`, `levels` по `id` панели), в дереве — только то, что нужно для
восстановления: путь потока, ключ ресурса, запрос. Закрытая вкладка
забывается в конце кадра (`apply_dock_ops`). Изменения дока, о которых
просят во время его рисования, копятся в `dock_ops` и применяются после.

Выбор в списке потока показывается в **Details**; двойной щелчок
(средняя кнопка, «Open in tab») открывает ресурс отдельной вкладкой со своими
просмотрщиками. Щелчок в Files открывает поток в последней вкладке потока,
Ctrl+щелчок — в новой. Переход по ссылке и результат поиска идут в
последнюю вкладку потока.

**Открытые файлы.** Все вкладки читают потоки через один кэш
(`app/docs.rs`, `StreamCache`). Перед записью в игру (Apply, Revert, моды,
Restore originals) кэш освобождается целиком (`release_files`), после —
вкладки потоков и ресурсов открываются заново (`files_changed`), выбор и
состояние просмотрщиков сохраняются.

## 2. Команды, меню, горячие клавиши, палитра

Все действия — варианты `Command` в `app/commands.rs` и строки таблицы
`COMMANDS`: ключ текста, меню, клавиши, область действия клавиш. Меню,
палитра команд и шпаргалка клавиш строятся из таблицы; выполняет команду
`BrowserApp::run`, доступность — `enabled`, галочки — `checked`.

| Меню | Команды |
|---|---|
| File | Open game… (Ctrl+O), Open stream… (Ctrl+Shift+O), Recent games, Save, Export… (Ctrl+E), Unpack selected…, Pack folder into workspace…, Close tab (Ctrl+W), Quit (Ctrl+Q) |
| Edit | Undo (Ctrl+Z), Redo (Ctrl+Shift+Z, Ctrl+Y), Preferences… (Ctrl+,) |
| View | Command palette (Ctrl+Shift+P), Back/Forward (Alt+←/→), панели Files/Details/Changes/Log (Ctrl+1…4), Outliner/Zones/Undo history (Ctrl+5, Ctrl+6, Ctrl+7), Another Details panel, Content Drawer (Ctrl+Space), New Content Browser, Welcome, тема, масштаб (Ctrl+Plus/Minus/0), Maximize tab (Ctrl+M), Full screen (F11), Save layout as…, Reset layout, подменю Layouts (§11.4) |
| Level | Select, Move, Rotate, Scale, Local axes, Snap always — для уровня впереди (§11.2) |
| Tools | Search the game (Ctrl+F), New search tab (Ctrl+Shift+F), All resources (Ctrl+Shift+R), Level editor (Ctrl+L), New level tab (Ctrl+Shift+L), Logic graph (Ctrl+G), Mods (Ctrl+Shift+M), Check game files, Look into a save file…, Sound: archives, speech, mixer (окно «Звук», `docs/viewers.md` §4a), Rebuild game index, Apply changes to game, Revert game files, Restore originals, Play (F5), Play options…, Find installed games; новая зона (этап 103, `docs/levels.md` §12): New stream…, New SimGroup…, World grid cell…, Clone resources…, Add resource from a file… |
| Wizards | What do you want to do? (F2), Retexture a model…, Replace a model…, New outfit…, Change game parameters…, Edit texts…, Place an object in a level…, New voice line…, New zone…, Package a mod… (§10) |
| Help | User guide (F1), Keyboard shortcuts (Ctrl+/), Show log file, About |

**Клавиши и поля ввода.** Клавиши разбираются в начале кадра, до виджетов
(`BrowserApp::shortcuts`), более специфичные первыми: egui считает, что
Ctrl+Z совпадает и с Ctrl+Shift+Z. У каждой команды область: `Global`
работает всегда (клавиша ничего не значит для поля ввода: Ctrl+O, Ctrl+W,
F1), `NotInText` — только когда поле ввода не держит клавиатуру (Ctrl+Z,
Alt+стрелки), `Egui` — клавишу обрабатывает сам egui (масштаб). Тесты
проверяют, что клавиши не повторяются, что клавиши правки текста не
`Global` и что клавиша без Ctrl/Alt бывает только функциональной.
Клавиши просмотрщиков (W A S D Q E, F, 1, 2 в уровне; F в модели) без
модификаторов и до них не доходят Ctrl-сочетания оболочки.

**Палитра** (Ctrl+Shift+P): команды (по меню и названию), недавние игры,
потоки (по подстроке пути) и ресурсы через индекс игры этапа 8 — тот же
запрос, что в поиске (`имя`, `car_*`, `0x9cf57f36`, ключ, `type:mesh`,
`text:слова`). Стрелки выбирают, Enter выполняет, Esc закрывает.
File → Open stream… — палитра только с потоками.

Добавить команду: вариант `Command`, строка в `COMMANDS` (ключ `cmd.*` в
`en.toml`), ветка в `run` и, если нужно, в `enabled`/`checked`.

## 3. Настройки

`$XDG_CONFIG_HOME/doctor-toolkit/settings.toml` (`~/.config/doctor-toolkit/`,
на Windows `%APPDATA%\doctor-toolkit`, на macOS
`~/Library/Application Support/doctor-toolkit`), каталог можно задать
`DOCTOR_TOOLKIT_CONFIG_DIR`. Файл можно править руками: неизвестные ключи
пропускаются, недостающие берутся по умолчанию, сломанный файл заменяется
умолчаниями с предупреждением в журнале и всплывающем сообщении.

```toml
version = 1
theme = "dark"                 # dark | light | system
ui_scale = 1.0                 # 0.5–3.0; Ctrl+Plus/Minus/0
language = ""                  # пусто — язык системы (этап 20)
renderer = "auto"              # auto | wgpu | glow; со следующего запуска
reopen_last = true             # открыть последнюю игру с вкладками и выбором
last_game = "/путь/к/The Godfather II"
last_stream = "gf2/frontend.str"
last_resource = "gf2/frontend:tg4h:00000000.4802e0a7.f3d257db.078bd24a"
recent_games = ["/путь/к/The Godfather II"]   # до 10, новые первыми

[window]                       # внутренний размер в точках; x, y — где окно было
width = 1200.0
height = 760.0
x = 0.0
y = 0.0
maximized = true

[external_editors]             # команда, {file} — файл; пусто — программа рабочего стола (docs/external-editors.md)
image = ""
model = ""
text = ""
audio = ""

[export_dirs]                  # с каких папок начинают диалоги; запоминаются
export = "/куда/экспортировали"
extract = "…"
pack = "…"
import = "…"

[level]                        # вид уровня (этап 54, §11.8)
classic_camera = false         # true — камера и клавиши как до этапа 54

[games."/путь/к/The Godfather II"]   # этап 21, для каждой игры
skip_first_run = false         # не предлагать снимок оригиналов и старый тулкит

[games."/путь/к/The Godfather II".play]
apply_before = true            # записать рабочее пространство перед запуском
revert_after = true            # вернуть оригиналы, когда игра закроется

[games."/путь/к/The Godfather II".play.method]
method = "wine"                # auto | steam | steam_shortcut | wine | proton | lutris | heroic | bottles | direct | command
prefix = "/путь/к/префиксу"    # поля способа: app_id, prefix, wine, dll_overrides, proton, compat_data, game, app, runner, bottle, flatpak, command
```

Рядом — `layout.json`: дерево дока (`egui_tiles`, serde) с версией
формата и счётчиком `id`, ящики, свои раскладки и раскладки экранов
(версия 4, §11.4); файлы версий 1–3 читаются и переводятся,
файл другой версии или испорченный пропускается.
Настройки и раскладка пишутся через временный файл и переименование: при
закрытии окна, по Quit, при закрытии Preferences, после открытия игры и раз
в 30 секунд, если что-то изменилось.

Режимы снимков и самопроверки (`DOCTOR_TOOLKIT_GUI_SHOT`,
`DOCTOR_TOOLKIT_GUI_SELFTEST`) начинают с умолчаний и ничего не пишут, если
не задан `DOCTOR_TOOLKIT_CONFIG_DIR` — тогда снимок сохраняет настройки перед
выходом (так проверяется восстановление).

## 4. Сообщения, журнал, задачи

Сообщения (`app/shell.rs`, `Notes`) — информация, предупреждения и ошибки:
последнее в строке состояния, все — в панели **Log** (фильтр, «Show info»,
до 1000 записей), предупреждения и ошибки ещё и всплывают в правом нижнем
углу на 8 секунд и пишутся в файл журнала (`doctor_toolkit::report`,
`~/.local/state/doctor-toolkit/log.txt`). Новый код вызывает
`BrowserApp::notify(Level, текст)`; старый код и просмотрщики пишут в
`status`, уровень тогда определяется по словам («Cannot …», «… failed» —
ошибка, «warning», «not found» — предупреждение).

Строка состояния собирает все фоновые задачи в одном месте: открытие игры,
извлечение и упаковка (`jobs.rs`), индексация и экспорт (`nav.rs`), задачи
менеджера модов, загрузка уровней. Первая показывается с прогрессом и
кнопкой отмены, остальные — по кнопке «+N». Слева — кнопки ящиков, в том
числе «Output Log» с числом новых проблем (§11.3).

## 5. Строки интерфейса и перевод

Механизм — `doctor_toolkit_mods::i18n` (общий для редактора и менеджера
модов):

- `tr("menu.file")` возвращает строку по ключу, `trf("status.opened_game",
  &[("name", &имя), ("streams", &n)])` — с подстановкой `{name}`;
- `trn("count.files", n, &[])` — текст с числом в нужной форме: ключ —
  встроенная таблица форм, `{n}` — число. В английском формы `one` и
  `other`, в русском `one` (1, 21, 101), `few` (2–4, 22–24) и `many` (0,
  5–20, 25…). Общие существительные с числом лежат в таблице `[count]`;
  текст с несколькими числами подставляет их готовыми:
  `trf("dialogue.counts", &[("nodes", &trn("count.nodes", n, &[])), …])`;
- таблицы вкомпилированы из `crates/doctor-toolkit-mods/i18n/en.toml` и
  `ru.toml` (таблицы TOML дают первую часть ключа, ключи сгруппированы по
  окнам: `model.*`, `level.*`, `mods.*`…); язык добавляется файлом той же
  формы и строкой в `LANGUAGES`;
- английский — запасной: ключ без перевода показывает английский текст,
  ключ, которого нет нигде, — сам себя (так опечатка видна);
- язык при запуске: `DOCTOR_TOOLKIT_LANG`, затем `language` из настроек,
  затем язык системы — на Windows `GetUserDefaultLocaleName`, в остальных
  системах `LC_ALL`/`LC_MESSAGES`/`LANG` (`ru_RU.UTF-8` → `ru`); незнакомый
  язык — английский;
- язык меняется без перезапуска (`choose_language`): строки берутся при
  каждой отрисовке, следующий кадр уже на новом языке. Что было записано
  раньше — сообщения журнала, подписи операций рабочего пространства —
  остаётся на языке своего момента.

**Выбор языка.** Preferences → Language (Настройки → Язык): «Как в системе
(…)», English, Русский; выбор сразу переключает интерфейс и сохраняется в
`language` файла `settings.toml` (пусто — язык системы). У менеджера модов
Open Mod Manager такой же список справа вверху; его выбор хранится в
`mods.toml` рядом с `settings.toml`, а пока его нет — берётся язык редактора.

**Что не переводится:** имена форматов и типов ресурсов (`mesh`, `lh2`,
glTF, PNG), идентификаторы, хэши, пути, имена классов игры (`SimGroup`),
синтаксис примеров в подсказках (`mission:…`, `send:…`), вывод командной
строки, файл журнала разработчика и тексты ошибок библиотеки
`doctor-toolkit` — они показываются по-английски внутри переведённой фразы
(«Не удалось открыть игру: …»). Подписи операций, которые пишет сама
библиотека (как и командная строка), тоже английские; подписи, которые
делают окна и мастера, переводятся. Палитра команд находит команду и по
английскому названию («pref», «apply» из руководства работают в русском
интерфейсе).

**Шрифты.** Встроенные шрифты egui покрывают кириллицу целиком: Ubuntu Light
(пропорциональный) и Hack (моноширинный — hex, таблицы, Lua). Отдельный шрифт
не нужен; проверено снимками окон на русском (§8).

**Тесты** (`crates/doctor-toolkit-mods/tests/i18n.rs`): ключи `en.toml` и
`ru.toml` совпадают, совпадают плейсхолдеры `{…}`, у множественного числа
есть все формы языка и `{n}`, русский текст не повторяет английский (кроме
списка имён `KEPT_IN_ENGLISH`), и у каждого `tr("…")`/`trf("…")`/`trn("…")`
с ключом-литералом в исходниках обеих программ есть строка (`trn` — именно
множественное число). Правила форм — в модульных тестах `i18n.rs`. Уровень
сообщения в строке состояния по словам (§4) узнаёт и русские («Не
удалось…», «Ошибка», «не найден»).

**Новая строка интерфейса** — ключ в обоих файлах сразу: тест не даст
забыть русский текст.

## 6. Значок и ярлык

Значок рисуется кодом из нескольких фигур (`doctor_toolkit_mods::icon`):
тёмный скруглённый квадрат, крест (красный у редактора, зелёный у
менеджера модов) и тёмный квадратик в центре; сглаживание — 16 выборок на
пиксель. Те же фигуры дают значок окна (64×64, `with_icon`), PNG 16–256 и
SVG. `app_id` окна (`doctor-toolkit`, `open-mod-manager`) совпадает с
именем ярлыка и `StartupWMClass` — так Wayland и X11 связывают окно с
ярлыком.

- `doctor-toolkit-gui --write-icons DIR` пишет `DIR/hicolor/<n>x<n>/apps/*.png`
  и `DIR/hicolor/scalable/apps/*.svg` обоих программ;
- `tools/desktop/*.desktop` — ярлыки;
- `tools/install-desktop.sh` ставит ярлыки и значки пользователю
  (`~/.local/share/applications`, `~/.local/share/icons/hicolor`), без root;
  `--uninstall` убирает их, `--bin-dir DIR` — где программы;
- `tools/release.sh` кладёт в архив `install-desktop.sh`, `desktop/` и
  `icons/`.

**Ошибка действия без рук (этап 103).** Первая ошибка останавливает
цепочку: следующие правки `act=` вкладки уровня не выполняются, мастер не
идёт дальше шага, который не прошёл проверку, пункты
`DOCTOR_TOOLKIT_GUI_RESOURCE`, `_SOUND`, `_LIVE_DO` после отказавшего не
выполняются. Текст ошибки печатается в stderr строкой `error: …`, снимок
всё равно записывается (на нём видно сообщение), а редактор выходит с
кодом **2** (код 1 — не записался сам снимок, 0 — ошибок не было). Ошибкой
считается любое сообщение уровня Error за запуск: отказ записи правки,
неизвестная зона, неизвестный мастер или пункт предустановки, не найденная
заметка базы знаний. Устроено это одним местом — `BrowserApp::preset_failed`
(`app.rs`), его зовёт `notify(Level::Error, …)`.

**Запятая в значении.** Пункты предустановок мастеров, `_RESOURCE`,
`_SOUND` и `_LIVE_DO` разделяются запятыми. Запятая внутри значения
пишется `\,` либо значение целиком даётся строкой JSON в двойных кавычках:
`replace=Привет\, мир` и `replace="Привет, мир"` — одно и то же. Больше
ничего не экранируется, поэтому прежние предустановки (в том числе пути
Windows с `\`) читаются как раньше.

Модульные тесты без окна (`app.rs`, `app/*`): команды меню переключают
панели и тему, команды без игры недоступны, клавиши Ctrl+Shift+P, Esc,
Ctrl+4, Ctrl+, и Ctrl+Q доходят до команд, палитра находит команды,
раскладка и настройки восстанавливаются, Reset layout возвращает панели;
настройки — круговой тест, частичный и сломанный файл; раскладка —
круговой тест с вкладками потока, поиска и ресурса и спрятанной панелью.
Окно для них создаётся через `CreationContext::_new_kittest`.

## 9. Первый запуск и «Играть» (этап 21)

Код: `app/play.rs` (окно), библиотека — `doctor_toolkit::install`
(автопоиск), `edition` (издание), `play` (способы запуска, процессы,
слежение), `mods::integrity` (эталон, старый тулкит). Руководство —
`docs/guide/02-first-run.md` §2.1, §2.4 и `docs/guide/11-play.md`.

**Автопоиск.** Приветствие при первом показе запускает
`install::detect(SearchRoots::from_env())` в фоне (доли секунды) и
`Edition::identify` для каждой находки; список «Found on this computer» —
папка, издание, где найдена. Tools → Find installed games ищет снова. Что и
где ищется — руководство §2.1; `SearchRoots` собирает все места, поэтому
тесты (`install::tests`) работают на поддельном домашнем каталоге со
Steam (две библиотеки, Proton, ярлык), Wine (реестр с диском D:), Lutris,
Heroic, Bottles и приманкой без файлов игры. Разборщики (`install::parse`:
текстовый и двоичный VDF, файлы реестра Wine, вывод `reg query`, строки
YAML с переносами Lutris) не паникуют на обрезанных данных.

**Издание.** `Edition::identify`: размер и SHA-256 `godfather2.exe`, версия
из `VS_FIXEDFILEINFO`, дата сборки и имена разделов PE (SecuROM —
`.securom`, Steam DRM — `.bind`), языки `text/localetable.txt`, загрузчик
ASI и папка старого тулкита. Таблица `edition::KNOWN` — только проверенные
сборки (на этой машине — две, руководство §2.1); `detect DIR` печатает всё
нужное для новой строки. Издание пишется в журнал, в строку состояния при
открытии, в About и в подсказку над путём к игре.

**Первое открытие.** После открытия игры поток проверяет её
(`first_run_state`: эталона нет; быстрый `integrity::check`): изменения
старого тулкита → окно с выбором «Take over its patches as mods» (окно
Mods, `import_old_toolkit`, когда оно загрузит моды), «Restore the original
files» (`adopt_old_backups` + `restore_backups` в фоне), «Not now», «Don't
ask for this game» (`skip_first_run`); ничего не изменено и нет резервных
копий → предложение сохранить эталон (`save_reference` в фоне, ход в строке
состояния).

**Play.** `PlayConfig` игры из настроек; `Auto` разрешается
`play::auto_method` (первая подсказка автопоиска для этой папки, иначе Wine
в префиксе вокруг игры или `godfather2.exe` на Windows). Перед запуском —
`apply`, если выбрано (не записалось — игра не запускается). `Session`
следит за запуском: программа, запущенная напрямую (Wine, Proton, команда,
исполняемый файл), сама считается игрой, пока жива; у лаунчеров (Steam,
Lutris, Heroic, Bottles) — только процесс игры, ожидание появления — 3
минуты. Когда игра закрылась — `unapply`, если выбрано.

**Блокировка записи.** `GameWatch` сканирует процессы раз в 1,5 с в своём
потоке (Linux — `/proc`: программа процесса `godfather2.exe`, в том числе с
путём Windows, как у процесса Wine; Windows — `tasklist`). Пока игра идёт,
`enabled` выключает Play, Apply, Revert и Restore originals, а `apply`,
`unapply`, `restore_originals` (значит, и «Write to game at once», и
Changes) отказывают с предупреждением; окну Mods передаётся
`set_write_lock` — его записывающие задачи отказывают. Менеджер модов
Open Mod Manager держит свой `GameWatch`.

**Проверка.** Модульные тесты библиотеки (`install`, `edition`, `play`:
планы всех способов, поддельный `wine`, записывающий окружение, поддельная
игра-скрипт, падающий лаунчер, тайм-аут, процесс-пустышка
`godfather2.exe` — обычный и с путём Windows в `argv[0]`), тесты окна без
экрана (`writing_waits_while_the_game_runs`,
`play_starts_and_follows_a_fake_game`, `first_run_offers_follow_the_game_files`),
CLI (`play_applies_runs_a_fake_game_and_reverts`: скрипт-игра видит
записанный поток, после выхода в игре снова оригинал). Под настоящим Wine
9.0 (свой префикс, скрытый Xephyr, `notepad.exe` под именем
`godfather2.exe`): процесс найден, `restore` предупредил, второй `play`
отказал, после `wineserver -k` — «the game has exited». Саму игру агент не
запускал.

### 9.1 Старт и игра во вкладке (этап 33)

Код: `app/gametab.rs` (старт, «Играть отсюда», кнопки вкладки),
`game_view/` (вкладка: `keys.rs` — клавиши, кнопки, координаты;
`nested.rs` — свой X-сервер и жизнь процесса; `x11.rs` — кадры и ввод;
`windows.rs` — встраивание окна на Windows), библиотека —
`play::start` (`StartOptions`, `CmdFile`, `spawn_points`, `level_streams`,
`top_level_stream`, `nearest_spawn`), `play::command`/`spawn`,
`Session::adopt`. Руководство — `docs/guide/11-play.md` §11.4–11.6.

**Старт.** `play.start` игры (`StartOptions`) показывается в окне Play
options тремя режимами (`gametab::StartMode`): как обычно (пусто), сразу в
город (`streams = [поток]`), в точку (`spawn`). Список потоков —
`level_streams` (потоки `ПАПКА/ИМЯ` рядом со своим TOC, без `_global` и
`gf2/frontend`, города сюжета первыми); точки — `spawn_points` в фоне,
кэш по потоку (`PlayState::spawns`, сбрасывается при каждом запуске:
применённое рабочее пространство могло добавить точку). `SpawnPoint`
знает свой SimGroup и номер объекта (`resource`, `object`) — по ним
«Играть отсюда» делает копию. Правила этапа 32 проверяет `start_problem`:
несколько потоков или дочерний поток — запуск не начинается.
`launch_options` добавляет для вкладки `-resolution` экрана вкладки
(1280×720 по умолчанию), на Windows ещё `-windowed`; строка `cmd.txt`
видна в окне.

**Вкладка, Linux.** `GameSettings::in_tab` (по умолчанию да на Linux).
`Server::find`: `DOCTOR_TOOLKIT_NESTED_X`, затем `Xvfb`, затем `Xephyr` из
`PATH`. Почему Xvfb первым: экран только в памяти, не нужен дисплей хозяина
(работает и в сеансе Wayland), нет вывода в окно хозяина (у Xephyr он и
задаёт предел частоты, этап 9). Xephyr — запасной путь стенда: окно-родитель
создаётся на дисплее хозяина через x11rb и не отображается; `-parent` стоит
**перед** `-screen` — после него Xephyr заводит второй экран для родителя, а
первый (тот, где игра) показывает отдельным окном на дисплее хозяина
(ошибка была и в `tools/game-bench.sh`, исправлена). Номер дисплея сервер
сообщает сам (`-displayfd 1`). Игра запускается командой способа
(`play::command`) с `DISPLAY=:N`, без `WAYLAND_DISPLAY`, в своей группе
процессов; для Wine и Proton — в виртуальном рабочем столе Wine размером
с экран (`in_virtual_desktop`: `explorer /desktop=doctor_toolkit,WxH` перед
`godfather2.exe`; на голом сервере игра под Wine останавливается окном
«Graphics Card does not meet … minimum requirements», проверено на стенде).
Способы-лаунчеры (`LaunchMethod::detached`) во вкладке не запускаются —
игра открывается отдельно с предупреждением.

**Кадры** (`x11::Link`, поток `game-frames`): DAMAGE на корневом окне;
изменился экран — `GetImage` (ZPixmap, 32 бита) всего экрана, BGRX → RGBA,
не чаще 60 раз в секунду; кадр — `Arc<ColorImage>` в текстуру egui без
копирования (`ImageData::Color`). Число прочитанных кадров — это частота
игры; раз в 10 с она пишется в журнал («game tab: N frames/s, frame read
in M ms»). MIT-SHM не нужен: чтение 1280×720 — 1,3–1,7 мс (до 5–10 мс под
нагрузкой).

**Ввод** (`x11::Input`, XTest): щелчок по картинке — захват (`CursorGrab
Confined`, курсор скрыт, указатель вложенного сервера ставится в точку
щелчка — `keys::to_game`), слой поверх окна забирает указатель, а
`GameView::take_input` в начале кадра забирает события клавиатуры и мыши
до горячих клавиш редактора. Клавиши — физические (`physical_key`, работает
при любой раскладке хозяина), `keys::keysym` → keysym US-раскладки →
keycode по раскладке вложенного сервера (`keycodes`: без Shift раньше, чем
с ним). Повторы нажатий не передаются; нажатые клавиши и кнопки
отпускаются при освобождении мыши. Мышь — относительными движениями
(сырое движение `Event::MouseMoved`, без него — движение указателя), колесо
— кнопки 4–7. Esc освобождает мышь, Shift+Esc и кнопка «Esc в игру»
нажимают Esc в игре (кнопка держит его 0,7 с: меню паузы игры пропускает
короткие нажатия). Потеря фокуса окна и показ другой вкладки освобождают
мышь.

**Жизнь процесса** (`nested::TabGame`): «Остановить» — SIGTERM группе,
через 4 с SIGKILL; игра под Wine живёт в своём сеансе (Wine отрывает
процессы от родителя), поэтому вслед за игрой останавливается X-сервер — с
ним закрывается всё, что на нём было. Сервер умер — игра останавливается.
После выхода: свежий список процессов, `cmd.txt` убирается (`CmdFile`),
откат (`unapply`) ждёт, пока процесс игры исчезнет из списка (до минуты, иначе
предупреждение), затем «Перезапустить» запускает игру снова.

**Вкладка, Windows** (`game_view/windows.rs`, только 64 бита): игра
запускается как обычно с `-windowed -resolution`, её окно верхнего уровня
ищется по процессам игры (`EnumWindows`), получает `WS_CHILD` вместо рамки,
`SetParent` в окно редактора (HWND из `eframe::Frame`) и ставится над
картинкой вкладки (`MoveWindow` в пикселях окна); вкладка не на экране —
окно прячется; при выходе окно возвращается на рабочий стол. Ввод идёт в
окно игры напрямую. Собирается (`cargo check --target
x86_64-pc-windows-gnu`), на Windows не запускалось; `in_tab` там по
умолчанию выключен.

**Ускорение DXVK** (`play::dxvk`, настройка `play.dxvk`). Внутри
вложенного сервера нет DRI3: OpenGL Wine — llvmpipe, уровень 1–2 кадра/с.
С флажком «Играть» для способа Wine ищет DXVK (`find`: `DOCTOR_DXVK`,
Lutris `runtime/dxvk/*/x32`, Proton `files/lib/wine/dxvk/i386-windows`,
Bottles, Heroic — новейший), проверяет 32-битный Vulkan (`vulkan32`:
`libvulkan.so.1` и ICD из `vulkan/icd.d`, чья библиотека есть 32-битным
ELF; llvmpipe не считается), кладёт `d3d9.dll` в папку игры
(`DxvkInstall`, копия в `_doctor_toolkit/dxvk/`, откат как у модуля связи:
изменённый кем-то файл остаётся, `restore_stale` перед следующим запуском) и
дополняет `WINEDLLOVERRIDES` (`apply_env`: `d3d9=n,b` после `dinput8=n,b`,
журнал DXVK в `_doctor_toolkit/dxvk`, уровень `warn`). Не получилось —
игра запускается без DXVK с предупреждением. Proton — «уже с DXVK», другие
способы — не поддерживаются (переопределение DLL до игры не дойдёт).
Поиск DXVK и Vulkan — один раз за сеанс редактора (`PlayState::dxvk_found`),
папка игры — каждый раз. CLI — `play --dxvk`. Замеры — `docs/analysis/game-bench.md`
§19: 1280×720 — 27–35 кадров/с, 800×600 — 61.

**Сервер уходит с редактором.** Xvfb/Xephyr вкладки запускается с
`PR_SET_PDEATHSIG` = SIGKILL (из потока интерфейса): редактор закрыт без
деструкторов, упал или убит — ядро гасит сервер, игра под Wine без
X-сервера завершается. Без этого игра однажды осталась работать в
невидимом Xvfb после закрытия редактора.

**«Играть отсюда»** (`LevelAction::PlayHere`): поток верхнего уровня зон
вкладки (`top_level_stream`, только из `level_streams`), положение камеры;
окно предлагает ближайшую точку (`nearest_spawn`, точки с сообщением
пропускаются) или копию точки по умолчанию в месте камеры
(`level::edit::duplicate` со сдвигом, через рабочее пространство, как
«Дублировать»; включается `apply_before`). Затем старт записывается в
настройки и выполняется «Играть».

**Проверка.** Тесты: `keys` (клавиши, кнопки, колесо, вписывание экрана,
перевод координат, накопление дробного движения), `x11` (раскладка,
пиксели), `nested` (жизнь процесса на поддельном сервере `sh -c 'echo N;
…'` и поддельной игре: игра видит `DISPLAY`, остановка гасит группу и
сервер, SIGKILL игре, игнорирующей SIGTERM, сервер без номера, лаунчер
отклоняется, аргументы Xvfb/Xephyr), `gametab` (старт → `cmd.txt`, правила
этапа 32, подписи, рабочий стол Wine), окно без экрана
(`play_in_a_tab_follows_a_fake_game_on_a_fake_server`: игра получает
`:77` и `-resolution 1280 720 -stream gf2 cuba`, остановка убирает
`cmd.txt`), корпус (`player_spawns_of_the_cities`: потоки уровней, точка
ведёт к своему объекту, ближайшая точка). Стенд — `docs/analysis/game-bench.md`
§17.

### 9.2 Живая связь (этапы 34, 49, 35, 48, 46, 47)

Код: `app/live.rs` (панель «Связь», поток связи, окно подтверждения,
установка модуля при «Играть»), `level_view` (`LevelView::live`,
`live_marks`), библиотека — `doctor_toolkit::live` (`Client`, `Endpoint`,
`ModuleInstall`, `restore_stale`, `loader::find`, `fake::FakeGame`,
`LiveOptions`), протокол и адреса — крейт `doctor-toolkit-live`, модуль —
`doctor-toolkit-live-asi` (вне workspace, `tools/build-live-module.sh`).
Исследование и протокол — `docs/analysis/live-link.md`, руководство —
`docs/guide/11-play.md` §11.7.

**Модуль при «Играть».** `PlayConfig::live` (`enabled`, `writes`;
`settings.toml`, `play.live`) — флажки на панели «Связь». `play()` сначала
убирает модуль прошлого запуска (`live_after_exit`, `restore_stale`), затем
`install_live`: нет загрузчика (`loader::find`) или собранного модуля
(`module_binary`: `DOCTOR_LIVE_MODULE`, рядом с программой,
`target/live/` репозитория) — предупреждение, игра идёт без модуля; иначе
`ModuleInstall::write` с конфигурацией `LiveOptions::config` (свободный
порт от 47801, новый токен). После старта поток связи подключается к этому
адресу; после выхода игры (`poll_session`) модуль убирается, журнал — в
`_doctor_toolkit/live/last.log`. Без «Играть» кнопка «Подключиться» берёт
порт и токен из `scripts/doctor_live.cfg` игры (`Endpoint::of_game`).

**Без записи в игру (этап 46).** `PlayConfig::overlay` (`OverlayMode`:
`auto` по умолчанию, `on`, `off`; `settings.toml`, `play.overlay`) —
выпадающий список «How the changes reach the game» в Play options.
`play()` при применении рабочего пространства или старте в уровне зовёт
`play::overlay::choose` (модуль собран, загрузчик есть, `exe` проходит
`edition::check_file`); при `Overlay` — `Overlay::build` (зеркало игры
ссылками в кэше, `Workspace::apply` туда, разница → подмены, `cmd.txt`
рядом) вместо `apply`, `cmd.txt` в игру не пишется, модуль ставится
`install_live_with` с `redirects` (живая связь выключена — без записи и
журнала, только подмены и управление), откат после выхода не нужен
(`Launched::revert_after` ложь), `poll_session` удаляет зеркало. При `auto`
без условий — предупреждение «записано в папку игры: причина» и прежний
путь. Строки — `play.overlay*` в `en.toml`/`ru.toml`. Руководство —
`docs/guide/11-play.md` §11.11, устройство — `docs/analysis/live-link.md`
§14.

**Ресурсы в памяти (этап 100).** `PlayConfig::streams` (`overlay::Streams`:
`rebuilt` по умолчанию, `patched`; `settings.toml`, `play.streams`) —
флажок «Put resources into streams in memory (experimental)» под списком
выше, недоступный при записи в папку игры. `play()` зовёт
`Overlay::build_with(…, config.streams)`; `install_live_with` получает два
списка — подмены файлов и заплатки ресурсов (`Config::redirects`,
`Config::resources`). Строки — `play.resources_in_memory*`. Устройство —
`docs/analysis/resources-in-memory.md`.

**CLI.** `play --apply|--mods [--no-game-writes|--write-game]`: решение
то же (`--write-game` — `off`, `--no-game-writes` и `--mods` — `on`); при
подмене `play` ждёт выхода игры, убирает модуль и зеркало и пишет,
сколько подменённых файлов игра открыла (`live::redirected_in_log` по
журналу модуля). `live install ИГРА [--apply [--workspace-dir DIR] |
--mods] [--cmd-txt=ТЕКСТ] [--files-log]` — то же для стенда: зеркало
остаётся до `live uninstall`. `live files [--json]` — запрос `Files`
(протокол 5): подмены, сколько раз игра открыла каждую. С
`--resources-in-memory` (`play` и `live install`; у последнего ещё
`--resources-dump`) изменённые потоки идут заплатками ресурсов; `play` в
конце пишет, сколько потоков модуль собрал и не было ли отказов
(`live::composed_in_log`); `live resources [--json]` — запрос `Resources`
(протокол 9), `live resource IDS [--out|--compare ФАЙЛ]` — запись
загруженного ресурса в таблице игры и его данные, `live resource-check
ПАПКА ПОТОК… [--original ИГРА]` — ресурсы потоков папки против памяти
игры.

**Поток связи** (`LiveState`, `worker`): пока нет связи — попытка раз в
2 с (тайм-аут 3 с); со связью — каждые 250 мс Status, Player, Camera (они
отвечаются из снимка последнего кадра игры, сразу) и действия из канала
(тайм-аут 40 с: игра под llvmpipe — 1–2 кадра/с). Результаты — в
`Shared` под мьютексом, панель читает копию и просит перерисовку. Обрыв
(ошибка ввода-вывода) — переподключение; отказ модуля (`Refused`) — текст
под кнопками, связь остаётся.

**Панель** (справа во вкладке «Игра», `Panel::right("live-link")`):
флажки «Играть», загрузчик и другие модули `.asi`, состояние связи,
издание (на чужом — красная строка и больше ничего), состояние цикла,
кадр, игровое время, время суток, игрок (щелчок — копия позиции), камера с
углом обзора; «Объекты рядом» (радиус, до 200, класс/расстояние/GUID;
щелчок — GUID в получатели, позиция в телепорт) и «Потоки». Запись (если
модуль её разрешает): телепорт X, Y, Z и курс, сообщение и получатель
(GUID в любом виде, пусто — всем), Lua (многострочное поле, вывод под
ним). Каждое действие записи открывает окно подтверждения
(`live_confirm`) — без него ничего не отправляется.

**Журнал игры и все объекты (этап 49).** Если модуль говорит на протоколе
2 (`Client::has_journal`), поток связи на каждом опросе читает новые
события журнала (`poll_journal`: `Events` после последнего номера, виды —
`LiveState::kinds`, общий `AtomicU8` с флажками панели) в `Shared::journal`
(последние 2000) и `Shared::fresh`. `play_frame` каждый кадр зовёт
`live_journal_to_log`: вывод игры и ошибки Lua из `fresh` идут в панель
«Журнал» редактора строками «игра: …» (`live::names::describe`), первая
ошибка Lua за связь — ещё и предупреждением; сообщения шины остаются на
панели «Связь». При связи панель в фоне читает имена
(`LiveNames::open(корень игры)`: все SimGroup игры и рабочего пространства;
`NamesState`) — GUID → имя, класс, поток; хэш → имя сообщения.

На панели: флажок «Все объекты» (с «только логика») вместо радиуса — кнопка
«Показать» шлёт `Cmd::World`; поле «Найти» — GUID или подстрока имени
(`LiveNames::search` → список GUID → `World`); список ответа (класс —
модуля или из SimGroup, слушатель вкл/выкл, поток, GUID, имя; фильтр;
щелчок — GUID в получатели, позиция в телепорт; `show_rows`). «Журнал игры»:
флажки «Вывод», «Ошибки Lua», «Сообщения» (сообщения модуль записывает,
только пока их просят), фильтр, «Очистить», число потерянных событий,
строки новые сверху, ошибки красным, стек вызовов — подсказкой при
наведении. С модулем протокола 1 флажок «Все объекты» недоступен с
подсказкой «модуль старее», журнала нет.

**Метки в уровне.** `BrowserApp` перед `LevelView::ui` кладёт в
`level.live` метки (`LiveState::marks`, только при живой связи);
`live_marks` рисует поверх картинки (`painter`, без перерисовки сцены)
точку и отрезок: игрок — зелёный, 1 м по направлению взгляда; камера —
жёлтая, 3 м. Обновляются, когда поток связи будит интерфейс. «Камера
редактора = камера игры» и обратно — ниже, этап 35.

**Отладка вживую (этап 35).** Код: `app/live_debug.rs` (раздел

## 10. Мастера (этап 23)

Код: `app/wizard/` (рамка и семь задач), `wizard_view.rs` (кнопки
«Wizard:» над ресурсами), библиотека — `workspace::Workspace::squash` и
`rollback`, `tunables` (параметры игры), `retexture` (текстуры модели),
`import::model::ImportPlan` (новые материалы, оттенки, id мешей),
`character::Character::load_with` (меши, которых ещё нет в игре).
Руководство — `docs/guide/15-wizards.md`.

**Рамка.** Мастер — вкладка `Pane::Wizard { id, kind }`; состояние — в
`BrowserApp::wizards` по `id` (как у других вкладок; вкладка из сохранённой
раскладки открывается заново с первого шага). Задача реализует `Task`:
свои шаги, рисование шага, проверку (`check` — пока шаг не готов, Next
неактивна и рядом написано, чего не хватает), действие при уходе с шага
(`leave`), сводку и запись. Рамка добавляет шаги **Summary** и **Done**,
кнопки Cancel, Back, Next и Record, а на Done — Test in game (команда Play),
Build mod… (мастер сборки мода) и Another task.

**Одна операция.** Перед записью рамка запоминает длину истории
рабочего пространства (`Tx::mark`); задача пишет как угодно (несколько
вызовов библиотеки — несколько операций), затем `Workspace::squash(mark,
"Wizard: …")` склеивает всё сделанное после отметки в одну операцию: для
каждого ресурса, потока и файла `before` первой правки и `after` последней,
правки, вернувшие всё как было, выпадают, у результата — название мастера;
номер операции — номер последней склеенной, так что `log_seq` манифеста
остаётся верным, журнал переживает перезапуск. Если запись упала на
середине, сделанное откатывается (`Workspace::rollback`: отмена до отметки
и удаление отменённого, без повтора). Мастер, который пишет по ходу
(размещение объекта: правки редактора уровня внутри мастера записываются
сразу), открывает отметку раньше, на уходе с первого шага; Cancel тогда
откатывает. Тест библиотеки: `operations_of_a_task_join_into_one_or_roll_back`.

**Задачи.**

| Мастер | Шаги | Что пишет |
|---|---|---|
| `retexture` | модель (меш, metamodel, `partsdb` с набором, объект уровня) → текстуры с ролями, копиями, материалами; экспорт PNG и «Edit in image program» → новые картинки рядом со старыми (новая — после сжатия, как в игре) | `import_texture` каждой копии каждой текстуры |
| `model` | модель → образец glTF (экспорт или Blender со слежением за файлом) → файл и коллизия → план и просмотр | `ImportPlan::commit` |
| `outfit` | база частей, слот, наборы → меш (клон части-образца, обязательно со скелетом; необязательный второй файл — меш меньшей детализации) → оттенки новых материалов → имя части, теги → просмотр персонажа (`CharacterView::preview_with` с ещё не записанным мешом) | план импорта новым набором (и вторым, `<имя>_lod2`, для меша меньшей детализации) + `partsdb` с частью (`models[0]`, `models[1]`), вариантом и `allow` |
| `params` | параметры списка `data/gf2/tunables.toml` по категориям или «Find attribute» → значения (одно для всех, множитель, по объекту) с проверкой | `tunables::apply`: все SimGroup одной `change_resources` |
| `texts` | таблица (языки первыми) → поиск, правка, замена, CSV во внешней программе | `set_string_table` |
| `place` | metamodel или файл новым набором, клон в зону, своя коллизия → редактор уровня внутри мастера (`levels` под id мастера; поле Add object заполнено и не меняется выбором) | правки редактора уровня, склеенные в одну |
| `zone` | новый поток (имя, родитель, способ загрузки, «пустая SimGroup») → ячейка мировой сетки (уровень — по родителю, коробка, сетка, имя) | `zone_ops::add_stream`, `add_simgroup`, `add_zone_cell` одной операцией; на Done — «Open the zone in the level view» |
| `package` | изменения → имя, автор, версия, описание, картинка → проверка (манифест, сборка игры, конфликты, установленные моды с теми же ресурсами, тот же id) | ZIP (`build_from_workspace`); рабочее пространство не меняется; на Done — Install in Mods |

**Список параметров.** `data/gf2/tunables.toml` (версия 1): строки

**Контекст.** Команда меню начинает с ресурса в Details; кнопки «Wizard:»

## 11. Оболочка в духе Unreal Engine 5 (этап 52)

Цель волны 7 (этапы 52–56) — редактор, похожий на Unreal Engine 5 по виду
и удобству. Этап 52 — оболочка: тема, главная панель инструментов, строка

### 11.1 Тема и значки

`crates/doctor-toolkit-mods/src/theme.rs` (с этапа 64 тема общая с Open Mod
Manager; в редакторе `app/theme.rs` её реэкспортирует). Тёмная тема — нейтральные серые с лёгким холодным

### 11.4 Раскладки

`app/layouts.rs`. Раскладка (`Arrangement`) — дерево плиток, в котором
документы заменены одним местом `Pane::Documents`, и список панелей-ящиков.
Применение раскладки (`arrange`) оставляет все открытые документы: они
встают на место `Documents` одной группой вкладок (если документов нет —
Welcome). Обратная операция `template_of` берёт док как есть, убирает
документы и ставит `Documents` в группу активного документа. Видимость
спрятанных панелей и доли разделений сохраняются.

Готовые раскладки (`Builtin`):

| Раскладка | Как устроена |
|---|---|
| **Level Editor** | документы (вид уровня) на ~¾ ширины; справа Outliner (за ним вкладки Zones и Files) над Details, 42/58; ящики — Content Browser, Log, Changes, History |
| **Resources** | прежняя раскладка: Files слева, документы, Details справа, Log и Changes под документами; ящик — Content Browser |
| **Asset Editor** (этап 56) | редактор ассета на ~¾ ширины, Details справа во всю высоту; ящики — Content Browser, Files, Log, Changes, History |
| **Cinematics** (этап 62) | вид уровня с роликом на ~70 % ширины, под ним Timeline; справа Cut-scene Preview над Details (за ней Outliner и Zones); ящики — Content Browser, Files, Log, Changes, History (§11.11) |

Свои раскладки: View → **Save layout as…** (и правый щелчок по вкладке)

своих раскладок с «Apply», «Rename», «Delete» (повторный щелчок —
подтверждение). View → **Layouts** — подменю: готовые и свои раскладки
(отмечена текущая), Save layout as…, Reset layout, флажок «Remember the

Layouts: <имя>» (и по-английски в русском интерфейсе). Reset layout
возвращает готовую раскладку
текущего экрана (для своей раскладки — готовую раскладку экрана).

**Раскладка по типу экрана** (`Screen`: `Level` — вкладка уровня,
`Resources` — потоки, поиск, все ресурсы; `Assets` (этап 56) — редакторы
ассетов: ресурс во вкладке, граф логики, скрипты, ролики; Welcome,
мастера, игра, проект экран не меняют). Когда документ другого экрана
открывается (`DockOp::Open`, `Focus`) или по его вкладке щёлкают, док
уходящего экрана запоминается (`Layouts::screens`), а для нового экрана
берётся его запомненный док или готовая раскладка; документы остаются.
Щелчки внутри вкладок экран не меняют: два документа разных экранов рядом
не перекладывают окно. Пока вкладка развёрнута (Ctrl+M), экран не
меняется. Флажок «Remember the layout of each screen» выключает это —
тогда Tools → Level editor, как раньше, разворачивает вкладку уровня на
всё окно.

Формат `layout.json`, версия 6 (этап 62: панели Timeline и
Cut-scene Preview; у версий 2–5 тот же вид):

```json
{
  "version": 6,
  "next_pane": 7,
  "tree": { "...": "дерево egui_tiles с панелями и документами" },
  "drawers": ["ContentBrowser", "Log", "Changes", "History"],
  "layouts": {
    "current": { "builtin": "level" },
    "screen": "level",
    "remember": true,
    "screens": { "resources": { "layout": { "user": "Мой" }, "arrangement": { "tree": {}, "drawers": [] } } },
    "user": [ { "name": "Мой", "arrangement": { "tree": {}, "drawers": ["ContentBrowser"] } } ]
  }
}
```

Версия 1 (`version`, `next_pane`, `tree`) читается: дерево остаётся,
ящиков и своих раскладок нет, текущая — Resources. Версия 2 (этап 52)
читается так (`layouts::parse`, `migrate`): панель `ObjectDetails` — это
теперь `Details` (`#[serde(alias)]`), и из двух Details остаётся одна —
видимая, иначе первая (если Details — ящик, ни одной плитки); где есть
Outliner, а Zones нет нигде, Zones становится вкладкой за Outliner (или
ящиком, если Outliner — ящик), чтобы зоны было где загружать. Так
переводятся текущий док, свои раскладки и запомненные раскладки экранов.
Версия 3 (этап 53) читается так: раскладка с Outliner (в дереве или в
ящиках), где нет панели History, получает её ящиком — как в Level Editor
(`layouts::add_history`); раскладки без Outliner не меняются. Версия 4 (этапы 54–55) читается так:
вкладки ресурсов и граф логики жили на экране Resources, поэтому если его
запомненная раскладка — своя (пользователя), она же становится раскладкой
нового экрана `assets` (`layouts::seed_assets`): кто настроил себе экран,
не теряет настройку; иначе редакторы получают готовую Asset Editor. При
сохранении пишется версия 5. Панель не бывает и в дереве, и в ящиках:
при чтении такая плитка убирается из дерева, `Documents` тоже.

### 11.5 Ящики

`app/drawer.rs`. Ящик — панель не в дереве, а поверх нижней части окна:
над группой документов (боковые панели остаются видны), на 45 % высоты
дока (край тянется, 20–85 %), с янтарной полосой и заголовком «Dock in
layout» и «×». Открывается кнопкой в строке состояния, View → панель
(Ctrl+1…6) или Ctrl+Space (Content Browser: его ящик, его плитка или,
если его нет нигде, новый ящик). Прячется повторным нажатием, Esc (если не
открыта палитра), щелчком мимо ящика и его кнопки (не пока открыто
всплывающее меню) и «×». Одновременно открыт один ящик.

Правый щелчок по вкладке любой панели → **Make drawer**: плитка уходит из
дерева в ящики (`DockOp::MakeDrawer`) и ящик сразу открывается. **Dock in
layout** в ящике (`DockOp::DockDrawer`) возвращает панель в дерево полосой
под всем доком (`dock::dock_below`, 28 % высоты); оттуда её можно
перетащить куда угодно. Ящики входят в раскладку и в `layout.json`.

### 11.6 Outliner, Zones и Details (этап 53)

Вкладка уровня — только вид. Всё остальное — три панели, которые
показывают «уровень впереди» (`BrowserApp::panel_level`: уровень активной
вкладки, уровень мастера впереди, нарисованный последним, любой открытый);
без уровня в них «No level is open» и кнопка Level editor. Код — в
отдельных модулях: `app/outliner.rs`, `level_view/zones.rs`,
`app/details/` (`object.rs`, `resource.rs`); механизм `set_hosted` этапа
52 убран. Каждая панель перетаскивается, делится, закрывается, делается
ящиком; ничего не зашито в вёрстку.

**Outliner** (`app/outliner.rs`). Дерево зона → класс → объекты строится
из `Level::groups` один раз на ревизию уровня (`LevelView::revision`:
загрузка, правка), строки — при изменении дерева, сворачивания или поиска;
рисуются только видимые строки (`ScrollArea::show_rows`, строка 19 pt),
так что 18 000 объектов `gf2/cuba/local` (324 зоны) не стоят ничего.
Строка: «глаз», «замок» (виден, если включён или под указателем), стрелка
сворачивания, имя (имя объекта или «класс #N»), справа число объектов
(у зоны и класса) или метка **new**/**edited**. Поиск — по имени, классу,
хэшу класса, GUID и `#номеру`: совпадения с зоной и классом, развёрнутые.
Выбор: щелчок — один объект, Ctrl — добавить/убрать, Shift — диапазон от
последнего щелчка по видимым строкам (Ctrl+Shift — добавить диапазон),
правый щелчок по невыделенному выбирает его. Выбор в виде раскрывает зону
и класс и прокручивает к объекту. Двойной щелчок — подлететь. Над списком:
F — подлететь, Ctrl+D — дублировать, Del — удалить выделенные.
Контекстное меню объекта: Fly to, Duplicate, Delete (с числом выделенных),
Show logic, Open the SimGroup, Copy GUID, Hide/Show, Lock/Unlock; зоны и
класса — Select N objects, Expand/Collapse, Hide/Show, Lock/Unlock.

«Глаз» и «замок» — множества `ObjectSet` вида (`level_view/scene.rs`):
SimGroup целиком (зона), класс в SimGroup (класс зоны), объект. Скрытое не
рисуется (`scene::fill`); запертое не выбирается щелчком в виде, у него нет
гизмо, поля Transform в Details недоступны (в Outliner выбрать можно —
посмотреть свойства). После правки, сдвигающей номера (удаление),
выделение, «глаз» и «замок» объектов следуют за объектами по GUID.

Метки **new** и **edited** (`level_view/marks.rs`): для SimGroup, которые
изменены в рабочем пространстве, версия игры (кэш на загрузку) сравнивается
с текущей по GUID: объекта нет в игре — new, есть, но пакеты, атрибуты,
связи или компоненты другие — edited.

**Zones** (`level_view/zones.rs`, `Pane::Zones`) — бывшая левая панель
вкладки уровня: «Load N zones», Clear, «Play from here», ход загрузки,
покрытие, фильтр и зоны с флажками; «Show» — что рисовать, LOD, текстуры,
свет, каркас, коллизия, классы во всех зонах, «Show the hidden objects»;
«Walk»; «Navigation graphs». В раскладке Level Editor — вкладка за
Outliner; кнопка «Zones…» в Outliner и «Choose zones…» в пустом виде
показывают её.

**Details** (`app/details/`). Один инспектор для того, что выбрано
последним (`details::Focus`): объект уровня (выбор в виде или в Outliner
любой вкладки уровня) или ресурс (выбор в Files, вкладке потока, поиске).
Решение: прежние `Details` (ресурс) и `ObjectDetails` (объект) слиты в
одну панель, как в UE; в старых раскладках обе читаются как она.
Объект — группы Transform, Model, Add object, Logic, Collision, Advanced
(`docs/levels.md` §6); ресурс — заголовок, ссылки и просмотрщики, как
прежняя панель Details. **Pin** оставляет панель на том, что она
показывает (объект — по SimGroup и номеру, ресурс — свой загруженный
документ). View → **Another Details panel** (и палитра) открывает
`DetailsCopy` — ещё одну панель, сразу закреплённую на том, что показывает
первая: два объекта рядом. Копия закрывается насовсем; её закрепление в
раскладку не пишется.

Перетаскивание на поле модели: тип payload — `app::dnd::DraggedAsset
{ type_id, id, stream, resource }` (`id` — последний из четырёх id
заголовка, тот, на который ссылается `CMD_SetModel`); поле принимает
`metamodel` из потока зоны объекта или её предков, иначе объясняет отказ.
Источник перетаскивания — Content Browser этапа 55 (§11.7): плитка
кладёт `DraggedAsset` в `egui::DragAndDrop` в начале протяжки.

Мастер «Place an object» показывает вид со своими Zones слева и Details
справа (`level_with_panels`): ему не нужна раскладка.

### 11.7 Content Browser (этап 55)

`app/content/` — обычная панель оболочки: по умолчанию ящик (Content
Drawer, Ctrl+Space), «Dock in layout» ставит её в раскладку, оттуда её
можно перетащить, разделить, сделать ящиком снова. View → **New Content
Browser** (и «+» на самой панели, палитра) открывает ещё один
(`Pane::ContentExtra { id }`) со своим местом, фильтрами и размером
плиток; он, как вторая Details, — панель, которая закрывается насовсем
(«Content Browser 2», «3»…).

**Устройство.**

- `catalog.rs` (без окна): дерево папок потоков (`FolderTree`: Content →
  `gf2` → `cuba` → поток `local`; поток — папка ассетов; новые потоки
  рабочего пространства — с меткой NEW), категории типов (`Category`:
  модели — `metamodel` и `mesh`, текстуры — `tg4h`, материалы, звуки —
  `sbk`, `mix`, `emx`, `auc`, SimGroup, скрипты, ролики, строки, диалоги,
  анимация, коллизия, прочее), спутники не показываются (`tg4d` при
  `tg4h`, `meshvolatile` при `mesh`), метки рабочего пространства
  (`Marks`: добавленный ресурс — NEW, изменённый — EDITED; текстура
  изменена, если изменён заголовок или данные). Имена — из индекса игры
  (глобальный поиск); у метамодели своего имени нет (её имена — состояния
  и части), у сеток имена вида `model_high`, `lodmodel01`, поэтому модель
  называется по первому материалу (`display_name`). До готовности индекса
  — id в hex.
- Справа — сетка плиток (`show_rows`: рисуются только видимые ряды) или
  список. Место — папка (подпапки и потоки; с фильтром типа — ещё ассеты
  всех потоков под ней, до 5000) или поток (его ассеты и добавленные
  рабочим пространством). Сортировка: категория (модели первыми), имя.
  Один и тот же ресурс из многих потоков показывается один раз; флажок
  **Copies** — все копии.
- Фильтры — «чипы» категорий (щелчок — одна категория, Ctrl+щелчок —
  добавить). **Поиск** — тот же разбор и поиск по индексу игры, что Ctrl+F
  (`navigation::search`: имена, hex-id, `type:`, `kind:`, `text:`), в
  фоновом потоке через 250 мс после ввода, с ограничением `stream:`
  показанной папкой и типами фильтра; до 20 000 результатов.
- Щелчок по ассету — Details (как выбор в списке), двойной — ресурс в
  своём редакторе (вкладка ресурса; добавленный рабочим пространством —
  его поток). Папка и поток: двойной щелчок — войти. Контекстное меню:
  Open, Show in the stream (вкладка потока с выделением и панель Files),
  Copy the key, **Clone into the workspace** (`create::clone_resources` со
  спутниками, новые id, одна операция «Clone …», отменяется Ctrl+Z),
  Export… (как Export выбранного), у звукового банка — Play.
- Звук: кнопка ▶ на плитке банка `sbk` декодирует его первый звук в
  фоне и играет (`audio_out`, как просмотр звука); ■ — стоп.
- Сверху — Back, Up, путь кнопками, Open stream; строка поиска со
  слайдером размера плиток (56–256), Tiles/List и «+»; под ней чипы.
  Строка состояния панели: число элементов, сколько превью сделано и по
  сколько миллисекунд (модели, текстуры), сколько прочитано с диска,
  память превью.

**Превью** (`preview.rs`, `thumb.rs`).

- Плитка при отрисовке просит превью (`Previews::get`); просьбы кадра в
  его конце уходят в очередь (`end_frame`). 2–4 рабочих потока берут
  самую свежую просьбу; просьбу, которую никто не повторил 1,5 с
  (плитка уехала с экрана), выбрасывают. Пока превью нет — цветной
  квадрат с типом и «бегущие точки».
- Ключ кэша — 64-битный хэш (`DataHash`, по 8 байт, стабилен между
  сборками) от версии рендера `RENDER_VERSION`, вида (модель/текстура),
  типа и id ресурса и хэша **данных**: сырые байты блоков ресурса в
  потоке (без распаковки; у текстуры — и её `tg4d`) или SHA-256 версии
  рабочего пространства (она уже есть в манифесте). Изменение данных в
  игре (apply) или в рабочем пространстве даёт новый ключ; новая версия
  рендера — тоже, и старые картинки удаляются при чистке.
- Диск: `<cache dir>/doctor-toolkit/previews/v<версия>/<2 hex>/<16
  hex>.png` (каталог кэша — тот же, что у индекса игры:
  `$DOCTOR_TOOLKIT_CACHE_DIR`, `$XDG_CACHE_HOME`, `~/.cache`,
  `%LOCALAPPDATA%`), у модели рядом `.box` — её габариты (24 байта) для
  призрака при перетаскивании. Запись атомарная. Чтение обновляет время
  файла; при первом открытии игры фоновая чистка удаляет другие версии и,
  если кэш больше 1 ГиБ, самые старые файлы до ¾.
- Память: превью — текстуры окна (256×256, с MIP-уровнями); больше 256 МиБ
  — забываются нарисованные давнее всего (не текущего кадра).
- Текстура: самый маленький MIP не меньше 256, декодируется
  (`pixels::decode`, нормали DXT5nm восстанавливаются) и уменьшается вдвое
  до 256, альфа — непрозрачная.
- Модель: метамодель раскрывается в сетки, как уровень
  (`level::model::expand`, самый подробный LOD; сетки ищутся из области
  потока, версии рабочего пространства первыми); сетки загружаются, как в
  просмотре моделей (`model_view::load_limited`: игровые поверхности —
  маски оттенков, кожа, волосы; материалы и текстуры по всей игре;
  текстуры не шире 256) и рисуются тем же `SceneRenderer`, что виды
  моделей и уровня, — своим экземпляром на устройстве окна (или на своём
  `wgpu`-устройстве, если окно на OpenGL) — в 256×256 на прозрачном фоне с
  MSAA; картинка читается обратно, края делятся на покрытие (альфа не
  домножена). Сеток в модели — до 48; когда текстуры рендера превью
  занимают больше 384 МиБ, он создаётся заново.
- Перед записью в файлы игры потоки превью закрываются (`release`), после
  — превью делаются заново (`files_changed`); место и фильтры панелей
  остаются.

**Перетаскивание.** Протяжка плитки кладёт `app::dnd::DraggedAsset`
(этап 53) в `egui::DragAndDrop`; у сетки — метамодель, которая её
показывает (из «used by» индекса), у ресурса рабочего пространства
`resource` — `usize::MAX`. Имя и габариты для призрака лежат рядом
(`level_view::drop::Ghost`, временные данные egui). У указателя — превью и
«Place <имя>». Ящик, из которого вытащили ассет, прячется, как в UE.
Принимают поле модели в Details (этап 53: замена модели объекта) и вид
уровня (`level_view/drop.rs`):

- пока модель над видом, луч из-под указателя бросается в коллизию Havok
  загруженных зон (мир «Walk» этапа 37, `Walk::world_for`: строится в фоне
  при первом перетаскивании, затем используется последний построенный);
  попал в поверхность, смотрящую вверх, — это и есть точка; в стену —
  шаг назад от неё по горизонтали и луч вниз до земли; в потолок — вниз
  из-под него (`ground_point`). Призрак — габаритный ящик модели, стоящий
  на точке, кружок и координаты;
- отпускание — то же `LevelAction::Add`, что «Add object»: одна
  отменяемая операция рабочего пространства. Шаблон (класс, логика,
  SimGroup) — выделенный объект, иначе ближайший объект с той же моделью,
  иначе ближайший с моделью; только тот, которому модель можно дать
  (`level::compat::model_problem`: объекту, который ломается, нужна
  ломающаяся модель). Модель берётся как есть, если игра найдёт её из
  потока SimGroup (тот же поток или предки), иначе клонируется в него;
- модель, отпущенная до готовности коллизии, ждёт её и встаёт потом; нет
  земли под указателем — объект ставится в 10 м по лучу, со словами в
  строке состояния.

`DOCTOR_TOOLKIT_GUI_CONTENT=<папка или поток>[;опции]` — предустановка
новых панелей для снимков: `filter=model,texture,…`, `size=<px>`, `list`,
`search=<текст>`, `select=<часть имени>` (выбрать первый такой ассет и
показать в Details); `<путь>/` — папка, когда есть поток с тем же именем.
`DOCTOR_TOOLKIT_GUI_SHELL=content` открывает ещё одну панель в раскладке.

**Цифры** (RTX 4070, Vulkan; `cargo test --release -p doctor-toolkit-gui
previews_of_a_large_stream -- --ignored` с `EARS_GF2_DIR`, превью одно за
другим): `gf2/globalfolder/characters/allcharacters` — 849 моделей по
4,5 мс и 1052 текстуры по 2,0 мс, всё за 5,9 с; из кэша — 0,1 и 0,2 мс,
0,3 с на все; кэш — 1901 PNG и 849 `.box`, 39 МиБ. `gf2/cuba/local` —
89 моделей по 5,5 мс (у 22 метамоделей только деревья — превью нет), 150
текстур по 2,9 мс, кэш 11 МиБ. В окне (2–4 рабочих потока, рендер и
диск делятся) первые превью модели потока — 20–80 мс.

### 11.8 Вид уровня как в UE (этап 54)

Вкладка уровня по-прежнему только вид (`level_view`), но управляется как
вьюпорт Unreal Engine 5. Новые модули: `level_view/viewbar.rs` (панель над
видом), `level_view/interact.rs` (клавиши, рамка, контекстное меню, End,
сетка), `app/history.rs` (панель History); `level_view/camera.rs` и
`level_view/gizmo.rs` расширены. Без видеокарты (OpenGL) вид всё равно
принимает клавиши и мышь (на нём надпись «нужна wgpu»), поэтому всё ниже
проверяется тестами без окна.

**Панель над видом** (левый верхний угол, полупрозрачная подложка):

| Кнопка | Что в ней |
|---|---|
| Perspective ▾ | проекция: Perspective, Top (сверху, север вверх), Front (вдоль −Z), Side (вдоль −X); ортографические виды центрируются на выделении или на точке впереди и возвращаются в перспективу с тем же направлением (`FlyCamera::set_projection`) |
| Lit ▾ | освещение: Lit, Unlit (без света), Wireframe (рёбра поверх сцены); там же текстуры, задние грани, LOD («By distance»/«Finest»), «Skip tiny» |
| Show ▾ | модели, маркеры, деревья, точки ИИ, коллизия выбранного, навигационные графы, сетка, статистика, «Show the hidden objects» — те же поля, что «Show» панели Zones: состояние одно |

Справа: включение привязки (значок) и шаги сдвига, поворота, масштаба —
те же, что на главной панели инструментов (`Snap` вида один); скорость
камеры (ползунок 0,5–2000 м/с, логарифмический); «?» — клавиши и мышь для
текущего режима камеры. Прежний текст с подсказками в углу вида убран:
статистика кадра и строки об объекте под указателем и выбранном — по
флажку **Stats** в Show; прогулка (§11 `docs/levels.md`) показывает свою
строку как раньше; короткие сообщения (Ctrl+A сверх предела, End) — под
панелью на 4 с.

**Камера и клавиши** (`camera::Controls`; вид в фокусе или под указателем,
не в поле ввода):

| Ввод | Как в UE (по умолчанию) | «Камера: как раньше» |
|---|---|---|
| ПКМ + мышь | обзор | обзор (и СКМ) |
| W A S D, Q E | полёт только при зажатой ПКМ (Shift — ×4) | полёт всегда (Shift ×4, Ctrl ×¼) |
| стрелки, Page Up/Down | движение без ПКМ | движение |
| колесо | вперёд-назад; при зажатой ПКМ — скорость камеры (×1,004 на точку прокрутки) | вперёд-назад |
| СКМ | панорама (точка у опоры идёт за указателем) | обзор |
| ЛКМ в пустом месте | вперёд-назад и поворот (режимы Move/Rotate/Scale) | — |
| Alt + ЛКМ | облёт опоры (центра выделения или точки в 20 м впереди) | облёт |
| Alt + ПКМ | к опоре и от неё | — |
| Q, W, E, R | Select, Move, Rotate, Scale (без ПКМ) | — |
| пробел | следующий режим гизмо (Move → Rotate → Scale) | — |
| 1, 2, 3 | Move, Rotate, Scale | Move, Rotate, Scale |
| F | подлететь к выделенному (без выделения — всё) | то же |
| End | опустить выделенное на землю | то же |
| Ctrl+A, Esc | выделить всё показанное, снять выделение (Esc во время протяжки отменяет её) | то же |
| Ctrl+D, Del | дублировать, удалить выделенное — одна операция | то же |
| ПКМ без протяжки | контекстное меню | то же |

Решение: старое поведение — настройка Edit → Preferences → «Camera: as
before» (`[level] classic_camera`), чтобы не ломать привычку; по умолчанию —
как в UE. В ортографических видах ПКМ и СКМ панорамируют, колесо меняет
масштаб, стрелки (и W A S D Q E при ПКМ) двигают вид; ЛКМ-протяжка — всегда
рамка. Прогулка (Walk) и следование за камерой игры переводят вид в
перспективу.

**Выделение.** Щелчок — объект; Ctrl + щелчок — добавить или убрать;
Shift + щелчок — добавить. Рамка — протяжка ЛКМ из пустого места в режиме
Select, с Shift (добавить), с Ctrl (убрать) или в ортографическом виде:
выбираются нарисованные объекты (не скрытые «глазом», не отфильтрованные
Show, не отсечённые LOD), чей центр (центр сферы меша или начало объекта)
внутри рамки; запертые «замком» не выбираются. **Ctrl+A** — все объекты
загруженных зон, кроме скрытых (глаз, классы Show) и запертых, не больше
1000 (`SELECT_ALL_LIMIT`: каждая правка выделения пишет столько объектов;
сверх предела выбираются первые по порядку и показывается сообщение).

**Гизмо на нескольких объектах.** Гизмо стоит в центре рамки, охватывающей
начала выделенных незапертых объектов; локальные оси — главного
(последнего выбранного). Одна протяжка меняет всех: сдвиг — на один вектор,
поворот — вокруг оси через центр (позиции поворачиваются вокруг него),
масштаб по оси — у каждого вдоль его собственной оси, а смещения от центра
вдоль оси гизмо растягиваются так же; равномерный масштаб (кубик в центре
гизмо Scale) — все строки матрицы и смещения от центра. У Move между осями
— квадратики плоскостей (сдвиг в плоскости двух осей, привязка по каждой).
Привязка — как прежде: всегда или с Ctrl (`gizmo::Handle`, `grab`,
`change`, `apply_change`). Отпускание записывает **одну операцию**
(`LevelAction::Many`; сдвиги объектов одной SimGroup пишутся одной записью
группы — `record_many`). **Alt + протяжка гизмо** — копии: исходные
объекты стоят, копии (голубоватые, рисуются поверх, пока тянется) едут;
отпускание — `LevelAction::DuplicateTo` на каждый объект (дубликат на месте
и его матрица — одна операция), всё вместе — одна операция; выделяются
копии. Esc во время протяжки возвращает всё. Если в Details включено
«Гизмо двигает и в игре» (этап 47, §9.2), отпускание гизмо двигает в запущенной
игре каждый сдвинутый объект (копии Alt — нет; разрешение спрашивается
один раз, как и для одного объекта).

**End** опускает выделенное на землю: нужна коллизия уровня этапа 37;
если её нет, она строится в фоне (сообщение «Building the collision of the
level…»), затем для каждого объекта луч идёт вниз из нижней точки его
мешей (без видеокарты — из начала объекта), пропуская коллизию самих
выделенных объектов (`Walk::ground_below`, `World::below_except`); если
внизу ничего нет — ещё раз с высоты 1 км. Объект сдвигается по вертикали
так, чтобы низ встал на найденную поверхность; всё — одна операция.

**Контекстное меню** (ПКМ без протяжки): объект под указателем (с
видеокартой — id-проход, на программном адаптере — луч) выделяется, если
не выделен; пункты — Fly to, Duplicate (N), Delete (N), Put on the ground
(N), Show in the Outliner (раскрывает и прокручивает Outliner к объекту и
показывает панель — `LevelAction::ShowInOutliner`), Show logic, Copy GUID
(GUID всех выделенных, по строке), Select all, Play from here (у объекта
под указателем, иначе у камеры).

**Сетка** (Show → Grid): в перспективе и сверху — горизонтальная, на
высоте выбранного объекта (без выбора — ниже трёх четвертей объектов), под
точкой, куда смотрит камера; спереди и сбоку — в плоскости вида. Шаг 0,1,
1, 10, 100 м по расстоянию, каждая десятая линия ярче; линии с проверкой
глубины.

**Transform в Details для нескольких объектов** (`app/details/object.rs`):
если показанный объект выделен вместе с другими, поля Transform правят
всех выделенных незапертых объектов с матрицей; где значения различаются,
поле показывает «—». Протяжка поля сдвигает каждого на одну величину,
введённое значение получают все; вид показывает всех на новом месте,
отпускание — одна операция (`transforms_action` → `LevelAction::Many`).

**История отмены** (`Pane::History`, `app/history.rs`, View → Undo history
panel, Ctrl+7): все операции рабочего пространства от старых к новым,
первая строка — «Start (no edits)», текущая позиция подсвечена янтарным,
отменённые — курсивом. Щелчок по строке отменяет операции после неё или
повторяет отменённые до неё (`BrowserApp::go_to_history`: `undo`/`redo` по
одной, затем одно обновление уровней и документов). В Level Editor панель —
ящик; как любую панель её можно закрепить в раскладке.

Снимки (`tools/screenshots.sh`): `level-select` — шесть выделенных объектов
с общим гизмо и сеткой, Details с «—»; `level-history` — три правки и ящик
History. Опции `DOCTOR_TOOLKIT_GUI_LEVEL`: `nearby=N` (N объектов с
моделью ближе всего к `look`), `grid`, `stats`, `top`;
`DOCTOR_TOOLKIT_GUI_SHELL=drawer=history`.

Не сделано: закладки камеры (Ctrl+цифры в UE), привязка к поверхности,
опора гизмо по главному объекту (в UE — переключатель), несколько видов в
одной вкладке (четыре вьюпорта).

Перетаскивание модели из Content Browser (этап 55, §11.7, `level_view/drop.rs`)
работает в новом виде: рамка модели рисуется под панелью над видом, а
брошенная модель — правка `Add` — становится выделенной (главным
объектом), так что её сразу двигает гизмо и показывает Details.

(`ResourceViewer::tab_body` = `Fill`); просмотрщики `Scroll` в такой

под полосой, как раньше; `Toolbar` — только кнопки на полосе. Заголовок
ресурса (тип, ids, размеры, «Save data as…», hex) и ссылки Uses / Used by
— в Details. Те же команды ассета (`asset_tab::AssetCmd`) — в контекстном
меню ярлыка вкладки и (Open, Show in the stream, Copy the key, Export…) в
Content Browser. View → новый Content Browser не нужен: «Show in Content
Browser» открывает главный (ящик или панель) на потоке ресурса с
выделенным ресурсом (`Content::reveal`).

**Details** (`details::Focus::Document(DocRef)`, `app/details/document.rs`)
следует за редактором так же, как за объектом уровня: щелчок во вкладке,
по её ярлыку, открытие вкладки. Просмотрщик отдаёт выбранное через
`ResourceViewer::has_inspector`/`inspector`, граф логики —
`LogicEditor::inspector`, скрипты — `ScriptEditor::inspector_ui`, ролики —
`MoviesWindow::details_ui`. Своя колонка редактора остаётся как запасной
вариант: её рисуют, только когда главная Details не видна (закрыта,
закреплена Pin, вкладка развёрнута) — `BrowserApp::details_follow`, в
просмотрщики — `ViewContext::details`. Pin закрепляет Details и на
редакторе (`Pinned::Document`).

**Главная панель** с редактором впереди (`toolbar::Context::Asset`):
Undo и Redo, для ресурса — **Browse** (Show in Content Browser); кнопка
Movies открывает вкладку роликов и подсвечена, когда она впереди.

**Клавиши** (одинаковые во всех редакторах; «?» на полосе каждого, раздел

### 11.11 Ролик в виде уровня (этап 62)

Ролик правится в виде уровня, как в Sequencer UE; всё — панели оболочки.
Руководство — `docs/guide/16-cutscenes.md` §15.3a.

**Устройство.**

- `doctor_toolkit::cutscene::edit` (без окна) — ключи кадра на моменте:
  `set_camera` (шесть кривых `0x304`: ключ на моменте в пределах
  `KEY_TOLERANCE` = 1/60 с меняется, иначе вставляется с наклоном кривой в
  этой точке; углы — рядом с текущими, `unwrap_degrees`), `set_focal_length`
  (`0x307`), `set_actor` (`0x206`: ключ положения и/или поворота; новый
  ключ положения сохраняет поворот места; актёр без `0x206` получает его
  там, где создан), `delete_key` (последний ключ кривой остаётся),
  `key_times`, `key_at`, `next_key`, `euler_of` (углы камеры из матрицы,
  ближайшее из двух решений), `quaternion_of`, `focal_length` (мм из
  вертикального поля зрения 16:9).
- `level_view/cine.rs` — слой ролика над видом уровня (`LevelView::cine`):
  актёры (`cutscene_view::preview::draw_actors`, общая с просмотром
  вкладки), камера кадра пирамидой (`frustum_lines`), пути камер всех
  кадров и точки ключей, путь выбранного актёра; выбор щелчком (проекция
  точек на экран, 14 pt — работает и без видеокарты), гизмо
  (`interact::Target::cine`, протяжка `Drag::cine`), отпускание —
  `LevelAction::Cutscene(CineAction::Transform)`; полоса ролика внизу вида
  (Play, время, «через камеру кадра», персонажи, ключ из вида, «×»).
  Экземпляры ролика добавляются после экземпляров уровня
  (`base_instances`) и кэшируются по `Layer::revision`; ключ рендера —
  `RenderKey::cine`.
- `app/cinema.rs` — сессия ролика (`BrowserApp::cine`): загруженный ролик
  (из рабочего пространства), шкала, Play со звуком (`SoundPlayer`),
  выбор зон в фоне (`cutscene_view::world::choose_streams` →
  `LevelView::load_streams`), правки (`cine_action` → `cine_edit`: кадр
  на курсоре → `SeqMaster::to_bytes` → `Workspace::set_resource`, одна
  операция), панели **Timeline** (`Pane::Timeline`) и **Cut-scene
  Preview** (`Pane::CutscenePreview`, `Preview` с камерой кадра), Details
  камеры и актёра (`details::Shown::Cutscene`), выгрузка видео.
- **Общий курсор**: `cutscene_view::SharedCursor` — время, Play и
  запросы вкладок (`toggle`, `moved`); приложение кладёт его в
  `ViewContext::cursor`, вкладка ролика того же папочного потока берёт
  курсор оттуда и отдаёт свои перемотки и Play обратно; сессия двигает
  время в `cine_tick` до дока, вид уровня получает его в `Layer::time`.
  После любой правки, отмены и повтора (`after_edit`) сессия перечитывает
  ролик (`reload_cine`).
- Команды: `ViewAction::OpenInLevel` (кнопка вкладки ролика),
  `AssetCmd::OpenInLevel` (Asset ▾ и меню ярлыка вкладки кадра),
  контекстное меню Content Browser; View → Timeline panel (Ctrl+8),
  Cut-scene Preview panel (Ctrl+9); Level → Cut-scene: play or pause,
  Cut-scene: camera key from the view. Outliner — ветка **Cut-scene**
  (камера и актёры кадра на курсоре).
- Видео (`cutscene_view/render.rs`, `doctor_toolkit::cutscene::video`):
  `Job::run` рендерит `Preview::render_pixels` (кадр камеры, мир загружен
  заранее `Preview::load_world`) кадр за кадром; `write_video` отдаёт
  кадры кодеру VP6 потоком YUV4MPEG2 (кадры рендерятся, когда кодер их
  читает, — весь ролик в памяти не держится), PNG и ffmpeg (сырой RGBA в
  stdin, звук — WAV рядом). В редакторе — свой `SceneRenderer` на
  устройстве редактора в фоновом потоке; без окна —
  `doctor-toolkit-gui --render-cutscene` (`GpuContext::headless`), его
  запускает `doctor-toolkit cutscene render`.

**Раскладка Cinematics** (`Builtin::Cinematics`): вид на ~70 % ширины,
под ним Timeline (30 % высоты), справа Cut-scene Preview над Details (за
ней Outliner и Zones); ящики — Content Browser, Files, Log, Changes,
History. Включается при открытии ролика, если панели Timeline нет ни в
доке, ни в ящиках. `layout.json` — версия 6 (новые панели); версии 1–5
читаются как раньше.

Найдено при проверке: скиннинг копировал боксы частей из позы привязки —
вид уровня (он отсекает по боксам) не рисовал персонажей, которые клип
увёл от начала координат; теперь `skin` пересчитывает боксы частей.
Позированные копии одного ролика в виде уровня и в Preview — разные
ключи мешей (`Loaded::salt`); загрузка уровня бюджет мешей только
повышает.

Снимок — `tools/screenshots.sh … cutscene-level`
(`DOCTOR_TOOLKIT_GUI_CINE=time=<s>,characters,select=camera|<актёр>,nomarkers,behind=<м назад>/<м вверх>,through,view=<глаз>/<цель>`).

Тесты (`app/cine_tests.rs`, `cutscene::edit`, `cutscene::video`,
`cutscene_view/render.rs`, `app/layouts.rs`, корпус
`camera_keys_change_in_place`): открытие ролика мини-игры в виде уровня
(зоны, раскладка Cinematics, ветка Outliner, Details камеры, закрытие);
протяжка гизмо камеры — ключ на курсоре, повторная — правка того же
ключа, две отмены; гизмо актёра — ключ его пути, удаление ключа; ключ из
вида (положение, направление, поле зрения), команда Level, фокусное
расстояние; общий курсор вкладки и вида, Play двигает время и актёра,
пауза со стороны вкладки; «через камеру кадра» и панель Preview;
несколько кадров в PNG и VP6 (без видеокарты — пропуск); корпус —
ключ камеры каждого кадра правится на месте: 259 кадров, байты отличаются
только в изменённом значении (и 252 ключа фокусного расстояния).

## 12. Проверки и справка в окне (этап 103, пакет 103-C)

Всё, что в MCP дают `validate`, `check_refs`, `lookup_hash`, `kb_search`,
`kb_note` и `game_types`, есть в окне.

**Check edits и панель Findings** (`app/checks.rs`). Tools → Check edits
проверяет правки рабочего пространства до записи в игру: каждый изменённый
ресурс читается своим разборщиком, объекты SimGroup могут показать свои
модели, добавленные правкой ссылки сходятся, конфликты с файлами игры,
сообщения изменённых SimGroup, открытый проект. Проверка одна на все
поверхности — `doctor_toolkit::validate::validate` (параметры `Params`,
итог `Report` с находками `Finding`): её зовут инструмент MCP `validate`,
команда `doctor-toolkit check-edits <игра> [--filter] [--project] [--json]`
(ошибки — ненулевой код) и редактор. Находки показывает панель Findings:
ошибки и предупреждения, место находки — ссылка, открывающая ресурс.
Та же проверка идёт перед записью: «Apply to game» (меню, панель
инструментов, панель Changes без конфликтов) при ошибках ничего не пишет,
показывает Findings и сообщает об ошибке; кнопка «Apply anyway» панели
пишет несмотря на ошибки. Запись с подтверждением конфликтов (панель
Changes), прямой режим и Play идут без проверки. Шаг Check мастера Package
a mod добавляет находки проверки к своим: ошибки о выбранных изменениях не
дают собрать мод.

**Check references.** В Content Browser в меню потока и папки — «Check
references»: `create::ReferenceChecker` в отдельном потоке выполнения,
итог — в панели Findings (место находки открывает ресурс игры).

**Панель Hashes.** Tools → Hashes: имя под каждой хеш-функцией движка и в
скольких ресурсах встречается каждый хеш; если текст читается как хеш
(`0x9cf57f36`, восемь шестнадцатеричных цифр, десятичное число) — известные
имена с источником, тег типа ресурса, число ресурсов и первые десять;
щелчок по хешу — поиск по игре.

**Вкладка Knowledge base** (`app/knowledge.rs`). Help → Knowledge base:
заметки `docs/kb/` вшиты в редактор при сборке (`build.rs`, как в сервере
MCP). Слева поиск (`kb::search`), справа заметка: заголовки, списки,
таблицы, блоки кода, ссылки; ссылка на другую заметку открывает её, кнопка
`<` возвращает; ссылки наружу открываются в браузере, ссылки на документы
вне базы только называются в строке состояния. В Details объекта уровня и
ресурса — ссылка «Knowledge base note» на заметку класса
(`classes/<Класс>.md`) и типа ресурса (`resources/<тег>.md`). Раздел Data
types той же вкладки: списки значений (`game_types::enums`) с фильтром,
сообщения по части имени (хеш, род, сколько шлют и слышат), атрибуты
класса с известным смыслом (`LogicSchema::typed_attrs` — та же функция, что
у инструмента `game_types`).

**Навигационный граф.** В панели узла (Zones → Navigation graphs) — тип
графа флажками и кнопка Rebuild R-tree; без рук — `act=nav-rtree` и
`act=nav-flags:<hex>` предустановки `DOCTOR_TOOLKIT_GUI_LEVEL` при выбранном
узле (`nav=<граф>:<узел>`).

**Окно Mods.** Install… сначала показывает, что в каждом файле мода
(`mods::file_info`: имя, версия, автор, ресурсы и потоки, связи,
исполняемый код, проверка целостности), и только потом ставит; файл,
который не читается, поставить нельзя. В меню карточки мода — «Save as
file…» (`ModManager::export`).

Тесты: `app/checks_tests.rs` (проверка правок, удержание Apply, находка в
мастере Package a mod, ссылки потока и папки, хеши, разбор заметок, вкладка
базы знаний и типы данных, предустановки), `level_view/nav.rs`
(R-дерево и флаги графа), `crates/doctor-toolkit-mods/src/tests.rs` (вопрос
перед установкой и запись мода файлом).
