# 19. Проект: мод как папка исходников

Проект — способ вести мод как проект движка: нужные ресурсы игры лежат в
папке файлами в обычных форматах (PNG, JSON, Lua, glTF/FBX/USD), каждый
поток — своя папка, имена — из индекса игры. Вы правите файлы в любых
программах, а **сборка** записывает в рабочее пространство только то, что
изменилось, одной отменяемой операцией. Оттуда — как всегда: **Apply to
game**, **Play** или мод. Устройство и форматы — `docs/project.md`.

## Создать проект

В редакторе: **Tools → Project browser**, вкладка **Project** → **New
project**: перечислите потоки через запятую (`gf2/frontend,
gf2/text/dd7d7050`) или отметьте **From the changes of the workspace** —
тогда в проект попадут ресурсы, которые вы уже правили. **Create project…**
спросит новую или пустую папку.

В командной строке:

```sh
doctor-toolkit project new "$GAME" my_mod --stream gf2/frontend --stream gf2/text/dd7d7050
doctor-toolkit project new "$GAME" my_mod --from-workspace
```

Внутри папки:

- `project.toml` — название и id мода, автор, версия, игра и её издание,
  язык, нужные моды (`[dependencies] mods = [...]`), формат текстур и
  моделей;
- `src/<поток>.str/<тип>/<имя>.<расширение>` — файлы ресурсов и
  `stream.toml` с их типом, id, политикой памяти;
- `shared/` — то, что одинаково в нескольких потоках, один раз;
- `patches/` — ваши правки объектов уровня (ниже);
- `.doctor/` — служебные данные (`build.json` можно удалять).

Какие ресурсы чем становятся:

| Ресурс | Файл | Правится |
|---|---|---|
| текстура | PNG (кубические — DDS) | в GIMP, Krita |
| строки | JSON | в текстовом редакторе |
| логика уровня, metamodel, переменные, части персонажей | JSON | значения |
| диалог, события речи, кадры ролика | JSON | весь документ |
| скрипт Lua | `.lua` | исходник |
| модель | `.glb` (или FBX, OBJ, USD) | в Blender |
| банк анимаций | `.bin` и `.events.json` | события клипов |
| граф путей, риг, редактор лица | `.bin` и `.view.json` | только `.bin` (JSON — для чтения) |
| остальное | `.bin`, `.apx` | как есть |

## Править и собирать

Откройте файл: в браузере проекта выберите его и нажмите **Open in
external editor** (программа из настроек, глава 12) или правьте в
проводнике. Вкладка сама замечает изменённые файлы (раз в 2 секунды):
у файла — оранжевая метка «изменено», на кнопке — **Build (n)**.

**Build** записывает изменённые файлы в рабочее пространство; файлы, которые
вы не трогали, не пересобираются (картинки и модели не перекодируются).
Вся сборка — одна операция: **Undo** (Ctrl+Z) убирает её целиком. Если
файл не собрался (например, сломан JSON), в журнале будет его путь и
причина, остальные файлы соберутся.

```sh
doctor-toolkit project status my_mod        # что изменилось
doctor-toolkit project build my_mod         # собрать изменённое
doctor-toolkit project build my_mod --apply # и сразу записать в игру
```

Метки состояния:

| Метка | Значит |
|---|---|
| серая — без изменений | файл как при создании |
| оранжевая — изменено | файл правился после последней сборки |
| зелёная — собрано | правка собрана в рабочее пространство |
| синяя — расходится | в рабочем пространстве уже другое (отменили сборку, правили ресурс в редакторе): **Build** вернёт версию проекта, `project pull` заберёт правку редактора в файл |
| красная | файла нет или правится файл только для чтения |

## Свои объекты в уровне

Чтобы не править большой JSON уровня, положите рядом файл правок
`patches/<поток>.str/simgroup/<имя>.toml`:

```toml
[[object]]
name = "door_01"                 # или guid = "…"
position = [10.0, 0.0, -4.5]

[[new]]
name = "my_lamp"                 # новый объект — копия шаблона
copy = "lamp_02"
position = [12.0, 0.0, -4.5]
```

У нового объекта GUID получается из его имени и id мода: при каждой сборке
он тот же, поэтому ссылки на объект (сообщения логики, точка появления для
быстрого входа в уровень) не ломаются. Если игра или JSON изменились и
объекта из `[[object]]` больше нет, сборка предупредит и применит остальное.

## Мод из проекта

**Build mod…** во вкладке или

```sh
doctor-toolkit project mod my_mod -o my_mod.zip --build
```

пишет мод (`.zip`, глава 6) из изменений, которые сделал проект, с
названием, версией и автором из `project.toml`. Другие правки рабочего
пространства в него не попадают.

## Из Python

```python
import doctor_toolkit as dt
game = dt.Game("/path/to/The Godfather II")
project = dt.Project.create(game, "my_mod", streams=["gf2/frontend"], index=game.index())
# … правка файлов …
print(project.build())
project.build_mod("my_mod.zip")
```

## Ограничения

- Новые ресурсы из новых файлов проект не добавляет (файл помечается «не
  входит в проект»); удалить ресурс нельзя.
- Графы путей, таблицы точек укрытий, модели деревьев и банки звуков пока
  собираются только из `.bin`.
- **Build all** перекодирует все картинки и модели: данные станут
  немного другими, чем в игре, даже без правок.

**Pull.** Кнопка **Pull** на вкладке Project делает обратное сборке:
записи проекта, которые разошлись с рабочим пространством (состояние
*out of sync* — ресурс правили в редакторе или другим инструментом),
получают в файлах проекта версию рабочего пространства. То же делают
`doctor-toolkit project pull` и инструмент `project_pull`.
