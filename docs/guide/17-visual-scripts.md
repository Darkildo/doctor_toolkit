# 17. Свои скрипты из узлов

Скрипт для игры можно собрать из узлов, как Blueprint: «когда пришло
сообщение — подождать две секунды — послать другое сообщение». Тулкит
переводит граф в Lua 5.0, компилирует его и кладёт в уровень так, как
устроены скрипты самой игры: ресурс `lua` и объект `LuaAudioScript`,
который его запускает. Скрипт слышит те же сообщения, что триггеры и
`MultiManager` миссий, и посылает свои — так он включается в логику
миссии. Подробности и справочник узлов — `docs/scripts.md`.

## Как устроен скрипт

- **События** запускают цепочки: *On start* (скрипт запустился), *On
  message* (пришло сообщение), *On timer* (прошло N секунд), *On stop*.
- **Цепочка** — узлы, соединённые белыми exec-проводами: что за чем
  делать. *Branch* выбирает ветку, *Delay* ждёт, *Sequence* выполняет
  несколько веток по очереди, *Gate* и *Do once* ограничивают проходы.
- **Данные** идут цветными проводами: числа, текст, логические значения,
  позиции. Чистые узлы (математика, сравнения, «время игры», «позиция
  игрока») считаются там, где их результат нужен.
- **Действия**: послать сообщение, записать переменную игры, запустить
  таймер, вызвать функцию игры, оставить файловую пробу для проверки.

## Редактор

**Tools → Script editor** открывает окно редактора:

1. Слева палитра: щелчок по узлу добавляет его на холст (или правый щелчок
   по холсту → **Add node**).
2. Соедините пины, протянув провод от выхода к входу: белые провода —
   порядок действий, цветные — данные (зелёный — числа, розовый — текст,
   красный — да/нет, жёлтый — позиции).
3. Выделенный узел настраивается справа (имя сообщения, секунды таймера,
   значения входов без провода). Без выделения справа — настройки
   скрипта: запуск при загрузке или по сообщению, переменные.
4. Внизу: **Problems** — ошибки (красный значок на узле, щелчок по строке
   показывает узел), **Lua** — что получится, **Dry run** — прогон на макете
   игры: `send:audio_init_delay wait:6`.
5. **Deploy to level** — записать скрипт в поток уровня (поле **Level
   stream**, по умолчанию `gf2/globals_global`) через рабочее
   пространство; затем **Apply to game**. **Save** сохраняет граф в файл.

## Пример: реле с задержкой

Файл `hello.json`:

```json
{
  "format": "doctor-toolkit-script", "version": 1,
  "name": "hello",
  "start": { "on_load": true },
  "nodes": [
    { "id": 1, "kind": "event.message", "params": { "message": "audio_init_delay" } },
    { "id": 2, "kind": "flow.delay", "inputs": { "seconds": 5 } },
    { "id": 3, "kind": "action.send_message", "inputs": { "message": "doctor_noon" } }
  ],
  "links": [
    { "from": [1, "then"], "to": [2, "exec"] },
    { "from": [2, "then"], "to": [3, "exec"] }
  ]
}
```

Проверка без игры — скрипт выполняется на макете API игры:

```sh
T=./target/release/doctor-toolkit
$T script-compile hello.json            # Lua-текст и ошибки с номерами узлов
$T script-run hello.json send:audio_init_delay wait:6
#    5.000  timer dts_hello_d2
#    5.000  send doctor_noon
```

## В уровень

```sh
GAME="/path/to/The Godfather II"
$T script-deploy "$GAME" gf2/globals_global hello.json   # в рабочее пространство
$T workspace apply "$GAME"                              # записать в игру
```

`gf2/globals_global` загружается с любым уровнем — скрипт там работает
всегда. Поток города или задания — пока загружен он. Главное меню
(`gf2/frontend`) не подходит: там нет симуляции, и тулкит откажет.

Запуск: по умолчанию при загрузке уровня (`"on_load": true`);
`--start-message ИМЯ` — когда придёт сообщение, `--stop-message ИМЯ` —
остановка. Повторный `script-deploy` обновляет тот же скрипт, `workspace
undo` отменяет, `script-remove` убирает. Граф сохраняется рядом с рабочим
пространством (`_doctor_toolkit/workspace/scripts/hello.json`) и попадает в
мод вместе с правками.

## Что учесть

- Ошибки скриптов игра не показывает. Узел **File probe** (`debug.probe`)
  и флаг графа `"trace_errors": true` оставляют следы в трассировке файлов
  стенда (`docs/analysis/game-bench.md`).
- *On start* выполняется на первом такте игры после запуска: скрипт,
  запущенный при загрузке, иначе слал бы сообщения объектам, которых ещё
  нет.
- Переменные игры, созданные скриптом, — целые числа.
- Часть функций API (звук, группы, полиция, машины) помечена в справочнике
  как не проверенная в игре.
