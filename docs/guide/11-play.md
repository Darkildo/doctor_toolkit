# 11. Запуск игры

## 11.1 Кнопка Play

**Play** на панели инструментов (Tools → Play, **F5**) запускает открытую
игру. Как именно — задаётся в **Play options…** (кнопка «…» рядом, Tools →
Play options…) для каждой игры отдельно:

| Способ | Что выполняется |
|---|---|
| Automatic | то, что нашёл автопоиск для этой папки ([2.1](02-first-run.md)): Steam, Lutris, Heroic, Bottles, ярлык Steam; иначе Wine (в префиксе, внутри которого лежит игра, или в префиксе по умолчанию), на Windows — сам `godfather2.exe` |
| Steam | `steam -applaunch 24830` (или `steam://rungameid/24830`, если команды `steam` нет); так же запускается игра под Proton |
| Steam shortcut | `steam://rungameid/…` для сторонней игры, добавленной в Steam |
| Wine | `wine godfather2.exe` в папке игры с `WINEPREFIX`; можно указать свою программу `wine` и `WINEDLLOVERRIDES`. Если в папке игры лежит загрузчик ASI (`dinput8.dll`), по умолчанию добавляется `WINEDLLOVERRIDES=dinput8=n,b`, иначе Wine не загрузит его |
| Proton | `proton run godfather2.exe` с папкой `compatdata` (`STEAM_COMPAT_DATA_PATH`) — для копии игры вне Steam |
| Lutris | `lutris lutris:rungame/<игра>` |
| Heroic | `heroic://launch?appName=<игра>&runner=<runner>` |
| Bottles | `bottles-cli run -b <бутылка> -e godfather2.exe` (или через Flatpak) |
| The executable | сам `godfather2.exe` (Windows) |
| Command of your own | своя команда: `{exe}` — исполняемый файл, `{dir}` — папка игры; запускается без оболочки, слова с пробелами — в кавычках |

Окно показывает получившуюся команду целиком. Внизу окна — два флажка:

- **Apply the workspace before starting** — записать изменения рабочего
  пространства в игру перед запуском (как Apply to game). Если записать
  нельзя (например, файлы изменил кто-то ещё), игра не запускается.
- **Put the original files back after the game exits** — когда игра
  закроется, вернуть оригиналы (как Revert game). Изменения остаются в
  рабочем пространстве.

Так удобен цикл «правка → проверка в игре → правка»: оригиналы в игре
возвращаются сами, а следующий Play снова запишет свежие изменения.

## 11.2 Пока игра запущена

Редактор следит за процессом игры (раз в полторы секунды; `godfather2.exe` —
и обычный, и под Wine или Proton, в том числе запущенный не из редактора).
Пока игра идёт:

- вместо кнопки Play — надпись **Game running**;
- Apply, Revert, Restore originals, «Write to game at once» и запись модов
  в окне Mods не выполняются: запущенная игра держит старые данные и может
  упасть, когда подгрузит изменённый поток. Правки по-прежнему копятся в
  рабочем пространстве;
- менеджер модов `doctor-toolkit-mods` тоже не пишет в игру.

Когда игра закрылась, в журнале появляется «The game has exited», запись
снова разрешена, и, если выбран откат, оригиналы возвращаются. Если игра не
появилась за 3 минуты (лаунчер не смог её запустить), об этом пишется
предупреждение.

Для Steam, Lutris, Heroic и Bottles редактор видит только процесс игры:
лаунчер может открыть своё окно и ждать, это нормально.

## 11.3 Из командной строки

```sh
doctor-toolkit play "$GAME" --dry-run                    # показать команду, ничего не делать
doctor-toolkit play "$GAME"                              # запустить способом Automatic
doctor-toolkit play "$GAME" --apply --revert-after       # записать, играть, вернуть оригиналы
doctor-toolkit play "$GAME" --method wine --prefix ~/.wine-gf2
doctor-toolkit play "$GAME" --method lutris --launcher-game godfather-2
doctor-toolkit play "$GAME" --method command --command 'wine "{exe}"'
```

`--dxvk` (способ `wine`) рисует игру видеокартой через DXVK: `d3d9.dll`
лежит в папке игры только пока она запущена (подробности — 11.5):

```sh
doctor-toolkit play "$GAME" --method wine --dxvk --stream gf2/cuba
doctor-toolkit play "$GAME" --method wine --dxvk --dry-run   # где DXVK, команда
```

`--wait` ждёт, пока игра закроется; `--revert-after` ждёт и возвращает
оригиналы. Если игра уже запущена, `play` отказывается. Команды, которые
пишут в игру (`workspace apply`, `restore`, `mods apply` …), при запущенной
игре предупреждают.

### Сразу в уровень

Игра умеет начинать прямо в уровне — без заставок, меню, профиля и
сохранения. Свои параметры она читает не из командной строки, а из файла
`cmd.txt` в папке игры; `play` пишет его на время запуска и убирает после
выхода игры (поэтому с этими параметрами `play` ждёт её выхода):

```sh
doctor-toolkit play "$GAME" --stream gf2/cuba                 # Гавана
doctor-toolkit play "$GAME" --stream gf2/miami --windowed --resolution 1280x720
doctor-toolkit play "$GAME" --stream gf2/cuba --list-spawns   # точки появления
doctor-toolkit play "$GAME" --stream gf2/cuba --spawn 26d7c8323dfa11aa464f574c45523130
```

- Поток — один и верхнего уровня: `gf2/cuba`, `gf2/miami`, `gf2/queens`,
  карты сетевой игры (`mp_mall/mp_mall`). С двумя потоками и с дочерним
  (`gf2/cuba/local`) игра падает.
- `--spawn` — объект `PlayerSpawn` этого потока (`--list-spawns`). Точка с
  сообщением (`sends checkpoint_001_load`) начинает миссию. Своя точка —
  копия точки по умолчанию в другом месте: `level duplicate ИГРА gf2/cuba
  6 1 --offset=X,Y,Z`, затем `--apply --spawn НОВЫЙ_GUID`.
- Прогресс сюжета — как у новой игры; сохранения игрока не трогаются.
- В редакторе то же задаёт таблица `play.start` игры в `settings.toml`
  (`streams = ["gf2/cuba"]`, `spawn = "…"`, `windowed = true`,
  `resolution = [1280, 720]`); кнопка «Играть» пишет и убирает `cmd.txt`
  так же; выбирать поток и точку удобнее в окне (раздел 11.4).
  Подробности — `docs/analysis/launch-flags.md`.

## 11.4 Старт: как обычно, в город, в точку

В **Play options…** (Параметры «Играть») под способом запуска — раздел
**Старт**:

- **Как обычно** — заставки, меню, профиль, сохранение. `cmd.txt` не
  пишется.
- **Сразу в город** — поток верхнего уровня из списка игры: `gf2/cuba —
  Гавана`, `gf2/miami — Майами`, `gf2/queens — Нью-Йорк`, сетевые карты
  (`mp_mall/mp_mall` …). Игрок появляется у точки по умолчанию.
- **В точку** — список объектов `PlayerSpawn` выбранного потока с номером,
  пометкой «по умолчанию», сообщением, которое точка запускает
  («запускает checkpoint_001_load» — такая точка начинает миссию), и
  положением. Поле **GUID точки** принимает и свою точку: копию точки по
  умолчанию, сделанную «Дублировать» во вкладке уровня, `level duplicate`
  или кнопкой «Играть отсюда» (11.6). Точка, которой ещё нет в файлах игры
  (она только в рабочем пространстве), помечается — «Играть» запишет её
  перед запуском, если включено «Применять рабочее пространство».

Под списком — правила этапа 32: **один поток верхнего уровня**; с
несколькими потоками или с дочерним (`gf2/cuba/local`) игра падает, и
редактор такой запуск не начинает; точка должна быть в этом потоке; сюжет —
как у новой игры, места с прогрессом — через сохранение.

Раздел **Окно**: «Показывать игру во вкладке редактора» (11.5), «В окне
(-windowed)» для обычного запуска и «Размер экрана» (`-resolution W H`).
Внизу окна видна команда запуска и строка `cmd.txt`, которую получит игра.
Всё хранится в `settings.toml` (`[games."…".play.start]`, `in_tab`).

## 11.5 Игра во вкладке редактора

Если включено «Показывать игру во вкладке редактора» (на Linux — по
умолчанию), «Играть» открывает вкладку **Игра** и показывает игру в ней.

- **Linux.** Игра запускается на своём X-сервере: **Xvfb**, если он
  установлен (экран только в памяти, нужен пакет `xvfb`), иначе **Xephyr**
  внутри скрытого окна (пакет `xserver-xephyr`; нужен X-дисплей — сеанс X11
  или XWayland). На рабочем столе ничего не появляется. Для способов Wine и
  Proton игра идёт в виртуальном рабочем столе Wine размером с экран вкладки
  (`explorer /desktop=doctor_toolkit,1280x720`): без него игра под Wine
  останавливается окном «Your Graphics Card does not meet … minimum
  requirements». Для своей команды это нужно сделать самому:
  `wine explorer /desktop=doctor_toolkit,1280x720 "{exe}"`.
- **Windows.** Игра запускается в окне (`-windowed -resolution W H`), и её
  окно встраивается во вкладку. Эта часть собрана, но на Windows не
  проверялась; если окно не встроилось, игра остаётся в своём окне. На
  Windows вкладка по умолчанию выключена.
- Способы Steam, Lutris, Heroic и Bottles передают игру другой программе:
  вкладка её не покажет, игра откроется в своём окне (об этом —
  предупреждение).

**Управление.** Щелчок по картинке отдаёт игре мышь и клавиатуру: клавиши,
кнопки, колесо и движение мыши (поворот камеры) идут в игру, а не в
редактор; горячие клавиши редактора в это время не действуют. **Esc**
возвращает мышь редактору (кнопка «Отпустить мышь» — тоже); **Shift+Esc**
или кнопка «Esc в игру» нажимает Esc в игре (меню паузы). Мышь отпускается
и при переключении на другую вкладку или окно.

**Кнопки вкладки:** «Остановить» (игра закрывается, через 4 с —
принудительно; файлы возвращаются, как после обычного выхода),
«Перезапустить» (закрыть и запустить с тем же стартом; рабочее пространство
снова применяется), «Снимок» (PNG последнего кадра в папке настроек,
`screenshots/`), «Параметры…». Строка под кнопками — старт, сервер, размер,
кадры в секунду и время чтения кадра.

**Частота кадров.** Внутри своего X-сервера Wine рисует игру через OpenGL,
а у такого сервера нет DRI3 — OpenGL идёт программно (llvmpipe): меню
24–29 кадров/с, уровень — **1–2 кадра/с** при 1280×720. Включите в Play
options флажок **Ускорение через DXVK**: тогда игра рисуется видеокартой
через Vulkan — в уровне **27–35 кадров/с** при 1280×720 и около 60 при
800×600 (проверено на RTX 4070, Linux Mint). Сама вкладка успевает 60
кадров/с; предел теперь — передача кадра в X-сервер без DRI3.

Для DXVK нужны:

- DXVK на компьютере — тулкит его не скачивает, а берёт 32-битный
  `d3d9.dll` у Lutris, Proton, Bottles или Heroic (или из папки в
  переменной `DOCTOR_DXVK`);
- 32-битный Vulkan видеокарты: загрузчик (`libvulkan1:i386`) и драйвер —
  NVIDIA: `libnvidia-gl-<версия драйвера>:i386`; AMD и Intel:
  `mesa-vulkan-drivers:i386` (Arch: `lib32-vulkan-icd-loader`,
  `lib32-nvidia-utils`, `lib32-vulkan-radeon`, `lib32-vulkan-intel`);
- способ запуска **Wine** (Proton рисует через свой DXVK и так).

Чего не хватает, окно пишет под флажком. «Играть» кладёт `d3d9.dll` в папку
игры на время запуска, задаёт `WINEDLLOVERRIDES=d3d9=n,b` (вместе с
`dinput8=n,b` ASI-загрузчика) и убирает файл после выхода; префикс Wine и
система не меняются. Свой `d3d9.dll` в папке игры (другой DXVK, загрузчик)
не трогается — тогда ускорение не включается. В строке вкладки видно,
каким способом идёт отрисовка. Из командной строки — `play --dxvk`.

## 11.6 Играть отсюда

Во вкладке уровня (левая панель) — кнопка **Играть отсюда**. Она берёт
поток верхнего уровня загруженных зон (`gf2/cuba` для
`gf2/cuba/local/…`) и положение камеры и предлагает:

- **Играть от этой точки** — ближайшая точка появления потока (точки,
  запускающие миссию, не предлагаются) и расстояние до неё;
- **Сделать точку здесь и играть** — копия точки по умолчанию в месте
  камеры, в рабочем пространстве (как «Дублировать»); «Применять рабочее
  пространство перед запуском» включается само. Держите камеру у земли:
  игрок появляется там, где камера, и падает вниз.

Выбранная точка записывается в старт (11.4), и игра запускается. После
выхода оригиналы возвращаются, если включено «Возвращать оригинальные
файлы»; точка остаётся в рабочем пространстве для следующих запусков.

На стенде (этап 33): точка, сделанная так на балконе отеля в Гаване, —
игрок появился в ней с точностью до миллиметра (чтение памяти).

**Управление при старте сразу в уровень.** Без меню игра создаёт игрока
раньше, чем назначает ему клавиатуру, и сама этого не исправляет: игрок
стоит, мышь не поворачивает камеру, работает только `Esc` (этап 45,
`docs/analysis/live-link.md` §5.1). Поэтому при старте «сразу в город» и
«в точку» «Играть» ставит на этот запуск модуль связи (раздел 11.7) даже
при выключенной живой связи: он отдаёт игроку клавиатуру, запись по сети
у него выключена, после выхода он убирается. Нужен ASI-загрузчик в папке
игры; без него «Играть» предупреждает, что игрок не сможет ходить, — тогда
начните с сохранения.

## 11.7 Живая связь с игрой

Редактор видит запущенную игру и может на неё влиять через свой модуль в
игре — `doctor_live.asi` (этап 34, `docs/analysis/live-link.md`).

**Что нужно.** ASI-загрузчик в папке игры: Ultimate ASI Loader в виде
`dinput8.dll` (он же грузит другие моды `.asi`). Тулкит его не скачивает и
не ставит; если загрузчика нет, панель «Связь» об этом говорит, и «Играть»
запускает игру без модуля. Под Wine способ запуска Wine сам добавляет
`WINEDLLOVERRIDES=dinput8=n,b`; в Steam с Proton это строка запуска
`WINEDLLOVERRIDES="dinput8=n,b" %command%`. Модуль собирается
`tools/build-live-module.sh` (в архиве выпуска он уже лежит рядом с
программами). Модуль работает только с изданием PC 1.0.789.0; в другой
сборке он ничего не делает и сообщает об этом.

**Как включить.** Вкладка **Игра**, панель **Связь** справа: флажок
«Живая связь: ставить модуль в игру при „Играть“» и, если нужно менять
игру, «Разрешить телепорт, сообщения и Lua». «Играть» кладёт
`scripts/doctor_live.asi` и `scripts/doctor_live.cfg` на время запуска и
убирает их после выхода (как `cmd.txt`); журнал модуля остаётся в
`_doctor_toolkit/live/last.log`. Для уже запущенной игры с модулем —
кнопка «Подключиться».

**Что видно:** состояние игры (меню, уровень, номер кадра, игровое время,
время суток), игрок (позиция и курс; щелчок копирует позицию), камера
(позиция, направление, угол обзора). Во вкладке уровня зелёная точка —
игрок, жёлтая — камера игры; они двигаются вместе с игрой. «Объекты
рядом» — объекты SimGroup вокруг игрока: класс, расстояние, GUID;
«Потоки» — что игра загрузила.

**Журнал игры** (там же, раздел «Журнал игры»): что печатают скрипты игры
(`print` — со скриптом и строкой), её отладочный вывод, ошибки Lua — и
скриптов игры, и своих из поля Lua — со стеком вызовов (наведите на строку
ошибки), сообщения логики с получателями (флажок «Сообщения»; пока он
включён, модуль их записывает; сообщения, которые игра шлёт каждый кадр,
показываются не чаще 4 раз за 5 секунд). Фильтр оставляет строки с
нужным текстом. Вывод и ошибки игры попадают и в панель **Журнал**
редактора со словом «игра:»; первая ошибка Lua за запуск ещё и всплывает.

**Все объекты.** Флажок «Все объекты» показывает не только объекты рядом, а
все объекты SimGroup, которые сейчас есть в игре, — и логику без
положения: реле, переключатели, триггеры, скрипты (флажок «только логика»
оставляет их одних). У каждого — класс, поток, включён ли его приёмник
сообщений, GUID и имя (имена и классы редактор берёт из SimGroup игры и
рабочего пространства; первые секунды после подключения он их читает).
Поле **Найти** ищет по GUID или части имени; если объект с таким именем
есть в файлах, но не в игре, — его поток сейчас не загружен.

**Что можно сделать** (каждый раз с подтверждением):

- **Телепорт** — в X, Y, Z (Y вверх) и, если задан, с курсом; кнопка
  «Позиция игрока» подставляет текущую, щелчок по объекту в списке — его
  позицию. Игра переносит игрока так же, как своим объектом
  `PlayerTeleportRelay`, с затемнением экрана.
- **Сообщение** — имя сообщения логики (или `0x`-хэш) всем слушателям, как
  его шлёт игра, или одному объекту по GUID (щелчок по объекту в списке
  подставляет его GUID).
- **Lua** — строка Lua 5.0 в состоянии скриптов игры; возвращённые
  значения и ошибки показываются под полем (`return GetSimTime()`).

Меняется только запущенная игра, не её файлы; но то, что сделали
сообщения и Lua, игра может записать в сохранение.

**Из командной строки** — то же для скриптов и стенда:

```sh
doctor-toolkit play ИГРА --live --live-writes --stream gf2/cuba
doctor-toolkit live status --game ИГРА
doctor-toolkit live player --game ИГРА [--json]
doctor-toolkit live camera --game ИГРА
doctor-toolkit live objects --game ИГРА --radius 30 [--class VariableSwitch]
doctor-toolkit live objects --all [--logic] [--stream cuba] [--names] --game ИГРА
doctor-toolkit live find venue_132_vault --game ИГРА   # или GUID
doctor-toolkit live log --game ИГРА [--follow] [--filter TEXT] [--errors | --messages] [--names] [--json]
doctor-toolkit live teleport 274.5,0.5,368.5 --yes --game ИГРА
doctor-toolkit live send boundary_fade_out [--to GUID] --yes --game ИГРА
doctor-toolkit live lua 'return GetSimTime()' --yes --game ИГРА
doctor-toolkit live install ТЕНЬ --writes    # в теневую копию для стенда
doctor-toolkit live fake --writes            # поддельная игра для проб
```

`--game` берёт порт и токен из `scripts/doctor_live.cfg`; без него —
`--port` и `--token`. Запись без `--yes` не выполняется. `--names` (и
поиск по имени в `live find`) читает имена из SimGroup папки `--game` и её
рабочего пространства. Модуль старой версии (без журнала) отвечает на всё,
кроме `live log`, `objects --all` и `find`; поставьте модуль этой версии
тулкита.

## 11.8 Отладка вживую

Поверх живой связи (§11.7) редактор отлаживает логику в запущенной игре:
показывает сообщения на графе логики по мере их прохождения, ставит игру
на паузу и на точки останова, ведёт журнал своих скриптов-Blueprints,
сводит камеру редактора и камеру игры и подменяет текстуры без перезапуска
(этап 35, `docs/analysis/live-link.md` §12). Нужен модуль этой версии
тулкита (протокол 3); со старым модулем эти кнопки недоступны.

**Сообщения на графе логики.** На вкладке графа логики включите
**«Вживую»** (строка под панелью инструментов). Пока связь есть, узлы и
провода вспыхивают, когда через них проходит сообщение игры: получатель —
зелёной рамкой, отправитель — оранжевой, провод — голубым с бегущей
точкой; над узлами — счётчики («in 12 out 3»). Справа, над свойствами
узла, — раздел **«Вживую: сообщения игры»**: сколько сообщений пришло,
сколько коснулось этого графа и сколько журнал потерял, и лента последних
сообщений (новые сверху): время, сообщение, «отправители -> получатели».
Наведите на строку — её узлы и провода подсветятся; щелчок выделяет их.
«Только выделенное» оставляет сообщения выделенных узлов, «И вне графа»
показывает и те, что этого графа не коснулись. **«Стоп-кадр»** замораживает
картинку и ленту (новые сообщения ждут и войдут, когда отпустите) — если
игру останавливать не нужно. **«Сохранить…»** пишет ленту строками JSON
(тот же вид, что у прогона логики без игры).

Игра называет сообщение и его получателей, но не отправителя: если
сообщение может послать несколько узлов графа, вспыхивают все. Сообщения,
которые игра шлёт каждый кадр (такты, отрисовка), журнал записывает по
одному не чаще 4 раз за 5 секунд, а остальные — числом раз в секунду; на
графе они считаются полностью.

**Пауза и точки останова.** Панель **Связь**, раздел **«Отладка»**:

- **Пауза** — игра встаёт в следующем кадре уровня; **Кадр** — один кадр
  и снова стоп; **Продолжить**. Пока игра стоит, панель отвечает:
  объекты, потоки, телепорт, сообщения, Lua.
- **Точки останова**: на сообщении (имя или `0x`-хэш; с GUID — только
  когда его получит этот объект), на тексте вывода (`print` скрипта), на
  любой ошибке Lua. Игра встаёт **до** доставки сообщения — прямо внутри
  своего кода; в этом месте отвечает только чтение (объекты, потоки),
  а запись и Lua ждут «Продолжить». Если сообщение послали вы сами
  (кнопкой «Послать»), игра встанет в следующем кадре.
- Остановленная игра сама продолжит через «стоять не дольше» (по
  умолчанию 120 с, до 900), чтобы её не забыть на паузе.

На графе логики точку останова ставит выделенный узел: в разделе
«Вживую» — кнопки сообщений, которые он слушает («Остановить игру, когда
этот объект получит:»). Узлы с точкой останова отмечены красной точкой,
а получатель сообщения, на котором игра стоит, — красной рамкой; на
панели инструментов вкладки — «Продолжить» и «Кадр».

**Журнал своих скриптов.** В редакторе скриптов (§17) в настройках
скрипта включите **«Отмечать узлы в игре»** и разместите скрипт заново:
каждый узел, срабатывая, печатает `dt:имя:узел;`. Внизу вкладка **«Игра»**:
какие узлы сработали и когда, ошибки Lua с узлом, на котором они
случились (щелчок — выделить узел). На графе сработавшие узлы вспыхивают,
над ними — «×N». У выделенного узла — флажок **«Остановить игру на этом
узле»**: игра встанет, когда узел сработает.

**Камера.** Во вкладке уровня при связи внизу картинки — строка «Игра:»:

- **«Следовать за камерой игры»** — вид редактора движется вместе с
  камерой игры (положение, направление, угол обзора);
- **«Игрока сюда»** — перенести игрока на место камеры редактора лицом
  туда, куда она смотрит (с подтверждением);
- **«Камера → игра»** — игра рисует из камеры редактора (свободная
  камера), пока вы не нажмёте **«Камера игры»**. Мир игра подгружает
  вокруг игрока: далеко от него он может быть пустым.

**Текстуры без перезапуска.** Кнопка **«Отправить изменённые текстуры»** на
панели «Связь» ставит текстуры, изменённые в рабочем пространстве
(импорт DDS или PNG, мастер ретекстура), прямо в запущенную игру — картинка
меняется в следующем кадре. Так можно, если у новой текстуры тот же
размер, формат и число уровней, а её поток сейчас загружен; иначе нужен
перезапуск уровня. Модели так не подменяются.

**Из командной строки:**

```sh
doctor-toolkit live break --message doctor_ping [--to GUID] --game ИГРА
doctor-toolkit live break --print 'dt:my_script:4;' --once --game ИГРА
doctor-toolkit live break --lua-error --hold 60 --game ИГРА
doctor-toolkit live break --game ИГРА              # точки и где стоит игра
doctor-toolkit live break --message X --wait --game ИГРА   # ждать остановки
doctor-toolkit live break --clear --game ИГРА
doctor-toolkit live pause --game ИГРА
doctor-toolkit live continue [--step] --game ИГРА
doctor-toolkit live freecam 283.9,20,380 --yaw 180 --pitch -60 --yes --game ИГРА
doctor-toolkit live freecam --release --yes --game ИГРА
doctor-toolkit live texture [0xИМЯ] --yes --game ИГРА     # изменённые текстуры
doctor-toolkit live fake --writes --activity        # поддельная игра с движением
```

`live log --messages` показывает и строки «messages without own events»
— сколько сообщений прошло без отдельной записи.

## 11.9 Мир и состояние игры

Для проверок без прохождения редактор меняет мир и состояние запущенной
игры: время суток, потоки, деньги, переменные сюжета (этап 48,
`docs/analysis/live-link.md` §13). Нужен модуль этой версии тулкита
(протокол 4) и разрешённая запись; каждая запись — с подтверждением.

Панель **Связь**, раздел **«Мир и состояние»**:

- **Прочитать** — время суток и его скорость, дождь, деньги игрока, его
  команда, текущий чекпоинт, запросы потоков и переменные из списка
  раздела.
- **Время суток** — `ЧЧ:ММ` и **«Поставить время»**: небо, свет и туман
  меняются в следующем кадре (это ключи времени суток). **Скорость** —
  игровых секунд в секунду (в игре 60; 0 останавливает часы — удобно для
  снимков ночью), **«Скорость уровня»** возвращает прежнюю.
- **Погода.** Дождь в игре — объект `WeatherManager`, но ни один уровень
  одиночной игры его не создаёт: дождя нет, и раздел так и пишет. Небо и
  туман меняет время суток.
- **Деньги** — **«Поставить»** или **«Добавить»** (отрицательное число
  отнимает); счётчик на экране меняется сразу, игра записывает их как
  доход.
- **Команда** — семь мест: открыто ли, кто занимает (имя — из SimGroup),
  ранг и специальности. Только чтение.
- **Потоки** — имя потока (`gf2/cuba/local/yuri/high/filler_056_01`) и
  **«Загрузить»** или **«Выгрузить»**. Модуль делает по одному запросу:
  пока предыдущий не загружен (или игра сама грузит поток), новый
  отклоняется — два запроса подряд роняют игру. Выгружается только то, что
  загрузила связь; поток игры — с флажком **«и игровой»** (его объекты
  пропадут из-под ног игры: только для дальних зон). Ниже — последние
  запросы: готово, идёт или «ждать перестали» (через 2 минуты).
- **Переменные сюжета** — имя из `variabledictionary` (например
  `Use_Surveys`) или `0x`-хэш, **«Прочитать»**, значение и
  **«Поставить»**: игра реагирует сразу — `VariableWatcher` срабатывает,
  `VariableSwitch` возьмёт новое значение при следующей проверке.

Миссии: панель показывает текущий чекпоинт (после старта сразу в уровень
его нет) и чекпоинты загруженных потоков; переход на чекпоинт связь не
делает — прогресс задают переменные сюжета и сообщения (`live send`).

**Из командной строки** (запись — с `--yes`):

```sh
doctor-toolkit live time --game ИГРА                      # 16:31:05, день 0, скорость
doctor-toolkit live time 23:30 --rate 0 --yes --game ИГРА # ночь, часы стоят
doctor-toolkit live time 12:00 --default-rate --yes --game ИГРА
doctor-toolkit live weather --game ИГРА
doctor-toolkit live money [--set 500 | --add 12345] [--yes] --game ИГРА
doctor-toolkit live family [--names] --game ИГРА          # команда и семьи
doctor-toolkit live mission [--names] --game ИГРА         # чекпоинты
doctor-toolkit live var get Use_Surveys Bridge_test --game ИГРА
doctor-toolkit live var get --find tutorial --game ИГРА   # по части имени
doctor-toolkit live var set Use_Surveys 1 --yes --game ИГРА
doctor-toolkit live stream load gf2/cuba/local/yuri/high/filler_056_01 --wait --yes --game ИГРА
doctor-toolkit live stream unload gf2/cuba/local/yuri/high/filler_056_01 --wait --yes --game ИГРА
doctor-toolkit live stream list --game ИГРА               # загруженные и запросы связи
```

Пример проверки: `live var set Use_Surveys 1 --yes`, затем `live send
check_should_use_surveys --yes` — игра показывает окно опроса; с
`Use_Surveys 0` то же сообщение ничего не делает. Так проверяются ветки
логики, не доходя до места по сюжету.

## 11.10 Неполадки

- Под Wine игре нужна папка профиля `Documents\EA Games\The Godfather™ II`;
  если игра пишет «Unable to find your profile», запускайте её с
  `LC_ALL=en_US.UTF-8` (раздел [9](09-troubleshooting.md)). Для способа Wine
  это можно сделать своей командой: `env LC_ALL=en_US.UTF-8 wine "{exe}"`.
- Wine создаёт папку профиля ссылкой на `~/Документы`: сохранения игры
  лежат там. Это поведение Wine, редактор его не меняет.
- «The game did not start»: проверьте способ в Play options — команда видна
  целиком, её можно запустить в терминале.
- В журнале игры нет вывода: модуль записывает его, только если в
  `scripts/doctor_live.cfg` нет `journal=0` («Играть» без живой связи
  ставит модуль только ради управления и без журнала); строка «модуль
  записывает только часть» — перехват не поставился, причина в журнале
  модуля.
- Панель «Связь» ждёт модуль и не подключается: нет загрузчика или Wine
  грузит свой `dinput8.dll` (нужен `dinput8=n,b`); журнал модуля —
  `scripts/doctor_live.log` (после выхода — `_doctor_toolkit/live/last.log`);
  если его нет, модуль не загрузился.
- Во вкладке 1–2 кадра в секунду: включите «Ускорение через DXVK» в Play
  options (11.5); строка под флажком скажет, чего не хватает. Журнал DXVK —
  `_doctor_toolkit/dxvk/godfather2_d3d9.log` в папке игры.
- Редактор закрыт или упал, пока игра шла во вкладке: X-сервер вкладки
  уходит вместе с редактором, игра без него завершается. Оставшиеся
  `cmd.txt`, модуль связи и `d3d9.dll` убирает следующий запуск «Играть».
- Мод GF2ASI открывает своё окно консоли и забирает фокус: игра свёрнута и
  стоит, пока ей не вернуть фокус (щелчок по её кнопке на панели задач).
